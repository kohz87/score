# 3.17.0 — Take over a bot's desktop (design note)

Owner, 2026-11-02: "can we integrate into interact-able bot screen?" → "yes, do the take over mock-up". Mock-up:
https://claude.ai/artifact/9dWyfTob55Y3TZW3d2xDdY (boards "Take over"). This changes a standing rule: the agent's screen
was read-only by design (AGENTS.md "not a remote desktop"; 3.3.0 brief, decision 135). Lead-coded: adapter boundary and
security. Needs this note's review (below) before any code.

## What Hermes already has (read from its source, `tools/bot_desktop/lease.py`)
- A per-profile **lease** on disk (`<HERMES_HOME>/bot-desktop/lease.json`, fcntl-locked): `holder: agent|human`,
  `viewer_id`, `since`, `reason`, `epoch` (bumped on every change).
- `acquire(viewer_id, reason)`: a human takes control, **last writer wins** (a second viewer evicts the first).
  `release(viewer_id, epoch=…)`: hands back; with `viewer_id` only that holder can release.
- While a human holds it, `computer_use` and the browser tools refuse to act **and to screenshot** ("they may be typing a
  credential"). Scope: a tool-level fence. A program the agent started by hand against the display is not stopped
  (Hermes' documented same-user boundary).
- Hermes' own viewer path (Desktop app: `display.lease.acquire`, ticket, `/api/display/ws`) needs the dashboard
  credential, which Score must not read (decision 135).

## Design
1. **Taking and returning the lease goes through Hermes' own functions, never a file write by Score.** Two new
   server → plugin commands on the existing command channel (`rewind-broker.ts` / `score_bridge/commands.py`):
   `desktop_take { viewerId, reason }` and `desktop_hand_back { viewerId, epoch }`, run in the profile's gateway, calling
   `lease.acquire` / `lease.release(viewer_id=…, epoch=…)` through `score_bridge/hermes_private.py` (the only place that
   names Hermes internals). They answer the resulting lease (`holder`, `viewerId`, `epoch`). `viewerId` =
   `score:<random per takeover>`, never reused.
2. **Input** goes over the RFB socket Score already reads (`<profile home>/bot-desktop/rfb.sock`). That direct socket
   bypasses Hermes' input filter, so **Score is its own filter**: the encoder gains KeyEvent and PointerEvent only
   (no ClientCutText, no SetDesktopSize); every input batch is sent only after reading the lease (read-only, as today)
   and finding `holder = human`, `viewer_id = ours`, `epoch = ours`. Anything else (evicted by the Hermes app, handed
   back, file unreadable) → input stops at once and the takeover ends. "Type text" sends KeyEvents per character
   (keysym mapping for printable text; no clipboard).
3. **Who can take over:** a paired browser session with the security password or a passkey (`authorize`, as the
   Remote access and security lock), on a screen that is `running` and not sandboxed. One Score takeover per desktop.
4. **While Score holds control:** frames are served **only to the session that took over** (today a human holder means
   no frames for anyone; that stays true for every other session and for a holder that isn't Score's). The input route
   accepts events only from that session.
5. **Handing back** happens on: Hand back; the page closing or hiding (the client stops its heartbeat); 5 minutes without
   input; 30 s without a heartbeat (server timer); Score shutting down or restarting (on start, Score releases any lease
   whose `viewer_id` starts `score:`, by `viewer_id`, so a crash can't leave the agent paused); the lease changing under
   us (nothing to release then). Release always passes our `viewer_id` and `epoch`, so it can never take control back
   from someone who took over after us.
6. **The agent is told.** The step log shows "Paused: you took over its desktop" and "Back in control"; the job thread
   gets one line "You took over builder's desktop 21:16–21:19". Hermes' own tools already tell the agent a human has
   control.
7. **Never stored or logged:** input events, typed text, frames. The audit row keeps who, which agent, start, end and
   why it ended.

## API (contract §, to be added)
- `POST /api/agents/:agentId/bot-screen/take-over` `{ password? | passkey assertion }` → `{ takeoverId; expiresAt }`;
  `409 conflict` (not running, sandboxed, someone holds it), `403 locked` without the password.
- `POST /api/agents/:agentId/bot-screen/input` `{ takeoverId; events: ({ k: 'key', keysym, down } | { k: 'pointer', x, y,
  buttons })[] }` (≤ 200 events per call, coordinates within the screen) → `204`; `409` when control was lost.
- `POST /api/agents/:agentId/bot-screen/heartbeat` `{ takeoverId }`; `POST …/hand-back` `{ takeoverId }`.
- `BotScreenStatus` gains `control: { takeoverId; yours: boolean; since; idleExpiresAt } | null` and `state: 'human'`
  stays for a holder that isn't this session. Input over HTTP batches (no WebSocket) keeps the server's existing
  transport; ~50 ms batching is fine for clicks and typing.

## Threats and answers (lead's review)
| # | Threat | Answer |
|---|---|---|
| 1 | A paired phone (or a stolen session) drives a desktop where the agent's browser is signed in to things. | Password/passkey per takeover; one per desktop; 5-min idle; audit; the screen page shows "You have control" (protected). |
| 2 | Score keeps sending input after the Hermes app took over (last writer wins). | Lease read before every input batch; any mismatch stops input and ends the takeover. Race: one batch in flight (≤ 50 ms) can land; acceptable, same as Hermes' own bridge. |
| 3 | Score crashes while holding control; the agent stays paused forever. | Start-up release of `score:` viewers by `viewer_id`; the 30-s heartbeat timer; Hermes' own idle watch also reclaims abandoned leases (`runtime.py`). |
| 4 | A bug sends input while only watching. | Input route requires a live takeover for this session; the encoder for input sits behind the takeover object; tests assert no input bytes are written without one. |
| 5 | Another Score session sees what the person types (passwords). | Frames only to the taking session; others get `state: human`, as today. |
| 6 | Hand back yanks control from someone who took over after us. | Release passes `viewer_id` + `epoch`; Hermes ignores a stale release. |
| 7 | A sandboxed desktop. | Not offered (Score can't see it today either). |
| 8 | The agent keeps acting through a script it started. | Hermes' documented boundary; the confirm card says programs in its terminal keep running. |

## Tests
Plugin (pytest): the two commands call acquire/release with the right args, refuse bad input. Server (vitest, fixtures):
encoder bytes for KeyEvent/PointerEvent; no input without a takeover; lease mismatch stops input; frames only to the
taking session; heartbeat/idle/start-up release; password gate. Web: the flow in the mock-up. E2E against the fake
(fake bot screen gains a takeover). Live check on a test profile's Bot Desktop with no credentials involved.
