## Design (from the lead)
- Reuse 3.13's built-asset serving (`apps/server/src/http/web-assets.ts`): in production (`NODE_ENV=production` or a
  `SCORE_SERVE_WEB=1` flag set by `pnpm start`) the server serves `apps/web/dist` in local mode too, on the same loopback
  port as the API (default 8740); Vite is for development only. Same CSP/security headers as remote mode; SPA fallback.
- `pnpm start` (root): checks `apps/web/dist` exists (clear message otherwise), then starts the server (tsx or Node's
  native type stripping — pick what works with the codebase, say which). `pnpm build` builds web (and typechecks server).
- `scripts/score` launcher (bash, `set -euo pipefail`, no shell-string evaluation of user input): `score start|stop|status|
  logs|pair` using a PID file in `$SCORE_HOME`; `pair` prints a fresh pairing link (reuse 3.13's console pair command or an
  equivalent loopback-only mechanism).
- `docs/score.service.example` (systemd **user** unit; documented, not installed) and SETUP §9 "Run Score every day".
- Migrations run at start (already); document backup of `$SCORE_HOME` (score.db + media) before upgrades.
- Smoke e2e (`e2e/production.spec.ts`): build, start on a throwaway SCORE_HOME and port, load /now, pair, see the shell —
  then stop. Keep the existing dev-mode e2e unchanged.
