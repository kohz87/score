# 8.3 Theme packs (design v1; decision 84; PLAN 8.3)

Goal: Settings › Look offers a few built-in themes that change Score's whole look — colours, fonts, corner radius,
spacing density and navigation layout — switched live and remembered per browser. Today's look stays the default theme.
No theme editor or import (decision 84).

## What exists
- `apps/web/src/styles/tokens.css`: 161 custom properties (colours per area, `--radius-*`, fonts, …) with light and dark
  sets (`:root[data-theme='dark'|'light']`, "System" follows the OS). Settings › Look switches light/dark/system.
- Gaps: 17 stylesheets use literal `border-radius` values, 8 use literal colours; spacing is mostly literal `px`; the
  navigation is one fixed top bar.

## Model
- A **theme** = a token set (colours for light and dark, fonts, a radius scale, a density scale) + a **layout** choice
  (`top` navigation as today, or `side` navigation: a left rail with the destinations, the search and the avatar).
- Applied as `<html data-pack="<id>" data-theme="light|dark" data-layout="top|side" data-density="comfortable|compact">`.
  The colour mode (light/dark/system) stays a separate choice, so every pack has a light and a dark variant.
- Packs live in `apps/web/src/styles/packs/<id>.css` (tokens only) + an entry in `packs.ts` (id, name, layout, density,
  fonts to load). Fonts only from `@fontsource/*` (AGENTS.md), licensed OFL-1.1; loaded lazily per pack.

## Built-in packs (first set)
| id | name | look | layout | density |
|---|---|---|---|---|
| `score` | Score (default) | today's tokens, Bricolage Grotesque / Hanken Grotesk, 28px cards | top | comfortable |
| `paper` | Paper | warm off-white, serif headings (Source Serif 4), soft 12px corners, lower contrast lines | top | comfortable |
| `night` | Night shift | dark-first, deep blue-black, cool accents, 16px corners | side | comfortable |
| `dense` | Dense | neutral greys, Inter, 8px corners, tighter spacing for big screens | side | compact |

## Work
1. **Tokenise what's left:** every literal radius → `--radius-*` scale (`--radius-s/m/l/card/pill`), literal colours →
   tokens, a spacing scale (`--space-1…8`) used by layout gaps/paddings of shells, cards and lists (not every pixel —
   the places a density change must move). Visual baselines must stay identical for the `score` pack.
2. **Pack files and loader:** apply the attributes before first paint (inline boot script reads `localStorage`, try/catch,
   falls back to `score`); lazy-load a pack's fonts.
3. **Side navigation layout:** the app shell renders the destinations as a left rail when `data-layout='side'` (same
   links, same order, keyboard and screen-reader behaviour, phone width collapses to today's top bar).
4. **Settings › Look:** a pack picker with a small live preview card per pack, plus the existing light/dark/system.
5. **Contrast:** each pack's light and dark colour pairs for text/background, buttons, focus rings and agent colours pass
   WCAG AA (a test computes contrast ratios from the pack tokens). Agent identity stays colour + shape (AgentGlyph).

## Done when
`score` pack pixel-identical to today (visual e2e baselines unchanged); each pack has visual baselines (light, dark, phone)
for Now, Chat, Knowledge and Settings; contrast test passes for all packs; the choice survives reload; phone width works
in `side` layout; no CSS framework added; `pnpm check` + full e2e.
