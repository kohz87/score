# 9.4 Customizer (PLAN 9.4; design docs/briefs/9-themes.md §8; decision 90)

Goal: Settings › Look › **Customize** opens a full-screen editor that builds a theme live and saves/exports/imports it,
using only the theme API (API-CONTRACT § 16: GET/PUT /api/themes/:id, import, export, PUT /api/look) — no server change.

Work:
1. **Route** `/settings/look/customize[/:themeId]`: start from any theme ("Start from…"; built-ins are copied under a new
   id as a custom theme). Left: live preview of the real app inside the page (the actual routes rendered in a preview
   frame or region with interactions disabled, reading the same data; the engine applies the draft manifest + sanitised
   CSS to the preview only, never to the rest of the page until saved). Right: controls in sections.
2. **Sections**: Colours (each public token, light and dark, colour inputs + hex; live contrast warnings using the same
   contrast code as 8.3/9.2), Fonts (heading/body/code from built-ins + upload woff2 faces), Shape (radius, density,
   border, elevation, surface), Layout (nav, width, **menu editor**: drag to reorder, rename, hide; Settings can't be
   hidden), Now (drag cards, set spans, columns), Chat (messages, room list), Background (upload image, fit, dim),
   Custom CSS (code editor — reuse the existing CodeEditor component — with the 9.2 sanitiser report live), Name/author/
   version/description.
3. **Keyboard alternatives** for every drag (move up/down buttons). Undo/redo for the draft; "Discard" back to saved.
4. **Save** (PUT, etag conflicts in plain words), **Save as new**, **Export** (zip), **Import** (shows the install
   preview: name, author, what it changes, sanitiser report; nothing applies until "Install"), **Use for every device** /
   **Use on this device**.
5. Imported theme preview cards in Settings › Look show the theme's own colours (follow-up from 9.2).

9.3 (layout options) is built in parallel: bind every control to the manifest fields in packages/contract/src/themes.ts;
where an option's rendering isn't in main yet, the preview shows it once 9.3 merges — don't implement layout rendering here.

Done when: e2e builds a theme from scratch, saves, exports, re-imports and applies it; keyboard-only editing works;
axe-style checks (roles, names, focus order) pass; visual baselines of the Customizer (light/dark/phone);
`pnpm check` + full e2e.

## Lead notes (2026-10-18, before the build)
- 9.3 is merged: every layout/shape/background option already renders; the preview uses it directly.
- Contrast warnings must also cover small, non-protected text over images/glass (seen in 9.3 review: "for Hermes",
  "Rooms", "Direct rooms" nearly unreadable on a busy background) — measure against the actual composited background
  where possible, and warn in plain words with the element named.
- The draft is never applied outside the preview, including through `look.changed` or the boot cache, until Save + Use.
