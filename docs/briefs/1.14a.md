## Design (from the lead; follow it)

**Migration `apps/server/migrations/0004_bridge.sql`** (exactly this):

```sql
CREATE TABLE producers (
  id TEXT PRIMARY KEY,                 -- random id
  profile TEXT NOT NULL,
  incarnation TEXT NOT NULL UNIQUE,
  pid INTEGER NOT NULL,
  kanban_task_id TEXT,
  isolation TEXT NOT NULL CHECK (isolation IN ('in_process','host','unknown')),
  plugin_version TEXT NOT NULL,
  hermes_version TEXT,
  hermes_code_sha TEXT,
  private_apis TEXT NOT NULL,          -- JSON object name -> bool
  token_hash TEXT NOT NULL,            -- sha256 hex of the current producer token
  token_expires_at INTEGER NOT NULL,   -- epoch ms
  acked_through INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  last_seen_at TEXT NOT NULL
) STRICT;
CREATE INDEX producers_profile ON producers(profile);
CREATE TABLE session_tool_calls (
  profile TEXT NOT NULL,
  session_id TEXT NOT NULL,
  tool_call_id TEXT NOT NULL,
  tool TEXT NOT NULL,
  args_preview TEXT,                   -- redacted, <= 2 KB
  command_digest TEXT,
  status TEXT NOT NULL CHECK (status IN ('running','ok','error','blocked')),
  started_at TEXT NOT NULL,
  ended_at TEXT,
  duration_ms INTEGER,
  result_preview TEXT,                 -- redacted, <= 2 KB
  kanban_task_id TEXT,
  version INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (profile, session_id, tool_call_id)
) STRICT;
CREATE TABLE approval_signals (        -- raw approval-hook observations for task 1.14b
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  producer_id TEXT NOT NULL,
  profile TEXT NOT NULL,
  hook TEXT NOT NULL,
  session_key TEXT,
  request_id TEXT,
  payload TEXT NOT NULL,               -- redacted JSON
  at TEXT NOT NULL
);
```

**Bootstrap token** (`hermes/bridge/bootstrap.ts`): on startup, create `<SCORE_HOME>/bridge.token` if missing
(32 random bytes, base64url, file mode 0600 via exclusive create; reuse it if present and owner-only, refuse to
start if its mode allows group or other access). The server keeps only its sha256 in memory.

**Routes** (`hermes/bridge/routes.ts`, registered by `buildApp` when the bridge is enabled; `/bridge/*` is already
excluded from the CSRF guard):

- `POST /bridge/v1/hello`, auth `Bearer <bootstrap>` (constant-time hash compare). Validate with
  `BridgeHelloRequestSchema`. Create or refresh the producer for this `incarnation`: a new random producer token
  (32 bytes base64url) stored as a sha256 hash, expiring in 1 h. Respond with `BridgeHelloResponseSchema`:
  `enabled.watch = true`; `enabled.gatewayApprovals = isolation === 'in_process'` and the private APIs
  `list_gateway_approvals`, `register_gateway_settle` and `resolve_gateway_approval` are all true and the
  compatibility gate doesn't disable `gateway-approvals`; `enabled.kanbanGrants = false` (feature-flagged until 1.13c).
  A bootstrap token is **only** valid for hello.
- `POST /bridge/v1/events`, auth `Bearer <producer token>` (lookup by hash, not expired). Body limit 2 MB, ≤ 200
  events, validated with `BridgeEventsRequestSchema`. For each event, in counter order, submit one ingest
  `Observation`:
  `source: 'bridge:<incarnation>'`, `identity: 'bridge:<incarnation>:<counter>'`,
  `checkpoint: { scope: 'events', position: counter, incarnation }`. `apply` translates the hook
  (`hermes/bridge/translate.ts`):
  - `pre_tool_call` → upsert `session_tool_calls` (status `running`, `args_preview` = redacted JSON of `args` ≤ 2 KB,
    `command_digest` from the payload) + `log.line` (kind `tool`).
  - `post_tool_call` → complete that row (guarded: terminal statuses final; `status` = `blocked` when the nested
    `result` JSON has `status: 'blocked'`, `error` when the hook status says error, else `ok`), `duration_ms`,
    redacted `result_preview` ≤ 2 KB, + `log.line`.
  - `pre_approval_request`, `post_approval_response`, `on_human_input_request`, `on_human_input_resolved` → insert an
    `approval_signals` row (redacted payload) + `log.line` (kind `approval`). Don't create approvals; that's 1.14b.
  - `on_session_start`, `on_session_end`, `subagent_start`, `subagent_stop`, `on_interim_message`, the `on_kanban_*`
    hooks → `log.line` (kind `system`/`message`) with a short redacted text.
  - `bridge.gap` → insert into `gaps` (`source = 'bridge:<incarnation>'`) + `gap.recorded`.
  - Unknown hooks → counted metric, no drafts (never fatal).
    Every text field goes through `redact()` again (D6 layer 2), even though the plugin already redacted it.
    Response `{ ackedThrough }` = the highest counter such that every counter up to it has been ingested or was a
    duplicate for this producer (store it in `producers.acked_through`). Update `last_seen_at`.
- Errors: 401 for bad tokens (same body for unknown and expired, to avoid oracles), 413 for too large, 400 for
  invalid. Never echo tokens. Producer tokens can't call `/api/*` (they're never accepted there, and add a test).
- Decision delivery (`/bridge/v1/decisions*`) and grants are **not** in this task.

**System status**: `SystemStatus.bridge` = `{ producers: count with last_seen_at in the last 5 min, lastSeenAt: max,
isolation: that of the most recently seen producer, or 'unknown' }`, merged in `system-status.ts` for live mode
(fake mode keeps its own values).

**Wiring**: `start-server.ts` creates the bootstrap token and passes the bridge deps (db, ingest, compatibility
accessor) into `buildApp`. The fake mode doesn't need the bridge but may register it harmlessly.

**Observation identity ≠ entity identity** (from the 1.4a review). The ingest key `(source, identity)` names one
immutable _observation_, not the entity it's about. Each source namespaces its keys by kind, so different tables can
never collide:

- Immutable redeliveries use the upstream event's own ID: `task_event:<id>`, `sse:<run_id>:<seq>`,
  `bridge:<incarnation>:<counter>`.
- Observations of **mutable** state add a revision: `task_run:<id>@<status>:<ended_at>`,
  `message:<uid>@<active>:<compacted>`, `run_status:<run_id>@<status>`. A changed entity therefore produces a new
  observation, not a dropped duplicate.

Projections key on the entity ID. Their `versionColumn` guard (`guardedUpsert`) rejects stale writes. A producer
that sees a conflicting payload for an immutable key logs it as a source fault; it doesn't overwrite.

Bridge events carry `(producer_incarnation, counter)`; the unique ingest key makes re-delivery harmless.
**Terminal-state guards:** a delayed observation can't move a finished run, approval or tool call back to an
earlier state. Upstream cursors are persisted per source: SSE `seq` per run, `task_events.id`, `messages.id` per
DB incarnation, bridge counters per producer.

### D7. Security posture (single user, local first)

- **Network.** The server binds `127.0.0.1`.
- **Browser.** Mutations require `X-Score-Client` + same-origin (CSRF).
- **D7.1 Human decisions** (approval decisions, grants, rule changes, credential actions) additionally require a
  **paired browser session**. On first run the server prints a one-time pairing URL **to its own terminal**. The
  browser exchanges it for an HttpOnly, SameSite=Strict session cookie. The server stores only a hash, never in a
  file the bridge uses.
  - **Threat-model limit (owner decision 2026-10-06: accepted, option a):** agents run as the same OS user, so a determined agent with
    shell access could still read browser cookie stores or `~/.score`. Pairing stops casual or accidental
    self-approval and CSRF, not a hostile same-user process.
  - Real isolation means running agents in Hermes's sandboxed terminal backend (docker/ssh) or as a different
    OS user. Score shows the current isolation level on the Settings page.
- **Bridge identity.** The bootstrap secret `~/.score/bridge.token` only allows `POST /bridge/v1/hello`. Each
  producer then gets a short-lived **producer token** scoped to its profile, process incarnation and
  `HERMES_KANBAN_TASK`. It can post only its own events, receive only decisions targeted at its own approvals,
  and redeem only grants for its own task. Bridge tokens can't call `/api/*`.
- **Secrets.** Score never reads `~/.hermes/.env`, `auth.json` or key files. Payloads are redacted per D6.

## Contract §11 (and SystemStatus)

## 11. Internal: bridge plugin ↔ server (not for the front end)

Served under `/bridge/v1` on the same port. Bridge tokens can't call `/api/*`, and browser sessions can't call
`/bridge/*`.

**Handshake**

- `POST /bridge/v1/hello`, auth `Bearer <~/.score/bridge.token>` (bootstrap secret, allowed for this call only):
  ```ts
  req: {
    profile: string
    pid: number
    incarnation: string /* random per process */
    kanbanTaskId: string | null
    isolation: 'in_process' | 'host' | 'unknown' /* unknown → observe only; actions disabled */
    pluginVersion: string
    hermes: {
      version: string
      codeSha: string
    }
    privateApis: Record<string, boolean> /* which hermes_private functions resolved */
  }
  res: {
    producerToken: string
    expiresAt: string
    enabled: {
      gatewayApprovals: boolean
      kanbanGrants: boolean
      watch: boolean
    }
  }
  ```
  Every other call uses `Authorization: Bearer <producerToken>`. The token is scoped to profile, incarnation and
  `kanbanTaskId`, and is renewed by calling `hello` again.

**Events** (all redacted in-plugin with `force=True` before truncation)

- `POST /bridge/v1/events` `{ events: { counter: number; hook: string; at: string; sessionKey: string | null;
sessionId: string | null; toolCallId: string | null; payload: object }[] }` → `{ ackedThrough: number }`.
  `(incarnation, counter)` is the ingest key; redelivery after a spool drain is harmless.

**Gateway approvals** (D4.2)

- The `pre_approval_request` event payload includes the exact `requestId` read via `list_gateway_approvals`
  (or `null` → the operation is not actionable) and a `commandDigest`. Settle callbacks arrive as
  `approval.settled` events with `{ requestId, reason }`.
- `GET /bridge/v1/decisions?wait=25` (long-poll; `wait` = integer seconds 0–30, default 25) → `{ items: { deliveryId; leaseUntil; sessionKey; requestId;
choice: ApprovalChoice; reason: string | null }[] }`. Only decisions for approvals **this producer reported**
  are returned.
- `POST /bridge/v1/decisions/:deliveryId/ack` `{ outcome: 'applied' | 'not_pending' | 'failed'; resolved: number; error?: string }` → `204`

**Kanban grants** (D4.3)

- `POST /bridge/v1/grants/redeem` `{ taskId; taskRunId: number; commandDigest; toolCallId }` →
  `200 { grantId; patternKey }` or `404 no_grant` / `409 not_eligible` (wrong attempt, expired, already redeemed).
  Allowed only when the producer token's `kanbanTaskId` equals `taskId`.
- `POST /bridge/v1/grants/:grantId/consume` `{ toolCallId; outcome: 'executed' | 'blocked' | 'revoked' }` → `204`

Hook → domain mapping lives in `apps/server/src/hermes/translate.ts`; payload fixtures in
`apps/server/test/fixtures/bridge/` (seeded from `docs/spike/`).
