# Phase 6 design: agent Workspace and a central Knowledge base

Owner request and decisions, 2026-10-09 (AskUserQuestion):

- **Knowledge lives inside Score** (a "Knowledge" destination built from the owner's Artemis code, `../reference/artemis`).
- **Agents read and write it** through the Score plugin; every agent write is a git commit the owner can see and undo;
  deletes need the owner's approval.
- **Workspace: browse, preview, edit** per agent (its Hermes working folder), and set which folder it is.
- **Vault folder: a new `~/score-vault`** (git-tracked; changeable in Settings).
  References: nesquena/hermes-webui (MIT) for the workspace panel (`api/workspace.py`: workspace = `terminal.cwd`, blocked
  paths, remote-backend handling); Artemis for vault, index, wikilinks, backlinks, git history.

## 6.1 Workspace (per agent)

**Root.** The agent's `terminal.cwd` from its config (read through the adapter's cached CLI read). Unavailable, with the
reason shown, when the terminal backend is not local (ssh, docker, modal…: files are not on this machine) or `cwd` is
unset/`.`. Score refuses roots that are `/`, the home folder itself, `~/.hermes`, `~/.score`, `~/.ssh`, or inside them.
**Set the folder:** **H** `PUT /api/agents/:id/workspace/root {path}` → `hermes -p <profile> config set terminal.cwd <path>`
after the same refusal checks and an existence check (the folder is never created implicitly).

**Files API** (all **H**, JSON unless noted; `path` is relative to the root, POSIX):

- `GET  /api/agents/:id/workspace` → `{ root: string | null; available: boolean; reason: string | null }`
- `GET  /api/agents/:id/workspace/tree?path=` → `{ entries: { name; kind: 'file'|'dir'|'symlink'; size; mtime }[] }`
  (one level; sorted dirs first; hidden entries included but flagged)
- `GET  /api/agents/:id/workspace/file?path=` → text (≤ 1 MiB, UTF-8) with `ETag`, or the raw bytes for images/PDF
  (`Content-Type` from a fixed allowlist, `Content-Disposition: inline`, `X-Content-Type-Options: nosniff`, CSP sandbox);
  anything else → `{ binary: true, size }` with a download link
- `PUT  /api/agents/:id/workspace/file?path=` `{ content; etag | null }` → 200 `{ etag }`; 412 on a stale etag;
  atomic (temp file in the same directory + fsync + rename); `etag: null` creates and refuses an existing file
- `POST /api/agents/:id/workspace/entries` `{ path; kind: 'file'|'dir' }`, `POST …/move` `{ from; to }`,
  `DELETE …/entries?path=` (a non-empty directory needs `?recursive=1` and a typed confirmation in the UI),
  `POST …/upload?path=` raw body ≤ 25 MiB (`Content-Type: application/octet-stream`; no multipart dependency)

**Path safety (the core of this feature).** Resolve every request with `realpath` of the root and of the _parent_ of the
target; the result must stay inside the root. Open files with `O_NOFOLLOW`; never follow a symlink for writes, moves or
deletes (symlinks are listed, previewed only if they resolve inside the root). Reject `..` segments, NUL, absolute paths,
and paths whose any component matches the **blocked list**: `.env*`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`,
`auth.json`, `.netrc`, `.git/` internals (listing `.git` is allowed, reading/writing inside it is not), plus anything that
resolves under `~/.hermes`, `~/.score` or `~/.ssh`. Blocked entries are not listed at all. Size limits as above.
Remote (LAN) access requires HTTPS (5.18) and a paired browser; editing files an agent runs is equivalent to giving that
browser the agent's powers, which pairing already grants. Every write is logged (path, size, who: never content).

**UI.** Team › agent › **Workspace** tab: breadcrumb + tree (lazy), a preview/editor pane (CodeMirror 6 for text with
language by extension, Markdown preview toggle, image/PDF preview), Save with etag conflict handling ("Changed on disk:
reload / overwrite / compare"), new file/folder, rename, delete (confirm), upload (button + drag and drop), "Set folder".
Mobile: tree and file as two screens. Changes made by the agent show on refresh and on window focus (a later step may add
`fs.watch` → `workspace.changed`).

## 6.2 Knowledge server (vault, index, git, API)

**Vault.** `$SCORE_VAULT` (default `~/score-vault`; Settings shows it). Created on first use with `git init` and a
`README.md`; plain `.md` files with optional YAML frontmatter; attachments under `attachments/`. The files are the source
of truth: Score's DB only indexes.
**Index.** Migration adds `knowledge_notes (path PK, title, mtime, size, hash, frontmatter_json)`,
`knowledge_links (from_path, to_target, to_path NULL)` and an FTS5 table `knowledge_fts (path, title, body)`. A scanner
reindexes changed files by `(mtime, size)` then hash, at start, on every Score write, and on `fs.watch` events (debounced;
a periodic full scan every 5 min covers missed events). Titles: frontmatter `title`, else first `# H1`, else file name.
Wikilinks `[[Target]]`, `[[Target|alias]]`, `[[Target#heading]]` resolve Obsidian-style (exact path, then unique basename,
case-insensitive); unresolved links are kept (they show as "missing note").
**Git.** Every save is a commit (`git -C <vault> commit` via execFile, argv arrays): author `You <you@score.local>` for the
owner, `<agentId> (agent) <agentId@score.local>` for agents; commits from rapid edits of one note by one author within 60 s
are amended into one. A dirty tree from outside edits is committed as "Outside changes" before Score's own commit.
History and restore per note. No remote push in 6.2 (Artemis's remote/pull/push can come later).
**API** (**H** for writes from browsers; agents use the bridge, 6.4):

- `GET /api/knowledge` → `{ vault: string; notes: number; gitAvailable: boolean }`
- `GET /api/knowledge/tree` → folders and notes (path, title, mtime)
- `GET /api/knowledge/notes/*path` → `{ path; title; frontmatter; body; etag; backlinks: {path; title}[]; links: … }`
- `PUT /api/knowledge/notes/*path` `{ body; frontmatter?; etag | null }` → `{ etag }`; 412 on conflict; atomic write + commit
- `POST /api/knowledge/move` `{ from; to; updateLinks: boolean }` (rewrites `[[links]]` in other notes in the same commit)
- `DELETE /api/knowledge/notes/*path` (owner only)
- `GET /api/knowledge/search?q=&limit=` → FTS5 ranked hits with snippets (query sanitised to FTS5 syntax)
- `GET /api/knowledge/notes/*path/history` → commits; `POST …/restore {commit}` → new commit restoring that version
- Stream: `knowledge.changed { path; by: 'you' | AgentId | 'outside' }`
  Same path-safety rules as 6.1 with the vault as root (`.git/` blocked; only `.md` and `attachments/*` writable).

## 6.3 Knowledge web

A **Knowledge** destination in the main nav (after Team). Left: search + folder tree + recent; centre: CodeMirror 6
Markdown editor with a rendered preview (react-markdown + remark-gfm), wikilink autocomplete on `[[`, clickable links,
"missing note → create"; right: backlinks, outgoing links, frontmatter properties, history (with diff and restore).
Autosave with etag, conflict banner, keyboard: ⌘K search, ⌘N new note. Agent-written changes are marked
("edited by builder · 2 min ago") with "Undo this change". Design from the Score design system (white cards, ink actions,
Bricolage headings, JetBrains Mono code); reuse Artemis's components' behaviour, not its UI kit.
New dependencies (all MIT, owner-visible in the task log): `@codemirror/state`, `@codemirror/view`, `@codemirror/commands`,
`@codemirror/language`, `@codemirror/lang-markdown`, `@codemirror/autocomplete`, `react-markdown`, `remark-gfm`; server:
`gray-matter` (MIT; brings `js-yaml` MIT). **Not** BlockNote (MPL-2.0).

## 6.4 Agent knowledge tools (score_bridge)

The plugin registers Hermes tools (through `hermes_private.py` only if a private API is needed; Hermes's public plugin tool
registration otherwise): `knowledge_search(query, limit)`, `knowledge_read(path)`, `knowledge_list(folder)`,
`knowledge_write(path, body, expected_etag | null)`, `knowledge_append(path, text)`. Calls go over the authenticated
bridge to Score (new bridge RPCs, contract §Bridge), attributed to the calling agent (producer identity), rate-limited
(e.g. 60 writes / hour / agent) and size-limited (256 KiB per note). Agent writes are passed through `redact()` before
they are stored (D6: model output may carry secrets). No delete or move tool: an agent that wants one asks in chat.
The owner can turn agent access off per agent (Team › agent › Tools) and globally (Settings › Knowledge).

## Lead adversarial review (Codex unavailable, owner rule 2026-10-08)

1. _Path traversal via symlink swap between check and use_ → open the parent directory fd, `realpath` it, operate with
   `O_NOFOLLOW` relative to that resolved parent; re-check after `rename`. Tests with symlinked parents and a symlink race.
2. _Secrets exposure through the workspace_ (a repo with `.env`, keys) → blocked list never listed or served, also in
   search and previews; tests per pattern. Not a guarantee for arbitrarily named secret files: the UI says so.
3. _Remote browser edits = code execution_ → only paired browsers over HTTPS (5.18); every write logged; no anonymous
   path. Accepted risk, same as Chat's ability to make agents run commands.
4. _Agent writes clobbering owner edits_ → etags on every write; agents get 409 with the current etag and must re-read;
   git keeps every version; "Undo this change" restores the previous commit.
5. _Index drift after outside edits (Obsidian, git pull)_ → watcher + periodic scan; index is disposable (rebuild command).
6. _Huge vaults / binary files_ → index only `.md` ≤ 2 MiB; attachments listed, not indexed; scan is incremental.
7. _Git unavailable or a broken repo_ → notes still save; history/undo show "git unavailable"; never `git reset` or
   rewrite history; amend only Score's own last commit within 60 s and only if it is still `HEAD`.
8. _FTS5 query injection / syntax errors_ → user text is tokenised into quoted terms; errors return empty results, not 500.
9. _Agents filling the vault (loops)_ → per-agent rate and size limits, visible counters, global off switch.
10. _Wikilink rewrite on move touching many files_ → one commit, dry-run count shown before applying.
11. _Workspace root set to something dangerous by a compromised browser_ → refusal list + must exist + stays an existing
    directory owned by the user; changing it is logged.
12. _Persona names in fixtures_ (rule 5) → fixtures use neutral notes and agents only.
