# 11.1b-scope-tests: tests for the job-scoped prerequisites of 11.1b

PLAN 11.1b is a lead task. The lead has implemented its prerequisites (commit `584ab8b2` on `task/11.1b-exchanges`,
which this worktree starts from): what was per room is now per job, so a room can safely hold several jobs. This task
writes the **tests** that prove it. Write tests only. If a test shows a real bug, keep the test, mark it
`test.fails(...)` with a one-line comment naming the bug, and describe it in the report; don't fix server code.

Read first: `AGENTS.md` (Testing); `docs/briefs/11.0-bold.md` §3.2–§3.3; the commit itself
(`git show 584ab8b2 --stat`, then the files); `apps/server/migrations/0080_jobs.sql` and `0081_exchanges.sql`;
`apps/server/src/domain/job-sessions.ts`; the existing `apps/server/test/jobs-migration.test.ts` (its helpers
`room`, `message`, `turn` and its migration setup are the pattern to follow); `docs/API-CONTRACT.md` for the HTTP
shapes. Domain tests use a migrated SQLite database as the existing tests do; HTTP tests use Fastify `inject()` as
`test/http/rooms.test.ts` does.

Every test builds a room with **two jobs**: its default job (session scheme `room`) and a second job inserted with
`session_scheme = 'job'`, with messages and turns in both. Each test asserts that the operation touches only the
job it names and leaves the other job exactly as it was.

## Cover
1. **Rewind** (`domain/versions.ts`): `rewindScope` counts hidden messages and turns of the anchor's job only, and its
   `sessionId`s are the job's (`score-<room>-<agent>` for the default job, `score-<room>-<job>-<agent>` for the
   other); `createVersion` hides only that job's messages after the anchor; `markRunsRewound` marks only that job's
   runs. One HTTP test through the rewind-plan route.
2. **Summaries** (`domain/room-summaries.ts`, `summary-stale.ts`): `requestSummary(…, jobId)` covers only that job's
   messages; a summary in job A is not context for job B; a new summary replaces the older one of the same job only;
   `markStaleSummaries` marks a stale summary in either job; `shouldAutoSummarise` and `uncoveredTokens` count per job.
3. **Turn context** (`roomRunInput` in `domain/message-runs.ts`): a turn's input holds its own job's messages only,
   with and without a summary.
4. **Where messages land**: `POST /api/rooms/:roomId/messages` with `jobId` stores the message in that job and the
   reply in the same job (`message.created` events carry `jobId`); a `jobId` of another room is `404`; an edit
   (`edits`) stays in the original's job, and a different `jobId` with `edits` is `400`; an approval card
   (`approvalMessage`) and a failure notice (`failMessageRun`) land in their turn's job.
5. **Unread** (`readRoom`, `markRoomRead`): the room's `unread` sums both jobs; reading up to job A's newest message
   leaves job B's messages unread.
6. **Search** (`GET /api/search/messages`): every hit carries its `jobId`; `jobId=` filters to one job.
7. **Shares** (`POST /api/rooms/:roomId/shares`, `buildShareSnapshot`): `jobId` snapshots only that job and titles it
   with the job title; without `jobId` the default job with the room name; a job of another room is `404`. Use the
   existing share test setup for the security password.
8. **Coding CLI sessions** (`runtimes/coding/store.ts`, `service.forgetRoomSession`): sessions are kept per
   (job, agent); forgetting a job's Score session key forgets that job's CLI session only.
9. **Session owner** (`sessionOwner`): resolves a job-scheme key that no turn recorded; an unknown job id is `null`.
10. **Team room** (`domain/team-room.ts`): `ensureTeamRoom` creates exactly one room with `role 'team'` and
    `routing 'exchanges'`, no lead, sorted members; it takes "Team room 2" when "Team room" is taken; an empty agent
    list changes nothing; a changed agent list updates members and emits `room.upserted` once; `GET /api/rooms` leaves
    it out; `GET /api/rooms/:id` still returns it. Web: the classic `roomsQuery` reducer
    (`apps/web/src/routes/chat/queries.ts`) ignores a `room.upserted` with `role: 'team'` (Vitest, next to existing
    tests of that file or a new `queries.test.ts`).
11. **Rename**: renaming a room (the existing PATCH route) renames its default job, not its other jobs.
12. **Migration 0081** on a database at version 80 holding: a `room_reads` row, a share, a `coding_sessions` row for an
    existing room and one for a deleted room, a `coding_pending_terminals` row with a room id: after migrating,
    `job_reads`, `room_shares.job_id`, `coding_sessions` (the deleted room's row dropped) and the pending terminal's
    `job_id` point at the default job; `PRAGMA foreign_key_check` is empty.

Put them in `apps/server/test/jobs-scope.test.ts` (domain) and `apps/server/test/http/jobs-scope.test.ts` (HTTP);
split further if a file passes ~600 lines.
