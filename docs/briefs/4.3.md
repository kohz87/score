## Task (from docs/PLAN.md)
**4.3 Media store**: `/api/media/:id`, quota, cleanup. Done when quota tests pass.

## Design (from the lead)
- Store under `$SCORE_HOME/media/` (0700 dir, files 0600), content-addressed (sha256) with a DB index (migration **0019**:
  id, sha256, content_type, size, created_at, last_used_at, refs). Allowed types: png, jpeg, webp, gif (sniff magic bytes;
  never trust the declared type); max 8 MB per item; total quota 512 MB (env-configurable) with LRU eviction of
  unreferenced items; a cleanup sweep in hub/retire.ts.
- `POST /api/media` (contract §5 composer attachments; **H**, multipart, bounded) and `GET /api/media/:mediaId` (bytes,
  `Content-Type` from the sniffed type, `X-Content-Type-Options: nosniff`, `Content-Disposition: inline`, `Cache-Control:
  private, max-age=…`, 404 for unknown ids, no path input ever reaches the filesystem).
- A server-side `storeMedia(bytes, contentType) → mediaId` for the Watch frame capture (4.1) to call for browser
  screenshots (bridge sends them base64 within the payload cap, or as an artifact path that the **bridge** reads — decide
  with the plugin's existing caps and say which).
- The composer's attach button (currently disabled) is enabled to upload images; the message part references the media.
