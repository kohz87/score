## Design (from the lead; follow it)
**Paths** (`apps/server/src/hermes/live/paths.ts`): `hermesPaths(hermesHome)` → `kanbanDb = <home>/kanban.db`,
`stateDb(profile)` = `<home>/state.db` for `default`, else `<home>/profiles/<profile>/state.db`. Profile names must
match `^[a-z0-9][a-z0-9_-]{0,63}$` (reject anything else, so there's no path traversal). Add config
`SCORE_HERMES_HOME` (default `~/.hermes`) in `src/config.ts`.

**Read-only open** (`apps/server/src/hermes/live/sqlite.ts`): `openReadOnly(path)` →
`new DatabaseSync(path, { readOnly: true })`, then `PRAGMA query_only = 1` and `PRAGMA busy_timeout = 2000`. Never
create the file (missing → typed `HermesDbMissing` error). Provide `incarnationOf(path)`: a stable string from the
file identity, `<dev>:<ino>:<birthtimeMs or ctimeMs>`. When Hermes replaces the file (new inode), the incarnation
changes. Close helpers too.

**Kanban reader** (`kanban.ts`), all inputs and outputs zod-validated (columns per `docs/spike/kanban-schema.sql`):
- `tailTaskEvents(db, { afterId, limit })` → rows `{ id, task_id, run_id, kind, payload (parsed JSON or null),
  created_at }` with `id > afterId ORDER BY id LIMIT limit`.
- `readTasks(db, ids)`, `readTaskRuns(db, { taskIds })`, `readTaskLinks(db, { taskIds })`,
  `readTaskComments(db, { taskIds })` with the columns Score needs (id, title, body, assignee, status, priority,
  created_by, created_at, started_at, completed_at, current_run_id, block_kind, session_id, result,
  workflow_template_id, current_step_key for tasks; the run columns from the schema for runs). Chunk `IN (...)`
  lists at 500.
- Payload JSON that fails to parse becomes `{ unparsed: <string> }`. Never throw on one bad row; count it in a
  `malformed` metric returned with the batch.

**Sessions reader** (`sessions.ts`), per profile `state.db`:
- `tailMessages(db, { afterId, limit })` → `{ id, session_id, role, content, tool_call_id, tool_calls (parsed or
  null), tool_name, timestamp, active, compacted, message_uid, tool_call_uid }` by `id`.
- `readSessions(db, ids)` → id, source, profile_name, model, title, started_at, ended_at, end_reason,
  message_count, tool_call_count, input/output/cache tokens, estimated_cost_usd, actual_cost_usd,
  last_activity_at, parent_session_id.

**Tailer** (`tailer.ts`): `createTailer({ path, scope, read: (db, afterId, limit) => rows, idOf: row => id, limit = 500 })`
with `poll(checkpoint?: { position, incarnation })` →
`{ rows, checkpoint: { position, incarnation, resetIncarnation } }`:
- Opens lazily, keeps the connection, and re-opens if the incarnation changed.
- If the stored checkpoint's incarnation differs from the current file's (DB replaced), restart from position 0 and
  return `resetIncarnation: true` (the ingest path requires it for incarnation changes).
- Position = the max `id` returned (unchanged if no rows). **IDs only, never timestamps.**
- A missing DB returns no rows and `missing: true` (Hermes not installed or profile not created yet). That's not an error.

This task produces readers and tailers only. Mapping rows to Score observations/events is task 1.11a
(`translate.ts`). Export from `src/hermes/live/index.ts`.

**Test fixtures** (`apps/server/test/fixtures/hermes/`): copy the two schema files from `docs/spike/` (tests must
not read `docs/`). A helper builds a temp `kanban.db`/`state.db` from them and inserts neutral rows (agents
`lead`/`builder`/`reviewer`/`designer`, generic task titles).

## Done when
1. Tailing by id: rows inserted with **older timestamps after newer ones** are still delivered (carried rows); two
   rows with the **same millisecond timestamp** are both delivered once; repeated polls with the returned checkpoint
   deliver nothing twice and nothing is skipped (insert between polls).
2. Replacement: replacing the DB file (write a new file, rename over the old one) changes the incarnation; the next
   poll returns `resetIncarnation: true` from position 0.
3. Read-only: a write attempt through the reader's connection throws; the DB file's mtime and size are unchanged
   after polling; `query_only` is on.
4. Missing DB → `missing: true`, no throw; invalid profile names rejected.
5. Malformed JSON payload rows are returned with `{ unparsed }` and counted, not thrown.
6. Validation: rows go through zod; a schema drift (e.g. a missing column in a fixture variant) produces a clear typed
   error naming the column.
7. `pnpm --filter @score/server test`, `pnpm typecheck`, `pnpm lint`, `pnpm format:check` pass, and the boundary
   test still passes (all Hermes names stay under `src/hermes/`).

**Observation identity ≠ entity identity** (from the 1.4a review). The ingest key `(source, identity)` names one
immutable *observation*, not the entity it's about. Each source namespaces its keys by kind, so different tables can
never collide:
- Immutable redeliveries use the upstream event's own ID: `task_event:<id>`, `sse:<run_id>:<seq>`,
  `bridge:<incarnation>:<counter>`.
- Observations of **mutable** state add a revision: `task_run:<id>@<status>:<ended_at>`,
  `message:<uid>@<active>:<compacted>`, `run_status:<run_id>@<status>`. A changed entity therefore produces a new
  observation, not a dropped duplicate.

Projections key on the entity ID. Their `versionColumn` guard (`guardedUpsert`) rejects stale writes. A producer
that sees a conflicting payload for an immutable key logs it as a source fault; it doesn't overwrite.

Bridge events carry `(producer_incarnation, counter)`; the unique ingest key makes re-delivery harmless.
**Terminal-state guards:** a delayed observation can't move a finished run, approval or tool call back to an
earlier state. Upstream cursors are persisted per source: SSE `seq` per run, `task_events.id`, `messages.id` per
DB incarnation, bridge counters per producer.

## ARCHITECTURE D2.4
**D2.4 Recovery per source.**
- **Run SSE**: resume with `Last-Event-ID`. On `replay.truncated` or a gateway restart, poll `GET /v1/runs/{id}`,
  reconcile tools and messages from `state.db`, and record a visible **gap interval** on the run.
  `run.queued`/`run.started` are **not** emitted by the Runs API, so lifecycle starts from Score's own dispatch
  record plus status polling.
- **Bridge**: a bounded on-disk **spool** per producer (`~/.score/spool/`, size-capped, oldest dropped, with a
  drop counter) when Score is unreachable. It drains on reconnect, and dropped ranges become gap intervals.
- **kanban.db**: tail `task_events` by `id` (append-only). Re-read `tasks` rows touched by new events.
- **state.db** (per profile): ingest new rows by `messages.id` > checkpoint, scoped to a DB incarnation
  (file identity + `state_meta`). Hermes inserts carried/cloned rows with **older timestamps** and orders by ID,
  so timestamps are never a cursor. Edits, `active`/`compacted` flips, rewinds and compaction create or change rows
  without new IDs, so a periodic **session reconciliation** compares logical identities (`message_uid`,
  `tool_call_uid`) for sessions active in the last N hours. Fixtures cover rewind, compaction, carried timestamps
  and restore.
