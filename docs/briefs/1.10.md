## Observed upstream wire format (from the spike, Hermes v0.21)
- `200 text/event-stream`. Frames are `id: <seq>` + `data: <json>`, with no `event:` line; the JSON carries `"event": "<name>"`
  and `"seq"`. The first bytes are a comment `: open`; keepalives are `: keepalive`; before closing, the server sends
  `: stream closed`.
- Resume: `Last-Event-ID: <seq>` header (or `?last_seq=`). If the requested seq is older than the server's buffer,
  it sends a frame whose JSON has `"event": "replay.truncated"` (no `id:`) with `oldest_retained_seq`.
- Auth: `Authorization: Bearer <key>`.

## Design (from the lead; follow it)
`apps/server/src/hermes/live/sse-client.ts`:
1. **Parser** `createSseParser()`: a pure, incremental WHATWG event-stream parser (spec: html.spec.whatwg.org
   "Parsing an event stream"). Handle: CRLF, CR and LF line endings, including split across chunks; a leading BOM;
   multi-line `data:` joined with `\n`; a single optional space after the colon; comments (lines starting with `:`)
   surfaced as `{ type: 'comment', text }`; `id:` with a NUL (ignored); `retry:` (digits only); fields without a colon;
   dispatch on a blank line; no dispatch for an empty data buffer; UTF-8 decoding with `TextDecoder` streaming
   (a multibyte character split across chunks).
2. **Client** `connectSse({ url, headers, lastEventId?, signal?, fetch = globalThis.fetch })` → an async iterable of
   `{ type: 'event', id, event, data } | { type: 'comment', text }`, plus a `closed` reason when the iteration ends
   (`'server_closed'` if `: stream closed` was seen or the body ended, `'aborted'`, or `'error'` with the error).
   Non-2xx responses or a non-`text/event-stream` content type throw a typed `SseHttpError(status, bodySnippet ≤ 500
   chars)`. Never log or include header values (bearer keys) in errors.
3. **Resumable wrapper** `resumableSse({ connect: (lastEventId?) => …, onEvent, onTruncated, signal, backoff })`:
   reconnects after a network error or an unexpected end **without** `: stream closed`, resuming with the last seen
   `id`. It doesn't reconnect after `: stream closed` (the run is over) or abort. Backoff 0.5 s doubling to 10 s with
   jitter, reset after a successful frame, injectable timers. When an event's JSON has `event: 'replay.truncated'`,
   call `onTruncated({ oldestRetainedSeq, requestedSeq })` (the caller records a gap). Stop after `maxAttempts`
   consecutive failures (default 8) and resolve with `{ ended: 'gave_up', lastEventId }`.
