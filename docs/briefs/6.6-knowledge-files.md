# 6.6 Knowledge files: manage, upload and read documents (owner request 2026-10-10)

Owner: "a file system management for rag reading/uploading for management etc or direct upload md (will be given a
choice to go to knowledge or not?)"

Today: Knowledge (6.2–6.5) holds Markdown notes in the vault (git-backed), searchable (FTS5) and readable/writable by
agents through their knowledge tools (6.4 plugin + 7.4d MCP). Chat attachments (5.30) go to an agent's workspace.

## 1. Files in Knowledge
- **Files view** in Knowledge (a "Files" tab or the tree itself): folders and every file — notes and documents — with
  size, type, modified, last author. Actions: upload (button + drag-and-drop, multiple files, onto a folder), new folder,
  rename/move (existing move API for notes; same rules for documents), delete (owner only, confirm), download.
- **Types:** `.md`/`.markdown` → notes (as today). `.txt` → a note (`.md`, body as text). `.csv`, `.json`, `.html` →
  stored as documents with their text indexed (HTML as text, scripts stripped). `.pdf` → stored + text extracted with
  `unpdf` (MIT; lead adds it). `.docx` → stored; text extraction only if the owner approves `mammoth` (pending — build
  the extractor behind a small interface so it plugs in; without it DOCX is stored and downloadable, marked "text not
  available"). Images: stored, not indexed.
- **Limits:** 25 MB per file; documents ≤ 10 MB are committed to the vault's git; larger ones are stored but not
  versioned (shown as such). Extracted text ≤ 2 MB per document (truncated with a marker). A Knowledge storage figure in
  Settings › Knowledge.
- **Search and reading:** extracted text is indexed in Score's FTS with the document's path; Knowledge search shows
  documents with a type badge and snippet. A document page shows a preview (PDF inline as in 5.30, text/CSV as text) and
  the extracted text.
- **Agents (RAG):** the existing knowledge tools — `knowledge.search` covers documents; `knowledge.read` on a document
  returns its extracted text (bounded, with a note when truncated or unavailable). Agents can't upload binaries; their
  write tool stays notes-only. Update the plugin/MCP tool descriptions and API-CONTRACT accordingly.
- **Safety:** path rules as notes (no traversal, no dotfiles, no `.git`), extension allow-list, content sniffing for
  PDF/DOCX/ZIP, extraction in a worker with a time limit (≤ 20 s) and memory limit; extraction failures leave the file
  stored with "text not available". Redact extracted text before indexing (D6) like notes.

## 2. "Save to Knowledge" from Chat
- When the person attaches a supported file in the composer, its chip offers **"Also save to Knowledge"** (off by
  default) with a folder picker (default `inbox/`). On send, the file goes to the agent as today **and**, if chosen,
  into Knowledge.
- A message's attachments and an agent's reply get "Save to Knowledge" in the message menu (reply → a note with the reply
  text and a link back to the room).
- Name clashes ask: keep both (suffix) or replace (shows the existing file's date).
