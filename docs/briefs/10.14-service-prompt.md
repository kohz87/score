# 10.14 — Offer the service on first start

Owner (2026-10-20): setup should offer running Score as a service (PLAN 10.13 added `scripts/score service install`).
The contract change is committed: `About.service: boolean` (docs/API-CONTRACT.md, `packages/contract/src/about.ts`).

## Done when (PLAN 10.14)
1. **The prompt** (`scripts/score`, `cmd_start` without an installed unit): before starting, when **all** hold —
   stdin and stdout are terminals (`[[ -t 0 && -t 1 ]]`), the user manager answers (`systemctl --user
   show-environment`), the unit isn't installed, no answer is remembered, and `SCORE_NO_SERVICE_PROMPT` is unset — ask:
   `Run Score as a service, so it starts at boot and restarts after a crash? [Y/n] `.
   - Enter or y/yes → `service install` with the current environment (exactly what `service install` does, including
     its messages, linger warning and pairing link), and nothing else (no second launcher start).
   - n/no → remember it (`$SCORE_HOME/service-prompt` containing `declined <ISO date>`, 0600) and start as today. Print one
     line: `Not installed. 'scripts/score service install' does it later.`
   - Anything else: ask again (at most 3 times, then treat as no for this run without remembering).
   - The question goes to the terminal only; scripts, CI, e2e and nohup/pipe starts never see it (non-terminal = today's
     behaviour exactly). `service uninstall` doesn't reset the remembered answer; `service install` clears it.
2. **The server reports it**: `scripts/score run` exports `SCORE_RUN_AS=service` when it runs under systemd
   (`INVOCATION_ID` is set by systemd for service processes) and the unit is installed; `GET /api/about` returns
   `service: process.env.SCORE_RUN_AS === 'service'` (validated, false otherwise).
3. **Settings › About** shows a row "Runs as a service": "Yes — starts at boot and restarts after a crash" or "No —
   `scripts/score service install` turns it on" (the command as copyable code, using the existing copy pattern).
4. **Docs**: SETUP.md step 9a says the first terminal start offers it; README quick start mentions the prompt.
