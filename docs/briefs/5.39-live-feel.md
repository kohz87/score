# 5.39 Live feel

Owner 2026-10-11, after an "agent loop" explainer video (dark neon diagram: status line "calling query_metrics()…",
glowing active node, tool results checked green in place, context compacting, counters ticking up, a closing summary).
The owner wants the **feel**, inside Score's own look (`docs/design/`, light and dark themes), and in the workflow
editor too. Everything here is presentation of data Score already has, plus a client-only preview.

## Goal
Make running work feel alive and readable at a glance, without new noise.

## Scope
1. **Status line** for a working agent: one short, live line of what it is doing now, e.g. "Calling
   `search_changelog()`…", "Writing the reply…", "Waiting for your approval", "Compacting context…", "Thinking…".
   - Source: the streaming message's latest part (tool card running → "Calling `<tool>()`…", text streaming → "Writing
     the reply…"), open approvals for that agent, an in-flight compaction (context meter state), the `typing` event
     where it exists (fake mode). No new server events unless one is clearly missing; if so, propose it in the report
     and update `docs/API-CONTRACT.md` → contract → both sides in the same change.
   - Where: Now (the agent's lane/card), Chat (under the reply being written and on the agent chip in the room
     header), Flow (run header and the inspector of the active step), orchestration and workflow live diagrams (the
     active node's caption).
   - Text follows `docs/WRITING.md`; tool names in code style; at most ~60 characters, ellipsis-trimmed.
2. **Active-step glow**: the running step in Flow and the live diagrams gets a soft halo in the agent's colour (agents
   are always colour + shape: keep `AgentGlyph`). Tokens only from `tokens.css`; works in light and dark.
3. **Live counters**: tool calls, tokens and spend for a run tick up as they change (Flow stats, orchestration and
   workflow run headers). Spend keeps its "not settled"/estimated wording. Count-up animation through the existing
   `apps/web/src/motion/` module (anime.js); reduced motion → numbers just change.
4. **Checks in place**: a resolved approval or gate doesn't vanish: it becomes a compact chip where it was ("✓ Approved
   by you · 14:02", "✗ Rejected · 14:03", "✓ Always allowed"), in Chat, Now's Needs-you list (for a short while, then it
   leaves) and workflow gate cards.
5. **Run summary** when a run ends (Flow run, orchestration, workflow run): one line of facts Score has, e.g. "6 tool
   calls · 2 approvals · context compacted 34 → 12 · $0.009 (estimated) · 3 min". Only include a fact when it is known;
   never invent zeros.
6. **Workflow editor** (`/now/flow/workflows/:id`):
   - **Live overlay**: when a run of the version on screen is active, show "Live: run started 14:02 ›" (link to the run)
     and overlay its step states, glow and status line on the canvas; it never changes the draft.
   - **Preview**: a "Preview" button plays the drawn workflow through the same renderer as the live diagram (dots
     travelling, steps lighting up in order), clearly labelled "Preview: nothing runs, no tokens". At a gate it pauses
     with "Continue as approved / as rejected"; at a branch it asks which outcome to follow (default first rule);
     joins wait for all incoming paths; speeds 1×/4× like replay; Stop ends it. Pure client code: no server calls.
     Disabled with a reason when the draft has errors.

## Constraints
- Follow AGENTS.md (design rules, colour + shape, no new dependencies, licensing) and `docs/WRITING.md`.
- Calm motion only (no flashing, no constant pulsing of idle things); `prefers-reduced-motion` turns all of it off.
- No layout jumps: status lines and counters reserve their space.
- Phone and tablet layouts (5.34) keep working; no horizontal scroll at 360 px.
- Don't edit `docs/ARCHITECTURE.md`. Don't commit to main; don't merge.
- **Never use pkill, killall or pattern-based kills; kill only PIDs you started yourself. Never stop, restart or connect
  tests to the live Score on ports 8740/8741 or anything started from /home/raven/score. Before you finish, make sure no
  background shell, wait-loop or watcher you started is still running. Don't use git stash (shared across worktrees):
  save a patch, check out, test, apply back.**
