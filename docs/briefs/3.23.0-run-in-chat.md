## Done by the lead (server, contract) — build on it
`POST /api/orchestrations` and `POST /api/workflow-runs` take `topic?: { roomId, title, exchangeBudget?, jobTurnLimit?,
spendCapUsd? }` and make the run's topic in that chat **in the same transaction**; the answer adds `topicId`
(packages/contract/src/run-topic.ts; docs/API-CONTRACT.md under `POST /api/orchestrations`; server test

## Web (this task)
1. **One call.** `apps/web/src/bold/BoldStartJob.tsx`: a lead-decides or recipe run sends `topic` in its run body
   (title, the job limits it sends today) instead of `createLinkedJob` (the second call). Use the answer's `topicId` as the
   job id in the result. The "Orchestration created / the job wasn't" partial path (`PartialJob`, `setPartial`) becomes
   unreachable for runs: remove it and its tests (say which). Plain jobs (recipe None) keep `POST …/jobs`.
2. **Start in this chat.** BoldStartJob gets the chat to start in (today always the team room, `startRoom`): a team or
   group chat passes its room; the default stays the team room. A direct chat can't hold a run: say so.
3. **`/run`** in the palette (room/topic-commands.ts): `/run` opens Start a job for this chat on "lead decides";
   `/run <name>` preselects the saved recipe with that name (case-insensitive; several or none → open with the picker
   and a line saying so). Description in the palette. In a direct chat: "Runs start in a group chat."
4. **Run card in the stream.** A topic whose job links a run (`job.recipe`, kind orchestration or workflow) shows a live
   card right after its divider (also when the topic has no messages yet), as the mock-up: title, status, steps done of
   total, who is on what (active agents with AgentGlyph), and a needs-you line when the run waits on the person
   (protected: `data-protected`, protected list). **Show graph** opens the side panel's Graph tab for that topic. Reuse
   `recipeRun`/`RecipeRunCard` logic (room/thread-model.ts, chats/TopicInfo.tsx) and the existing queries; no new
   endpoints.
5. **Graph tab.** The side panel's tabs become Info | Results | **Graph**; Graph shows when the current topic links a run
   (and by `?work=graph`). Content as the mock-up: "Run · <title>", then the graph: the **job map**
   (`bold/jobmap/JobMap.tsx`, its moving dots and phases) for an orchestration, the workflow run's live graph for a
   recipe run (as `bold/BoldRuns.tsx` › `WorkflowRun` shows it), then **Session log** (the run page's live log,
   `routes/orchestrations/LiveLog.tsx` / `OrchestrationLive`, the same pane the Runs page shows). Updates live (it already
   does on the Runs page). The side panel is 300px: make the graph fit (scale, or scroll inside its box), never a
   horizontal page scroll. Phone: Graph is a tab of the Info sheet. "Open the run" keeps going to `/b/recipes?run=`.
6. **Links.** `?run=<id>` (BoldRoom, `chatForRun`) lands on the chat and topic *with the Graph tab open*.
