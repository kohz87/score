## Part 1 — journal foundations (design §2, §3 journal parts, §6b); e2e port 5490
- Installation identity: `$SCORE_HOME/installation.json` + the registry outside the home
  (`<journal dir>/installations.json`) under a registry-wide OS lock (batch Z `os-lock.ts`), per-namespace
  `manifest.json`, recovery of a missing home id from the registry/manifests, refusal on ambiguity, copied-home detection
  (new path ⇒ refuse executor/coding admission until confirmed; a CLI `scripts/score installation confirm-move` or a
  Settings action is fine — pick the simplest and document it).
- Per-installation journal namespace `<journal dir>/<installation id>/journal.ndjson` with its own `lock.sqlite`;
  migration from today's path-scoped journal under both locks with a fsynced `cutover` record; `scripts/restore.mjs`
  follows the cutover; orchestration writers use the new namespace. Keep batch EE's `roots.json` provenance working.
- Journal API: `journal.critical(fn)` holding the lock across read → CAS → append+fsync → DB projection (design §3);
  coding record types (`launch-requested`, `armed`, `releasing`, `revoked`, `released-seen`, `ended`, `settled`,
  tombstones kept forever, checkpoint sequence stored in the DB; a DB checkpoint behind the journal fences admission).
  Not yet used by the coding runtime (part 3 does), but fully tested.
- Migration number **0057** if you need a table/column (e.g. the checkpoint).

## Part 2 — supervisor, wire protocol, launcher, unit builder (design §1, §2 of v3/v4 text, §4, §5); e2e none
- `apps/server/src/runtimes/coding/supervisor.mjs` (Node built-ins only, plain JS): spec reading, `hello`/`ready`/
  `go`/`cancel`/`stop`/`out`/`eof`/`exit`/`end`/`ack-end` protocol, chunked stdout/stderr with sequence numbers,
  backpressure (pause CLI pipes above a high mark), the INT → TERM → KILL escalation, stays alive until its cgroup's
  `payload/` is empty, watchdog pings via `systemd-notify` from the control loop, receipts (`released` before exec,
  `ended`) written O_EXCL + fsync + directory fsync in the receipt directory it is given.
- The exec wrapper (`pdeathsig-exec.py`) gains `--cgroup <dir>`: write own pid to `<dir>/cgroup.procs`, then `execv`.
- `runtimes/coding/units.ts`: builds the exact `systemd-run --user` argv of design §1 (properties, deny list,
  `env -i` bootstrap, unit name validation), parses `systemctl --user show` output, reads `cgroup.events`, manager
  incarnation (`systemctl show user@<uid>.service`), capability check (design §8/§7: manager reachable, properties
  accepted, cgroup v2, linger, socket path length), exact-name stop/reset gated on InvocationID.
- `runtimes/coding/coding-socket.ts`: the Score side of the wire protocol (Unix socket at
  `$XDG_RUNTIME_DIR/score/<installation8>.sock`, 0700 dir, single-use tokens, frame bounds, reassembly, completeness
  bookkeeping, explicit destroy on shutdown).
- Tests: protocol unit tests with a fake supervisor and a fake Score; supervisor tests with harmless CLIs (`node -e`)
  **without** systemd (cgroup parts injected); opt-in real-systemd tests: a unit with a `setsid` survivor, supervisor
  SIGKILL ⇒ whole cgroup killed, SIGSTOP ⇒ watchdog kill, manager sentinel env never reaching the CLI, Stop sequence.

## Lead answers to part 2's open questions (for part 3)
- **Unit names**: launch ids are UUIDv4 (server-minted); the unit name is `score-<installation8>-c-<launch id without
  dashes>.service`, so uniqueness follows from the UUID. Store the exact unit name in the launch row and journal record;
  never derive it again from other fields.
- **Limits**: keep part 2's `DEFAULT_LIMITS` (1 MB record = today's driver line allowance, 64 MB per stream, 128 MB per
  run, 64 MB installation-wide) as named constants beside the driver allowance, with a comment that they are policy.
- **Spec delivery**: `$XDG_RUNTIME_DIR/score/<installation8>/launches/<launch id>/spec.json`, directory 0700, file
  O_EXCL 0600; the supervisor deletes it right after reading (before `hello`); Score deletes it on `ready` or settlement
  as a backstop. The receipt directory (outside the home) stays as the design says.
- **Capability check**: once at startup (logged, shown on coding agent cards) and on demand from the card's "Check
  again"; cached otherwise. A failed check keeps the process-group backend for Chat and refuses executor workers.
- **No `ended` receipt when the CLI never started**: agreed; no-launch is proven by the journal (`revoked` / no
  `releasing`), never by receipts.
- **Supervisor's `kill(-pgid)` on the CLI group**: acceptable — the CLI is the supervisor's own unreaped child, so its
  group id can't be reused while the supervisor still holds it; everything else goes through `cgroup.kill`.

## Part 3 — integration (brief; parts 1 and 2 are merged)
Wire parts 1 and 2 into the coding runtime as backend `unit`, per design v7 §§1–8 and the answers above. Read the merged
code first: `installation.ts`, `coding-journal.ts`, `coding-records.ts`, `coding-checkpoint.ts`, `journal-migration.ts`,
`supervisor.mjs`, `coding-socket.ts`, `units.ts`, and today's `service.ts`/`process.ts`/`proc.ts`/`translate.ts` and the
drivers.
1. **Backend selection** at startup from the capability check: `unit` when every capability passes, else the process-group
   backend (W–DD). Stored per launch in `coding_launches` (add columns in **0058** as needed: backend, unit name,
   invocation id, cgroup, receipt dir, spec dir, stop cause, disposition, eligibility). Both inventories reconciled before
   any admission; never switch backend for an uncertain launch.
2. **Launch** (unit backend): `CodingJournal.requestLaunch` → spec + receipt dirs → `systemd-run` (units.ts) → supervisor
   `hello`/`ready` → verify identity against systemd and `/proc` (§5) → `arm` → for Chat the authorisation is "not
   stopped, agent not fenced" → `release` (critical section) → DB commit → `go`. Revocation via `revoke` at every phase as
   the design says. Spec dir per the lead answers.
3. **Streaming**: socket records feed today's driver parser/translator unchanged (stdout records) and stderr notes;
   5.39 status lines keep working; completeness per §4 (ack-end only after every stdout record is processed).
4. **Termination and evidence**: ended proof (§6) from the unit's cgroup; terminal commit after proof; `settled` +
   collection (§6b); DD's pending-delivery table reused for results that can't be saved yet.
5. **Acceptance matrix** (§6): pinned driver rules (Claude Code explicit success with text; Codex validated final
   `agent_message` before `turn.completed`, nothing dropped; Antigravity `SUCCESS` + response); remove the exit-zero /
   commentary fallback in `service.ts`; Chat hand-offs and plans use only the eligible authoritative reply (v3 §5).
6. **Recovery** at start: journal ↔ DB checkpoint ↔ live units (`score-<installation8>-c-*`) ↔ receipts; orphans fence;
   `may have executed` without proof ⇒ `unconfirmed` + fence + Release (W/X semantics mapped onto units).
7. **Stop**: protocol `stop` if connected, else `systemctl --user stop <exact name>` gated on InvocationID;
   `StopOutcome` semantics unchanged.
8. **UI**: the coding agent card shows the backend ("Runs as a supervised system service" / the fallback note) and the
   capability check result with "Check again".
Tests: everything listed in design v7 "Done when" that parts 1–2 didn't cover, through the real `CodingRuntime` with the
fake systemd boundary, plus the opt-in real-systemd suite extended with a real coding turn of a harmless fake CLI driver
through `CodingRuntime` (start, stream, stop, restart recovery). e2e: the coding-agents specs green on the fake adapter.
Migration **0058** is yours. e2e port 5491.

## Second fix round (review `docs/reviews/2026-10-12-7.7a-code-rereview.md`): FY1 and FY2, by layer

**Shared journal API (FY2 implements, FY1 calls exactly these names):**
- `CodingJournal.recordStop(launchId: string, cause: StopCause): Result` — appends a fsynced `stop-requested` record
  (first cause wins, monotonic) **before** any signal is sent; DB projection updated in the same critical section.
- `CodingJournal.waive(launchId: string, by: string): Result` — appends a `waived` record and settles the launch
  (disposition `waived`) in one critical section; recovery treats a waived launch as permanently settled (never stops
  it again, never "rebuilds" it).
- `CodingJournal.isOwned(launchId)` / records carry `inherited: true` for witnesses copied from another installation;
  inherited launches are never acted on (stop/reset/recover), only kept as evidence that their turns are unsendable.

**FY1 — runtime layer** (`supervisor.mjs`, `supervisor.d.mts`, `coding-socket.ts`, `units.ts`, `unit-backend.ts`,

## Fourth fix round FW (review `docs/reviews/2026-10-12-7.7a-code-rereview3.md`; decision 70)
One builder, directly on `task/7.7a-part3` (worktree `../score-worktrees/7.7a-3`), all files, in this order:
1. **Copies, unconditional** (#3, #4): `confirmCopy` retires every non-terminal orchestration attempt (created, refused,
   send_started, running, unknown), every pending/sent/unknown intent of any kind that can execute, every process row and
   member, every run handle and owed Stop, durably in the `inherited-retired` record; dispatch and Stop delivery consult
   that disposition. Production always wires a conservative ownership check: unresolved installation identity, a copy
   without its retirement record, or unreadable history ⇒ **no** signal.
2. **Scope** (#1, #2): the capability marker must be durably written (and retried) before the first unit launch is
   allowed; positive evidence is also recoverable from owned unit history; `SCORE_CODING_BACKEND=process-group` is only
   honoured when `NODE_ENV=test`/the test harness sets it (never in production; remove it from SETUP.md).
3. **Missing journal** (#5): before a `journal_missing` fence can be lifted, every surviving launch folder (routing,
   identity, receipts) becomes a permanent unsendable turn disposition in a fresh journal; the lift is refused until
   that reconciliation succeeds (no timestamp shortcut).
4. **Terminal evidence** (#6): the supervisor writes a durable final receipt (`acked.json`, after it has *read* `ack-end`,
   before exiting 0); eligibility requires it; missing unit exit metadata is uncertainty, never "clean".
5. **Drivers** (#7): every unknown or rejected record is loss unless explicitly allow-listed as ignorable per driver;
   Claude Code gets the same final loss check as Codex; loss is evaluated after final EOF processing.
6. **Redaction before bounds** (#8): redact whole CLI fields before cutting; the diagnostic accumulator discards an
   uncertain open credential (mask to the end) instead of cutting it.
7. **Forced closure on the fallback** (#9): natural stdout EOF vs destruction tracked separately; destruction is loss.
8. **Budget** (#10): charge parser + translator (`translationBytes`) + pending delivery; release only when cleared.
9. **Stop cause** (#11): projection never overwrites an adopted cause with null; adoption validates and reports bad
   receipt files and the generation.
Every item: a failing-first test at the real boundary (patch/checkout/apply, never stash). Run `pnpm check`, the opt-in
real-systemd suite once, and the full e2e (SCORE_WEB_PORT=5491, production build) at the end.

## Fifth fix round FV (review `docs/reviews/2026-10-13-7.7a-code-rereview4.md`; decision 71)
One builder, directly on `task/7.7a-part3`, in this order:
1. **Freeze rare states** (#2–#5): one predicate `executionFrozen(): string | null` (installation unresolved, home is a
   copy — confirmed or not —, journal missing or truncated/mismatched with surviving launch folders). While frozen: the
   orchestration executor dispatches nothing and delivers **no Stops**, Hermes intent recovery delivers no Stops for
   inherited/unowned runs, the coding runtime admits nothing and recovery signals nothing; the existing automatic
   copy-retirement and missing-journal reconciliation paths are removed (not just bypassed). New
   `scripts/score installation reset-history` (Score stopped; confirmation prompt; `--yes` for scripts): retires every
   non-terminal attempt, intent, process row, member, handle, owed Stop and coding launch in the database, records a
   permanent `history-reset` in a fresh journal namespace, and lifts the freeze. Fence UI and coding card say "Score is
   holding all agent work: <why>. Run scripts/score installation reset-history to continue." Tests: every rare state
   freezes dispatch, Stop delivery and signals (the review's probes as tests), and reset-history unfreezes and never
   re-sends.
2. **Small durability fixes** (#1, #6): an existing capability marker is trusted only after a successful directory
   fsync (re-fsync on EEXIST); the supervisor unlinks `acked.json` if its directory fsync fails before exiting non-zero,
   and Score requires the receipt **and** a clean exit (or a receipt carrying `durable: true`, written only after the
   fsync succeeded) — never absence alone.
3. **Ordinary paths** (#7–#11): validate allow-listed "ignorable" records (an `error` envelope or a `system` record that
   reports an error invalidates authority); an adopted stop cause disqualifies completion; resume retry happens only
   after the first attempt's loss is evaluated (and never if it had loss); raw commentary is redacted before it is cut
   for terminal storage; a memory-budget violation keeps charging the run's actual retained bytes until they're
   cleared (no timed release while retained state exists).
Failing-first tests for each. Then `pnpm check`, the opt-in systemd suite and the full e2e (SCORE_WEB_PORT=5491).
