## Task (from docs/PLAN.md)
**3.12 Profile management** (owner request): create (blank or cloned) / describe / delete agents from Team via
`hermes profile …`; a new agent is ready for Score; delete needs the typed name and keeps an export first.

**Binding design: the Codex adversarial review `docs/reviews/2026-10-08-3.12-profiles-design-codex.md` (read it fully) plus
these lead decisions, which override the draft where they differ:**
1. **Contract first** (update `docs/API-CONTRACT.md` §8 and `packages/contract` in this task — the lead authorises it):
   **H** `POST /api/agents` (create), **H** `PATCH /api/agents/:id` (description, Score display name), **H**
   `DELETE /api/agents/:id` (typed name in the body), `GET /api/agents/operations/:opId` (status), and a
   **H** `POST /api/agents/preview` that returns exactly what a create/clone/delete will do (inherited data and
   capabilities for a clone: memories, plugins, approval settings, credentials present — names only, never values; for
   delete: pending work and its disposition, the export location). The create/delete calls carry the preview's hash; a
   stale hash is 409. Events: `agent.updated` (existing) — no new event types.
2. **Create**: canonical-name validation (Hermes rules; reserved: default and retired names). Exact argv
   `hermes -p default profile create <name> [--clone-from <src>] --description <text> --no-alias` (never --clone-all /
   --clone-channels / --sync-imports). Then: fresh Score-generated API key written to `/hermes-keys/<name>` (0600,
   atomically) **before** `hermes -p <name> config set API_SERVER_KEY <key>` (never log argv containing it; the CLI runner
   must redact that argument); model via the existing 2.16 path; **team rules** via the 2.18 write loop; the bridge plugin
   via the Hermes CLI only (`hermes -p <name> plugins install <pinned file/git URL of hermes-plugin/score_bridge>` then
   `plugins enable score-bridge`; if Hermes refuses, stop and report — never link or copy files into Hermes). No gateway
   start/stop/install: the host gateway serves new profiles. Score marks the agent **ready** only after verifying: key
   accepted by the gateway for that profile, model and permissions read back, bridge handshake seen; until then the agent
   is shown as "Setting up" and Score routes nothing to it.
3. **Operations**: a durable operation row (id, kind, target name, request hash, per-step state, created_at) with a
   lock per target; each step verifies its postcondition; recovery after a crash continues or stops at a clearly reported
   state ("needs attention" with the exact next step). Never adopt an existing directory as "ours"; never delete,
   import, rotate or restart automatically.
4. **Rename**: not in this task. PATCH sets a Score **display name** only (Score-owned; the Hermes profile id stays).
5. **Delete** (H): refuse `default`, refuse while Score shows any active run, queued turn or pending approval for it
   (freeze admissions first, then re-check); typed name must match; export first with
   `hermes -p default profile export <name> -o <path>` to `/profile-backups/` (0700 dir, path-checked, private,
   never served over HTTP); the UI says the export omits credentials and isn't a full undo. Then
   `hermes -p default profile delete -y <name>`; reconcile (directory gone; purge state). Score retires the agent: routing,
   room membership, lead selection and pending turns removed; history kept with "removed" attribution; the name is
   retired (re-creating the same name later requires an explicit "this is a new agent" confirmation and gets a new
   incarnation id so old turns can't reach it).
6. **UI** (Team page, design language of docs/design/team.png): "Add agent" button in the Team list; a dialog with name,
   role/description, start from (blank / copy from agent), model, color + shape (AgentGlyph), the preview of what's
   inherited with a confirmation checkbox when cloning, progress per step, and a clear failure state. Agent page:
   "Edit description", "Display name", and a danger zone "Delete agent" with typed-name confirmation, the pending-work
   summary and the export path.
7. **Tests**: fakes and recorded/stubbed CLI only (AGENTS.md). Exact argv for every step, key never in logs/argv
   captures, crash after each step + recovery, stale preview 409, name reuse, delete refusals, guard on every mutation.
   The lead will do a manual live check on throwaway test profiles after review.
