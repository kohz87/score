## Build (apps/web only, bold shell)
1. **Start a job** (`apps/web/src/bold/BoldStartJob.tsx`, lead mode `isLead` only), next to the check section added in 3.13:
   an optional **Advisor** choice: "None" (default) or any agent of the team except the chosen lead (Hermes or coding).
   One line of help: "A strong model Score asks before the plan, when a failure repeats, and before it finishes. Its advice
   goes to the lead; the lead decides. Choose an agent set up for reviewing: it runs with its own tools."
   - Send `advisorAgentId` only when chosen.
   - The advisor must be included in the preflight query's `allowedAgents` (`GET /api/orchestrations/preflight`), and a coding
     advisor's policy id in `codingPolicies` (and in `acknowledgeCodingReach` if its reach goes beyond its workspace), exactly
     like the allowed agents already are. Find that code and extend it; don't add the advisor to `allowedAgents` in the body.
   - If the lead changes to the chosen advisor, reset the advisor to None.
2. **The job's view** (`bold/BoldRuns.tsx` and `routes/orchestrations/RoomRunPanel.tsx`, where `CheckCard` went): an
   **Advisor** card when `detail.advisor` is non-null: the advisor's name (AgentGlyph as elsewhere), then each consult:
   checkpoint label ("Before the plan" / "Same failure twice" / "Before it finishes"), the reason when non-empty, status
   (looking / advice given / failed …), time, and the advice text (pre-wrap, wraps at phone width).
   - Steps with `role === 'advisor'` must not appear as the lead's steps in step lists/counters/graphs of the job views;
     filter them out there (they are shown in the Advisor card instead). Check every place that renders `stepsList`.
3. Styles: reuse the CheckCard look (`orchestrations.css`), bold tokens, phone width without horizontal scroll.
