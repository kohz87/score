# 2.3.0 Agent questions: the UI (brief)

Decision 128 (end of docs/DECISIONS.md). Contract: docs/API-CONTRACT.md §6a "Agent questions" and the two stream events
`question.requested` / `question.updated`; schemas in packages/contract/src/questions.ts (already committed). The lead
builds the server (routes, store, Hermes adapter, fake mode) in this same branch in parallel; until it lands, test with
mocked fetch. When the lead says the server is in, add the e2e.

## Done when
1. **Data**: `apps/web/src/data/` gets a questions query (`GET /api/questions?status=pending`, and per room with
   `room=`), kept fresh by the stream events (follow how approvals are cached and patched from `approval.requested` /
   `approval.updated`), and an `answerQuestion(id, answer)` mutation (`POST /api/questions/:id/answer`, mutation headers
   like other H routes). A 409 refreshes the item from `details`.
2. **Card** (new shell): a pending question is a needs-you item wherever approvals are: the room's needs-you strip /
   RoomRequests, the dock's needs-you count, the phone job list badge, and the one-to-one (DM) view of that agent.
   The card: agent glyph (mood `needs`) + "builder asks", the question text (plain text, preserve line breaks, never
   HTML/markdown-rendered), then:
   - options, single select: one pill button per option (tap answers);
   - options, multiSelect: toggle pills + "Send" (disabled until one is picked);
   - no options: a textarea (grows like the composer, ≤ 16 384 chars) + "Send"; Enter sends, Shift+Enter newline.
   - "Delivering…" while `delivery: 'delivering'`; on `failed` an inline "Couldn't deliver, try again" and the inputs
     come back; `expiresAt` shown as "waits until 3:42 PM" (local time).
   - answered/withdrawn/expired questions leave the needs-you strip; in the room's message stream show a compact,
     muted line where it was asked ("builder asked: … — you answered: …" / "— no answer (timed out)").
   Copy the card look from the approval card in the bold shell (docs/design/bold/prototype.html is the source of truth
   for the needs-you card: light object on the dark ground, pill buttons, 20–30px radii). Class names `bold-question-…`.
3. **Protected**: the question card asks the person to decide, so it carries `data-protected` and is added to the
   protected list (`styles/protected.css`, `themes/protected-surfaces.ts`, their tests), like the approval card.
4. **Accessibility**: the card is a `region` labelled "builder asks"; option pills are buttons (multi: `aria-pressed`);
   focus goes to the first input only when the person opened the card, never on arrival; live-region announcement on a
   new question in the open room ("builder has a question") once.
5. **Tests**: unit tests for the card (each mode, delivering/failed, 409), the cache patching from stream events, and
   needs-you counts including questions. e2e `e2e/bold-agent-questions.spec.ts` (fake mode) once the lead's fake
   adapter can raise a question: answer free text, single and multi; the item leaves needs-you; phone layout.
