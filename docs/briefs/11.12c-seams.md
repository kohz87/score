# Brief 11.12c: The new shell's seams (phase-gate findings)

PLAN 11.12, decision 121. The phase-gate review of `/b` found these where tasks built by different coders meet. Fix
exactly these; report anything you find on the way instead of fixing it.

## Decisions must never be missed (P2)
1. **Empty room hides approvals** — `room/BoldTeamRoom.tsx` mounts `RoomRequests` only when `!empty`; an approval with
   no room ref belongs to every room, so a fresh team room shows `RoomEmpty` and no card. Mount the strip whenever it has
   something (approvals, exchanges, run-safety, the fence), empty room or not.
2. **Phone: no "needs you" outside the room list** — add a protected count badge on the tab bar's Room button (the
   same total the strip uses; `data-protected`, protected-surfaces.ts; colour + text, not colour alone) and make the
   agent page's "Needs you · …" line a link to the room (or the job). Report as a difference from the prototype.
3. **Screen page during replay** (`BoldScreen.tsx` ~292): the approval bar shows only while live. While replaying, show
   a protected "Needs you — go live" chip that returns to live and shows the bar.
4. **One rule for "needs you"** — the dock (`BoldShell.tsx` ~103), the strip (`room-model.ts` `approvalNeedsYou`) and
   the screen bar (`BoldScreen.tsx` `pendingApproval`) disagree. Export one `approvalNeedsYou` and use it in all three
   (and anywhere else an approval's open state is decided in `bold/`). Unit test the shared rule.
5. **New cards are announced** — the strip is `role="region"` (`aria-label="Needs you"`) with a visually hidden
   `role="status"` that says "N need you" when the count grows (not on every render). Drop the nested live region:
   `#bold-room-stream` is `aria-live` and each streaming part is too (`routes/chat/MessageItem.tsx` ~610) — keep the
   part's, remove the stream's (or the reverse; say which and why).

## Navigation and state (P2/P3)
6. **Search → Library note does nothing** — `boldNoteLink` goes to `/b?note=<path>` but nothing reads `note`.
   `BoldRoom` reads `note`, switches the side panel to Library (sheet open on phones) and `BoldLibrary` opens that note.
7. **Escape closes two layers** — on a phone the sheet's Escape runs before the side-panel menu's (`BoldRoom.tsx`
   ~94/~108). One Escape closes only the top layer: the menu's listener is a capture listener that stops propagation,
   or the sheet skips while the menu is open. Same check for any other menu inside a sheet.
8. **Params clobbered** — Recipes' `navigate('/b')` (`BoldShell.tsx` ~100) drops `job`/`message`/`work`/`file`;
   `boldOneToOneLink` drops `job`, so leaving a one-to-one returns to All; `selectJob` keeps another job's `file`.
   Preserve the unrelated params in these navigations and delete `file` when the job changes.
9. **Links into the retired classic pages** from `/b`: `BoldScreen.tsx` ~100 (`/chat` for a non-actionable approval —
   point to the bold place that answers it, or say "answer it in Hermes" as the room does), `BoldLook.tsx` ~84,
   `BoldFirstRun.tsx` ~256 and any `/settings/...` classic link from `bold/` that has a `/b/settings/...` home. Grep
   `bold/` for `to="/` and `navigate('/` targets outside `/b` and list what remains (kept classic pages like
   `/workflows`, `/runs`, `/watch`, the Customizer are fine).

## Consistency and cleanup (P3)
10. **One label per state** — job state ("Needs you" everywhere, not "Waiting on you"), one agent-state label helper
    (`bold-agents.ts` `agentStateLabel`; remove the copies in `BoldAgent.tsx` and `BoldScreen.tsx`), agents named the
    same way in the dock, side menu, DM header, Results and room (use the contract's display rule: `name`, falling back
    to `id`), one helper for 401/403 text ("Pair this browser first.") used by every bold surface.
11. **One team-room read** — `['bold-search','team-room']` (plain query, BoldHome/BoldFirstRun/Search) and
    `['bold','team-room']` (bold-results-queries) both duplicate `teamRoomQuery` (room-queries.ts): move them onto
    `teamRoomQuery` (Search keeps reading fresh when it opens). `jobResultsKey` read by `RoomMessageStream` for
    `workspace://` links: refetch it when the link is used if it is stale.
12. **Same key, different reducer** — `roomMessagesQuery(room, job, null, null)` in `BoldThread.tsx` vs the room's call
    with `defaultJobId`: pass the same `defaultJobId` in the thread so the one registration is right for both.
13. **Dead code** — delete unless a test proves a use: `needsRecipeRun` (thread-model.ts), `sortPinCards` (PinCards.tsx),
    test-only exports `shouldShowFirstRun`, `addAgentPalette`, `moveChatToTeamRoom`, `moveRecipeStep`, `orderNodes`
    (drop with their tests if nothing ships them), `sideCopy` and its unreachable placeholder branch (BoldRoom.tsx).
