# 8.7 Coding agents' sub-agents: recognised and shown (owner 2026-10-17; decision 92)

Owner asked whether coding agents can use their own sub-agents inside a task and come back to update the orchestration.
They can (Claude Code at workspace-write/full; read-only only has Read/Grep/Glob), and the step result reaches the lead as
usual. A real captured turn (Claude Code 2.1.302, workspace-write, one general-purpose sub-agent, 2026-10-17:
`/home/raven/.claude/jobs/999c85f0/tmp/8.7/claude-subagent-2.1.302.jsonl`) showed two problems:

1. **Bug: a turn that used a sub-agent ends with `loss`** ("Claude Code sent a system record that Score could not rule
   out as a failure"): the system subtypes `task_started`, `task_progress`, `task_updated`, `task_notification` (and
   `thinking_tokens`, new in 2.1.302) are unknown to the parser (7 unknown records). In an orchestration this marks a
   successful step as not cleanly finished.
2. Sub-agent activity is flattened: the sub-agent's tool calls (records with `parent_tool_use_id`) look like the main
   agent's.

## Work
1. **Parser** (`apps/server/src/runtimes/coding/claude.ts`): zod schemas for the `task_*` system records and
   `thinking_tokens` (read the captured shapes; keep them strict enough that a *failed* sub-agent is visible: a
   `task_notification`/`task_updated` reporting failure marks the **sub-agent** failed, not the turn — the turn's verdict
   stays the `result` record's, FV #3 rules unchanged otherwise). Unknown system subtypes keep producing loss (don't
   weaken that). Records with `parent_tool_use_id` produce events carrying `parentCallId`.
2. **Events and storage**: the coding event types and their translation into chat/tool cards (`translate.ts`, the
   contract types the web reads — find where tool cards are described in `packages/contract`) gain an optional
   `parentCallId`; the Agent tool's card gets a sub-agent summary (description, subagent type, tool-call count, status,
   duration, tokens if reported). Contract doc first.
3. **UI**: in Chat, Flow's step log and Watch, the sub-agent's tool calls nest under the Agent tool card (collapsed by
   default: "Sub-agent · List files in folder · 1 tool call · done"), with AgentGlyph of the coding agent and a small
   "sub-agent" label. Plain words (docs/WRITING.md).
4. **Fixture**: copy the capture to `apps/server/test/fixtures/coding/claude-subagent.jsonl`, replacing the home path
   with `/work/ws`, ids with stable fake ids, and keeping every record type; the driver test asserts `loss: null`,
   `unknown: 0`, the nesting, and the result.
5. **Docs**: a short section in the coding-agents help/docs: sub-agents are available at workspace-write and full, they
   share the agent's folder, sandbox, blocked paths and plan quota, and the lead gets the step's final answer.

Not in scope: Antigravity sub-agents (no captured records yet; note it), progress reports to the lead mid-step, adding
2.1.302 to the tested versions (the lead does that after a separate plain-turn check).
