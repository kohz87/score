## Spike: listing a profile's MCP server tools without Score reading credentials (2026-10-24, from Hermes source)
Read in `../reference/hermes-agent` at `e97923c38a` (2026-10-06); to be confirmed live on the test profile
`scoretesta` before report-back ships.
- **Yes, three ways, none of which hands Score a credential.** Hermes resolves `${ENV}` headers and OAuth tokens
  itself in every probe.
  1. **In the gateway process (preferred).** A connected (or schema-cached) MCP server's tools are registered in Hermes's
     tool registry under the toolset `mcp-<server>` (`tools/mcp_tool_registration.py`), with name, description and
     the full input schema (`registry.get_tool_names_for_toolset`, `registry.get_entry(name).schema`). The bridge
     plugin runs in that process, so a plugin command can return them. That is a private API: it goes in
     `score_bridge/hermes_private.py` and is covered by the plugin's compatibility fingerprint.
  2. `hermes --profile <p> mcp test <server>` (`hermes_cli/mcp_config.py::cmd_mcp_test`): connects, lists tools; human
     output only, descriptions cut to 55 characters, no schemas. Exit codes 0/1/3.
  3. The dashboard API `POST /api/mcp/servers/{name}/test?profile=` (`hermes_cli/web_routers/mcp.py`): JSON
     `{ ok, tools: [{ name, description, schema_chars? }] }`, no input schemas, and only while `hermes dashboard` runs.
- **Decision:** route 1 for ranking and argument mapping (D18 step 4 needs the schemas); route 2 as the fallback when
  the plugin can't answer (tool names only, the owner maps arguments by hand, as PLAN's fallback says).
