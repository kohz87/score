## Done when

1. **Organise rooms.** Pin (pinned first), archive (hidden behind "Show archived"), projects (named groups with a colour,
   a room belongs to at most one; rooms list grouped by project, collapsible), `#tags` (tags parsed from the room name or
   set explicitly; chips; click filters). Score DB only (migration **0035**), contract §5, stream `room.upserted` carries
   the new fields. Keyboard and screen-reader friendly; matches the Chat design.
2. **Search message content.** `GET /api/search/messages?q=&roomId?&limit≤50` over Score's messages (SQLite FTS5 on
   text parts, deleted messages excluded, user text tokenised to quoted terms as in Knowledge); results with room, author,
   time and a snippet; in the command palette ("Messages" section) and in a Chat search box; opening a hit scrolls to the
   message.
3. **Export.** Per room: Markdown transcript and JSON (`GET /api/rooms/:id/export.md|.json`), text parts and file/image
   references (no media bytes), redacted, deleted messages excluded, with a header (room, members, exported at).
4. **Share link — security design (lead, 2026-10-09; implement exactly):**
   - Creating one is **H** and needs the **security password** (same check, limits and errors as pairing management):
     `POST /api/rooms/:id/shares { password, expiresInDays: 1..30 (default 7), includeImages: false }` →
     `{ id; url; expiresAt }`.
   - The share is a **frozen snapshot** taken at creation: text parts only (Markdown source) plus, only when
     `includeImages`, image media ids copied into the share's own reference list; **no** tool, thinking, file-path, plan,
     review or approval parts; every text passed through `redact()`; author names and times kept; no room settings,
     members' ids, workspace paths or profile data.
   - Token: 32 random bytes (base64url), **stored only as a SHA-256 hash**; URL `https://<public origin>/s/<token>`.
   - `GET /s/:token` is the only unauthenticated route added: constant-time hash lookup; expired/revoked/unknown → the
     same 404 page; rate-limited per IP (e.g. 30/min); served as **server-rendered static HTML** (escaped text, Markdown
     rendered on the server without raw HTML), no app JavaScript, `Content-Security-Policy: default-src 'none'; img-src
'self'; style-src 'unsafe-inline'`, `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`;
     images (if included) via `/s/:token/media/:n` only for ids in that share. Plain-HTTP requests get the HTTPS guide as
     everything else (5.18).
   - Reachable only by people who can reach Score (LAN/Tailscale); the create dialog says so.
   - Settings › Shares: list (room, created, expires, views), Revoke (H, no password needed to revoke), and room menu
     "Share…" shows active shares. Migration 0035 (same file as point 1 is fine).
   - Tests: token never stored in clear, hash lookup, expiry, revoke, rate limit, snapshot excludes every non-text part and
     redacts, CSP/headers, unknown vs expired indistinguishable, password required and limited.
5. **Outside sessions.** List each agent's Hermes sessions that Score did not start (read-only from the profile's
   state.db through the adapter: id, source/platform, title or first user message, started, message count), in Chat
   ("From elsewhere" section, grouped by source like Telegram, CLI, Discord). **Import** creates a Score room whose
   history shows that session's messages (read-only copies, redacted, marked "from Telegram/CLI"). **Continue here**: if the
   gateway runs API accepts that `session_id` for new runs (check Hermes `api_server_runs.py`; mind a session that is
   still active on its platform — refuse with a clear message while it is busy), new turns from the room go into the same
   Hermes session; otherwise the room starts a new session with a short summary of the imported history as context, and
   the UI says which happened. Never write Hermes SQLite.
6. Tests for each, e2e on the fake adapter (pin/archive/project, search, export download, share create → open /s/ page →
   revoke → 404, import an outside session), visual baselines for Chat changed areas checked by eye.
