# 10.3 — A previewed zip isn't sent twice

Owner (2026-10-19): a big zip uploaded to Knowledge goes up twice, once for the preview and again for Keep/Unzip.

## Goal and "done when" (from docs/PLAN.md 10.3)
- A previewed zip is kept or unzipped with **no second upload** (one PUT in the network log).
- A `409 exists` retry (choosing Keep both / Replace) also sends nothing.
- An expired or unknown stage (`404 staged_gone`) falls back to sending the file again, with the progress panel.
- Staging is bounded (8 zips, 256 MB total, 30 minutes), emptied when Score starts, and stores files under random ids
  only, never under a client-given name or path.

`docs/API-CONTRACT.md` › Knowledge › "Staged zips (PLAN 10.3)"; `packages/contract/src/knowledge.ts`:
`KnowledgeZipPreviewSchema.staged`, `KnowledgeFromStagedRequestSchema`. Don't edit them; raise anything that doesn't fit.

## Server (`apps/server`)
- Find the Knowledge upload route (`PUT /api/knowledge/files/*path`, `mode=preview`) and the `files-from-media` route; the
  new `POST /api/knowledge/files-from-staged` mirrors files-from-media and must reuse **the same keep/unzip code paths**
  as the PUT (same checks, conflicts, history, events) — refactor so both feed bytes into one function; no copy.
- A small staging store (`src/knowledge/staging.ts` or next to the existing upload code): `$SCORE_HOME/knowledge-staging/`
  0700, files 0600 written via temp + rename, id = random 24+ chars base64url, metadata in memory (path previewed for,
  size, expiry). Read with the project's existing no-symlink file helpers. Bounds: 8 entries / 256 MB (evict oldest),
  30-minute expiry (lazy sweep on each use plus on start); start-up removes every file in the folder.
- Answers: as in the contract (`404 staged_gone`, `409 staged_mismatch`; a `409 exists` keeps the stage; success removes
  it). Pairing/host guard (**H**) as the other Knowledge writes.
- Tests failing first (Fastify `inject()`): preview returns `staged`; keep and unzip from staged produce the same results
  as the PUT; mismatch path; gone after success, after expiry (fake clock), unknown id, malformed id (400); conflict keeps
  it; eviction at 8 / 256 MB; start-up cleanup; files are 0600 under random names.

## Web (`apps/web/src/routes/knowledge/`)
- `knowledge-files.ts`: `keepStaged`/`unzipStaged` calling the new route with `apiFetch`; `UploadFlow.tsx` uses
  `preview.staged.id` when present for Keep and Unzip and for 409 retries, and falls back to `uploadBlob`/`unzipBlob`
  (with the progress panel) when `staged` is null/absent or the server answers `404 staged_gone`.
- While the staged call runs, the progress panel shows "Saving…" / "Unzipping…" (no percent: nothing is being sent).
- Tests failing first: the flow sends one PUT for preview + keep, preview + unzip, and preview + 409 + retry; the
  `staged_gone` fallback re-sends with progress. One e2e in `e2e/` (fake mode): drop a zip, preview, unzip, and assert
  only one request carried the zip body (count `PUT /api/knowledge/files` requests).
