# Brief 6.5: Knowledge editor — live preview (owner 2026-10-10)

**Problem (owner):** "the knowledge has no editor and doesn't render markdown like table". Today notes open in a raw
CodeMirror source editor; the rendered view is behind a Preview toggle, and `knowledge.css` has no table styles, so
tables render unstyled.

## Do

1. **Rendered by default:** opening a note shows it rendered (read mode). "Edit" switches to the editor; on screens
   ≥ 1200 px a "Split" mode shows editor and rendered view side by side (scroll roughly in sync). Remember the person's
   last mode per device (localStorage, wrapped in try/catch).
2. **Live preview editor (Obsidian-style), CodeMirror 6 decorations** — no WYSIWYG library: in the editor, Markdown is
   rendered inline on every line except the one(s) the cursor is on: headings sized, **bold**/_italic_/`code` styled
   with markers hidden, links and `[[wikilinks]]` shown as links (Ctrl/Cmd-click opens), task list checkboxes clickable
   (toggle edits the source), horizontal rules, blockquotes/callouts styled, fenced code blocks styled as blocks,
   **tables rendered as a table widget when the cursor is outside them** (editing a table shows its source). Images:
   not in v1. The file content must stay byte-for-byte what the person typed (decorations only; no reformatting).
   Use only `@codemirror/*` / `@lezer/*` packages already in the repo (or add ones from the same MIT family — check
   licenses; no new framework).
3. **Preview styles:** tables (borders, header row, zebra optional, horizontal scroll on phones in a focusable region),
   code blocks, inline code, blockquotes, callouts (`> [!note]`), task lists, headings, lists, hr — reuse Chat's
   Markdown styles (`chat-md-*`) where possible; no raw HTML rendering (unchanged policy).
4. Keep everything that works today: wikilink autocomplete (`[[`), save (Ctrl/Cmd-S), conflict banner when an agent
   changes the open note, rename/move/delete, mobile layout.
5. Accessibility: the editor stays a real text editor for screen readers (decorations don't hide text from them);
   checkbox toggles are buttons with names; read mode is a normal document.

## Done when

Web unit tests for mode switching and remembered mode, the table widget toggling to source when the cursor enters it,
a checkbox toggle editing the source, byte-exact content after editing around decorations; e2e: open a note with a
table → rendered table visible; Edit → live preview; type; save; visual baselines for read, edit and split (light, dark,
390 px) checked by eye. `pnpm check` green.

## Constraints

AGENTS.md (design rules, licensing). No WYSIWYG libraries. Don't commit to main.
