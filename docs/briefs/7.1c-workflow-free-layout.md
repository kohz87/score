# 7.1c Workflow editor: free node placement (owner request 2026-10-11)

Owner: "the workflow isn't movable, it's arranged by setting the task, i cannot freely move it?" 7.1b auto-arranges nodes
because the definition has no coordinates.

- **Contract (additive):** `WorkflowDefinition.layout?: { nodes: Record<NodeId, { x: number; y: number }> }` (finite numbers,
  bounded e.g. ±100,000; unknown node ids rejected by validation as a warning-free error `layout_unknown_node`; nodes
  without a position are auto-placed). Layout is presentation only: it never affects validation of the graph, planner
  behaviour or the definition hash used for run identity? — it **is** part of the saved version (so a version reopens as
  drawn); runs freeze the version as today. Export includes it (no scrubbing needed: numbers only).
- **Editor:** drag nodes freely (pointer + touch), multi-select with Shift/drag box optional (nice to have), snap to a
  16 px grid (hold Alt to disable), keyboard move with arrow keys (Shift = bigger step) on the focused node, **Arrange
  automatically** (the 7.1b layout) as one undoable step; edges re-route to follow nodes; positions saved with "Save as new
  version"; moving nodes marks the draft unsaved. Existing definitions without layout open auto-arranged and keep that
  until moved. Canvas pans when dragging near edges; zoom keeps working.
- **Run view:** the live diagram uses the frozen version's layout when present (fallback: auto layout); dots follow the
  edges as drawn (5.37 motion uses the edge paths).
- Tests: contract (layout schema, bounds), server (save/load/export round-trip, validation of unknown ids), web (drag →
  position, snap, keyboard move, arrange-automatically undo, run view uses layout), e2e (drag a node, save, reload, same
  place; run view matches), baselines viewed.
Follow AGENTS.md; no new dependencies; migration only if layout can't live inside the stored definition JSON (it should).
