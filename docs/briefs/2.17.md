## Design (from the lead)

  `/api/jobs` if it exists and the profile is served — reuse `GatewayClient` with the profile's key; otherwise the jobs file
  the cron module persists, opened **read-only** through an allowlisted path under the profile home, zod-validated).
  `hermes cron list` has no JSON output; don't parse its text. Map to `RoutineSummary` (contract §8).
- **Write**: only through `hermes -p <profile> cron create|edit|pause|resume|run|remove` via `apps/server/src/hermes/live/cli.ts`
  (argument arrays; user text as `--opt=<text>` or after `--`; extend the CLI capture allowlist only if a command's
  output is needed, e.g. the created job id — prefer re-reading). Creates use a command intent / idempotency so a retry
  can't create a second job (look for an idempotency or name-based dedupe; if Hermes has none, record a Score-side intent
  keyed by `Idempotency-Key` and reconcile by name+schedule before retrying).
- **Endpoints** (§8): `GET /api/agents/:agentId/routines`, `POST …/routines {title, schedule, prompt}`, `PATCH
/api/routines/:id {enabled?, schedule?, prompt?}`, `DELETE /api/routines/:id`, `POST /api/routines/:id/run`. Human guard
  - idempotency on mutations. Wire 2.3's `/routine @agent <schedule> <prompt>` command (currently 501) to create one.
- **AgentDetail.routines** fills from the reader. **UI**: the Team page's Routines tab lists routines with
  pause/resume/run-now/delete and a small create form (title, schedule, prompt); the Overview "New routine" link opens it.
