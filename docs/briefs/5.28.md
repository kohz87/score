# Task 5.28: Phone: installable app, notifications, passkeys, phone-friendly Enter

Owner 2026-10-09 (learned from nesquena/hermes-webui, MIT). Score is HTTPS-only remotely (5.18) and reachable at
`https://hermesvm.<tailnet>.ts.net:8741` with a real certificate (5.22) — secure contexts make all of this possible.

## Done when

1. **Installable app (PWA).** `manifest.webmanifest` (name "Score", short_name "Score", theme/background from tokens,
   `display: standalone`, start_url `/now`, icons 192/512 + maskable generated from the Score mark as PNG at build time
   or committed); a service worker that caches the **app shell only** (index.html, hashed assets, fonts) with a
   network-first strategy for index.html and **never caches `/api/*`, `/s/*`, media or the stream**; an offline page that
   says "Score can't be reached" with a retry. Update flow: a new build shows "Update available · Reload". iOS meta tags
   (apple-touch-icon, status bar). The service worker is served with `Service-Worker-Allowed` scope `/` and passes the
   remote guard as a public asset; it must not intercept `/pair` token handling.
2. **Notifications.** Settings › Notifications: per-device opt-in (Notification permission requested only on a click),
   choose kinds: approvals waiting, a routine finished, an agent error, a reply to you while the tab is in the background.
   Delivery while Score is open in any tab/app window: from the stream events (no push server). True push when the app is
   closed (Web Push with VAPID) is **optional**: implement only if it needs no new dependency beyond what the lead
   approves (ask first; `web-push` would need approval); otherwise document it as a follow-up. Clicking a notification
   opens the right page. No message text in notifications unless the owner turns on "Show message previews".
3. **Passkeys — security design (lead, 2026-10-09; implement exactly):**
   - WebAuthn RP ID must be a domain: passkeys work on the **ts.net name and localhost only, not on an IP address**; the UI
     explains this on the LAN IP and offers the ts.net link.
   - **Register** (Settings › Remote › Passkeys): only from an already-paired browser **and** with the security
     password; `residentKey: 'preferred'`, `userVerification: 'required'`, ES256 and RS256; stored: credential id,
     public key, sign count, transports, a label, created/last used; challenges single-use, 5-minute expiry, bound to the
     session.
   - **Sign in** (the pairing page gets "Sign in with a passkey" when the origin can use passkeys): a successful
     assertion (userVerification required, origin and RP ID checked, sign-count regression → refuse and flag the
     credential) creates a normal paired-browser session with the same cookie, limits and expiry rules as a pairing link.
     Rate-limited like pairing.
   - **Manage**: list with labels and last use; **remove** requires the security password; "Terminate all other
     pairings" does not remove passkeys (say so); removing all passkeys leaves pairing links working.
   - Library: `@simplewebauthn/server` 14.0.3 and `@simplewebauthn/browser` 14.0.0 (both MIT) — **ask the lead to add
     them** (the lead runs the license check on their dependency tree first). Migration **0037**.
   - Tests: registration needs paired + password; challenge reuse and expiry refused; wrong origin/RP ID refused;
     userVerification false refused; sign-count regression refused; a passkey sign-in session behaves exactly like a
     paired one (revoke, renew, expiry); remove needs the password.
4. **Phone-friendly Enter.** On touch devices (`(hover: none) and (pointer: coarse)`), Enter inserts a newline and a
   Send button sends; a setting "Send with Enter / Ctrl+Enter" applies on desktop. Composer and Now composer both.
5. Tests for each (service worker caching rules with a mocked fetch/cache, manifest validity, notification routing,
   passkeys as listed, Enter behaviour), e2e (manifest served, SW registered, notification permission flow with Playwright
   permissions, passkey registration and sign-in using Playwright's virtual authenticator over the HTTPS e2e), visual
   baselines for changed Settings checked by eye.
