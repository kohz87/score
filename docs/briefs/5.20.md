# Task 5.20: Owner feedback round 2: browser messaging setup, delete messages, a task-first Now

Owner report and decisions 2026-10-09 (AskUserQuestion answers recorded here):

- Messaging connections must work from the browser. **Decision:** tokens are saved through `hermes config set <ENV_KEY>
<value>` (value on the command line; the VM is single-user; accepted by the owner).
- Messages in a thread can't be deleted. **Decision:** Delete removes the message from Score for everyone, with a short
  Undo; agents may still remember it in their Hermes session history, and the confirmation says so.
- The Now dashboard gets crowded when many messages run close together. **Decision:** lanes show tasks and briefs as
  blocks; plain chat replies become one thin "chatting" band per agent; blocks too close to read merge into one
  counted group that opens a list.

## Done when

### A. Messaging setup in the browser (Settings › Connections › Messaging, and Team › agent › Channels)

1. `POST /api/settings/messaging/:platform/connect` stops answering `run_in_terminal` for platforms whose setup is token
   based. New contract (update `docs/API-CONTRACT.md` §Settings and `packages/contract` first):
   - `GET /api/settings/messaging/:platform/fields` → `{ fields: { key; label; help: string | null; url: string | null;
secret: boolean; required: boolean }[]; browserSetup: boolean }`, field metadata taken from Hermes (find a
     read-only CLI that lists env-var metadata in ~/.hermes/hermes-agent, e.g. a `config` or `setup` subcommand with
     JSON output; if none exists, keep a small adapter-side table in `hermes/live/` for Telegram, Discord, Slack,
     Mattermost, Matrix, Signal, Email and Home Assistant using the names/labels/URLs in
     `hermes_cli/config_defaults.py`, and note it in the report).
   - **H** `PUT /api/settings/messaging/:platform` `{ values: Record<key, string>; agentId?: AgentId; secretReceipt }` →
     the connection row. Reuses the HMAC receipt pattern the API-key flow uses for secret bodies. Keys are checked
     against the platform's field list (no arbitrary env writes). Writes go through `hermes [-p <profile>] config set
KEY value` (argv array, never a shell), one per field, in the profile of `agentId` (default profile when absent);
     values are never logged, stored by Score or echoed back; error messages are redacted.
   - Platforms that need an interactive pairing (WhatsApp QR and similar, `browserSetup: false`) keep the terminal
     command, with a clear "This one needs the terminal" explanation.
2. Web: "Connect" opens a form with those fields (secret fields are password inputs with show/hide; help text and the
   "where to get it" link from the metadata), Save, then the row refreshes to its new status, with a note that the
   gateway picks it up after a restart (offer the existing restart action if Score has one; otherwise say so).
3. Tests: server (field whitelist, argv only, profile routing, no value in logs or responses, receipt required),
   web (form, secret toggle, success and error), fake adapter support, e2e for one platform in fake mode.

### B. Delete messages (Chat)

4. Contract: **H** `DELETE /api/rooms/:roomId/messages/:messageId` → `204`; stream event `message.deleted`
   `{ roomId; messageId }` (update §Chat and the event list). Refuse with `409` while the message is still streaming.
   Score-side only: migration **0028** adds `messages.deleted_at`; deleted messages are excluded from room reads, search,
   Now's thread and exports; runs, Reports and Hermes are untouched. Idempotent.
5. Web: a Delete action on every message (menu or hover action, keyboard reachable); clicking hides it at once and shows
   "Message deleted · Undo" for 6 s; the DELETE is sent only when the toast expires (Undo cancels locally). The
   confirmation copy: "Removes it from Score. Agents may still remember it."
6. Tests: server route + projection + event, migration test, web component test, e2e (delete, undo, delete for real).

### C. A task-first Now

7. Server (`domain/lanes.ts`, `domain/now.ts`): each `LaneBlock` gets `kind: 'task' | 'brief' | 'chat'` (contract
   change). Chat runs (a run whose origin is a plain chat reply, not linked to a task/brief) of one agent that are less than
   5 minutes apart merge into one `chat` block (a band, with `count` of replies); task and brief blocks stay exact and
   unmerged (5.17-pre2 rule: an ended run stays finite; retries stay distinct).
8. Web (`routes/now/ScoreTimeline.tsx`, `timeline-model.ts`): `chat` blocks render as a thin band under the lane's task
   blocks; task blocks that would be narrower than ~28 px or overlap visually are grouped into one block labelled
   "N tasks" that opens a small list (keyboard and screen-reader accessible, AgentGlyph kept). Matches the Now design
   (docs/design/now-score.png) for the normal case.
9. Tests: lanes unit tests (merge rule, kinds, retries), timeline-model tests (grouping thresholds), visual baseline
   for Now updated and checked by eye, e2e green.
