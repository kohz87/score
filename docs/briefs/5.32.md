# Task 5.32: Profile import

Owner 2026-10-09. Score can already export an agent (3.12 profile management, `hermes profile export`). Hermes has
`hermes profile import <archive>` (check its options and what it restores/overwrites in ~/.hermes/hermes-agent, read-only).

## Done when
1. Team › **Import agent**: upload an exported archive (≤ 200 MiB, stored in a private temp dir under Score's home, 0600,
   removed after the operation); Score inspects it **without extracting to the profiles dir**: profile name, model,
   skills, plugins, memory size, whether it contains credentials/.env (warn; never display their content), Hermes
   version it came from. A preview screen shows this and asks for the new agent id (default from the archive, refusing
   an existing id unless "replace" is explicitly chosen with a typed confirmation).
2. Import runs through the existing durable profile-operation machinery (steps, recovery, confirmable steps) calling
   `hermes profile import` with argv only, then installs/pins the Score bridge plugin like Add agent, then verifies the
   profile appears; failures leave nothing half-imported (or a clear "finish/undo" step).
3. Path safety for archive inspection (no traversal, no symlinks/devices, size and file-count limits, zip-bomb guard).
4. Contract first (§8), fake adapter support, tests (inspection safety cases, operation steps and recovery, refusal of
   existing ids, credential warning), e2e on the fake adapter (import a fixture archive), visual baselines checked by eye.

Follow AGENTS.md. No new dependencies without the lead (a tar/zip reader may be needed: propose it with license and
size). The live check, if any, only on a throwaway test profile name. `nice -n 19`, vitest `--maxWorkers=1`. Never touch
~/.score, the owner's real profiles or the live Score. Commit per point on `task/5.32-profile-import`; never merge or
push.
