# 3.29.0 — Recipes as a library; the old run pages retire (brief)

Owner, 2026-11-04: "the new recipe placement is awkward, do a new mock up, the old run and all run are looping back to
old structure which freezes, we don't really need old runs, just the graph and log from the chat group anyway?" → mock-up
approved (copies `docs/design/bold/mockups/23-recipes-library.dc.html`, `23-recipes-edit.dc.html`,
`23-recipes-phone.dc.html`; binding: where this brief and the mock-up differ, the mock-up wins and you report it). The
owner's screenshots (Troubleshooting note): the step settings dropped to the bottom-left under the recipe list in "As
text"; the run page (All runs · Steps · Graph · Log) is the old structure and freezes. Decision 165.

## What to build (under `apps/web/src/bold/`)
1. **Settings › Recipes is a library** (`BoldRecipes.tsx`, mock-up 23-recipes-library): heading "Recipes", Find a recipe,
   **+ New recipe**; the line "Saved plans a chat's lead can run with /run. A run shows in its chat: the run card, the
   Graph and the session log."; recipe cards in a responsive grid (3 / 2 / 1 columns by width): name, Built in or
   "version N", what it does (step count, inputs, approval), **Last run · <chat> · <state> ›** (or "Not run yet"), and
   **Edit** (not on Built in) · **Run in a chat…** (Start a job with this recipe chosen and the chat picker, as Run does
   today). Archived recipes behind "Archived recipes · N". Landing on Recipes never opens an empty "Untitled recipe";
   + New recipe does. The settings nav subtitle becomes "Saved plans agents run".
2. **The editor** (mock-up 23-recipes-edit): full width of the settings content with "‹ Recipes", the name, version and
   "unsaved changes", Graph | As text, Preview, ⋯ (Undo, Redo, Export, the rest of today's More), **Save**. The step's
   settings open in a **panel to the right of the recipe** (about 380px, its own scroll), in both Graph and As text — never
   below the list. Problems are one line under the header: "N things to fix before saving: <first problem>. Show it"
   (Show it selects that step); the big red boxes go. Keep every editing capability the editor has today.
3. **The old run pages go.** Remove the Runs list and the run frame (`BoldRuns.tsx` "All runs", Steps / Graph / Log /
   classic tabs) from Recipes. `boldRunLink(id)` becomes `/b?run=<id>`, which already lands on the run's chat with Graph
   open (`BoldRoom.tsx`). Every "Open the run" link (Info's run card, `chats/TopicGraph.tsx`, `chats/TopicInfo.tsx`,
   `BoldRecipes.tsx` preview overlay, `routes/chat/PlanCard.tsx` if bold) goes there or is removed where the chat already
   shows it. A run that belongs to **no chat** (from before 3.23) opens a read-only sheet over Recipes with the same Graph
   and session log as the chat's Graph tab (reuse `chats/TopicGraph.tsx`'s pieces), not the old run frame. Old
   `/b/settings/recipes?run=` links open that same way.
4. **Run details in the chat's Graph tab** (`chats/TopicGraph.tsx`): a folded "Run details" section under the log with
   what only the old run page showed — the spend / limits / team summary and the advisor, helpers and check cards
   (`routes/orchestrations/AdvisorCard.tsx`, `HelpersCard.tsx`, `CheckCard.tsx`) when the run has them. Decisions
   (approvals, reassign, abandon, waivers) already show in the chat (`room/RunSafetyRequests.tsx`); keep them there.
5. **Phone** (mock-up 23-recipes-phone): ‹ Settings, Recipes, + New, Find, cards; the editor full screen with the step
   panel as a bottom sheet.
6. Wording: Files and results' empty line in a group chat says "Nothing made in this job yet" (it still says topic).
7. Delete code that only the removed pages used (check imports; don't remove anything the chat still uses).
