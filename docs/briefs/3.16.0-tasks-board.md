# 3.16.0 — Tasks board (owner, 2026-11-02: "build the tasks board")

The Kanban board went in the 11.11 rework (decision 118). The owner wants it back in the new shell: one page with every
Hermes task across rooms, in columns, acting only on what needs the person. Approved mock-up (owner, 2026-11-02):
`docs/design/bold/mockups/13-tasks-board.dc.html` (desktop) and `13-tasks-board-phone.dc.html` (phone), canvas
https://claude.ai/artifact/9dWyfTob55Y3TZW3d2xDdY. Take layout, colours, radii and spacing from those files and from the
new shell's existing CSS/tokens (`[data-ui='bold']`); rebuild in React, never paste the mock-up's HTML.

## What to build (web only; no server or contract change)
- **Route** `/b/tasks` (`BoldTasksPage`, in `apps/web/src/bold/`), and **Tasks** in the top bar beside Recipes
  (`BoldShell.tsx`). The old `/tasks/*` redirect in `App.tsx` now goes to `/b/tasks` (keep the search string).
- **Data**: `GET /api/tasks` (already returns `{ asOfSeq, columns: { planned, working, in_review, needs_you, done } }`),
  kept live by the stream like the room's task list (`apps/web/src/bold/room/task-queries.ts`: reuse its patterns,
  `useStreamQuery`, `task.upserted`). Detail: `useTaskDetail`. Actions: `taskAction` (`unblock`, `comment`), and a task's
  `pendingApproval` approved through the same approval control the job thread uses (`RoomTasks.tsx` `ThreadTask`). Reuse
  those components/helpers (`taskStateLabel`, `taskBlockedReason`, `blockedTask`) instead of re-implementing them.
- **Desktop**: five columns Planned · Working · In review · Needs you · Done with counts; cards show key, room name
  (or "No room"), title, badge (`TaskSummary.badge`), progress bar when `progress` is set, the agent (AgentGlyph: colour +
  shape) and elapsed time. **Needs you** cards are light (the shell's "for you" objects). Done shows the 20 newest with
  "Show older". A side panel opens the selected task: key + Hermes status, title, room (link to it), doing it, reviewer,
  column; a light **Needs you** block with the action (Unblock for a blocked task, the approval for `pendingApproval`)
  and "Open in its room"; Steps (`TaskDetail.steps`), Comments (`TaskDetail.activity` comments) and a comment box.
  Filters: by agent (Everyone + one chip per agent with its glyph) and **by room** (the mock-up says "Job"; tasks are tied
  to rooms, not jobs; show the room filter only when tasks span two or more rooms). Header pill "N need you".
  No drag and drop, no create/edit (agents move their own tasks; those routes were removed in 11.11b).
- **Phone** (≤ 600px): "Needs you" first as light cards with their action buttons, then the other columns as tabs
  (Working first) listing cards; tapping a card opens the same detail as a full-width sheet.
- Empty states: no tasks at all ("No tasks yet. Hermes tasks your agents create show up here."), a filter with nothing.
- **Protected**: every needs-you card, the detail's needs-you block and the header pill carry `data-protected` and are
  added to the protected list (`apps/web/src/styles/protected.css` and its test); set your own `display` on them
  (`data-protected` sets display only under a custom look). A sticky/fixed element goes into `KNOWN_OVERLAYS`.
