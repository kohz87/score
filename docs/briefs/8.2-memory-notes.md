# 8.2 Memory notes from compaction (decision 83; PLAN 8.2)

When a Hermes session is compacted, Score saves the summary as a Knowledge note.
1. **Get the summary.** The bridge's compaction (`hermes_private.py` `compact_session`, the only place for private
   Hermes calls) returns the summary text Hermes's compressor produced (find it in the compression result — the MIT
   reference `../reference/hermes-agent` may be read for the structure), redacted, capped (e.g. 32 KiB), alongside today's
   result. Investigate whether automatic compressions (Hermes compacting on its own at a threshold) are visible to the
   plugin (a hook or event); if yes, report them too; if not, say so — Score-requested compactions are enough for now.
2. **Write the note** through the vault (normal history and write rules; author = the agent):
   `Memory/<agent>/<YYYY>/<MM>/<YYYY-MM-DD> <room name>.md` (date in the owner's timezone, GMT+8; a second compaction the
   same day gets ` (2)`), frontmatter `date`, `agent`, `room`, `session`, `weight: 3`, `source: compaction`; body = the
   summary. Never overwrite. If the vault is off or the write fails, the compaction still succeeds and Score logs it.
3. **Monthly index** `Memory/<agent>/<YYYY>/<MM>/index.md`, regenerated after each new note: links to that month's notes
   sorted by `weight` (5 first), then date. The person changes a note's weight by editing its frontmatter; the index is
   regenerated on the next compaction and on a vault scan.
4. A setting (Settings › Knowledge): "Save compacted summaries as memory notes" on by default; `docs/WRITING.md` words.
Tests: plugin (pytest) returns the summary; server writes the note (path, frontmatter, no overwrite, failure doesn't
break compaction); index ordering; fake mode e2e: compact a room → the note appears in Knowledge. Contract doc first
(the `session.compacted` payload gains `memoryNote: string | null`).
