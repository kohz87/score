# Task 5.19: Owner feedback round 1: model saves, slow settings, layout

Owner report 2026-10-09 (live LAN deployment, Hermes 0.21.5). Measured on the live server: every `hermes` CLI call costs
~2–2.7 s on this VM; `PUT /api/agents/:id/model` took 20–22 s (and succeeded); `GET /api/settings/providers` median 6 s
(max 18 s), `/api/settings/rules` median 15 s, `/api/settings/config` 8 s, `/api/settings/plugins` 7.5 s,
`/api/settings/connections` 4.4 s.

## Done when
1. **Agent model saves are fast and honest.** `setModel` (`apps/server/src/hermes/live/agent-tabs.ts`) does at most one
   read and the writes it needs: reads come from the config cache (2); the local-provider check runs only when the
   chosen provider is a local (`providers:`) one; the prior model pair comes from the cache. Target: a save is the two
   `config set` calls (≈5 s), no more. If Hermes offers one call that sets model and provider together (check
   `hermes config set --help`, `hermes model --help` in ~/.hermes/hermes-agent read-only), use it.
2. **Config reads are cached by file signature.** Generalise the existing pattern in `hermes/live/profiles.ts` (cache keyed
   by config.yaml's stat signature, retry after failure) to every `configJson`/`config get` read in `agent-config.ts`,
   `approvals.ts`, settings reads, rules, plugins: an unchanged config.yaml answers from memory; any Score write
   invalidates; an outside edit changes the signature. Concurrent identical reads share one CLI call. Never parse
   config.yaml in Node (Score reads it only through the CLI). Add a test per cache: unchanged → no CLI call; touched →
   re-read; failure → retried later.
3. **Team › agent › Model tab** (`apps/web/src/routes/team/ModelTab.tsx`): the picker shows the agent's current model
   (and provider) as the selected value when the tab opens, also when that model is not in `/api/models` (show it as
   "current: <id>"). Saving shows "Saving…", then a clear "Saved: <model>" confirmation (or the error with Retry), and the
   tab shows the new value without a reload (update the query cache from the response / invalidate). A save that takes
   long keeps the button disabled with progress, never a silent stall.
4. **"Model edit" in Settings › Models and keys**: reproduce in the fake adapter and in a unit test what "Edit" does on a
   connected provider row; fix whatever is broken (it must either open a working edit flow or not be offered). Report
   what was wrong.
5. **Plugins move to each agent.** Plugins are per profile, so the Hermes plugin list moves from Settings › Plugins and
   look to a new **Plugins** tab on Team › agent (same toggles, same `score-bridge` lock, the "takes effect on the next
   session" note). Settings keeps only the look (theme) part, renamed "Look". Contract: use the existing plugin endpoints;
   if they are keyed by agent already, no contract change; otherwise add the agent-scoped path to API-CONTRACT.md and
   `packages/contract` in the same change.
6. **Advanced is collapsible.** Settings › Advanced shows its heading, the search box and a "Show all N settings"
   disclosure; the list is collapsed by default and opens on click or when a search has text. Remember the open state
   per browser (localStorage, wrapped in try/catch).
7. Tests for each point (server unit + web component), updated visual baselines for the changed Settings and Team pages
   (check the new screenshots by eye), e2e green.
