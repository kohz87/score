## Fix round F1 (review `docs/reviews/2026-10-14-7.7c-code-review.md`)
One builder, in order, each with the review's probe as a failing-first test:
1. **Never `full` through a remap** (#1, also orchestrations): policy remap (orchestration step and workflow node) rejects
   a policy whose permission is `full` (or any permission the worker rules forbid) with the same refusal as create; the
   release check rejects a stored policy with a forbidden permission (`agent_changed` is wrong here: use a typed
   `permission_forbidden` cause ⇒ blocked, Needs-you text says why). Test the probe: agent changed to `full`, remap ⇒
   refused, nothing launches with `danger-full-access`.
2. **Remap targets the current attempt** (#2): retirement by renewal clears `suspended`; remap selects only the node's
   current, created, suspended attempt.
3. **Withdrawal refund consumed once** (#3): a withdrawal replacement is distinguished from a remap; the refunded slot
   is consumed by the next attempt exactly once; `attempts_max` is never exceeded.
4. **Readiness exhaustion on coding nodes** (#4): routes through the suspended hold, the `coding_held_back` card and the
   renewal cap (after the last renewal the node fails and releases its slot and reservation).
5. **Renewals survive restore** (#5): journal each renewal with the count and predecessor/successor ids; verification
   and replay restore and check them through compaction.
6. **Unsent coding inventory reserved** (#6): retained inputs of unsent/suspended coding attempts are reserved
   independently of `codingSteps`; capacity is checked before retaining one (refuse/park instead of spilling into the
   control reserve).
Then `pnpm check`, the systemd suite, the full e2e (SCORE_WEB_PORT=5491) and the real-CLI replay.
