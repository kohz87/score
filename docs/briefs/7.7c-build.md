# 7.7c build plan

Design: `docs/briefs/7.7c-coding-workflows.md` (v3, accepted). Two parts, **one builder each, in sequence** on one branch
`task/7.7c-workflows` (worktree `../score-worktrees/7.7c`); the lead reviews and runs the full check after each part;
Codex code review at max after part 2, then verification, then the live check (owner approval) and release v1.3.0.

Rules for every part: AGENTS.md (licensing, no new dependencies, contract doc first), the builder brief rules (no
pkill/killall or pattern kills, never touch 8740/8741 or the live Score, no git stash, no `SCORE_E2E_DEV=1`, no `pgrep -f`
wait-loops, **no background wait-loops at all**, clean up every process and `score-test-*` unit), failing-first tests at
the real boundary (each actually run against the old code), never open CLI config or credential files (stat only),
never call something that opens a DB transaction from inside one, `pnpm check` green, commit per item
("7.7c-<part> #n: …"), don't merge. Migrations from `0065`.

## Part 1: server and contract
Design §§0–5, §6 (server side: Needs-you items, `coding` block, limits decision), §7, Contract changes:
- `validateWorkflowAgents` with structured issues, used by Validate, save, new versions, preflight/start; zero-worker
  workflows send/store no coding fields;
- workflow preflight `workers[]`; start with policies, consent (workflow cardinality), `codingSteps`, unknown-cost
  sources; rerun asks again;
- verdict from the raw eligible reply (256 KiB bound, no prefix parsing), joined by `(attempt, generation)`;
- blocked coding nodes keep their step; assignment gate payloads carry the policy id; node policy-remap endpoint;
  incarnation remap with consent and closure of proven-unsent attempts; Try again as dispatch renewal; generation-cap
  Needs-you item; every coding closure cause mapped to a node transition;
- `WORKFLOW_CODING_ITEM_BYTES`, partition at creation, `setLimits` by planner constant, charging of `wf_results` and node
  output;
- Needs-you items and the `coding` block in summary/detail; limits decision fields.

## Part 2: web and e2e
Design §6 (web) and the UI parts of §§1–2:
- editor agent picker offers Claude Code/Codex for step nodes (badge), disables Antigravity/OpenCode with the reason;
  Validate shows the structured issues;
- run dialog: reach section, one acknowledgement, per-source unknown cost (when `unknownSpend = pause`), coding step
  limit; rerun asks again;
- shared decision cards refactored to explicit props (run `coding` block, `preflightWorker` callback, action callbacks)
  for orchestrations and workflows, no placeholder lead;
- live workflow view: CLI badge on coding nodes, the four new Needs-you cards;
- e2e (fake mode) for editor, Validate, run dialog, live view.
