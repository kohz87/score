# 3.15.3 — Coding agents run on a newer CLI unless it's broken (decision 157)

Owner, 2026-11-02: "set the score for coding agent to run regardless of version unless it's broken". Lead-coded (the
coding-runtime gate is security-relevant).

- `cliRefusal`: an `untested_version` CLI no longer needs the per-agent confirmation; the decision-138 help check decides
  (runtimes without one, Antigravity, simply run). A failed check refuses with its reason (`422 untested_cli_version`,
  cause `version_unchecked`, readiness `reach_unverifiable`).
- `CodingAgent.cli.confirmed` → `cli.problem: string|null`; `POST …/confirm-version` and `CodingVersionConfirmSchema`
  removed; the store stops reading `confirmed_version` (the column stays: migrations are forward-only).
- The Antigravity `/usage` reading no longer refuses an untested version.
- Web: the "Run with X anyway" card is gone; a broken version shows why in "Needs attention"; a checked newer version
  reads "newer than tested; Score checked it".
