## Part A: design (from the lead; follow it)

**Stream connection** (`apps/web/src/data/stream.ts`): `createStreamClient({ url = '/api/stream', EventSourceImpl =
globalThis.EventSource, random = Math.random, setTimeout, clearTimeout })`, one per tab (created once in
`main.tsx`, provided via React context).

- Opens `EventSource(url)` for the first connection (no `since`/`epoch`). Remembers `epoch` from `stream.hello`
  and `lastSeq` from every durable event's `id`.
- **Reconnects itself**: on `error`, close the EventSource and reopen
  `?since=<lastSeq>&epoch=<epoch>` (only if both are known; otherwise a fresh connection) after a backoff of 0.5 s,
  doubling to a 10 s cap with ±20% jitter, reset to 0.5 s after a successful hello. Never rely on the browser's
  automatic reconnect (it would reuse the first URL without an epoch).
- Parses each message with `parseStreamFrame` from `@score/contract`. Unknown types are ignored, with one
  `console.debug` per distinct unknown type. An invalid known frame logs `console.error` and is skipped (no throw).
- Exposes `subscribe(listener)` for events and `onControl(listener)` for hello/reset, plus `status`
  (`connecting | open | reconnecting`) via a small subscribable store for a "reconnecting…" indicator later.
- `stream.hello` whose epoch differs from the remembered one, and every `stream.reset`, emit a **resync** signal.

**Per-query resync** (`apps/web/src/data/resync.ts` + `queryClient.ts`): a registry of _stream queries_.

```ts
defineStreamQuery<T>({
  key: QueryKey,
  fetch: () => Promise<{ asOfSeq: number; data: T }>,   // a snapshot endpoint (contract "S")
  types: StreamEvent['type'][],                          // event types this query cares about
  reduce: (data: T, event: StreamEvent) => T,            // pure, must not mutate data
})
useStreamQuery(def) → { data: T | undefined, status, asOfSeq }
```

Rules (these are the D1 guarantees; implement exactly):

1. Each query stores its own `asOfSeq` next to its data in the TanStack Query cache.
2. While a query's snapshot fetch is in flight, events of its `types` are **buffered** for it.
3. When the fetch resolves: replace data, set `asOfSeq` from the response, then apply buffered events with
   `seq > asOfSeq` in seq order, and set `asOfSeq` to the last applied seq.
4. When idle, an event with `seq > asOfSeq` is applied immediately; `seq <= asOfSeq` is ignored (already in the
   snapshot).
5. **Stale fetches**: every fetch gets a generation number; a response from an older generation is ignored (and
   its buffered events stay buffered for the newer fetch).
6. **Resync** (epoch change or reset): every active stream query refetches (rule 2 applies during the refetch).
7. Inactive queries (no observers) don't buffer; they just refetch when they become active again.

Use TanStack Query's `queryClient.setQueryData` / `fetchQuery` underneath. Keep the module framework-light so it's
testable without React (the hook is a thin wrapper).

**Needs-you dot**: leave `useNeedsYou()` returning false (the approvals query arrives in Phase 2), but add a TODO
comment pointing to `/api/approvals`.

## ARCHITECTURE D1

### D1. One live stream: SSE with a fenced, transactional event log

**Transport.** One-way server → browser over SSE; every command is a REST request. One stream per tab.

**Single ordered ingest path.** Every producer (run SSE readers, bridge ingest, SQLite tailers, Score's own
domain actions) submits _observations_ to one in-process ingest queue, drained by **one writer**. Each
observation is applied in **one SQLite transaction** that:

1. checks the ingest key (unique `(source, source_identity)`, see D2.3) and drops duplicates;
2. updates the **projections** the screens read (D5);
3. appends zero or more domain events to `events` (`seq INTEGER PRIMARY KEY AUTOINCREMENT`);
4. advances that source's ingestion checkpoint.

`seq` is **strictly increasing**. Gaps are allowed and clients must not assume gap-free. A durable event and the
projection change it describes commit together.

**Snapshots.** Snapshot endpoints read the projection rows **and** `max(seq)` in **one read transaction**
(WAL snapshot isolation), so `asOfSeq` exactly describes the snapshot. Direct Hermes reads never feed live
snapshots; they feed reconciliation (D2.4), which goes through the same ingest path.

**Subscription fence.** On connect: register the subscriber with a buffer → capture head `H` → replay
`(since, H]` from the log → release buffered events with `seq > H` → live. Nothing is lost between replay and
live, and nothing is sent twice.

**Frames.** Durable events carry `id: <seq>`. Control frames (`stream.hello`, `stream.reset`, heartbeats) carry
**no `id`**. `stream.hello` includes the log **epoch** (a random ID stored in `score.db`, regenerated on restore
or reset). On connect the server answers `stream.reset` instead of replaying when:

- the cursor's epoch differs from the current one,
- the cursor is older than the retention floor, or
- the cursor is ahead of the head.

**Client resync (per query, not per tab).** Each cached query records its own `asOfSeq`. While a query refetches,
the client buffers stream events. When the fresh snapshot arrives it replaces the cache, then applies buffered
events with `seq > asOfSeq` for that query. Stale in-flight fetches are cancelled or ignored by request
generation. On `stream.reset` every active query enters this resync.

**Backpressure.** Per-client byte budget plus a socket write timeout. Exceeding either closes the connection; it
does not block the hub. The client reconnects with `Last-Event-ID`. A reset frame is best effort.

**Retention.** The event log keeps 7 days. Reports and history read durable tables (D5), never the log.

## Contract §2

## 2. Stream

### `GET /api/stream?since=<seq>&epoch=<epoch>`, `text/event-stream`

- Resume with the `Last-Event-ID` header (wins over `since`). `epoch` is the value from the last `stream.hello`
  the client saw. The first connection has no epoch yet, so the client **manages reconnects itself**:
  close the EventSource on error and open a new one with `?since=<lastSeq>&epoch=<epoch>` (backoff 0.5–10 s).
  A cursor without an epoch is treated as foreign (→ `stream.reset` with reason `epoch`). A fresh connection
  sends neither and gets live events from the head.
- **Durable events**: `id: <seq>`, `event: <type>`, `data: <envelope json>`. `seq` is strictly increasing; gaps
  are allowed. Nothing between replay and live is lost or duplicated (server-side subscription fence).
- **Control frames** (`stream.hello`, `stream.reset`) have **no `id:`**. Comment heartbeat every 15 s (`: hb`).
- `stream.hello` is always first and carries the log `epoch`. The server sends `stream.reset` instead of replaying
  when the cursor's epoch differs, the cursor is older than retention, or it is ahead of the head.
- Slow clients are disconnected (byte budget / write timeout); they reconnect with `Last-Event-ID`.
- **Client resync**: on `stream.reset`, and whenever a query refetches, buffer events; replace the cached snapshot;
  then apply buffered events with `seq > that query's asOfSeq`. Ignore responses from superseded fetches.
