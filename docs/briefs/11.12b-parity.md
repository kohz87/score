# Brief 11.12b: Parity gaps in the new shell (phase-gate findings)

PLAN 11.12, decision 121. The parity walk found these promised features missing or partial in `/b`. The server side is
done in 11.12a (this branch starts from it). Read `docs/API-CONTRACT.md` for each endpoint named here, AGENTS.md
(protected decision surfaces: `data-protected` + `themes/protected-surfaces.ts`; colour + shape), and the prototype
`docs/design/bold/prototype.html` (`jobMenu()`, the Started-by card, the thread header) — binding; report differences.

## 1. Job menu: rename, close and reopen, delete with undo (D6)
`room/RoomMenus.tsx` `JobMenu` today offers only share and export. Add:
- **Rename…** — inline title field (1–200), `PATCH /api/jobs/:jobId { title }`; not offered for the room's own thread
  (`isDefault`).
- **Close** / **Reopen** — `POST /api/jobs/:jobId/close|reopen`. A `409` "still working" is explained with a Stop button
  (the thread's Stop). A closed job leaves the tabs and the phone list; the room keeps a "Closed jobs" entry in the job
  filter/menu so a closed job can be found and reopened.
- **Delete…** — confirm (protected, typed job title as the room delete does), `DELETE /api/jobs/:jobId`, then an Undo
  toast for ~10 s → `POST /api/jobs/:jobId/restore`. Not for the room's own thread.
- Stream: handle `job.deleted { id, roomId }` (new event) in every job list query (`room-queries.ts`, the team-room
  reads, phone list, Results/Workbench if they key by job): drop the job; if it was open (`?job=`), go to All (phone:
  the list) with a short note. A person's message into a closed job gets `409` → show "This job is closed. Reopen it to
  write in it." with Reopen.
## 2. Report-back in the room (D17, protected)
`Job.reportBack { state; tool; at }` (contract §17). Show it on the job's Started-by card (`room/BoldTeamRoom.tsx`
`StartedBy`) and in the thread header: `waiting` "Will send the result back to <source> when done"; `needs_ok` "Send the
result back to <source>? <tool>" with Send; `sending` "Sending the result back…"; `confirmed` "Sent back <time>";
`not_confirmed` "Couldn't confirm the result was sent back" with Try again; `off` nothing. Send/Try again →
`POST /api/jobs/:jobId/report-back`. The surface is protected (`data-protected`, a protected-surfaces.ts class).
## 3. Hermes tasks (unblock, comment, steps)
Endpoints kept in 11.12a: `GET /api/tasks?room=<roomId>&needsYou=true`, `GET /api/tasks/:taskId` (checklist/steps,
activity), `POST /api/tasks/:taskId/actions { action: 'unblock' | 'comment'; text? }` (unblock's note optional), stream
`task.upserted`.
- **Needs you:** each blocked task of this room (and, in the team room, tasks with no room) is a protected card in the
  room's Needs-you strip (`room/RoomRequests.tsx`, counted like the other cards): title, assignee glyph, why it's
  blocked, **Unblock** (with an optional note) and **Comment**. It leaves when the stream says it's no longer blocked.
- **Thread:** a "Hermes tasks" section in the thread (`room/BoldThread.tsx`) listing this room's tasks with state and
  steps (checklist from the detail), each with Comment. Report as a difference if the prototype has no place for it.
