## Build
- `BoldRecipes` dialog opened from `/b?recipes=1` (the param 11.10f's Search already links to; also a "Recipes" entry
  wherever the prototype puts one) — on `/b`, not a new top-level page.
- The step list is an ordering of the workflow's nodes (topological, ties by the stored order). Moving a step changes the
  order and re-links `output` edges of a straight run; branches show their targets ("passed → step 4 · changes requested
  → back to step 2") with selects to change them, joins show what they wait for. Any definition the classic editor can
  make must load, show and save **unchanged** in the step list (round-trip test over every 7.1 e2e fixture in
  `e2e/workflow-fixtures.ts`); if a graph can't be shown as a list faithfully, show it read-only in the graph view with
  "Edit this one in the graph editor" linking to the classic editor, and say which shapes those are.
- Live checking uses `POST /api/workflows/validate` (debounced) plus the prototype's client-side problems; Save is a new
  version with the version you loaded (409 conflict → the classic conflict choices); "start from an older version";
  Export via the classic export (scrubbed); undo/redo (Ctrl/Cmd+Z, Shift+Z) via `use-draft-history`.
- Phone: the dialog becomes a full-screen sheet, inspector below the list.
