# 3.9.0 Effort per agent (owner, 2026-10-27, decision 147)

Owner: "for the agent, or coding agent, are we able to set effort level?" → chose **"Yes, for every agent"**. Today Score
can't set it; Codex agents only show the levels their model lists (`efforts` in `CodingModelOptionSchema`).

## Done when
1. **Hermes agents.** The agent's Model settings show an **Effort** choice: Default, low, medium, high, xhigh.
   - Hermes keeps it per profile as `agent.reasoning_effort` in config.yaml; default is "" (the model's own default).
   - Read it with the same `config get --json` path the model settings use (apps/server/src/hermes/live/model-settings.ts
     `KEYS`/`readRawSettings` via `configJson` in agent-config.ts). Add exactly the key `agent.reasoning_effort` to
     `ReadConfigKeys` in apps/server/src/hermes/live/cli.ts (its allow-list of readable config). Never read the whole
     `agent` section.
   - Write it with `config set agent.reasoning_effort <level>`, and Default = `config unset agent.reasoning_effort`, through
     `planWrites` (so undo, `undoOps`, keeps working). Validate the level against the fixed list (zod enum) before any
     write. Unknown values Hermes holds (set by hand) are shown as-is ("custom: x") and not rewritten unless changed.
   - Contract: `ModelSettings.effort: string | null` (null = Default) and `ModelSettingsUpdate.effort?: Level | null` in
     packages/contract/src/model-settings.ts; docs/API-CONTRACT.md section for model settings updated first.
2. **Coding agents** (Claude Code, Codex; not Antigravity: it documents no effort flag). An **Effort** choice next to the
   model on the coding agent's settings.
   - Stored on the agent: migration `0098_coding_effort.sql` adds `effort TEXT` to `coding_agents` (NULL = Default).
     `CodingAgentPatchSchema` and the coding agent summary/detail gain `effort` (nullable).
   - Claude Code levels: low, medium, high, xhigh, max → argv `--effort <level>` (Claude Code 2.1.311 `--help`:
     "--effort <level>  Effort level for the current session (low, medium, high, xhigh, max)").
   - Codex: argv `-c` `model_reasoning_effort="<level>"` (TOML string, like the existing `approval_policy="never"` in
     codex.ts buildArgs). Offer the levels the chosen model lists (`efforts` from models.ts) when known, else
     minimal, low, medium, high, xhigh.
   - Pass it in `buildArgs` only when set (Default sends nothing), for chats and for orchestration worker launches alike.
     Effort is not part of the worker policy's reach; don't add it to the policy inputs.
   - Validate with a strict regex `^[a-z]{1,12}$` plus the runtime's list; never put free text on argv.
3. Tests: server (model-settings planWrites/derive for effort; coding buildArgs with and without effort for both CLIs;
   PATCH validation, migration), web (the Effort select on both Model settings, sends the right update), contract schema
   table entries.
