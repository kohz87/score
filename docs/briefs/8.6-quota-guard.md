# 8.6 Quota guard for coding agents (owner 2026-10-17; decision 91)

Owner: "if quota is less than 10 percent, stop using [the coding agent] for this task". Chosen behaviour: **re-plan,
then ask** — the lead is told and picks another allowed agent; only if it can't (or insists) does Score ask the owner.

## Rule
- **Floor**: `quotaFloorPercent` 0–50 (0 = off). Default per coding agent (new field, default **10**), overridable per
  orchestration (start dialog + Limits card; default "each agent's own floor") and per workflow run.
- **Below the floor** = any window of the agent's latest reading (8.1 `CodingQuota`) with `usedPercent` known and
  `100 - usedPercent < floor`, **and** `resetsAt` in the future (a reading whose reset time has passed counts as reset).
  No reading or unknown share ⇒ not below (never block on missing data). Antigravity: only the windows of the model
  group the agent's model belongs to (map model id → `/usage` group name; unknown mapping ⇒ all groups; document the map
  next to the driver; "CLI default" model ⇒ the "Gemini Models" group).
- Readings: Claude Code/Codex as stored after each turn; Antigravity from the 60 s cached `/usage` (refresh before a
  decision if older than 60 s; a failed read ⇒ not below).

## Orchestrations (re-plan, then ask)
1. **At assignment** (the lead's step-creation tool, wherever the lead assigns a step to an agent): a coding worker
   below its floor ⇒ the tool returns a plain refusal the lead can act on: `quota_low` with the agent, window, % left,
   reset time and the allowed agents that are not below their floor; the tool description says to choose another agent,
   or to assign again with `ifQuotaLow: "ask_owner"` when no other agent can do the step.
2. With `ask_owner` the step is created **held**: Needs-you item `quota_low { stepId, agentId, window, leftPercent,
   resetsAt }` with three answers: **Use it anyway** (admits this step once), **Wait until it resets** (admitted
   automatically once `resetsAt` passes and a fresh check passes), **Stop the run**. Shown with the shared decision card
   components (also in the 8.4 user view).
3. **At admission** (`admission.ts` — a step queued earlier whose agent dropped below the floor since): the step is held
   the same way **and** the lead gets a cause ("s3 is held: builder-claude has 6% of its 5-hour limit left until
   3:40 pm") so it can re-plan around it (cancel/re-assign) while the owner may answer.
4. Running steps are never interrupted. Stored history: `quota_held`, `quota_override`, `quota_waited` entries.

## Workflows
Coding steps check at start; below the floor ⇒ the step waits with the same Needs-you item (no lead to re-plan).

## UI
Coding agent page: "Stop using this agent in runs when a limit is below [10]%". Start dialog / Limits card: the floor.
Timeline/Flow: the held step shows "Held: limit low (6% left, resets 3:40 pm)". The quota meters (8.1) mark the floor on
each bar.
