# Task 5.25: Chat: formatted replies, Stop, tool and thinking cards, context meter, clarify, voice

Owner 2026-10-09: features learned from nesquena/hermes-webui (MIT, `../reference/hermes-webui`; adapt with a one-line
source comment + THIRD_PARTY_NOTICES entry if you copy). Today chat text renders as plain `<p>` (MessageItem.tsx).

## Done when
1. **Markdown replies.** Text parts of agent (and your) messages render with `react-markdown` + `remark-gfm` (on main):
   headings, lists, tables, links (open in a new tab, `rel="noopener noreferrer"`), inline code, blockquotes. **No raw
   HTML** (react-markdown's default; never enable `rehype-raw`). Fenced code blocks: a header with the language, a
   **Copy** button (`copyText()`), and syntax highlighting with **CodeMirror's** highlighter (`@codemirror/language`
   + `@lezer/highlight` via `@codemirror/lang-*` already present) or a minimal tokenizer — no new dependency without
   asking the lead (Prism/highlight.js would need approval). Streaming text renders progressively without layout thrash
   (throttle to animation frames). **Mermaid** blocks (`mermaid` fenced): ask the lead before adding the `mermaid`
   package (check its license and size first and report); if not added, show the source with a "Mermaid diagram" label.
2. **Stop in the composer.** While an agent in this room is replying to your message, Send turns into **Stop** (and a
   Stop button appears on the streaming reply). It uses the existing Stop path for Score-started runs (`POST
   /api/runs/:runId/stop` or whatever 5.17-pre exposed; check the contract); the reply ends marked "stopped".
3. **Tool and thinking cards.** Translate Hermes run events (`tool.started`, `tool.completed` with its `preview`,
   `reasoning.available` text; see `hermes/live/translate.ts`, Hermes `gateway/platforms/api_server_runs.py`) into
   message parts: a `tool` part `{ tool; args preview; result preview; status }` per call and a `thinking` part
   (collapsed by default, "Thinking…" while streaming). Contract first (§5 MessagePart). Everything redacted
   (`redactBounded`) before storing; sizes bounded. An "Expand all / Collapse all" control when a reply has 3+ tool cards.
   Keep the existing compact `tools` summary for old messages.
4. **Context meter and commands.** Under the composer: the agent's session context use (tokens used / window, and
   cost when known) from the run's `usage` and the model's context length (from model options) — hidden when unknown.
   Slash commands: `/compress` (ask Hermes to compact the agent's session: find the supported way — a gateway session
   command or CLI — through the adapter), `/model <name>` (sets this agent's model via the existing PUT), `/usage` (shows
   the session's token/cost summary as a local card). Unknown commands keep today's behaviour.
5. **Clarify.** Investigate whether Hermes's runs API surfaces the `clarify` tool (tools/clarify_gateway.py) to API
   clients. If it can be supported through the gateway API or the bridge plugin (private calls only in
   `hermes_private.py`), render the question with its choices as buttons (and "Other" with a text box) and send the answer
   back; contract + tests. If it cannot be done without changing Hermes, do not hack it: write what is missing in
   `docs/proposals/hermes-clarify-api.md` and report.
6. **Voice input.** A microphone button in the composer using the Web Speech API (`SpeechRecognition` /
   `webkitSpeechRecognition`), shown only when supported; tap to start/stop, interim text appended to the draft, stops after
   ~2 s of silence; accessible label and pressed state.
7. Tests: component tests for each (Markdown incl. a script/HTML injection attempt rendered inert, code copy, stop,
   cards, meter, slash commands, voice with a mocked recognizer), server tests for the new parts/translation and redaction,
   contract fixtures, e2e on the fake adapter (a Markdown reply with code + copy, stop, tool cards), chat visual baselines
   updated and checked by eye.
