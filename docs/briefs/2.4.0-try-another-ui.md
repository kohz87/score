# 2.4.0 Try another reply: the UI (brief)

Decision 130 (end of docs/DECISIONS.md). Contract: docs/API-CONTRACT.md, `POST /api/rooms/:roomId/messages/:messageId/
retry` (body `{ another: true }` = Try another, `{}` = Retry) and `Message.alternativeOf` (packages/contract/src/
types.ts). The server is done (committed in this worktree); fake mode works as is (the fake agent answers again).

## Done when
1. **Grouping** (new shell message stream: team room, job threads, one-to-ones): agent replies with the same
   `alternativeOf` (and the first reply itself) show as **one** message at the first reply's place, never as separate
   messages. A version that streams in later appears inside that message (the group follows it while it streams).
2. **Pager**: when a group has ≥ 2 versions, a pager `‹ 2 / 3 ›` sits under the bubble — copy the prototype's `.vers`
   look (docs/design/bold/prototype.html, CSS line ~123, rendering line ~604: muted 12px text, round 26px buttons on the
   panel colour). Default selection: the newest version; a newly arriving version becomes selected. The selection is the
   viewer's (component state, remembered per group in localStorage with try/catch). Reuse `VersionControl`
   (apps/web/src/routes/chat/versions.tsx) if it fits the look, else a small `bold-` component. Keyboard: the buttons are
   real buttons with labels "Previous version" / "Next version"; the position is announced ("Version 2 of 3").
3. **Swipe** (touch, phone layout): a horizontal swipe on the bubble goes to the previous/next version (threshold
   ~48px, vertical scroll must keep working: only act when |dx| > 2·|dy|; never on a text selection). No swipe on
   desktop pointer devices.
4. **Try another**: on a finished agent reply that answers the person (where Retry is offered today — `retryableIds` in
   apps/web/src/bold/room/BoldMessage.tsx), the act row shows **Try another** (POST with `{ another: true }`); a failed
   reply keeps **Retry** (`{}`). While a new version is being written the button is disabled. 409 → "This reply can’t
   be tried again right now." Try another on any version of a group starts a new version of the same group.
5. **Memory note**: under a group with ≥ 2 versions, a muted line: "builder remembers its earlier answers" (the agent's
   display name). Not on single replies.
6. Everything that lists messages elsewhere (Results, search, pins, references, report-back) stays as it is: every
   version is a real message. Only the stream view groups them.
7. Tests: unit tests for grouping (order, a version streaming in, a group whose first reply was deleted — show the
   remaining versions in the first remaining one's place), the pager (keyboard, localStorage failure), the swipe gesture
   (dx/dy rule), the Try another / Retry switch. e2e `e2e/bold-try-another.spec.ts` (fake mode): Try another twice →
   pager shows 3/3, go back to 1/3, the note; phone: swipe changes the version; Retry on a failed reply still works
   (the fake has `[fake:refuse]`-style hooks; look at existing retry specs).
