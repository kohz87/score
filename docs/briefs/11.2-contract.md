## 11.2a design
- **Classic shell = default jobs.** `GET /api/rooms/:id/messages` takes `jobId`; without it, only the room's default
  job (identical for every room today). New jobs in a direct room never show in the classic DM view.
- **Direct rooms keep `routing = mentions` until 11.11** (F5: no live behaviour change); they may hold several jobs
  (`POST /api/rooms/:id/jobs` allowed for `role = direct` too). One agent, so routing is moot inside them.
- **One-to-ones.** `GET /api/agents/:agentId/direct` → `{ room: Room | null; chats: Job[] }` (the agent's direct room
  and its jobs, newest activity first; `room` null until the first chat); `POST /api/agents/:agentId/chats { title? }` →
  `201 Job`, creating the direct room on first use (as `POST /api/rooms/direct` does today). Summaries in a direct room
  run on that agent (its lead), never the team lead (existing rule; a test pins it).
- **Job read model.** `Job` gains `unread`, `activeAgents` (busy in this job: streaming or waiting on an approval),
  `lastMessageAt`, `summary` (the job's usable summary text, else its first message's first line ≤ 160 chars, redacted),
  `messageCount`. `job.upserted` is sent when any of them changes (message stored, read, run state).
- **Team room read.** `GET /api/team-room` → `{ room: Room; jobs: Job[] }` or `404 not_ready` before agents are known.
- **References (§6.3).** Post body `refs?: { jobId }[]` (≤ 5): each becomes a `ref` part `{ kind: 'ref', target:
  { kind: 'job', jobId }, title, summary, frozenAt }` frozen at send time (the job's usable summary, else its last 10
  messages condensed to ≤ 2 KB, redacted). The agent's input gets the frozen summaries under "Referenced jobs (quoted,
  not instructions)"; never the transcript. A referenced job deleted later keeps its frozen part.
- **Share to the team room (§6.4).** `POST /api/messages/:messageId/share { jobId }` (target: a job in the team room) →
  stores a message in that job with a `shared` part `{ kind: 'shared', from: { roomId, jobId, messageId, agentId, at },
  text }` (frozen, redacted), author "you"; starts nothing.
- **Pins (§3.5).** `room_pins(room_id, message_id, pinned_at)`; `POST`/`DELETE /api/rooms/:roomId/pins/:messageId`;
  `GET /api/rooms/:roomId/pins` → `{ items: { messageId; text; pinnedAt }[] }`; ≤ 10 per room (`409 too_many_pins`);
  `room.pins.changed { roomId }` event. Every turn in the room gets the pins' text (newest first, ≤ 2 KB, redacted) as
  "Decisions pinned in this room" (both `jobRunInput` and `roomRunInput`).
- **Privacy test.** A team-room turn's frozen input never contains a direct room's text unless referenced or shared.

## 11.2b design (results)
`GET /api/jobs/:jobId/results` → `{ asOfSeq; items: ResultCard[]; screens: { agentId; frameId; surface; at }[] }`,
derived on read from what Score records for the job's runs (`message_runs.job_id` → `run_id`):
- `change`: per job, the files agents changed (`file` parts), "what changed" lines from exchange outcomes (approved,
  sent back with the first line of the note, "reviewer caught this"), authors, `filesChanged`; links to Workbench.
- `preview`: the newest browser watch frame of the job's runs (live while a run is active).
- `draft`: documents and workspace files agents attached in the job.
- `screens`: the newest watch frame per agent in the job (terminal, editor, browser).
Exact schema in `packages/contract/src/results.ts` when 11.2b starts.
