## Build (apps/web only)
1. **JobMap component** (new, e.g. `apps/web/src/bold/jobmap/JobMap.tsx` + model + css), shown as the main view of a lead-decides
   job wherever the bold shell shows that job's graph today (find where `OrchestrationLive`/`buildGraph` or the bold job view
   renders the flow for an orchestration, and make JobMap the default view there; keep the existing views reachable if they
   have their own tab). Recipe (workflow) runs keep their own graph; plain chat jobs keep their thread.
   - Nodes (one per layer, only the layers the job uses): **You · prompt** (the goal, two lines) → **Lead** (agent, turn N of M,
     plan progress, what it is doing now from the latest lead attempt/note; pulses while a lead attempt runs) with the
     **Advisor** beside it on a dashed "on call" line (checkpoint marks ◆ used / ◇ not yet for before plan, same failure twice,
     before done; "N consults · tokens read X" counting `advisor.consults` + `advisor.onCall` totalTokens) → **Fork layer · votes**
     (`helpers.votes`: last 3, question, share bar, sharp/split/voting) → fan-out to the **Swarm** (one node per helper agent:
     its latest helper step's role, status, last sign of life) → fan-in → **Workers** (one node per worker agent of lead steps:
     step chips s1 ✓ … with status colors; the stuck-step warning + Stop reuse `StuckStepCard`/`StepStopButton` from
     `routes/orchestrations/StepStop.tsx`) → **Check** (`check`: command, last run outcome/time) → **Session log** (the job's
     events/timeline from the existing events endpoint used by the run views; newest at the bottom, last ~8; clicking a node
     filters the log to that layer).
   - When a worker has asked the advisor (`advisor.onCall` entries for its steps), draw the dashed advisor line to that worker
     node too, and show "asked the advisor 2× (18k tokens)" on it; the log gets "terra asked the advisor: <question>".
   - Lines: CSS (borders/positioned divs or one SVG layer behind the nodes); moving dots only along lines into a layer that is
     active right now (respect `prefers-reduced-motion`: no animation). Desktop: fixed layer rows centred, swarm fans out in a row.
     **Phone (≤ 600px)**: the mock-up's vertical version (advisor marks on the lead card, swarm as a 3-column row).
   - Nodes are buttons (focusable, `aria-label` with the layer and its state); the graph has a text alternative (the session
     log plus each node's label is enough). Decision surfaces (stuck card) keep `data-protected`.
   - Data: everything is in `OrchestrationDetail` (stepsList with role/helperRole/lastActivityAt, attempts, helpers, advisor,
     check, plan, status) plus the events endpoint. No new endpoints; if something is truly missing, stop and report it.
2. **Start a job › Advisor**: a choice "Helps: the lead and the workers (on call)" (default) / "the lead only (checkpoints)" →

   plan). Other workers get the lead's checkpoints only."; send `advisorMode` only with an advisor (the create schema now has it
   with a default; fix any typecheck the new output field causes).
3. **AdvisorCard** (`routes/orchestrations/AdvisorCard.tsx`): show the mode and the on-call consults (worker, step, question,
