## Task (from docs/PLAN.md)
**3.8 Reports aggregations**: tasks finished, runs, first-pass rate (review without `request-changes`), median time, spend
(`state.db` cost columns), approvals. Done when fixture DB tests produce known numbers.

## Design (from the lead)
- Pure aggregation module `apps/server/src/domain/reports.ts` over rows Score already has (task projections and task
  events, runs, approvals ledger) for `range=today|7d|30d` in the server's local time zone: `totals`, `byDay` (per agent
  finished tasks), `timeSplit` (working / waiting on you / waiting on another agent, from run and approval intervals),
  `byAgent`, `approvals` (asked/approved/denied/median wait; `insight` a plain sentence or null), `summary` sentence.
  First-pass rate = finished tasks whose review never requested changes (null when no reviewed tasks; reviewers' own row
  shows null = n/a).
- **Spend**: Hermes `state.db` cost columns, read-only through the adapter (`apps/server/src/hermes/live/`, `openReadOnly`;
  look up the columns in `../reference/hermes-agent` and in `apps/server/test/fixtures/`); null when unavailable. Fake mode:
  plausible neutral numbers.
- **Endpoint** `GET /api/reports?range=` exactly as contract §9 (`ReportsSchema` in `packages/contract/src/http.ts`);
  400 for a bad range. CSV export is a later task (3.11); no web UI here (3.10).
