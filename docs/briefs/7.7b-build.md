# 7.7b build plan

Design: `docs/briefs/7.7b-coding-workers.md` (the accepted version). Three parts, **one builder each, in sequence** on one
branch `task/7.7b-workers` (worktree `../score-worktrees/7.7b`): 7.7a showed that joining parallel batches made most of
the new bugs. The lead reviews and runs the full check after each part before the next starts. Codex code review at
max after part 3, before merge.

Rules for every part: follow AGENTS.md (licensing, no new dependencies without asking, contract doc first), the
builder brief rules (no pkill/killall or pattern kills, never touch 8740/8741 or the live Score, no git stash, no
`SCORE_E2E_DEV=1`, no `pgrep -f` wait-loops, clean up every process and `score-test-*` unit), failing-first tests at
the real boundary, `pnpm check` green, commit per item ("7.7b-<part> #n: …"), don't merge. Migration numbers: part 1
`0062`, part 2 `0063`, part 3 `0064`.

## Part 1: the executor ↔ coding runtime core
Design §§0, 2, 5, 6, 7, 10 (+ §9 Stop routing):
- composite port built once; `assertOrchestrationWorkers` (workflows keep `assertHermesOnly`);
- per-generation turn and launch ids minted in `beginSend` and journaled; joins by `(attempt, generation)`;
  `run_handle` with generation; `recordHandle` checks generation; 20-generation bound;
- coding journal `requested` carries the immutable owner; projection/tombstone keep it through compaction;
- `startRun` owner argument; one launch per generation (no resume fallback for owned turns);
- release: transaction ownership exactly as §6, `authorise()` = common admission rules + phase guard (+ hooks for the
  policy and limit checks part 2 fills in), typed causes, `send_closed`, the full cause table incl. the `suspended`
  attempt flag;
- evidence/late proof/`interrupted` rules; `result_text` (32 KiB) and the lead fed from it;
- routing by `runs.runtime`; coding Stop with no run row; agent removal `409 agent_busy`;
- restart matrix (§10) with a test per row.

## Part 2: policy, consent, limits, spend
Design §§3, 4, 8, 12a and the contract changes:
- worker policy + policy id at preflight (identities, environment hash, settings bytes, bound config sources by file
  identity only — **never read** CLI config or credential files); per-driver neutralise/bind declaration verified on
  the installed CLIs by help output only (no prompts);
- invocation built from the stored policy before arming; re-check of every identity inside the release critical
  section; deadline/expiry rules (§9);
- consent by policy id; `codingSteps` derived from launch owners; unknown cost per source; LimitsDecision changes;
  policy-only remap, gates bound to policy id, suspended attempt re-admission;
- contract doc, `packages/contract`, server.

## Part 3: storage, shutdown, UI
Design §§9 (Stop jobs + shutdown), 11, 12, 13:
- Stop delivery as tracked async jobs; shutdown order;
- storage reserve, admission charging, pruning by identity, unlaunched inputs hashed;
- web: start dialog (reach acknowledgement by policy id, unknown-cost per source, coding step limit), preflight
  readiness, CLI badges in Flow/logs/agent list, blocked "agent changed"/"limit reached" actions;
- e2e (fake mode): start dialog and a coding step in an orchestration.

## Part 1 review (lead) — carried into part 2, first
0. **One admission function.** `decideRelease` re-implements the common admission rules; `beginSend` keeps its inline
   checks. Extract the common rules into one pure function used by both (design §6), with the phase guards separate;
   a test that changing one rule changes both paths.
0b. **Expiry at spawn (A2):** the supervisor checks the absolute expiry in its `go` handler right before spawning;
   expired ⇒ no spawn, reported `expired` (receipt), the launch keeps `mayHaveExecuted` unless receipts prove no spawn.
0c. **§9 Stops:** decision 74 for executor-owned runs (an owed Stop for a coding run this process launched and is
   connected to is delivered while frozen; recovered/inherited still wait), and a deadline moved earlier owes a Stop
   for running coding attempts past it. (Stop *jobs* and shutdown stay in part 3.)
Accepted from part 1: late proof on an `unknown` attempt marks the step `failed` (never consumed); owned turns never
resume a CLI session; `limit` also suspends the attempt; a projection failure after `releasing` is `unknown` and a later
proof goes through the late-proof path.
0d. **Deterministic deadline test:** `coding-workers-release.test.ts` "terminal causes … deadline" races the deadline
   flow's own Stop under load (cause `stop` instead of `deadline`); make it deterministic (fake clock or ordering),
   don't widen the assertion.

4. **Per-step policy for remap** (#4): compare a remap against the suspended attempt's own approved policy (store the

   counters.
7. **Coding storage** (#7): coding inventory reserved separately from observations; raising `codingSteps` grows the
   reserve (or is refused when it can't); `coding_run_results` charged.
8. **Test artefact** (#8): the arming test uses an assign-only lead and asserts after executor idle.
