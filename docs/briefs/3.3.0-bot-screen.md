# 3.3.0 Bot Screen (design note and brief)

PLAN P2 "Bot Screen": a read-only live view of a profile's Hermes Bot Desktop (computer-use screen) on the agent's
screen page (`/b/screen/:agentId`). Owner order, 2026-10-26: after README and the stopped-setup removal.

## What Hermes offers (v0.22.5+1099, read from `~/.hermes/hermes-agent`)

- The screen is TigerVNC `Xvnc` per profile, listening **only** on a Unix socket
  `<profile home>/bot-desktop/rfb.sock` (`launcher.sh`: `-rfbport -1 -rfbunixpath … -rfbunixmode 0600
  -SecurityTypes None -AlwaysShared -SendCutText=0`). Same-UID processes are inside Hermes' trust boundary by design.
- The dashboard path the PLAN assumed (`display.observe` → single-use ticket → `/api/display/ws`) is a JSON-RPC method
  on the dashboard's `/api/ws`, admitted with the dashboard session token. Score has no such credential and must not read
  one. The gateway API (`/v1`) has no display route. **So the PLAN's route is not open to Score.**
- Input is filtered by Hermes' bridge (`rfb_filter.py` drops KeyEvent, PointerEvent, ClientCutText, SetDesktopSize,
  QEMU key unless the viewer holds the lease). A direct socket client bypasses that filter, so **Score's client itself
  must never send those messages.**
- The lease (`<home>/bot-desktop/lease.json`, `holder: agent|human`) says who drives. Hermes treats an unreadable or
  corrupt lease as `human`. Its own thumbnail returns nothing while a human holds control, because the frame may show
  what they type.
- A sandboxed screen (placement in the terminal backend) has no host socket (`rfb_socket_path()` returns None).

## Decision (135)

Score reads the screen **directly from the RFB socket**, inside the adapter (`apps/server/src/hermes/live/bot-screen/`),
with a minimal RFB 3.8 client of our own (no dependency; noVNC is MPL-2.0, rule 4), and serves **PNG snapshots** to the
browser, polled about once a second while the page is visible. No WebSocket, no input path, no lease calls.

The client may send exactly three message types: SetPixelFormat (0), SetEncodings (2: Raw 0 and the DesktopSize
pseudo-encoding −223 only) and FramebufferUpdateRequest (3). A unit test fails if any other byte sequence is written.

### Behaviour
- `GET /api/agents/:agentId/bot-screen` → `BotScreenStatus { state: 'running' | 'off' | 'sandboxed' | 'human' |
  'unavailable', width?, height?, frameSeq? , reason? }`. `human`: someone has taken over; no frame is served.
- `GET /api/agents/:agentId/bot-screen/frame` → `image/png` of the current framebuffer (`Cache-Control: no-store`,
  `ETag` = frame sequence; `If-None-Match` → 304). 404 when not running, 409 `human` while a human holds the lease.
- One RFB connection per profile, opened on the first request, closed after 15 s without a request. It never keeps the
  screen awake: Score does not touch Hermes' `activity` file, so Hermes' idle auto-stop still applies.
- The lease is read (read-only, `lease.json`) before every frame; unreadable/corrupt/missing-but-socket-present follows
  Hermes: treat as `human`. When `human`, the cached framebuffer is dropped, not just hidden.
- Socket path from the adapter's known profile home; refuse a socket that is a symlink, not a socket, or not owned by
  Score's UID (`lstat`). Max framebuffer 4096×4096; any larger ServerInit / DesktopSize closes the connection.
- Fake adapter: a synthetic screen (drawn framebuffer that changes over time) for unit tests and e2e.

### UI (agent's screen page)
A "Live screen" card above the replay: the image scaled to the card width, a small "Live · read-only" label, the state
lines ("The screen is off", "Runs inside the sandbox: Score can't show it", "Someone has taken over this screen: Score
hides it while they work"). Polling stops when the tab is hidden or the card is collapsed. No click/keyboard handlers on
the image. Phone: the same card, full width.

### Security and privacy
- Frames are as sensitive as the replay: served only to the same authenticated/paired sessions as every other `/api`
  read (remote mode included); never stored in `~/.score`, never logged, never in exports.
- Nothing crosses the boundary except through `HermesPort.botScreen*`; no other module learns the socket path.
- No writes to `~/.hermes`; one read of `lease.json` and a connect to a socket.

## Adversarial review (lead, 2026-10-26; Codex unavailable for Score)

| # | Attack / failure | Response |
|---|---|---|
| 1 | Score's client sends input (bug, malformed message) and drives the bot's desktop. | Writer is a fixed encoder for 3 message types; test asserts every written byte sequence; no API takes input. |
| 2 | A human takes over; Score keeps showing what they type (passwords). | Lease read before every frame; `human` drops the cache; unreadable lease = human (Hermes' rule). Race: a frame captured just before take-over can be served once (≤ 1 s); acceptable and documented — Hermes' own thumbnail has the same window. |
| 3 | Symlink swap: `rfb.sock` replaced to point Score at another socket. | `lstat`: must be a socket, not a symlink, owned by our UID, inside the profile home. |
| 4 | Hostile/buggy server sends huge dimensions or rect lengths → memory blow-up. | 4096² cap; rect bounds checked against framebuffer; unknown encodings close the connection. |
| 5 | Score keeps the screen alive forever. | No `activity` stamp; connection closes after 15 s idle. |
| 6 | Many browser tabs → many connections. | One connection per profile, shared; PNG encoded at most once per frame sequence. |
| 7 | Remote viewer sees the bot screen. | Same auth as the replay (paired session). |
| 8 | `-AlwaysShared` means Score's connection never disconnects a human viewer. | Confirmed in `launcher.sh`; ClientInit shared-flag = 1 anyway. |
| 9 | Sandbox screens are invisible. | Reported as `sandboxed`; reading Hermes' sandbox relay is out of scope. |
| 10 | PLAN wording ("dashboard ticket") differs. | Decision 135 replaces it with this note; the dashboard needs a credential Score must not read. |
