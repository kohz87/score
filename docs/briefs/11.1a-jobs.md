# 11.1a — Jobs and per-job sessions (lead)

Design: `docs/briefs/11.0-bold.md` §3.1–§3.3 and §9. Coded by the lead (CLAUDE.md, 2026-10-24: data model, sessions and
migration are lead work). Migration number **0080**.

## Scope (narrowed from PLAN while reading the code, 2026-10-24)
- **Server-only, no contract change.** Nothing new crosses to the web until 11.1b/11.2 expose jobs; AGENTS.md's
  contract rule applies when they do.
- **One job per room by construction.** Every room gets exactly one default job (migration for existing rooms, a
  trigger for new ones); nothing in 11.1a creates a second. Room-scoped behaviour (rewind, summaries, unread, search,
  shares, coding CLI sessions, compaction's busy check, active agents) is therefore exactly job-scoped, and moving each
  of those to job scope is an explicit **11.1b prerequisite** before any room gets a second job.
- **No team room yet.** Creating it now would put an empty room into the owner's live old-UI room list. It is created
  in 11.1b, when it can route, and hidden from the old shell.
- Room roles are `team` | `direct` | `room` (the UI calls `room` "older rooms"); every existing room keeps
  `routing = 'mentions'`, so the live Score behaves exactly as before.
