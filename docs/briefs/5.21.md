# Task 5.21: Reports: instant range switching and a custom range

Owner report 2026-10-09: choosing 1d / 7d / 30d on Reports takes ~5–7 s to show; there is no custom range.
Measured: `/api/reports` computes in ~50 ms, but on a cold agent cache it first waits on `port.listAgents()`
(`apps/server/src/http/reports.ts`), which runs several `hermes` CLI calls per profile (~2.5 s each). Live log:
3.3 s, 8.8 s, 5.2 s for three consecutive range clicks.

## Done when

1. **Reports never waits on Hermes CLI reads.** The agent ids come from Score's own agent projection in the DB (the
   same rows `reconcileAgents` keeps; read with the existing domain helpers), not `port.listAgents()`. `reportFacts`,
   `sessionCosts` and `reportHistoryRows` stay (read-only SQLite, fast); check each for CLI calls and remove any from this
   path. CSV export uses the same loader. Test: a port whose `listAgents` never resolves still answers `/api/reports`.
2. **Switching feels instant.** The web keeps the previous numbers visible (already `keepPreviousData`) **and** shows a
   clear in-place loading state (the range chip shows a small spinner, the figures dim slightly; `aria-busy`). Prefetch the
   other two preset ranges after the first report loads, so a click answers from cache and refreshes in the background.
3. **Custom range.** Contract first (`docs/API-CONTRACT.md` §Reports + `packages/contract`):
   `GET /api/reports?range=custom&from=YYYY-MM-DD&to=YYYY-MM-DD&tz=` (and the same for `export.csv`); `from ≤ to`,
   both inclusive local days in `tz`, at most 366 days, `to` not after today; 400 with a clear message otherwise. The
   domain's `reportWindow` handles it (day buckets per local day, as the presets do). Web: a "Custom" chip after 30d
   opens a small popover with two native date inputs (`<input type="date">`, min/max enforced) and Apply; the chosen range
   shows in the chip ("3 Oct – 9 Oct") and is kept in the URL (`?range=custom&from=…&to=…`) so reload/share keeps it.
   The CSV link follows the chosen range.
4. Charts and tables that assume 1/7/30 buckets work for any length (check the daily charts with 1, 2, 45 and 366 days;
   long ranges may bucket by week if a chart would get unreadable — say so in the report if you do).
5. Tests: server (custom window validation, inclusive days across a DST change, CSV), domain (bucketing), web (chip
   spinner, prefetch, custom popover validation, URL state), e2e for a custom range on the fake adapter, visual baseline
   for Reports updated and checked by eye.
