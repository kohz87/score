# 8.8 Role and personality for coding agents (owner 2026-10-17; decision 94)

Owner: "coding agent doesn't have personality etc?" Chosen: **stored in Score** and handed to the CLI; nothing written
into the workspace.

## Data
- `role` (exists, ≤ 2000, today only settable by API): shown and editable; optional field in the add form.
- New `instructions` (Markdown, ≤ 8000 chars): "Personality and instructions". Migration **0074**
  `coding_agents.instructions TEXT NOT NULL DEFAULT ''`. Contract doc first (coding agents section): create/patch fields,
  `CodingAgent` view, an `etag` for the instructions edit (follow how SOUL.md edits use etags).
- Not part of the 7.7b policy fingerprint (it isn't a safety setting): editing it never raises `policy_changed`.

## Delivery to the CLI (every turn Score starts: chat, orchestration worker, workflow step)
- **Claude Code**: `--append-system-prompt-file <file>`, the file written 0600 in the run's private folder (never in
  the workspace, never on argv), containing a fixed frame: "Your name in this team: … Your role: … The owner's
  instructions for you: …". Passed on every turn, resumed sessions included (verify the flag combines with `--resume`
  from `claude --help`; never run a prompt).
- **Codex, Antigravity**: no such flag (checked with `--help`, 2026-10-17). Score prepends the same framed block to the
  **first** message of a new CLI session; on a resumed session it is sent again only when role/instructions changed since
  that session started (store a hash per session), with "Your instructions were updated:".
- The frame says plainly these are the owner's instructions and that Score's rules (access level, blocked paths) still
  apply; the block never overrides permissions — they are enforced by the CLI flags, not by text.
- Empty role and instructions ⇒ nothing is added (today's behaviour exactly; existing driver tests unchanged).

## UI
Coding agent page: a "Personality" card like a Hermes agent's (role line + rendered instructions, Edit → editor with
Save/Cancel, etag conflict message). Add form: optional "Role" one-line field. The Team list shows the role under the
name like Hermes agents.

## Tests
Driver arg tests (Claude: file flag present only when non-empty, file content, 0600, outside the workspace; Codex/agy:
first-message prepend, resumed-session rules, change detection); route tests (patch, etag 409, length limits); web
tests; e2e in fake mode (edit instructions, run a turn, the fake CLI echoes that it received them). Real-CLI replays
unaffected (`loss: null`).
