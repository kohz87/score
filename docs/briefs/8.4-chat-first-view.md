# 8.4 Chat-first user view (design v1; decision 85; PLAN 8.4)

Owner 2026-10-16: "use grok bot as reference, the user only need chatbot like interface (for chat, room, orchestration
without the report, they gets the update from chat unless they use admin interface to see full details like current)".
Same single owner (multi-user accounts stay not planned). The current interface becomes the **admin view**.

## Shape (a Grok-style chat app, built from Score's own design tokens)
- **Left sidebar:** "New chat", then the rooms and direct rooms (agents, coding agents included) with search; running
  orchestrations marked with a small live dot; a footer with the avatar menu ("Switch to admin view", theme, sign out).
- **Main:** one conversation at a time, centred column, large composer at the bottom; empty state with the agent picker
  and a few suggestion chips ("Ask the lead…", "Start an orchestration…"). Markdown, code and tables as in Chat.
- **No** Now dashboard, Flow canvas, Reports, Team, Tasks board, Knowledge browser or Settings pages. Links that would
  open them (e.g. "Open in Flow") are hidden in this view.

## Orchestrations from chat
- The composer's "+" (and `/orchestrate <goal>`) starts an orchestration with the same dialog fields reduced to: goal,
  lead, allowed agents, budget (optional); defaults for the rest; coding-reach acknowledgement and unknown-cost
  questions shown when coding workers are chosen (reusing 7.7b's components).
- The run lives in its room (as today); **progress arrives as chat messages:** the lead's messages plus compact Score
  status messages (step started/finished, waiting for you, finished/failed) generated from orchestration events — shown
  only in this view's rendering of the room, never stored as fake agent messages.
- **Everything that needs you is answerable in the chat:** tool approvals (as today), step gates, "Settings changed",
  "Raise the limit", unknown cost, held-back/lost-input cards — rendered inline from the run's Needs-you items with the
  shared decision components (no new decision logic). Pause/Stop as in today's run controls.
- "See full details" opens the admin view's Flow for that run.

## Switching
- Avatar menu: "Switch to user view" / "Switch to admin view"; remembered per browser (localStorage, try/catch).
- Optional guard (Settings › Security in the admin view): "Ask for the security password to open the admin view" — off
  by default; when on, switching to admin needs the password (existing password check), and a browser that was opened
  in user view starts there. This is a convenience guard for a shared screen, not access control (the API stays the
  same; noted plainly in the setting's help text).
- URL: `/u/…` routes for the user view (deep links to a room: `/u/rooms/<id>`), admin routes unchanged.

## Not changing
API and server behaviour (no new permissions); data; approvals and orchestration rules. The user view is a second
front end over the same contract.

## Done when
User view: chat in rooms and direct rooms, start an orchestration from chat, see its progress as messages, answer every
Needs-you item inline, Pause/Stop, switch views; phone width works; packs (8.3) apply; e2e in fake mode for each of
those; `pnpm check`; screenshots for review (no personas).
