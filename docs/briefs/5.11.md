## Task (from docs/PLAN.md)
**5.11 Model picker** · `GET /api/models` from Hermes's model options (connected providers only); a searchable picker in Add
agent and the agent's Model tab; picking sets model and provider. Done when typing "gpt" lists matching models from each
connected provider with availability and price, and a created agent has both set (fake + tests + e2e).

## Design (from the lead)
Contract: §10 `GET /api/models?q=` (`ModelOption`, `ModelsResponseSchema`), §8 `provider?` on `POST /api/agents` and preview
(`AgentCreateInputSchema` already has it). Existing: `GatewayClient.modelOptions()` in `apps/server/src/hermes/live/gateway.ts`
(schema keeps only slug + name today — extend it with `models: string[]`, `authenticated: boolean`, `unavailable_models: string[]`,
`pricing: Record<model, {input, output, free}>` all optional/loose, bounded sizes), `LiveSettings` provider list, `live-port.ts`.
Real response shape (Hermes 0.21.5, default profile): each provider has `slug`, `name`, `authenticated`, `models` (ids),
`unavailable_models` (ids the account's plan can't use, e.g. Nous free tier), `pricing[model] = {input: '$2.00', output: '$10.00',
free: bool}`, `total_models`. Profiles share the root sign-ins (Hermes reads the global auth store as a fallback), so the
default profile's options are right for every agent.

1. **Server:** `HermesPort.listModels(q?)` (fake + live). Live: from `modelOptions()`, providers with `authenticated: true` and
   at least one model; label = Score's provider label (same as Settings, e.g. "ChatGPT (Codex)" for `openai-codex`);
   `available = !unavailable_models.includes(model)`, `reason` "Not on your plan" when unavailable; `free` from pricing or a
   `:free` suffix; `price` from pricing when both strings exist. Filter by `q` (case-insensitive substring of model or provider
   label, split on spaces = all terms must match), sort available first, then provider label, then model; cap 200. Cache the
   gateway response for 30 s (invalidate when Settings providers change is not needed). Gateway unreachable → `[]` and the UI
   says models couldn't be loaded. Route `GET /api/models` (paired session; zod-validated query).
   Fake: a few providers (e.g. `openai-codex` with `gpt-6.1-sol`, `gpt-6-luna`; `nous` with `openai/gpt-6.1-sol` unavailable and
   `upstage/solar-mini4:free` free; `local` with one model) — neutral, no persona names.
2. **Create with provider:** `POST /api/agents` and preview accept `provider`; the profile operation's model step calls
   `setAgentModel(name, { model, provider })` (live `agent-tabs.ts` `setModel` already sets `model.provider`); include provider
   in the preview hash input and the plan text ("Set the model to gpt-6.1-sol via ChatGPT (Codex)"). Fake port too.
   Persist it in the durable operation input (check `domain/profiles.ts` + its migration-free JSON input; no new migration
   unless unavoidable — if needed use number 0021 and say so).
3. **Web picker** `components/ModelPicker.tsx`: an accessible combobox (ARIA 1.2 pattern: input `role="combobox"`,
   `aria-expanded`, `aria-controls`, listbox with `role="option"` grouped by provider (`role="group"` + label), arrow keys, Enter,
   Escape, `aria-activedescendant`). Queries `GET /api/models?q=` debounced ~150 ms (TanStack Query, `placeholderData` keeps
   the previous list). Each option: model id, provider label, price ("$2.00 / $10.00 per 1M", "Free"), unavailable ones disabled
   with the reason. Free text stays allowed (custom/local models): typing a name that isn't in the list and pressing Enter keeps it
   with no provider. Value = `{ model, provider | null }`. Use it in `routes/team/AddAgent.tsx` (replace the datalist; send
   `provider`) and `routes/team/ModelTab.tsx` (send `provider` with `PUT …/model`). Style from tokens (`tokens.css`), matching
   the existing team form inputs; works at 390 px.
