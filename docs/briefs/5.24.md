# Task 5.24: Chat message actions under each message: Edit and resend, Copy, Delete, Retry

Owner report 2026-10-09: the Delete action on a message (5.20) sits at the top right and overlaps the timestamp; there is
no Edit for the owner's own prompt; actions belong under the prompt/reply. Owner decisions (AskUserQuestion):
- **Edit (own messages) = edit and resend:** opens the message in the composer; sending posts the corrected text as a
  new message to the same recipients; the original stays, greyed and marked "edited", with the replies it got. Agents see
  the correction as a new turn.
- **Agent replies get Copy, Delete, Retry.** Retry asks the same agent to answer the same message again.

2. **Edit and resend.** Contract first (`docs/API-CONTRACT.md` §Chat + `packages/contract`):
   - `POST /api/rooms/:roomId/messages` gains optional `edits: MessageId` (must be the sender's own, finished, not
     deleted message in the same room; else 400/404/409).
   - `Message` gains `editedBy?: MessageId | null` (set on the original when a later message edits it) and
     `edits?: MessageId | null` (on the new one). Event `message.updated` carries the original's new `editedBy`.
   - Recipients default to the original's `to` (the composer pre-fills text and recipients; attachments of the original
     are carried over by media id when present).
   - Server: migration **0029** (`messages.edited_by`, `messages.edits`, nullable) if the message row has no free JSON
     field for it; routing unchanged (the new message is an ordinary turn).

     with `edits`; the original renders greyed with "edited" + a link "see the new version" that scrolls to it.
3. **Copy.** Copies the message's text parts (Markdown source) with `copyText()` (data/clipboard.ts; never
   `navigator.clipboard` directly), shows "Copied" for 2 s. Works on plain HTTP fallback paths too.
4. **Retry (agent replies).** Contract: **H** `POST /api/rooms/:roomId/messages/:messageId/retry` → `202 { messageId }`
   of the new placeholder reply. Only for a finished agent reply that answers a human message (its parent turn); the new
   run goes to the same agent with the same input (reuse the routing/dispatch path that created the original reply, so
   pause holds, approvals, idempotency and attachments behave the same); idempotent per (reply, Idempotency-Key). 409
   while that agent is already answering that message, while paused, or when the reply has no parent turn. The original
   reply stays. Web: Retry shows the new reply streaming under the same parent.
5. **Delete** keeps the 5.20 behaviour (Score-side, 6 s Undo, the confirmation copy), only moved into the row.
