# 6.7 Knowledge export (owner request 2026-10-10)

Owner: "can the files and md be exported or mass exported?" Today documents have Download; notes don't; no bulk export.

1. **Single note download:** `GET /api/knowledge/notes/*path?download=1` (or a `/raw` route) → the note's `.md` bytes exactly
   as stored (frontmatter included), `Content-Disposition: attachment`, `nosniff`. "Download" on the note page and in Files.
2. **Bulk export as zip:** `POST /api/knowledge/export` `{ paths?: string[]; folder?: string; all?: true }` (exactly one) →
   streams `application/zip` (`attachment; filename="knowledge-<folder|selection|vault>-<date>.zip"`). Paired session
   only (H). Contents: the selected notes (`.md`) and documents (original bytes), folders kept as paths relative to the
   chosen root; no `.git`, no dotfiles, no Score index/extracted text, no symlinks. Limits: ≤ 10,000 files, ≤ 1 GB
   uncompressed (refuse with `413 export_too_large` before streaming, from the stored sizes); stream with jszip's streaming
   API (or store-only entries for already-compressed types) so memory stays bounded; a server-side timeout of 10 minutes.
   Large non-versioned documents included. A one-line `README.txt` in the zip root saying what it is and when it was made.
3. **UI:** Files view gets checkboxes + "Download selected (N)" and "Export this folder"; the Knowledge header (or Settings ›
   Knowledge) gets "Export the whole vault" with the file count and total size shown first. Progress: the browser's
   download; the button shows "Preparing…" until the response starts. Phone: same actions in the row/overflow menu.
4. Contract + API-CONTRACT first. Agents get no export tool.

Done when: server tests (single note bytes exact incl. frontmatter and non-ASCII names, selection/folder/all contents and
paths, exclusions, limits refused before streaming, pairing required, a large file streamed without buffering it whole),
web tests, e2e (export a folder and unzip it in the test to compare), baselines viewed; `pnpm check` green.
