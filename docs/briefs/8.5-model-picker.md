# 8.5 Model picker for coding agents (decision 86; PLAN 8.5)

Creating or editing a coding agent offers the CLI's models instead of a free-text field.
- **Antigravity:** `agy models` output (lines `id<TAB>name`, e.g. `gemini-4-argon-high	Gemini 4 Argon (High)`) — run with
  execFile, no prompt, 30 s timeout, parsed with a strict line pattern; groups by family with effort levels shown.
- **Codex:** `$CODEX_HOME/models_cache.json` (default `~/.codex`): read with `lstat` + `O_NOFOLLOW`, regular file, owned by
  the user, size cap; zod-validate and keep only `models[].slug, display_name, description, visibility,
  supported_reasoning_levels` (drop entries with `visibility` hidden); never read or store any other field (the file also
  holds an account identity) and never open `auth.json`.
- **Claude Code:** no listing command exists (`claude <word>` runs a prompt — never call it): offer the documented aliases
  `fable`, `opus`, `sonnet` from a constant, plus "Other…".
- Every list: "CLI default" (no `--model`) first, the models, then "Other…" (free text, as today). Lists cached ~5 minutes on
  the server, refreshed when the form opens; unreadable ⇒ the free-text field.
- Contract doc first: `GET /api/coding-agents/runtimes/:runtime/models` → `{ models: { id; name; description?: string;
  efforts?: string[] }[]; source: 'cli' | 'cache' | 'aliases' | 'none' }`.
- Web: the add-agent form and the agent's settings use a select with the list; an unknown current value shows as
  "Other…" with that value. Plain words (docs/WRITING.md).
Tests: parsers from fixtures (real `agy models` output captured 2026-10-16; a Codex cache fixture with an identity field
that must not appear in any output), the route, the form; e2e in fake mode.
