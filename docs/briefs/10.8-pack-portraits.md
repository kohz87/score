# 10.8 — Pet-pack portraits everywhere

Owner (2026-10-19): an agent with a pet pack should look like its character everywhere, not only on the Team card and
the agent page header (which keep the full animated `PetAvatar`, unchanged). Chosen: "a small round portrait cut from
the top of the idle animation, still at small sizes and moving when you point at it; the mark stays as a tiny badge so
colour and shape still identify the agent." This amends decision 108 (lists showed the mark).

## Done when (from docs/PLAN.md 10.8)
- Every `AgentGlyph` use (47 call sites: sizes `xs`, `sm`, `md`, `lg`) shows the portrait for an agent whose
  `style.pack` is set, and exactly today's mark otherwise. Do it **inside `AgentGlyph`** (or a component it renders), not
  by editing call sites; `bare`, `decorative`, `describeShape`/aria-label, `contrast='high'` and the glyph plate keep
  working.
- **Portrait**: the first frame of the pack's `idle` file, cropped to a square around the head — horizontally centred,
  top of the square at the top of the character's non-transparent pixels (scan the alpha of the decoded frame; fall back
  to the top 45% when the scan finds nothing), side = 45% of the frame height — drawn in a circle.
- **Identity** (AGENTS.md: color + shape, never color alone): `sm`/`md`/`lg`: the round portrait with a 2px ring in the
  agent's colour and the agent's mark as a badge at the bottom right (about 40% of the size, on a card-colour plate).
  `xs` (too small for a badge): the portrait clipped to the agent's **shape silhouette** with an outline in its colour.
- **Motion**: still by default; on pointer enter (and keyboard focus of an interactive parent) the circle plays the
  `idle` animation cropped the same way; back to still on leave. Under Settings › Look › Agents = Still, or
  `prefers-reduced-motion`, it never animates. No mood moves for portraits (the marks' moods stay for agents without a
  pack).
- **Cost**: the idle file is fetched once (it's an immutable URL) and decoded **once per page** into a small portrait
  (e.g. a 128 px canvas → object URL) shared by every glyph of that agent through a module cache keyed by agent id +
  pack rev; hover animation uses the cached file. Lists of 50 glyphs must not decode 50 times (test it).
- **Failure**: while loading or if decoding fails, show the mark (never a broken image).
- **Theme protection**: the portrait, ring and badge are part of the protected glyph surface — extend the guard's glyph
  checks and `protected.css` the way the cut-out mark is covered (see `apps/web/src/themes/guard.ts`,
  `protected-surfaces.ts`, `protected.css`, and their tests); a theme can't hide, recolour or replace them.

## Tests (failing first)
Unit: pack agent → portrait (canvas/object URL mocked), no pack → mark unchanged (existing AgentGlyph tests keep
passing), xs → shape-clipped with colour outline, badge present at sm+, decode once for many glyphs, failure → mark,
Still/reduced motion → no animated img on hover, guard/protected tests. E2E: upload a generated pack for a helper agent,
then see its portrait in the side list, a chat message and the Now page; hover animates; remove the pack → marks back.
Visual baselines: the seeded agents have no packs, so none should change; if any does, report it.
