# 9.1 Theme storage, API, import/export (PLAN 9.1; design docs/briefs/9-themes.md §1, §4.4, §5, §10; decision 90)

Goal: Score stores themes and serves them; theme packages import and export as zips; the server rejects anything unsafe.

Binding: API-CONTRACT § 16 and `packages/contract/src/themes.ts` (written by the lead; do not change their shapes — if
something is wrong or missing, report it). Add the stream event `look.changed { activeTheme, mode }` to
`packages/contract/src/stream.ts` (+ fixtures) and the contract doc's event list.

Work:
1. Migration **0071** `themes(id PK, name, version, manifest_json, css, source, created_at, updated_at)`; settings rows
   `look.activeTheme` (default `score`) and `look.mode` (default `system`). Built-ins (`score`, `paper`, `night`, `dense`)
   are not rows: the server lists them from a constant (`source: 'builtin'`, empty CSS, minimal manifests — 9.2 owns
   their real look, which lives in the web app).
2. Routes in `apps/server/src/http/themes.ts` exactly per § 16 (paired-only like other owner routes; mutations need the
   usual web-client header/origin checks). `etag` = hash of manifest + css. Assets on disk under
   `$SCORE_HOME/themes/<id>/assets/{fonts,img}/` (dirs 0700, files 0600), written atomically; delete removes the folder.
3. **Import** (`POST /api/themes/import`, multipart): reuse the Knowledge zip guards (find them in
   `apps/server/src/knowledge/documents.ts` / `http/knowledge.ts`): ≤ 5 MB upload, ≤ 20 MB uncompressed, ≤ 41 entries,
   no absolute/`..`/backslash paths, no symlinks, no nested archives, no other top-level files than `theme.json`,
   `style.css`, `assets/fonts/*`, `assets/img/*`. Magic-byte checks: woff2 `wOF2`, png, jpeg, webp (`RIFF….WEBP`), avif
   (`ftypavif`). `theme.json` via `ThemeManifestSchema` (a `format` > 1 ⇒ reason "made for a newer Score"); its `id` must
   not be a built-in; every `asset:` it or the CSS references must exist in the zip.
4. **Server CSS checks** (design § 5 import flow): unescape CSS escapes (`\XX…` hex with optional space, `\` + char),
   strip comments, then **reject** (never edit) if it contains `@import`, `url(` whose argument isn't `asset:…`,
   `content` as a property, `!important`, `position` `fixed`/`sticky`, `expression(`, `behavior`, `-moz-binding`,
   `javascript:`; also reject CSS > 256 KB. Same checks on `PUT`. Serving `style.css` rewrites `url(asset:x)` to
   `url(/api/themes/<id>/assets/x)`.
5. `PUT /api/look` + `look.changed` event; `GET /api/themes` includes `active` and `mode`.
6. Host escape hatch: `scripts/score look reset` sets `look.activeTheme=score`, `look.mode=system` (works with Score
   stopped: writes the setting the way other `scripts/score` commands do — look at how `scripts/score password` works).
7. Export: the same zip layout, deterministic order.

Tests (fail without the change): route tests with `inject()` for every status in § 16; an import test per rejection in
design § 10.4 and per CSS rule in item 4 (including escaped forms like `\63 ontent`, `u\72l(`, comments splitting
keywords `con/**/tent`); round trip import → export → import; assets served with exact type + `nosniff`; the reset
command. No e2e needed (no UI), but run the full `pnpm e2e` to prove nothing broke.

Not in scope: anything in `apps/web` (9.2 does the engine and UI).
