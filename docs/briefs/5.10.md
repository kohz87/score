## Task (from docs/PLAN.md)

## Design (from the lead)

Existing code: `apps/server/src/hermes/live/settings.ts` (`LiveSettings`: `listProviders`, `connectProvider`; the provider
catalog comes from the gateway's `GET /api/model/options` via `GatewayClient.modelOptions()`), `apps/server/src/http/settings.ts`,
`apps/web/src/routes/settings/{ProvidersSection,TerminalCommand}.tsx`, `settings-queries.ts`. Hermes source (read-only) is at
`~/.hermes/hermes-agent` (`hermes_cli/auth_commands.py` `auth_add_command`, `_OAuthAddSpec` table, `_add_api_key_credential`;
`hermes_cli/auth_codex.py` `_codex_device_code_login`; `auth_nous.py` `_nous_device_code_login`; `secret_prompt.py`).

1. **`signIn` per provider.** Gateway model options give `auth_type` per provider (`api_key`, …) — extend the gateway schema to
   keep it. Device-code providers = those whose Hermes login is a device-code flow printing a link + user code (read the source:
   at least `openai-codex`, `nous`; check `xai-oauth`, `minimax-oauth`, `qwen-oauth`); PKCE/localhost-callback flows (e.g.
   `openrouter` OAuth, `anthropic` OAuth) are `terminal`, but if a provider also takes an API key, offer `api_key`. Keep the
   mapping in one table with a comment citing the Hermes file. Fake adapter: one provider of each kind.
2. **Device-code sign-in** (`POST …/connect` for a `device_code` provider): spawn `hermes auth add <id> --type oauth --no-browser`
   via the existing runner/CLI module (argv array, add the shape to the CLI allowlist), `detached: true` (new session, no
   controlling terminal), stdin `ignore`, environment as the runner already builds it. Parse stdout with ANSI stripped for the first
   `https://` URL and the code (bounded buffer, e.g. 16 KB; give up with `failed` if not found within 30 s). Keep sign-ins in an
   in-memory map (`SignInManager` in `hermes/live/`), id = random; one per provider (a second connect returns the waiting one);
   on exit code 0 re-read `auth list` and mark `connected` only if the provider shows connected, else `failed` with a short
   generic message (never raw output); 15-minute expiry kills the child by handle; `DELETE` cancels (kill by handle, never by
   name/pattern); kill all children on server close. Never log or store the process output beyond the parsed link and code.
3. **API key** (`POST /api/settings/providers/:id/key`, human guard + idempotency): only for providers with `signIn: 'api_key'`
   (404/409 otherwise). Transport rule: allowed on loopback and TLS; plain-HTTP remote (`config.remote` without `tlsCert`; see
   `profileManagementAllowed` in `http/profiles.ts`) needs `acknowledgeInsecure: true`, else `400 insecure_transport`.
   Spawn `hermes auth add <id> --type api-key --label <label or "score-<date>">` detached (no controlling terminal, so getpass
   reads stdin), write `apiKey + "\n"` to stdin and end it; the key must never be in argv or env. Timeout 30 s. Then re-read
   `auth list`; return the provider item, or `409 not_verified`.
   **No trace of the key anywhere:** (a) the idempotency receipt for this route must not store an unsalted hash of the body —
   add an option to `requestIdempotency` to hash with HMAC under a random per-process secret (or hash only route + key) for
   secret-bearing routes; (b) zod errors for the body must not echo the input (check the error handler; return a generic
   `bad_request`); (c) Fastify must not log the body (confirm; add a test that a request with a sentinel key leaves no sentinel
   in captured logs, the DB file, or any response); (d) the runner must not capture/log stdin; (e) stderr/stdout of this
   process is never returned or logged.
4. **Web** (`ProvidersSection`): Connect on a `device_code` provider shows a panel with the link (opens in a new tab,
   `rel="noopener noreferrer"`), the code with Copy (use `data/clipboard.ts` `copyText`), "Waiting for you to approve…", polls
   `GET /api/settings/sign-ins/:id` every 2 s (background too) until a terminal state, then shows Connected and refreshes the
   providers query; Cancel calls DELETE. On an `api_key` provider: a form with a password input (`autocomplete="off"`,
   `spellcheck=false`), optional label, Save; on plain HTTP (`location.protocol === 'http:'` and host not loopback) show a
   warning and a required "I understand the key crosses my network unencrypted" checkbox that sets `acknowledgeInsecure`.
   Clear the key from state on success, failure and unmount. Every panel keeps "Use a terminal instead" → the existing
   `TerminalCommand`. Ids via `data/ids.ts` `newId` (never `crypto.randomUUID`).
5. **Live check (allowed: test profile only):** with a dev server against the live Hermes, run the device flow for
   `openai-codex` on `scoretesta`, confirm link + code appear, then cancel (do not approve). Add a dummy key
   (`sk-score-test-not-real-0000`) to a key provider on `scoretesta`, confirm it appears in `hermes -p scoretesta auth list`,
   then remove it with `hermes -p scoretesta auth remove <provider> <label>`. Never touch the `default` profile. Report the
   exact commands and outputs (redact codes).

The provider routes act on the profile Score treats as default for settings today (`LiveSettings` runs without `-p`); keep that,
but add a `profile` parameter internally so the live check can target `scoretesta` (e.g. env `SCORE_SETTINGS_PROFILE` read
only in tests/dev — say what you chose).
