# Brief 5.17a-1 stage 2a: Kanban attempts — contract and server consumers

**Design:** `docs/briefs/5.17.md` (v5 §F, §H, v5.1 #4–#6, v4 §5–§6) and the stage 1 code already on main
(`apps/server/src/domain/kanban-attempts.ts`, `apps/server/src/hermes/live/kanban-attempts/`). Stage 1 report and open
questions: `docs/TASKLOG.md` (5.17a-1 entries). Where this brief and the design disagree, ask; don't guess.

## Scope (server + contract only; the web pages are stage 2b)
1. **Contract** (`docs/API-CONTRACT.md` and `packages/contract` together):
   - `AttemptSummary` exactly as in v4 §5, plus `observationEndedAt`, `evidence: 'proven'|'partial'`, `order:
     [startedAt, upstreamAttemptId]`, `refusedUpdates: number`, and a qualified `task: TaskRef`.
   - `TaskRef { taskId; historyId; current: boolean }`.
   - `WorkItem = { kind: 'run'; run: RunSummary } | { kind: 'attempt'; attempt: AttemptSummary }`.
   - Stream event `attempt.updated` (data: `AttemptSummary`).
   - Now: `checks[].verdict: 'passed'|'changes_requested'|'unknown'` replaces `ok`. Lane blocks gain
     `observationEndedAt`, `provenance` and `order`. Handoffs may have a null agent endpoint (the Unattributed lane).
   - Flow: `tools: string[] | null`; attempt cost is `unknown`.
   - Reports: an `unattributed` bucket for counts and working time (session spend unchanged).
   - `TaskDetail.unresolvedRunLinks`.
   - Attempt detail: `GET /api/attempts/:id` returns `AttemptSummary` plus the frozen `taskSnapshot`.
2. **Server:**
   - The writer emits `attempt.updated`.
   - Now, Flow, Reports (including trend and CSV), Team history and notifications read attempts through
     `listAttempts`, behind `SCORE_KANBAN_ATTEMPTS`. With the flag off, every response is exactly as today.
   - Stop on a Kanban attempt is rejected before any profile lookup (the existing 501).
3. **Qualified ownership** (v5 §F):
   - `history_id` on task projections, `brief_tasks`, `task_rooms`, review edges, holds and Kanban denials.
   - Conservative upgrade: assign only to the current history when the task exists and there is no contradiction; otherwise inert.
   - Inert rows are displayed but never routed, parked or released. Pause release skips them and reports them (v5.1 #6).
   - Unqualified denials never authorize task actions.
4. **Legacy links:**
   - Resolve `kanban_upgrade_links` into `TaskDetail` (mapped ids or `unresolvedRunLinks`).
   - Rewrite stored idempotency receipts that reference old ids, without deleting the receipt (v5 §E).

Migration if needed: **0039**. Keep the flag default **off**. The lead turns it on after a live check.

## Done when
- Contract fixtures for every new or changed schema.
- Server tests for each consumer with the flag on and off (off must equal today's responses byte for byte).
- Ownership upgrade fixtures: a task present, a task missing, a contradiction, inert hold release.
- A receipt rewrite test proving the mutation can't run again.
- Stop rejection.
- `pnpm check` green.
