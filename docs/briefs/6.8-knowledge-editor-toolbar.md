# 6.8 Knowledge editor: one live editor, toolbar, tables and embedded images (owner request 2026-10-11)

Owner: "for knowledge md, can we not use preview? since it's actual output vs edit; for edit, can we have those editor line
that let you insert image (as binary codes so it will be retained without upload file, but edit shows image, not the
underlying) and tables etc?"

## 1. One mode
- A note opens directly in the 6.5 live-preview editor (formatted everywhere, raw Markdown only on the active line/block).
  Remove the Preview / Edit / Split switch; add a small **Source** toggle (plain Markdown, same CodeMirror, no decorations)
  for power users. Read-only cases (history versions, agent-locked, outside-change conflict) render in the same editor in
  read-only mode. Keep everything 6.5 had (wiki links, checkboxes, callouts, frontmatter properties panel, autosave/etag,
  conflict handling, keyboard shortcuts). Phone: same, toolbar scrolls horizontally.

## 2. Toolbar (sticky above the editor)
Headings (H1–H3 menu), bold, italic, strikethrough, inline code, bullet / numbered / checkbox list, quote, link (dialog;
`[[` for wiki links), code block (language), callout (type menu), horizontal rule, **table**, **image**, undo/redo. Buttons
toggle formatting on the selection (and show active state); each has a tooltip with its shortcut and an accessible name.

## 3. Tables
- Insert: a size grid picker (up to 8×8) inserts a GFM table with a header row.
- In the editor the table renders as a table widget (6.5 already renders tables when the cursor is outside); add editing
  controls when the cursor is inside or the table is focused: add/remove row and column, move column, alignment per column.
  Cell text stays editable as Markdown; Tab / Shift+Tab move between cells; the Markdown stays canonical GFM (pipes
  escaped).

## 4. Embedded images (inside the note, no upload)
- Image button, paste, or drag-and-drop an image onto the editor → decoded and **downscaled in the browser** (longest side
  1600 px, keep aspect; PNG kept for transparency/small images, else JPEG/WebP quality 0.85) → inserted as
  `![alt](data:image/<type>;base64,…)` with alt defaulting to the file name.
- The editor **always** shows the image (a widget replacing the whole data URI, also on the active line); the base64
  never appears, except in Source mode where it is collapsed to a short chip ("data:image/png · 240 KB", click to
  expand). Image widget: alt text editable, resize width presets (25/50/100 %, stored as `{width=50%}`-free plain
  Markdown: keep it plain `![alt](…)`; width only in Source if needed — no non-standard syntax unless already in 6.5).
- Allowed: `image/png`, `image/jpeg`, `image/gif`, `image/webp`. **No SVG.** ≤ 1.5 MB per image after downscale; a note
  ≤ 8 MiB in total (raise the 2 MiB note limit for notes; server validates both and the data-URI MIME/magic bytes).
- **Agents and search:** `knowledge.read` (plugin + MCP + bridge) returns notes with each data-URI image replaced by
  `[image: <alt>, <size>]`; FTS indexing skips data URIs; snippets never show base64. `knowledge.write` from agents may
  not add data-URI images (refused with a clear message) — keeps agent writes small.
- Export (6.7) keeps the note bytes exactly (images stay inside the .md).
- CSP: allow `img-src data:` only for these MIME types if the current CSP blocks it; never `script`/`object` data URIs.
