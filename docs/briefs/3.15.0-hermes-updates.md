## Behaviour (done when)
1. **Where:** a **Hermes updates** card at the top of Settings › System (`apps/web/src/bold/BoldSystem.tsx`). When
   `GET /api/system/hermes-update` says `available: false`, the card says updating Hermes isn't available here.
2. **The card:** the version (`status.version`), an **Update channel** select (`stable` "Stable releases" / `main` "Every
   change (main)"; default `main`, remembered per browser in localStorage, wrapped in try/catch), Score's check state from
   `GET /api/system` (`compatibility.tested` → "Tested", else "Approvals paused"), **Check for updates** →
   `POST …/check { channel }` showing `summary`, "Restarts: …" from `restarts`, and **Update Hermes…** when `available`.
3. **Update dialog** (inline light card as in the mock-up, `data-protected`): the four steps in words, the backup line from
   `backupNeedsBytes` / `diskFreeBytes` ("about 2.9 GB; 12.0 GB free"; refused by the server with `409 disk_full` → show its
   message), **Test with** select listing the **Hermes** agents only (`GET /api/agents`, exclude coding agents: see how other
   bold screens tell them apart) with each one's model, plus "No test message (checks only)" (→ `testAgentId: null`),
   **Security password** (required), **Back up and update** → `POST …/start { channel, testAgentId, password }`; the password
   leaves state as soon as the request is sent. Errors: `wrong_password`, `too_many_attempts`, `password_not_set` (link to
   Settings › Remote access and security), `update_running`, `disk_full`, in words.
4. **Progress:** while `job.state === 'running'`, poll `GET /api/system/hermes-update` every 2 s (stop when finished or the
   page is left) and show the four steps (`wait`, `update`, `check`, `test`) with their state and `note`, as in the mock-up:
   "Waiting for agents to finish", "Backing up and updating Hermes", "Checking the new version", "Test message to <agent>"
   (`skipped` shows "No test message"). A **Hermes's output** `<details>` shows `job.log` (monospace, scrollable).
5. **Results** (`job.outcome`):
   - `clear`: "Hermes <toVersion> works with Score. Approvals are on." (ok colour).
   - `differs`: the table of parts that are not `same` from `job.check.parts` (name, status, detail), the test result, and
     **Turn approvals on anyway** = the existing override: `POST /api/settings/hermes/accept { hash: job.check.hash,
     override: true, password }` with a password field (it needs the password again), plus **Stay paused**. On success
     refetch `/api/system`.
   - `broken`: what failed (`job.test.detail` or the check), "Approvals stay paused", the backup (`job.backup`, Hermes's
     backups folder) and **how to go back**, as copyable commands: `hermes update --channel stable` and
     `hermes import ~/.hermes/backups/<job.backup> --force`. **No "Restore the backup" button** (Score never changes
     Hermes's code itself; report this mock-up difference).
   - `failed`: `job.error`, with the output open.
   A finished job stays shown until the next check; the card returns to normal after.
6. **Connections:** the existing "Hermes was updated" banner (`routes/settings/HermesVersionBanner.tsx`) gains a link
   "Update Hermes from Settings › System" to the new card (keep the banner's own check and override as they are).
7. **Retention:** the mock-up's "backup kept 7 days" is not built (Hermes keeps its own backups by count,
   `updates.backup_keep`); say "Hermes keeps its last backups" instead and report the difference.
8. Protected: the update dialog, the progress and the results that ask for a decision carry `data-protected` and join the
   protected list (`styles/protected.css` + its test, `themes/protected-surfaces.ts`), per AGENTS.md.
9. Phone layout as `Phone.dc.html` (stacked, full-width buttons, ≥ 44 px targets).
