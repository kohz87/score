# 5.35 Chat versions like ChatGPT / Open WebUI (owner request 2026-10-10)

Owner: "can the chat versioning be like open webui or chatgpt, an arrow to toggle before past and later iteration?
otherwise there's a lot of Previous Version rows."

Today (5.33): each rewind (edit, delete) is its own `RoomVersion`; the thread shows a separate "Version 2 of 2 ‹ ›" row per
edit and a "Previous version" block for each delete (apps/web/src/routes/chat/versions.tsx, MessageItem.tsx, ChatPage).

## Behaviour
- **Edits:** all edits of one message form one chain. The current message shows a compact `‹ 2 / 3 ›` control in its own
  action row (bottom of the bubble, beside the other message actions) — no separate rows above it. Switching to an
  older version swaps that message **and everything after it** (the branch that followed) in place, read-only, with a
  slim "Viewing version 1 of 3 — read-only · Back to latest" bar; the composer stays for the latest branch only. Arrow
  keys work when the control has focus; screen readers hear "Version 1 of 3".
- **Regenerated agent replies** (if Score offers regenerate/retry today — check; otherwise skip) get the same control.
- **Deletes:** deleted messages disappear from the thread; no inline rows. The room's menu gets "Show deleted messages"
  (off by default) which shows them dimmed in place, read-only, with their "deleted" note and the existing details.
- Nested cases (an edit inside a hidden branch) keep working: the older branch view shows its own switcher.
- Agents that couldn't be rewound: the existing note moves into the read-only bar for that version.

## Constraints
Read-only older branches (no "continue from an older version": Hermes sessions were rewound). Contract additions only if
needed (e.g. a chain id on `RoomVersion`), additive, in API-CONTRACT + packages/contract together. Follow AGENTS.md;
no new dependencies.

## Done when
Web tests (chain grouping incl. nested, switching, deleted toggle, keyboard/aria), e2e update of chat-rewind specs,
visual baselines (desktop 1440 + 390) with an edited message showing `‹ 2 / 3 ›` — viewed by eye; `pnpm check` and
`pnpm e2e` green.
