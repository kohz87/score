# 7.7b Coding agents as orchestration workers (design v2, for re-review)

Stage 2 of PLAN 7.7 (decision 65). Stage 1 (7.7a, v1.1.0) made every coding turn a supervised systemd unit with a
journaled launch, a release barrier, receipts and an eligibility verdict. This stage lets the orchestration executor
give **worker** steps to Claude Code and Codex agents. Workflows are stage 3 (7.7c).
v1 was blocked (`docs/reviews/2026-10-13-7.7b-design-review.md`, 10 P1, 7 P2, 1 P3); [R n] marks the finding each rule
answers. Overall rules come from `docs/briefs/7.7-coding-workers.md` (v2).

## 0. What exists (corrected) [R 18, 7, 8]
- **7.7a:** `CodingRuntime.startRun({agentId, input, turnId, sessionId?, model?})`; the launch id is minted inside the
  unit backend; the journal folds `requested → armed → releasing → released-seen → ended → settled` with permanent
  tombstones and a folded `mayHaveExecuted`; `release(launchId, stillAuthorised)` returns `not_authorised` **without**
  writing a revoke (the revoke is a separate step); `turnWitnessed(turnId)` is true for any journaled launch of the
  turn, revoked ones included. Chat's qualified resume fallback may launch **twice** per turn. A success still pending
  at restart is downgraded to `interrupted` (its reply is not kept; enforced by a test).
- **Executor:** one `turn_id` per **logical attempt** (not per generation); `beginSend` journals `send_started` for
  generation g; `recordRefusal` keeps the old run/turn linkage and counts consecutive/lifetime refusals; `isEvidence`
  excludes only `recovered`/`unconfirmed`; evidence on an `unknown` attempt is consumed normally (only `abandoned`
  attempts get the non-consumable late-result path); owed Stops are delivered sequentially inside the pump, and a
  Hermes `void` counts as acknowledged; while frozen no Stop is sent at all; `recordRunResult` serves workflows only;
  orchestration results are the 8 KiB run output; `assertHermesOnly` guards orchestrations **and** workflows.

## 1. Scope [R 16]
- Workers: **Claude Code and Codex**, permission `read-only` or `workspace-write`; never `full`. Lead stays Hermes.
- **Antigravity is not a worker** (v2 finding 17: scheduling and subagents that may outlive its run; not shown to be
  contained by the unit). Revisit separately.
- **Only on unit hosts** (`backend().kind === 'unit'`, not paused). Process-group hosts refuse coding workers at
  create (`422 coding_workers_need_units`).
- **Orchestrations only.** Workflows keep `assertHermesOnly` and its tests until 7.7c; the new guard
  `assertOrchestrationWorkers(ids, team)` is used only by orchestration create/plan/remap.

## 2. One port, routing by run [R 15]
`start-server.ts` builds the composite port once and passes the same object to the executor and `buildApp`. Controls
(Stop, result reads) for a run route by the run's **recorded runtime** (`runs.origin`/launch row), not by whether the
agent still exists. A coding agent **can't be removed** while any of its runs is unresolved (launch not `settled`,
`unconfirmed`, held group) — `409 agent_busy`, as for an active run today.

## 3. Owned invocation: built from the frozen policy [R 2, 11]
- At **preflight** Score computes, per allowed coding worker, a **worker policy**: runtime, CLI executable identity
  (realpath, dev/ino, size, mtime, version), permission, workspace identity (realpath, dev/ino), the driver's effective
  reach in plain words, and the **owned invocation template** (argv minus prompt, environment allow-list). Its
  canonical JSON hash is the **policy id**. Preflight returns `{ policyId, reach }` per worker.
- **Ambient configuration is neutralised** for owned invocations: Claude Code runs with `--setting-sources` limited to
  the settings Score passes (`--settings <score file>`), `--strict-mcp-config` and no `--mcp-config`; Codex with
  `--strict-config` and `-c` overrides for every reach-relevant key (sandbox, approval policy, MCP servers, shell
  environment policy). A driver that can't neutralise a reach-relevant source reports `reach_unverifiable` ⇒ the
  worker isn't ready. The builder verifies the flags on the installed CLIs with recorded fixtures.
- `POST /api/orchestrations` must carry the `policyId` the person saw for each coding worker (`409 policy_changed`
  otherwise); it is stored with the orchestration and journaled with the admission.
- **At release** the runtime builds the actual invocation **from the stored policy** (never from the live agent row),
  re-reads executable and workspace identity, and authorises only if the recomputed hash equals the policy id. Any
  difference ⇒ "agent changed" (§6 classes) ⇒ remap/re-approval, which now accepts a new policy id (remap and
  re-approval carry the policy id the person viewed; an unchanged incarnation with a new policy id is allowed).

## 4. Consent [v2 §3, R 11]
The start dialog lists each coding worker's reach in plain words and the risk, and asks for one acknowledgement that
accepts it; the server requires `acknowledgeCodingReach: { policyIds: [...] }` covering every worker whose reach goes
beyond its workspace. Stored in the run history. 7.5's acknowledgement stays.

## 5. Identities per generation [R 3]
- Each dispatch generation g of an attempt has its own **coding turn id** `"<attempt turn_id>:g<g>"` and its own
  **launch id**, both minted by the executor in `beginSend`'s transaction and journaled with `send_started` (so a
  restore can't forget them). `startRun` accepts `owner: { kind: 'orchestration'; orchestrationId; attemptId;
  generation; launchId; policyId; maxTurnMs; authorise }`; the backend uses that launch id instead of minting one.
- `beginSend` returns the **committed** attempt row (generation g). The run handle is linked to `(attempt, g)`; a new
  generation replaces the linkage; a handle for an older generation is never accepted (`recordHandle` checks g).
- One launch per generation: the resume fallback and any second launch are disabled for owned turns.

## 6. Release, authorisation and transactions [R 1, 4, 5, 12]
- **Transaction ownership.** `release` is never called inside a database transaction (asserted:
  `db.sqlite.isTransaction` ⇒ throw). Inside `journal.critical`, in this order: (1) `authorise()` runs in **its own**
  read transaction; (2) on yes the journal records `releasing`; (3) the projection commits in its own transaction;
  (4) only after that commit is `go` written to the supervisor. On no: the journal writes the **revoke tombstone** in the
  same critical section before returning. No `go` before the owning commit; no DB transaction spans a journal append.
- **`authorise()` = the executor's full admission predicate**, extracted as one pure function used by `beginSend` and
  release: attempt still `send_started` for generation g, not retired, no owed Stop, orchestration not
  stopping/finishing/paused/fenced/frozen, no agent or team hold, inputs not withdrawn, run deadline not passed, fresh
  spend and budget, policy id matches (§3), coding limits allow (§8). It never writes and never awaits.
- **Proof of no execution** is only the durable revoke tombstone of that launch (folded `mayHaveExecuted = false`).
  Anything else — a projection failure, an exception, `releasing` without an outcome — is **uncertain** ⇒ attempt
  `unknown` (never `send_refused`).
- **Classes of "no"** (each with its own accounting):
  | cause | attempt | counters |
  |---|---|---|
  | paused / frozen / hold / deadline not yet decided | stays queued for the next admission (new generation) | none |
  | Stop / cancel / retired / owed Stop | `cancelled`, proven never executed | none |
  | policy changed | blocked "agent changed" ⇒ remap | none |
  | readiness (CLI missing/untested, paused engine, needs units) | `send_refused` | refusal counters (7.1) |
  | budget / coding limit exhausted | blocked "limit reached" (person raises it or stops) | none |

## 7. Evidence, late proof and results [R 7, 8, 10]
- Three separate facts per coding run: **end proof** (monotonic: none → proven), **disposition**
  (`completed | failed | cancelled | interrupted`), **result eligibility** (only 7.7a's eligible reply, only for the
  generation that is current when the proof arrives).
- An attempt is `running` → on proof + disposition: `completed`+eligible ⇒ result accepted; `failed`/`interrupted` ⇒ a
  failed try (retry policy); `cancelled` ⇒ obligations closed, no result, not retried. No proof ⇒ `unknown`,
  obligations kept, agent fenced.
- **Late proof** for an `unknown` (or `abandoned`) coding attempt closes obligations and settles accounting but its
  result is **permanently non-consumable** (a coding-specific path; the generic "evidence on unknown is consumed" path
  is not used for coding runs). 7.7a's unit reaping publishes executor reconciliation evidence when it records proof.
- **Restart keeps 7.7a's rule:** a success pending at restart is `interrupted` (its reply is not kept) ⇒ a failed try,
  "Score restarted before the answer was saved". No durable result envelope in this stage.
- **Result storage:** new `orc_attempts.result_text` (and `result_truncated`) written in the same transaction as the
  terminal state, sourced only from the eligible reply, before any display cut or Score annotation. Limit 64 KiB;
  longer ⇒ stored cut at a character boundary with `result_truncated = 1` and the lead is told it was cut. The executor
  feeds the lead `result_text`, never the 8 KiB run output, for coding workers.

## 8. Coding limits and spend [R 6, 13]
- Limits set at start and journaled with the admission: `codingSteps` (default 10), `codingMinutes` (default 60).
- **Allocation in `beginSend`'s transaction**, keyed by the pre-minted launch id: one step and a reservation of
  `min(remaining minutes, 30, minutes to the run deadline)`, journaled in the `send_started` record. The reservation is
  the turn's `maxTurnMs`.
- **Refund only with proof of no execution** (the revoke tombstone): the step and reservation are returned.
- **Settlement** at the verdict: measured wall time from the unit's receipts (start/end monotonic stamps in
  `released.json`/`ended.json`), journaled in a `coding-settled` record. No measured end (supervisor death, unproven
  end) ⇒ the full reservation stays charged.
- A restored database rebuilds allocations, refunds and settlements from the journal records (no double charge).
- **Unknown cost** keeps provenance per source (`hermes`, `claude-code`, `codex`). The person may accept unknown cost
  per source at start (journaled); an unaccepted source with unknown cost pauses the run **when a dollar budget is
  set** (today's rule); without a budget nothing pauses (coding limits still apply). Claude Code's cost is `estimated`.

## 9. Stop and deadline [R 9, 14]
- Owed Stops become **tracked asynchronous jobs** (one per attempt, retried with backoff); the pump never awaits them;
  shutdown drains them with the existing barrier. Acknowledgement: coding ⇒ only `stopped`/`not_running`; Hermes keeps
  today's `void` = acknowledged.
- **Decision 74 extends to executor-owned runs:** while frozen, an owed Stop for a coding run **this process launched**
  and is connected to is delivered; Stops for recovered/inherited runs still wait.
- The turn's `maxTurnMs` is at most the time to the run deadline (§8); if the deadline is moved earlier, the executor
  owes a Stop for running coding attempts past it.

## 10. Restart matrix
| journal state of generation g | executor outcome |
|---|---|
| no launch record | proven no-dispatch for g (the allocation is refunded) |
| revoke tombstone | as §6 class of the recorded cause |
| `releasing`/released, verdict proven `completed` but not yet delivered | `interrupted` ⇒ failed try (7.7a rule) |
| released, proven end with failure/stop | failed try / `cancelled` |
| released, end unproven | `unknown`, agent fenced; late proof per §7 |
| frozen home | nothing until `reset-history` |

## 11. Storage [R 17]
Inventory and charge every retained copy: `result_text`, policy snapshots, refusal and accounting records, coding
launches and pending terminals. Pruning removes them atomically with their attempt rows, keeping the journal tombstones.
The coding translator charges executor-owned observations through `chargeObservation` and drops ordinary ones when the
allowance is exhausted, keeping Stop and obligation evidence.

## 12. UI
CLI badge for coding workers in the Flow diagram, logs and agent list; live status lines as in Chat; preflight readiness
(`ready | not_installed | version_untested | level_unverified | reach_unverifiable | changed | paused | frozen |
needs_units`); the start dialog adds reach acknowledgement (by policy id), unknown-cost acceptance per source and coding
limits; "agent changed" and "limit reached" blocks offer remap or raising the limit.
