## Design (from the lead; follow it)
Package `hermes-plugin/score_bridge/`:
- `plugin.yaml`: `name: score-bridge`, version `0.1.0`, description, and the `hooks:` list: `pre_tool_call`,
  `post_tool_call`, `pre_approval_request`, `post_approval_response`, `on_session_start`, `on_session_end`,
  `on_interim_message`, `subagent_start`, `subagent_stop`, `on_human_input_request`, `on_human_input_resolved`,
  `on_kanban_worker_spawned`, `on_kanban_worker_exited`, `on_kanban_task_updated`.
- `__init__.py`: `register(ctx)` registers one wrapper per hook. Each wrapper takes `(*args, **kwargs)`, builds an
  event and **enqueues** it (non-blocking `put_nowait` into a bounded queue of 10,000; when full, drop the oldest and
  count `dropped`), then returns `None`. It never raises: catch everything, record it in a bounded error ring, and
  carry on. No network I/O on the hook thread.
- `hermes_private.py`: the **only** place that imports Hermes internals. Each lookup is wrapped in `try` and recorded
  in an availability map: `agent.redact.redact_sensitive_text`, `tools.approval.list_gateway_approvals`,
  `tools.approval.register_gateway_settle`, `tools.approval.resolve_gateway_approval`,
  `tools.approval.approve_permanent`, `tools.approval_detection.detect_dangerous_command`, plus the plugin isolation
  mode (`hermes_cli.plugin_isolation`, falling back to `"unknown"`). Expose `available() -> dict[str, bool]`,
  `redact(text) -> str` (calls `redact_sensitive_text(text, force=True)`; if unavailable, fall back to the local
  `redact.py`), and `isolation_mode() -> 'in_process' | 'host' | 'unknown'`. Decisions and grants (1.13b/c) will add
  functions here later; don't use them yet.
- `redact.py`: `scrub(value, redact_fn)` walks dicts, lists and strings recursively and applies redaction **before**
  truncation (strings ≤ 4,096 chars; `result` fields ≤ 16,384), plus a local fallback regex set matching the server's
  (`sk-…`, bearer tokens, `ghp_…`, AWS keys, private-key blocks, `password=`/`token=`/`api_key=`). Also
  `digest(raw: str) -> str` (sha256 hex) for **correlation on raw text**: `command_digest` is computed from the raw
  terminal command **before** redaction, and only the digest leaves the process (D6).
- `client.py`: `ScoreClient(base_url, token_path, transport)`:
  - Base URL from env `SCORE_URL` (default `http://127.0.0.1:8740`). The bootstrap token is read from
    `~/.score/bridge.token` (the Score server will create it in 1.14); a missing file means "Score not set up", so the
    plugin stays idle and keeps spooling.
  - `hello()`: `POST /bridge/v1/hello` with the bootstrap token (§11 request: `profile` from `HERMES_PROFILE` or the
    profile home name, `pid`, `incarnation` = a random hex per process, `kanbanTaskId` = `HERMES_KANBAN_TASK` or null,
    `isolation`, `pluginVersion`, `hermes` version/sha if available, `privateApis` = the availability map). It stores
    the producer token and its expiry, and re-hellos on 401 or within 60 s of expiry.
  - `send(events)`: `POST /bridge/v1/events` with the producer token; returns `ackedThrough`.
  - The transport is injectable (tests use a fake; production uses `urllib.request` with 3 s timeouts).
- `sender.py`: one daemon thread per process. Every 250 ms (or at 100 queued events) it builds a batch (≤ 200
  events): `counter` strictly increasing per incarnation, `hook`, `at` (ISO UTC), `sessionKey`/`sessionId`/
  `toolCallId` lifted from the payload when present, `payload` = scrubbed kwargs. Non-JSON values become `repr()`
  truncated to 300 chars. Before sending new events, it **drains the spool first** (oldest first), so order is
  preserved.
- `spool.py`: when sending fails (connection refused, timeout, 5xx), append the batch as one JSON line to
  `~/.score/spool/<incarnation>.jsonl` (create the directory 0700, files 0600). Cap 5 MB per file and 50 MB for the
  directory; when over the cap, drop the oldest lines and record a `dropped` range `{from_counter, to_counter}` that
  is sent later as a synthetic `bridge.gap` event. Drain in order on reconnect, then delete fully sent files. The spool
  directory is overridable for tests.
- Shutdown: `atexit` handler flushes with a 2 s budget; anything left goes to the spool.

## Done when (pytest, offline)
1. **Hooks never block or raise**: a wrapper returns in < 1 ms with a transport that sleeps 5 s; a payload that makes
   `json.dumps` and `repr` throw is still handled; 10,001 events with a stalled sender → `dropped == 1`.
2. **Batching and ordering**: counters strictly increase; batches ≤ 200; the spool drains before new events.
3. **Score down**: events go to the spool; when Score comes back, they're sent in order; caps enforced with a

6. **Isolation**: in `host` isolation mode, `hello` reports `isolation: 'host'`.
7. `uv run --offline pytest -q` passes, and `python -m compileall score_bridge` is clean.

## ARCHITECTURE D2.1 / D2.4 / D6 / D7
**D2.1 Two explicit boundaries.** (1) `apps/server/src/hermes/` for Node. Lint (`no-restricted-imports`) blocks
imports of its internals, and a test asserts that no other server module mentions Hermes paths, URLs, CLI verbs
or upstream event names. (2) The Python bridge `hermes-plugin/score_bridge/`. Every call into private Hermes
functions (`list_gateway_approvals`, `register_gateway_settle`, `resolve_gateway_approval`,
`approve_permanent`, the permanent-set discard, `detect_dangerous_command`, `redact_sensitive_text`) lives in
**`hermes_private.py`** and nowhere else. `HermesPort` has `live` and `fake` implementations.

**D2.4 Recovery per source.**
- **Run SSE**: resume with `Last-Event-ID`. On `replay.truncated` or a gateway restart, poll `GET /v1/runs/{id}`,
  reconcile tools and messages from `state.db`, and record a visible **gap interval** on the run.
  `run.queued`/`run.started` are **not** emitted by the Runs API, so lifecycle starts from Score's own dispatch
  record plus status polling.
- **Bridge**: a bounded on-disk **spool** per producer (`~/.score/spool/`, size-capped, oldest dropped, with a
  drop counter) when Score is unreachable. It drains on reconnect, and dropped ranges become gap intervals.
- **kanban.db**: tail `task_events` by `id` (append-only). Re-read `tasks` rows touched by new events.
- **state.db** (per profile): ingest new rows by `messages.id` > checkpoint, scoped to a DB incarnation
  (file identity + `state_meta`). Hermes inserts carried/cloned rows with **older timestamps** and orders by ID,
  so timestamps are never a cursor. Edits, `active`/`compacted` flips, rewinds and compaction create or change rows
  without new IDs, so a periodic **session reconciliation** compares logical identities (`message_uid`,
  `tool_call_uid`) for sessions active in the last N hours. Fixtures cover rewind, compaction, carried timestamps
  and restore.

### D6. Watch = event replay, not remote desktop
- Frames come from the bridge's `pre/post_tool_call` (terminal command + output tail, file path + unified diff from
  patch/write args, browser screenshots or artifact refs) and from interim/reasoning text. They are stored per
  session in `watch_frames` (64 KB per terminal chunk; images in `~/.score/media/` with a quota). Scrub = `seq` order.
- **Mandatory redaction (two layers).** Hermes hooks pass **raw** args and results (`model_tools.py:680`), and
  gateway approval text is redacted only if the user hasn't disabled redaction. So:
  1. the bridge runs `redact_sensitive_text(…, force=True)` on every command, argument and result **before
     truncation and before serialization**;
  2. the server runs its own secret-pattern pass before durable storage.

  Correlation uses digests computed in the plugin on raw text, never stored raw text. Fixtures include
  secret-bearing commands and outputs for every producer.
- "Take control" is **out of scope for v1**. v1 offers "Pause <agent>" and "Open in terminal" (copies the
  `hermes -p … --resume` command).

### D7. Security posture (single user, local first)
- **Network.** The server binds `127.0.0.1`.
- **Browser.** Mutations require `X-Score-Client` + same-origin (CSRF).
- **D7.1 Human decisions** (approval decisions, grants, rule changes, credential actions) additionally require a
  **paired browser session**. On first run the server prints a one-time pairing URL **to its own terminal**. The
  browser exchanges it for an HttpOnly, SameSite=Strict session cookie. The server stores only a hash, never in a
  file the bridge uses.
  - **Threat-model limit (owner decision 2026-10-06: accepted, option a):** agents run as the same OS user, so a determined agent with
    shell access could still read browser cookie stores or `~/.score`. Pairing stops casual or accidental
    self-approval and CSRF, not a hostile same-user process.
  - Real isolation means running agents in Hermes's sandboxed terminal backend (docker/ssh) or as a different
    OS user. Score shows the current isolation level on the Settings page.
- **Bridge identity.** The bootstrap secret `~/.score/bridge.token` only allows `POST /bridge/v1/hello`. Each
  producer then gets a short-lived **producer token** scoped to its profile, process incarnation and
  `HERMES_KANBAN_TASK`. It can post only its own events, receive only decisions targeted at its own approvals,
  and redeem only grants for its own task. Bridge tokens can't call `/api/*`.
- **Secrets.** Score never reads `~/.hermes/.env`, `auth.json` or key files. Payloads are redacted per D6.

## Contract §11
## 11. Internal: bridge plugin ↔ server (not for the front end)

Served under `/bridge/v1` on the same port. Bridge tokens can't call `/api/*`, and browser sessions can't call
`/bridge/*`.

**Handshake**
- `POST /bridge/v1/hello`, auth `Bearer <~/.score/bridge.token>` (bootstrap secret, allowed for this call only):
  ```ts
  req: { profile: string; pid: number; incarnation: string /* random per process */; kanbanTaskId: string | null
         isolation: 'in_process' | 'host'; pluginVersion: string; hermes: { version: string; codeSha: string }
         privateApis: Record<string, boolean> /* which hermes_private functions resolved */ }
  res: { producerToken: string; expiresAt: string; enabled: { gatewayApprovals: boolean; kanbanGrants: boolean; watch: boolean } }
  ```
  Every other call uses `Authorization: Bearer <producerToken>`. The token is scoped to profile, incarnation and
  `kanbanTaskId`, and is renewed by calling `hello` again.

**Events** (all redacted in-plugin with `force=True` before truncation)
- `POST /bridge/v1/events` `{ events: { counter: number; hook: string; at: string; sessionKey: string | null;
  sessionId: string | null; toolCallId: string | null; payload: object }[] }` → `{ ackedThrough: number }`.
  `(incarnation, counter)` is the ingest key; redelivery after a spool drain is harmless.

**Gateway approvals** (D4.2)
- The `pre_approval_request` event payload includes the exact `requestId` read via `list_gateway_approvals`
  (or `null` → the operation is not actionable) and a `commandDigest`. Settle callbacks arrive as
  `approval.settled` events with `{ requestId, reason }`.
- `GET /bridge/v1/decisions?wait=25` (long-poll; `wait` = integer seconds 0–30, default 25) → `{ items: { deliveryId; leaseUntil; sessionKey; requestId;
  choice: ApprovalChoice; reason: string | null }[] }`. Only decisions for approvals **this producer reported**
  are returned.
- `POST /bridge/v1/decisions/:deliveryId/ack` `{ outcome: 'applied' | 'not_pending' | 'failed'; resolved: number; error?: string }` → `204`

**Kanban grants** (D4.3)
- `POST /bridge/v1/grants/redeem` `{ taskId; taskRunId: number; commandDigest; toolCallId }` →
  `200 { grantId; patternKey }` or `404 no_grant` / `409 not_eligible` (wrong attempt, expired, already redeemed).
  Allowed only when the producer token's `kanbanTaskId` equals `taskId`.
- `POST /bridge/v1/grants/:grantId/consume` `{ toolCallId; outcome: 'executed' | 'blocked' | 'revoked' }` → `204`

Hook → domain mapping lives in `apps/server/src/hermes/translate.ts`; payload fixtures in
`apps/server/test/fixtures/bridge/` (seeded from `docs/spike/`).
