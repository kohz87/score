# Task 5.18: HTTPS-only remote access, with a setup guide

Owner request 2026-10-09: "disable http since most things cannot work; when accessing through http, force them to
reroute to https setup guide". Plain HTTP over the LAN is not a secure context, so browser APIs Score needs
(crypto.randomUUID, clipboard, secure cookies…) break, and pairing cookies and API keys cross the network in clear.

## Goal

Remote (LAN) mode serves the app **only over HTTPS**. Any plain-HTTP request to Score's remote port gets the
**HTTPS setup guide** instead of the app. Local mode (127.0.0.1/localhost) is unchanged: localhost is a secure context.

## Done when

1. **No insecure remote mode.** `SCORE_REMOTE_INSECURE_HTTP` no longer enables the app over HTTP. When set, startup logs
   that it was removed and ignores it. Remote mode without TLS starts in **guide-only mode**: it serves the guide and
   nothing else (no pairing, no API, no stream, no web app); `/api/*` answers `426` with error code `https_required`
   (zod-shaped like other errors); every other path answers `308` to `/setup/https`.
2. **One port, both protocols.** With TLS configured, the remote port accepts TLS and plain HTTP on the same port
   (peek the first byte of each connection: `0x16` = TLS handshake → the HTTPS server; anything else → a tiny HTTP
   handler). Plain HTTP there gets the guide page too (with a prominent "Open the secure address" link to
   `https://<host>:<port>/`), `/api/*` gets `426 https_required`. Use only `node:net`, `node:tls`, `node:http`: no new
   dependency. The Host/Origin checks of remote mode still apply to the HTTPS side unchanged.
3. **The guide** (`/setup/https`, static HTML rendered by the server, no app bundle, no external assets, inline CSS in
   the Score look: ground `#ECEEF2`, white card, ink `#12131A`, system font stack is fine here) explains in plain words:
   why HTTPS is required; option A (recommended) `scripts/score tls` on the server, then install Score's certificate
   authority on each device (download link `/setup/https/score-ca.crt` serving only the **public** CA certificate,
   `application/x-x509-ca-cert`; short per-platform steps: Windows, macOS, iOS, Android, Linux/Chrome); option B use your
   own certificate (`SCORE_TLS_CERT`/`SCORE_TLS_KEY`, e.g. from a reverse proxy or Tailscale); then restart and open the
   https address. It never shows secrets, never offers the CA private key, and is the same page in both modes.
4. **`scripts/score tls`** (bash launcher, `openssl` via argument arrays, no shell strings built from input): creates
   `$SCORE_HOME/tls/` (0700) with a local CA (`ca.key` 0600, `ca.crt`, 10 years, name "Score local CA (<hostname>)",
   basicConstraints CA:TRUE, keyUsage keyCertSign+cRLSign) and a server cert (`server.key` 0600, `server.crt`, 825 days,
   SAN = `SCORE_HOST` IP or DNS + `localhost` + `127.0.0.1`, extendedKeyUsage serverAuth) signed by it. Re-running keeps
   the CA and re-issues the server cert (so devices need not re-trust); `--new-ca` replaces both. Prints the files and
   the next steps. `scripts/score start` in remote mode uses `$SCORE_HOME/tls/server.{crt,key}` automatically when
   `SCORE_TLS_CERT`/`KEY` are unset, and derives https public origins.
5. **Cleanup** of the insecure path: Settings → Remote no longer shows the plain-HTTP warning flow; the
   `acknowledgeInsecure` requirement for API keys becomes unreachable in remote mode, so remove it from server, contract and
   web (contract §§ that mention it are updated). Keep any check that still guards something real.
6. Docs: `docs/API-CONTRACT.md` (426 `https_required`, `/setup/https`, CA download), `docs/SETUP.md` (remote setup is
   now HTTPS-only; the tls command; per-device trust), `docs/ARCHITECTURE.md` only if it describes insecure HTTP.
7. Tests: config (insecure flag ignored → guide-only; TLS → normal), server (guide-only mode: guide 200 HTML, `/api/*`
   426, `/` 308, pairing endpoints unreachable, CA endpoint 404 when no tls dir), the dual-protocol listener (a real
   ephemeral-port test: plain HTTP gets the guide and 426 on /api; TLS with a test cert generated in the test via
   `openssl` in a temp dir or a committed **test-only** self-signed fixture reaches the app), CA endpoint serves only
   `ca.crt` (never `ca.key`, no path traversal), launcher `tls` (bats-free: a vitest that runs `scripts/score tls` with a
   temp `SCORE_HOME` and checks files, modes and SAN with `openssl x509 -text`). Existing e2e (local mode) unchanged.
