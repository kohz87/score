## Design (from the lead)

`parseMessage(text: string, agents: readonly AgentId[]): ParsedMessage` — pure, no I/O, deterministic.

- `mentions`: `@agent` tokens for **known** agents only (case-sensitive ids, `[a-z0-9][a-z0-9_-]*`), in order, deduped;
  not inside inline code (`…`) or fenced code blocks, not part of an email (`a@b.com`) or a URL; trailing punctuation
  allowed (`@builder,` `@builder.` `(@builder)`). Unknown `@names` are reported in `unknownMentions` (not routed).
- `command`: only when the text **starts** with `/` + a known command (§5 table: `/assign`, `/routine`, `/remember`,
  `/skill`, `/model`). Return a discriminated union with the parsed fields, or `{ kind: 'invalid', command, error,
usage }` with a human-readable error (e.g. missing agent, missing title). Syntaxes exactly as §5:
  `/assign @agent <title> [-- body]` · `/routine @agent <schedule> <prompt>` (schedule: `5m|1h|2d`, `every 15m`, a
  5-field cron in quotes, or `daily HH:MM`; validate format only) · `/remember [@agent…] <fact>` (no agents → all
  mentioned none → `agents: []` meaning "the room lead", leave that decision to the router) · `/skill @agent <name>` |
  `/skill install <name>` · `/model <model> <message…>`. Unknown `/word` at the start → not a command (plain text).
- `text`: the message text with the command prefix removed for `/model` (the message part) and unchanged otherwise.
- Export `COMMANDS` metadata (`name`, `usage`, `description`) for `GET /api/commands` (task 2.6 wires the route;
  you may add the route now: `GET /api/commands` → `{ items }`, no auth beyond the default read model).
- Table-driven Vitest tests: ≥ 60 cases covering every syntax, invalid forms, emails, URLs, code spans/blocks,
  unicode, punctuation, repeated mentions, unknown agents, leading whitespace, CRLF.

Files: `apps/server/src/domain/parse.ts`, its test, and optionally `apps/server/src/http/commands.ts` + registration.
