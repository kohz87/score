# 3.28.0 — One job per chat (brief, web part)

Owner, 2026-11-04: "do we need topic/job in the chatgroup? since a chatgroup generally do 1 job at a time so it seems
redundant" → chose **"One job per chat, strictly"**; mock-up approved (copies `docs/design/bold/mockups/22-one-job.dc.html`
(desktop), `22-one-job-busy.dc.html` (starting work while a job runs), `22-one-job-phone.dc.html`). Decision 164. The
mock-up is binding; where this brief and the mock-up differ, the mock-up wins and you report the difference.

The server part is done by the lead (commit 33d56825; read `docs/API-CONTRACT.md` "One job per chat", `POST
/api/jobs/:jobId/end`, and §17 for the queue): a group chat holds one active job (active = not the default thread, not
deleted, state `open`/`working`/`waiting_on_you`); a second start is `409 job_running` with `details: { jobId; title }`;
**Stop job** is `POST /api/jobs/:jobId/end` (stops the run and the work, closes the job); a run's job closes when its run
ends; trigger calls into a busy team room wait in `GET /api/rooms/:roomId/queue` (Skip = `DELETE …/queue/:itemId`), and
queue changes emit the room's `room.upserted`. Schemas: `QueueItemSchema`, `RoomQueueResponseSchema`,
`JobRunningDetailsSchema` in `packages/contract/src/triggers.ts`. Direct chats are unchanged (their one-to-ones stay).

## What to build (group chats only; files are under `apps/web/src/bold/`)
1. **Job bar** (`room/`, new component) at the top of a group chat's conversation, under the chat header, when the chat
   has an active job (the mock-up's "Current job" section): a state dot, the `JOB` eyebrow, the title on one line with an
   ellipsis and the full title as its tooltip, a state line (who is working · step n · $spent of $cap when known), **Graph**
   (only when the job has a recipe run; opens the side panel's Graph tab as the run card's Show graph does) and **Stop
   job**. Stop job asks first with the existing confirm (copy: "Stop “<title>”?" / "Running steps stop and the job
   closes. What it made stays in Past jobs." / Keep going · Stop job), then `POST jobs/:id/end`. The bar and its confirm
   carry `data-protected`; add them to the protected list (`themes/protected-surfaces.ts`, `styles/protected.css`, its
   test). If the bar is sticky, add it to `KNOWN_OVERLAYS`. No bar when no job is active.
2. **Info** (`chats/ChatInfo.tsx`, `chats/TopicInfo.tsx`): "This topic" becomes **This job** (same contents and
   protections; its Stop becomes Stop job = `…/end`); the **Topics** section becomes **Past jobs · N** (folded by default;
   closed and done jobs, newest first, each row opening that job's conversation read-only as today's topic rows do).
   Legacy rooms with several active jobs show them under **Open jobs · N** above Past jobs until they end (each row
   keeps its "Needs you" mark). The "New topic" form goes.
3. **Stream** (`room/topic-divider.tsx`, `room/RoomMessageStream.tsx`): the "Topic · X" / "Back to topic · X" dividers
   go when the room has at most one active job (keep them only for legacy rooms with several, so their streams stay
   readable). Run cards stay.
4. **Composer and context bar** (`room/ContextBar.tsx`, the composer's target): a person's message goes to the active job
   when there is one, else the chat's own thread; the bar's "in <topic>" part goes (keep it only in legacy rooms with
   several active jobs). `/new` leaves the `/` palette (`room/topic-commands.ts`); typing it says "A chat does one job
   at a time: start one with /run, or Stop the current job first."
5. **Busy dialog** (new, protected, `data-protected` + protected list): when the person starts work (the + menu's Start a
   run…, `/run`, Start a job's submit into this chat) while a job is active, or any start returns `409 job_running`:
   title "<Chat name> already has a job", body "“<running title>” is still running. A chat does one job at a time, so stop
   it first, or start this in another chat.", a light box "New: <what they were starting>", buttons **Stop the job and
   start this** (POST `jobs/:runningId/end`, then retry the start; if the retry still answers 409, say "Still stopping…
   try again in a moment."), **Start in another chat…** (opens Start a job with the chat picker, the work kept),
   **Cancel**; the footnote "Stopping ends the running steps and keeps what the job made. It moves to Past jobs." Focus
   trap, Escape = Cancel, focus returns to the opener.
6. **Next up** (new, protected): under the job bar, one line per queued trigger call from `GET rooms/:id/queue` (refetched
   on that room's `room.upserted`): an amber dot, "**Next up:** “<title>” from <app> waits until this job ends." and
   **Skip** (`DELETE …/queue/:itemId`, then refetch).
7. **Phone** (≤ 860px): the job bar as the phone board (title, state line, Stop job); Info the same sections.
8. Wording: in group chats the visible word is "job", not "topic" (Info, dividers in legacy rooms, notices). Direct chats
   keep "chat".
