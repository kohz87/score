**3.1 Lanes + hand-offs builder**: server computes `LaneBlock[]`/`Handoff[]` from tasks, runs, Score runs and events. Done

## Design (from the lead)

- **Pure builder** `apps/server/src/domain/lanes.ts`: input rows (runs with profile/status/started/ended, task projections with
  assignee/status/timestamps, message_runs hand-off chains, approvals waiting) for a window `[from, to]` → `{ lanes: {
agentId; blocks: LaneBlock[] }[]; handoffs: Handoff[] }`. Rules: a run is a block (`working` while running, `waiting` while
  waiting for approval, `done` when finished); a task assigned to an agent and not started is `planned` (start = now, end =
  null, hatched future on the UI); consecutive runs for the same task merge into one block labelled with the task title;
  a message_runs hop (`from_agent_id` → `agent_id`) is a `handoff`; a review hand-off (reviewer agent / task in review)
  is `review`; a task sent back (kanban status back to in-progress after review) is `sent_back`. Blocks clipped to the
  window; every agent from the profiles list gets a lane even when empty; stable ids (`run:<id>`, `task:<id>`). Pure
  and fully unit-tested with fixture timelines (one that reproduces the design's lanes).
- **Endpoint** `GET /api/now?from=&to=` (contract §4; default window: the last 2 h to +1 h): `NowSnapshotSchema` in
  `packages/contract/src/http.ts` exactly as §4 says. Lanes/handoffs from the builder. `headline` counts working agents and
  pending approvals with plain text ("Two agents are working. One thing needs you."). `focusApproval` = the oldest
  actionable pending approval. `thread` = the most recently active room with its last 3 messages. `madeToday` = tasks
  finished today (title, `{kind:'task', taskId}` ref, files from tool_calls previews with path where present, added/removed
  0 when unknown, checks from review runs if available, else []). Snapshot uses `asOfSeq` like the other snapshots.
- Stream: the web will refetch on `run.*`, `task.upserted`, `approval.*`, `message.*` (no new event types).
- No web UI in this task (3.2/3.3 build it). Fake mode must return a non-empty, design-like snapshot (the fake scenario's
  runs/tasks/approvals; extend the scenario if needed, neutral agents only).
