## Task (from docs/PLAN.md)

**5.6 Verify a new Hermes version**: after a Hermes update, Settings says approvals in Score are paused until the new build is
checked, and offers "Check this Hermes version". Done when an update with unchanged internals is re-enabled by one
confirmed click and a changed one stays off with a clear report.

## Design (from the lead)

- Read first: `docs/reviews/2026-10-08-hermes-upgrade-drill.md` (5.4), the compatibility gate and registry
  (`apps/server/src/hermes/live/fingerprint*.ts`, `tested-fingerprints.json`, `apps/server/scripts/print-fingerprint.ts`) and
  how `disabled: ['gateway-approvals']` reaches the UI.
- Server (adapter only): **H** `POST /api/settings/hermes/check` computes the running build's fingerprint (version, codeSha,
  CLI string, capabilities, kanban/state schema hashes, bridge hook names, pattern keys from the installed Hermes source via
  the same extraction the drill used — read-only) and compares each part with the tested entries. Response: `{ build, parts:
{ name, status: 'same' | 'added' | 'changed' | 'removed', detail }[], compatible: boolean }` where compatible = schemas,
  hooks, private functions and capabilities unchanged (additions to pattern keys/config keys allowed). **H** `POST
/api/settings/hermes/accept` with the check's hash: appends the build to a **Score-side** accepted-builds store
  (`$SCORE_HOME`, not the repo file) and re-enables gateway approvals; refuses when not compatible. Union new pattern keys
  for display (read-only until a person adds them). Contract §10 + package (the lead authorises).
- UI: a banner in Settings (and a dot on the Settings nav) when a capability is disabled because the build is untested:
  "Hermes was updated to X. Approvals in Score are paused until you check this version." → Check → the parts table →
  Accept (only when compatible) or "Stay paused" with the changed parts listed.
- Tests: fixtures for an unchanged build (accept re-enables), an added-pattern build (accept allowed), a changed-schema build
  (refused), stale hash 409; never writes Hermes files.
