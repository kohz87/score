## Hermes facts (verified in `../reference/hermes-agent/tools/approval.py` and `approval_gateway_wait.py`)
- `list_gateway_approvals(session_key) -> list[dict]`: snapshots of the pending entries (`entry.data`, which includes
  `request_id`, `command`, `pattern_key`, `pattern_keys`, `description`, …) under the approval lock.
- `resolve_gateway_approval(session_key, choice, resolve_all=False, reason=None, request_id=None) -> int`: with a
  `request_id`, resolves only the entry with that id (0 if none). **Without one it resolves the oldest entry (FIFO).**
- The gateway wait appends its entry, releases the lock, then fires `pre_approval_request` **in the same thread**
  before notifying any surface. An identical pending command normally becomes a coalesced follower (no new entry),
  except during terminal approval preparation, so two identical entries are rare but possible.
- `register_gateway_settle` holds a single callback per entry; the gateway registers its own. **Never call it.**

## Design (from the lead; follow it)
1. **`hermes_private.py`**: add `list_gateway_approvals(session_key)` and `resolve_exact(session_key, choice,
   request_id)`. `resolve_exact` refuses (returns 0 without calling Hermes) unless `request_id` is a non-empty string;
   it always passes `request_id=` and never `resolve_all`. Remove `register_gateway_settle` from the probed APIs list
   and from anything else in the plugin. `privateApis` in hello reports the two functions it uses.
2. **Exact capture** (hook thread, inside the existing capture path, before enqueueing): for a
   `pre_approval_request` whose surface is not `smart`, not `transport:*`, and not `coalesced`, list the session's
   pending entries and pick candidates whose `command` and `pattern_keys` equal the hook's (compare the raw values the
   hook received, before any redaction). Report `requestId` only if there is **exactly one** candidate **and** its
   `request_id` isn't already claimed by another gate in this process; then claim it (a process-wide bounded set, at
   most 4,096 ids, oldest evicted; reset on fork). Otherwise `requestId: null`. Any exception → `null` (fail open).
   Bound the work: if the session has more than 64 pending entries, report `null` without comparing.
   Keep the 1.13a budget for the hook (fast path; `list_gateway_approvals` copies small dicts under a lock).
3. **Decision poller** (one per producer client, i.e. per profile, started only when that producer's hello returned
   `enabled.gatewayApprovals = true`): a daemon thread long-polling `GET /bridge/v1/decisions?wait=25` with the
   producer token (renew via hello on 401, like the sender). For each item: apply only if this process claimed that
   `requestId` for that `sessionKey` (else ack `failed` with error `not_reported`); call `resolve_exact(sessionKey,
   choice, requestId)`; ack `POST /bridge/v1/decisions/:deliveryId/ack {leaseId, outcome, resolved}`: `applied` iff
   `resolved == 1`, `not_pending` iff `0`, `failed` (error code only, never exception text) on an exception. Never
   resolve without a `requestId`. If an ack fails, retry it a few times within the lease; the server's late-receipt rule
   handles a delayed `applied`. Back off on errors (1, 5, 30 s). Stop within 2 s on shutdown/unload; reset on fork (the
   child starts its own lazily, like the sender).
4. **Server change** (`apps/server/src/hermes/bridge/routes.ts`): `enabled.gatewayApprovals` requires
   `list_gateway_approvals` and `resolve_gateway_approval` (no longer `register_gateway_settle`), plus `isolation ===
   'in_process'` and the compatibility gate, as before. Update its tests.
5. README: document what the plugin does with approvals and that it never answers without an exact id.
