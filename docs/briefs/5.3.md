## Task (from docs/PLAN.md)
**5.3 Performance**: 1k events/min sustained through ingest → SSE → web; budgets for ingest latency, stream lag, page render,
DB growth. Done when a repeatable load test meets the budgets.

## Design (from the lead)
- `scripts/load-test.ts` (run with `pnpm load-test`, not part of `pnpm check`): starts a server on a throwaway SCORE_HOME in
  fake mode with a load generator feeding observations through the real ingest path at a configurable rate (default 1,000
  events/min for 10 min, plus a 5x burst for 1 min): runs, tool calls, messages with streamed deltas, task updates,
  approvals, watch frames. Connect 3 SSE clients; measure p50/p95/p99 ingest commit latency, event→client lag, CPU, RSS,
  DB and WAL size growth, retention sweep cost. Print a table and write JSON to `$SCORE_HOME/load-report.json`.
- Budgets (fail the run if exceeded): ingest p95 < 25 ms, stream lag p95 < 250 ms, RSS < 400 MB, DB growth < 50 MB per
  10 min at 1k/min, no event loss or reordering (verify seq continuity on every client).
- Web: a Playwright perf check that opens /now, /chat/<room> and /now/flow during the load and asserts each renders within
  2 s and stays responsive (long tasks < 200 ms) — use the Performance API, no new dependencies.
- If a budget fails, find and fix the cause (index, batching, query shape) in this task and explain it; don't relax budgets
  without saying why.
