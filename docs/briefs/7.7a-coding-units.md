# 7.7a Coding runs as systemd user units (stage 1 of 7.7; design v1, for adversarial review)

Owner 2026-10-11 chose 7.7 "full, in stages" (decision 65). Two reviews of 7.7 (`docs/reviews/2026-10-11-7.7-design-
review.md`, `…-rereview.md`) kept finding that **process groups are not a job identity**: descendants can leave the group
(`setsid`), PIDs/PGIDs are reused, absence can't be proven by scanning, a deadline lives only in Score, and work that
finishes while Score is down loses its result. Stage 1 replaces that foundation for **every** coding run (Chat included)
before any orchestration work (stage 2) or workflow work (stage 3).

## Probe (2026-10-11, this host)
`systemd-run --user` (systemd 259) with `RemainAfterExit=yes`: the main process exited 0 while a `setsid sleep 60` child
stayed in the unit's cgroup (`TasksCurrent=1`); `systemctl --user stop` ended it and the unit unloaded. The user manager
runs with `Linger=yes`, so units outlive the login session.

## Design
1. **One unit per launch.** A coding launch gets a launch id and a transient user service `score-coding-<launchId>`:
   `systemd-run --user --unit=… --property=RemainAfterExit=yes --property=KillMode=control-group
   --property=RuntimeMaxSec=<limit> --property=StandardInput=file:<prompt> --property=StandardOutput=append:<out>
   --property=StandardError=append:<err> --working-directory=<workspace> --setenv=… <cli> <args>` (argv only, no shell).
   The cgroup is the job identity: every descendant, including ones that leave the process group, belongs to it. Unit
   names are never reused.
2. **Durable launch record first.** Before `systemd-run`, Score writes `coding_launches` (launch id, run id, unit name,
   prompt/output paths, boot id, owner, state `authorised`) and the prompt file (0600, Score's state dir). Then a final
   synchronous authorisation (Chat: the run wasn't stopped; stage 2 extends it), then `systemd-run`, then
   `state = started`.
3. **Proof of state, from systemd, not from scans.**
   - **Never started**: launch row `authorised`, the unit doesn't exist, no output file → proven no-launch (Score only
     starts a unit after recording it, and only collects a unit after recording its outcome, see 5).
   - **Running**: unit active with `TasksCurrent > 0`.
   - **Ended**: unit `inactive`/`failed`, or `active (exited)` with `TasksCurrent = 0` (cgroup empty; also read
     `cgroup.procs`). This is termination proof for the whole job.
   - **Main exited, leftovers alive**: `active (exited)` with tasks → the existing grace policy, then
     `systemctl --user stop` → proof as above.
   - **Another boot**: transient units don't survive reboot → ended (record the boot id; the output file is still read).
   - **systemd unreachable or ambiguous** → `unobservable`: keep the record, fence the agent, retry; X's Release stays
     available for the person.
4. **Output is a durable file.** The CLI's stdout/stderr go to files; Score tails them (fs watch + offset, bounded) to
   stream deltas, tool cards and the 5.39 status line. After a Score restart it **re-reads the file from its saved
   offset**, so a run that finished while Score was down is completed with its real result (no more "interrupted" for
   that case). The parser records whether any record was dropped (oversized/malformed) → `lossy`.
5. **Collect only after recording.** When a run ends, Score writes the terminal result (with `terminal_source =
   'runtime'` only if ended-proof held) in one transaction, then `systemctl --user stop`/`reset-failed` to unload the
   unit, then deletes the prompt and (after retention) the output files. A crash between keeps the unit, which the next
   start reconciles idempotently.
6. **Deadline outside Score.** `RuntimeMaxSec` enforces the wall-clock limit even if Score is down; systemd then stops
   the unit (cgroup kill). The run's note says "stopped at its time limit".
7. **Stop.** `systemctl --user stop <unit>` (SIGTERM to the cgroup, then SIGKILL after `TimeoutStopSec`); `stopped` only
   on ended-proof; otherwise `unconfirmed` and retried asynchronously.
8. **Restore / lost records (review N1).** On start Score lists `score-coding-*` units: a unit with no launch row (a
   restored database lost it) is reported on Now as needing review and **fences coding admission** until the person
   reviews it (stop it or keep it); never adopted silently. Units are the external witness the database can't lose.
9. **Final reply authority (review N15).** Drivers mark an authoritative final reply only from the CLI's own final event
   (Claude Code `result`; Codex the last `agent_message` **followed by** `turn.completed` with no dropped record between
   them); `lossy` output has no authoritative final reply. Chat still shows the streamed text; stage 2/3 consume only
   the authoritative one.
10. **Requirements and fallback.** Needs a running systemd user manager with linger. If missing, Score says so on the
    coding agent's card ("Coding agents need systemd user services: run `loginctl enable-linger $USER`") and keeps the
    current process-group runtime for Chat only; stages 2–3 then refuse coding workers.
11. **Security.** The unit runs as the same user with the same environment rules as today (env allow-list, no secrets
    in argv); the prompt file is 0600 in Score's state dir and removed after the run; units are named, so `systemctl
    --user list-units 'score-coding-*'` shows the person exactly what runs.

## Replaces
`coding_processes`/`coding_process_members` and the pgid logic become the fallback path only; batch W/X semantics
(unconfirmed, fence, Release, StopOutcome) are kept and mapped onto unit states.

## Done when
Tests with a fake `systemctl`/`systemd-run` boundary (argv recorded, states scripted) **and** an opt-in real-systemd
integration test (harmless `sh -c 'sleep …'` units, cleaned up) for: start/record order, never-started proof, escaped
`setsid` child kept and stopped, RuntimeMaxSec while Score is down, restart re-reading output to completion, Stop
outcomes, lost-record unit fenced, reboot (boot id), lossy output without an authoritative reply, fallback when
systemd is unavailable. `pnpm check`; the coding e2e on the fake boundary.
