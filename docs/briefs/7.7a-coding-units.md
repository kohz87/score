# 7.7a Coding runs as supervised systemd user units (stage 1 of 7.7; design v3, for re-review)

Owner 2026-10-11: 7.7 "full, in stages" (decision 65). v1 (`docs/reviews/2026-10-11-7.7a-design-review.md`) and v2
(`docs/reviews/2026-10-12-7.7a-design-rereview.md`) were blocked. Most v2 findings came from one feature: letting a
coding run finish while Score was down by persisting its output to disk (redaction on disk, replay, stream completeness,
quotas). **v3 drops that feature**: a coding run lives no longer than Score's connection to it, exactly as Chat behaves
today ("Score restarted while this ran"). What stays is what the units are for: a kernel job identity (cgroup), proof of
termination, the exact environment, no PID reuse, and a release barrier. Findings cited as [v1 n] / [v2 n].

## Guarantee, stated precisely [v1 18]
Score proves every process **in the run's cgroup** ended. Work a tool hands to another user service, scheduler or daemon
is outside that proof; the consent text (7.7b) and the user guide say so. Antigravity stays Chat-only [v2 19].

## 1. The unit [v1 1, 16, 17; v2 12, 14, 16]
`systemd-run --user --no-ask-password --expand-environment=no --unit=<name> --description="Score coding run"
--property=Type=exec --property=ExitType=cgroup --property=RuntimeMaxSec=<turn limit + grace>
--property=KillMode=control-group --property=KillSignal=SIGINT --property=TimeoutStopSec=<grace>
--property=FinalKillSignal=SIGKILL --property=SendSIGKILL=yes --property=TasksAccounting=yes
--property=StandardInput=null --property=StandardOutput=null --property=StandardError=null
--property=UnsetEnvironment=<every variable name the manager currently exports, read once per launch>
--setenv=PATH=… --setenv=HOME=… --setenv=LANG=… -- <node> <supervisor.mjs> <launch dir>`
- Signal contract INT → TERM → KILL is implemented by the **supervisor** (it owns the CLI and escalates on Score's
  grace); systemd's KillSignal/FinalKill are the backstop at `RuntimeMaxSec` [v2 12].
- The manager-environment race [v2 14] doesn't matter for the CLI: the supervisor starts the CLI with an environment it
  builds itself from the spec (replace, never merge), so nothing the manager exports reaches the CLI.

## 2. The attached supervisor (`runtimes/coding/supervisor.mjs`, Node built-ins only)
- Score creates the launch directory (`$SCORE_HOME/coding/launches/<id>/`, 0700, files `O_EXCL` 0600, no symlinks)
  with `spec.json` (executable, argv, exact env, workspace, limits, a single-use **launch token**) and `prompt` (the
  prompt bytes) [v2 16].
- The supervisor connects to Score's **coding socket** (`$SCORE_HOME/coding/sock`, Unix, 0600 in a 0700 dir),
  authenticates with the launch token, reports `ready` (its pid, `$INVOCATION_ID`, cgroup path, boot id), then **waits
  for `go`** [v2 1]. Only after `go` does it start the CLI (stdin = the prompt bytes, piped; stdout/stderr piped).
- It forwards stdout/stderr to Score **live** over the socket as framed records (line boundaries preserved, bounded);
  **nothing of the output is written to disk** [v2 4, 5, 6, 7; v1 7, 8, 13, 14].
- If the socket closes (Score stopped or crashed) before `go`: it exits without starting anything. After `go`: it stops
  the CLI's process tree (INT → TERM → KILL on the grace) and exits; `ExitType=cgroup` keeps the unit active until the
  cgroup is empty, and `RuntimeMaxSec` is the backstop.
- Receipts, the only files it writes (tiny, no output, fsynced with the directory): `released` (written **before**
  starting the CLI), `cli-exited` (code, signal), `ended` (after it saw its children gone).
- Stop: Score sends `stop` over the socket (supervisor escalates); if the socket is gone, Score uses
  `systemctl --user stop <unit>`.

## 3. Phases and the journal [v1 3, 4; v2 1, 2, 3]
Phases: `authorised` (DB) → `requested` (journal, before `systemd-run`) → `armed` (supervisor `ready` received; unit
identity recorded in DB) → `released` (Score sent `go`; the supervisor writes the `released` receipt before spawning) →
`ended` (proof, §4) → `settled` (terminal result committed; journal tombstone).
- **Revocation** [v2 1]: Stop or authorisation failure at `requested`/`armed` is persisted (DB + journal `revoked`)
  **before** anything is sent; an armed supervisor is told `cancel` (it exits, no CLI); a `requested` launch whose
  supervisor connects later is answered `cancel`. Absence of a unit after `requested` is never treated as no-launch by
  itself: no-launch = journal `revoked`/`settled(no-launch)` **and** no `released` receipt.
- After a Score restart every launch past `requested` is reconciled: `released` receipt absent and the unit/cgroup gone
  ⇒ proven no-launch (the supervisor writes `released` before it can start the CLI, and it exits on socket close);
  `released` present ⇒ it ran; it was stopped by the socket close; the run ends `interrupted` once ended-proof holds.
- **Journal** [v2 2, 3]: coding records carry launch id, phase, unit identity (installation id, InvocationID, cgroup,
  boot id), revocation, proof and disposition. Reconciliation compares the **latest phase and identity** in the journal
  with the database; any execution the journal witnessed but the database lacks (a restored snapshot) makes that run
  permanently unsendable and fences coding admission until reviewed. Compaction keeps each launch's latest record until
  settled + retention. The journal file is per **installation** (`<journal dir>/<installation id>/`) with an exclusive
  lock across processes for append, sequence allocation, tail repair and compaction [v2 3] — this also fixes the
  existing orchestration journal's multi-home race.

## 4. Proof, disposition, eligibility [v1 2, 19; v2 8, 11, 13]
- **Ended proof**: the cgroup recorded at `armed` is absent, or its `cgroup.events` says `populated 0` (recursive), with
  no pending unit job; boot changed ⇒ ended. The supervisor's own `ended` receipt is advisory [v2 11]. A missing unit
  alone is not proof; a missing unit **and** an absent/empty recorded cgroup is [v2 13].
- **Acceptance matrix** [v2 8]: a run is `completed` with an eligible result only when **all** hold: the CLI exited 0
  (no signal), no stop cause (user, limit, socket loss), the stream ended cleanly (the supervisor's `cli-exited` came
  after the pipes' EOF and no frame was dropped), ended proof, and the driver's terminal evidence (Claude Code: `result`
  success with non-empty text; Codex: validated final `agent_message` then `turn.completed`, nothing dropped in the turn).
  Anything else ⇒ `failed`/`cancelled`/`interrupted` with no eligible result.
- Proof is monotonic and separate from disposition and eligibility; late proof closes obligations only; Release/Keep is
  an audited waiver with a tombstone (W/X semantics).

## 5. Chat hand-offs and plans use only the authoritative reply [v2 9]
`completeRunMessage`/plan parsing take the eligible authoritative reply as an explicit input; streamed commentary stays
visible but never triggers an @mention hand-off or a plan. (This also fixes today's Chat behaviour.)

## 6. Identity, inventory, fallback [v1 11, 15, 20; v2 17, 18]
Unit names `score-<installation8>-c-<launch>.service`, server-minted and validated, exact names only. Launch records
bind installation, InvocationID, cgroup, boot, manager incarnation; the backend (unit | process group) is stored per
launch and never switched for an uncertain one; both inventories are reconciled before admission. Failed units are
collected (`reset-failed <exact name>`) only after `settled`; Score keeps its own start backoff (unique names bypass
systemd's rate limits) [v2 17]. Removing an agent keeps its launches' routing until settled [v2 18]. Capability check
(manager reachable, `Type=exec`/`ExitType=cgroup` accepted, cgroup v2 `cgroup.events` readable, linger); otherwise
Chat uses the process-group backend (W/X/Y) and stages 2–3 refuse coding workers.

## Done when
Fake `systemd-run`/`systemctl`/socket tests and an opt-in real-systemd suite (harmless CLIs) for: release barrier
(crash before `go` ⇒ never started; Stop at `requested`/`armed` ⇒ cancel, no CLI); socket loss after `go` ⇒ CLI stopped,
`interrupted`, ended proof; `setsid` survivor stopped and the unit kept until the cgroup is empty; manager-exported
sentinel variable never reaching the CLI; acceptance matrix rows; hand-off ignored from commentary; journal multi-home
lock and restore reconciliation; unit-name validation; both backends reconciled after upgrade.
