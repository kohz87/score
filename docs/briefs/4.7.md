## Task

4.1 stores browser frames with `imageUrl: null`. Make Hermes browser tools' screenshots reach the media store (4.3,
`app.media.store(bytes, contentType)` → `{ mediaId }`) and set `imageUrl: /api/media/<id>`.

## Design (from the lead)

- Find in `../reference/hermes-agent` where browser tools return screenshots (base64 in the result, or a file path).
- Plugin: for browser tool results only, extract the screenshot (base64 or read the file the result names, only if it is
  an image under Hermes's own browser/artifact directories, size ≤ 2 MB), downscale is not available — send as-is if it
  fits the plugin's per-payload cap (64 KB); otherwise send a marker "screenshot too large" (no image). Never send
  screenshots from `browser_vault_*` or any sensitive tool. Keep redaction rules unchanged for the text parts.
- Server: decode, `store` it (sniffing decides the type), set imageUrl; on any media error keep `imageUrl: null`. Media refs
  are incremented for frames that reference them so the quota sweep keeps them while frames exist (and the 7-day frame
  retention releases them).
- Tests: fixture browser results (small PNG), oversize, non-image, vault tools, path traversal attempts in a result's path.
- If the plugin cap makes typical screenshots impossible, say so and propose the smallest change (e.g. a separate
  bounded upload endpoint on the loopback bridge listener) instead of building it.

## Done when
