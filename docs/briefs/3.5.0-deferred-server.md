# 3.5.0 Deferred server items (brief)

PLAN "P3 Deferred phase-gate review items" (decision 121; each was judged safe to ship). Owner, 2026-10-26: "then all the
deferred items". Fix each at its cause, with tests; one commit's worth of change per item is fine.

1. **`hold()` when an exchange already holds a turn** (`apps/server/src/domain/exchanges/budget.ts` `hold`): it
   overwrites `exchanges.held`, so a second hold while the person hasn't answered the first would drop the first turn.
   First establish with a test whether a second hold is reachable (apply.ts / decisions.ts / budget.ts `release` paths,
   e.g. two agents' turns in one exchange, a release that re-holds with `check`, a reassignment). If reachable, keep
   both: the earlier held turn must never be lost (keep the first held turn and fail the newer turn with a visible
   notice in the job, or queue it behind the first; pick the simpler correct one and explain). If unreachable, make
   `hold()` refuse to overwrite (throw an internal error with a clear message) and add a test proving the invariant.
2. **Report-back `tool` limited to reporting tools** (triggers report-back, PLAN 11.1d; `apps/server/src/domain/triggers/`):
   a trigger's report-back names a tool the lead must call to report back; today any tool name is accepted. Accept only
   tools of the trigger's tool server that look like reporting tools, or accept any but show a warning in the trigger's
   settings response ("this tool may change things, not just report") — read the code and docs/API-CONTRACT.md for
   triggers to choose; the contract may gain an optional `warning` field (update the doc and packages/contract, both
   sides).
3. **Triggers that were never called (orphans of a retried create)**: a create that is retried can leave a trigger row
   nobody sees. List them in the triggers list (with "Never called" and created time) and allow deleting them, or stop
   the orphan at its cause (idempotent create). Prefer the cause; keep listing/deleting working for existing orphans.
4. **"Imported from" rooms created by Elsewhere previews**: previewing an outside Hermes session (Elsewhere / outside
   sessions, `apps/server/src/http/outside-sessions.ts`, `hermes/live/outside-sessions.ts`) must not create a room; only
   an explicit "Bring into Score"/continue action does. Find where a preview creates an `importedFrom` room; fix it, and
   clean up nothing that exists already (rooms people may have used stay).
