## Rules for each candidate
1. Search the whole repo for the name (including string uses, dynamic imports, re-exports through `index.ts` barrels,
   `e2e/`, `scripts/`, JSX, CSS class names built from it). If anything real uses it, leave it and note why.
2. **Keep test seams**: `reset…` functions, schedulers or clocks that exist so tests can control timing, and fixtures.
   Keep anything a test needs to reach a real production behaviour.
3. **Remove** code that only existed for a feature that is gone (only its own tests use it), together with those tests or
   test cases. When a test file still covers live code, remove only the cases for the removed code.
4. A removed export that leaves its helpers unused: remove those too (follow it down), then re-run the type check.
5. Do not touch `packages/contract` types, migrations (forward-only), `docs/`, or anything behaviour-changing. No renames,
   no reformatting beyond what removal needs, no "while I'm here" refactors.
6. Unused CSS classes that only a removed component used: remove them in the same change.

## Done when

- `pnpm lint`, `pnpm format`, the typecheck for all packages and `pnpm test` pass. Run `pnpm e2e` once at the end with
  `SCORE_WEB_PORT=6381` (a removed component that an e2e spec still drives must be caught).
