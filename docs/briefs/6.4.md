# Task 6.4: Agent knowledge tools (score_bridge)

Spec: **docs/briefs/6.0-workspace-knowledge.md § 6.4 and lead review items 4, 9**. The knowledge server (6.2) is on main:
`apps/server/src/knowledge/` exposes `writeNote(path, req, author)` etc. with agent authors, and the `agentAccess`
setting (stored, **not yet enforced**: enforcing it is this task). Owner decision: agents read and write; no delete or
move for agents; every agent write is a git commit the owner can undo.

## Done when
1. **Plugin tools** in `hermes-plugin/score_bridge/` registered with Hermes's public `ctx.register_tool()` (see
   `../reference/hermes-example-plugins/plugin-tool-example`, MIT; Hermes `hermes_cli/plugins.py`), JSON-Schema
   validated, structured results/errors: `knowledge_search(query, limit≤20)`, `knowledge_read(path)`,
   `knowledge_list(folder?)`, `knowledge_write(path, body, expected_etag | null)` (create when null; 409 with the
   current etag on conflict so the model re-reads), `knowledge_append(path, text)` (server-side append, no etag needed).
   Tool descriptions tell the model what the vault is and to search before writing. No private Hermes calls (if one is
   unavoidable it lives only in `hermes_private.py`).
2. **Bridge RPCs**: new authenticated bridge endpoints on the loopback bridge listener (contract §11 first, then
   `packages/contract`, then both sides): the calling producer identifies the agent (profile) exactly as hook events do;
   never trust an agent id from tool arguments. Responses bounded in size (read ≤ 256 KiB, list/search ≤ 200 items).
3. **Server enforcement**: `agentAccess` off (global) → tools answer "Knowledge is turned off for agents"; a per-agent
   switch on Team › agent › Tools ("Knowledge tools") stored in Score's DB (migration **0031**) and enforced the same way;
   rate limit 60 writes/hour/agent and 256 KiB per write (429/413 with a clear message to the model); agent-written content
   goes through `redact()` before it is stored; writes use the agent author (git `<agentId> (agent)`), emit
   `knowledge.changed` with `by: {agentId}`.
4. **Web**: the per-agent switch on the Tools tab (or a small "Knowledge" card there), and in Settings › Knowledge the
   global switch already exists (6.3) — make it show per-agent counts of today's writes.
5. **Tests**: pytest for the plugin tools (schema validation, transport errors, result shapes) with a fake bridge;
   server tests for the RPCs (auth, agent identity from the producer, access switches, rate limit, size limits, redaction,
   author attribution, conflict), web tests for the switch; an end-to-end check with the fake adapter if the fake can
   simulate a tool call, otherwise server-level integration tests.
6. **Live check** on the test profile `scoretesta` only (free model): install/refresh the plugin there the way earlier
   bridge tasks did (see docs/SETUP.md), ask the agent in a room to save a short note and to find it again, confirm the
   git author and the `knowledge.changed` event. Never touch the owner's real profiles; the lead will update the plugin
   on `default` after review.
