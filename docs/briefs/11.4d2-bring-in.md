# Brief 11.4d2: Bring into a job retries safely; imported chats stay reachable

Follow-up to PLAN 11.4d (merged). A Sonnet review after the merge found these; the lead verified the two P1s. Read
`docs/briefs/11.4d-room-menu.md`, AGENTS.md, `docs/API-CONTRACT.md` (outside sessions import, `POST
/api/rooms/:id/jobs`, `POST /api/messages/:id/share`, Idempotency-Key) and `apps/server/src/http/idempotency.ts`.

## Fix
1. **P1 — a reused Idempotency-Key replays the server's error** (`apps/web/src/data/outside-job.ts`). The server stores a
   receipt for every status and replays it for the same key and route (no rerun for these routes), so "Try again" after
   a 500 replays the 500 for 24 h. Use a **fresh key per HTTP call**; reuse a call's key only to retry that same call
   after a failure with **no HTTP response** (network error / aborted). Repeats are prevented by the client state
   (`attempt.job`, the set of shared message ids), not by the key. Unit test that models the real replay: a 500 then a
   retry must send a new key and succeed; a network error then a retry sends the same key.
2. **P1 — closing the panel loses the attempt and duplicates the job** (`BoldElsewhere.tsx` keeps it in a ref; the
   component remounts per session, on mode switch and on the phone sheet closing). Keep attempts in a module-level map
   keyed by `agentId:sessionId` (survives remounts while the page is open), cleared on success. After success, the
   Elsewhere view for that session says "Brought into <job title>" with a link to the job instead of offering the
   button again (for this page's lifetime). The error text must be true: "kept while this page is open".
   Unit test: partial failure → unmount → remount → retry creates no second job and shares only the missing messages.
3. **P2 — imported rooms are unreachable in /b** (`RoomMenus.tsx` filters `importedFrom` rooms out). Show them in the
   room dropdown under their own heading "Imported chats" (after older rooms); opening one works like an older room
   (read-write). If the classic shell sends into an imported room through `continue-session` (check how it does it),
   do the same; otherwise the normal send. The room menu's delete (typed-name confirm) works for them too.
4. **P2 — `onBlur` closes the menus before a click lands** in Safari/Firefox on macOS (buttons don't take focus on
   mousedown, so `relatedTarget` is null). Close on a `focusin` outside the menu root (document listener) plus the
   existing `pointerdown` outside; drop the `onBlur` closes (3 places in `RoomMenus.tsx`). Keep Tab-out closing.
5. **P3** — `importedMessages` sort: break `createdAt` ties by the numeric suffix of `import:<n>` (or keep the server's
   order). `broughtIntoJob` (BoldRoom.tsx) returns focus as `closeSheet` does on phones; `openElsewhere` moves focus into
   the panel's heading on desktop. Check `docs/design/bold/prototype.html` really hides the composer's To row on phones;
   if it does, the older-room cue on phones is the room title — make sure it reads "Older room" there.
6. **Tests** — e2e `bold-room-menu.spec.ts`: the retry test's mock must store receipts like the server (same key + route
   → replay the stored status) so it would have caught P1; add closing the panel mid-way then retrying; Imported chats in
   the dropdown open and send.
