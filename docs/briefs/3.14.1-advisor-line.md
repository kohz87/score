**Approved mock-up (owner, 2026-10-28: "that works"):** `docs/design/jobmap/graph-desktop.html` and `graph-phone.html` now
draw it: on desktop a dashed purple line from the Advisor node's right side, down the map's right edge, into the Workers node's

## Build (apps/web only)
1. **A real connector** from each worker node that asked the advisor back to the **Advisor node**: a dashed path drawn in an
   overlay `<svg>` (absolutely positioned over `.jobmap`, `pointer-events: none`, `aria-hidden`), routed as an elbow (out of the
   advisor node's bottom/side, down the right edge of the map, into the worker node's side). Measure node positions with refs
   (`getBoundingClientRect` relative to the map) in a layout effect, and re-measure with a `ResizeObserver` on the map (and when
   the model changes). Remove the old per-worker "on call" stub. Label the path near the worker end: "asked 2× · 18k tokens".
2. **Live consult**: while any of that worker's consults has `status === 'running'`, the path is solid-highlighted and a dot moves
   along it (CSS `offset-path` or an SVG `animateMotion`; none under `prefers-reduced-motion` / the map's `still` flag).
3. **Phone** (`jobmap--phone`): the advisor's marks live on the Lead card; draw the connector from the Lead card's advisor marks
   to the worker node the same way (down the right edge).
4. The worker node's aria-label already says it asked the advisor; keep it. The session log keeps its "<worker> asked the
   advisor: <question>" lines.
5. Tests (Vitest + Testing Library; jsdom has no layout, so stub `getBoundingClientRect`/`ResizeObserver`): a path is drawn for
   each worker with on-call consults and none otherwise; the running state marks it live; reduced motion has no moving dot; the
   label text. Update `e2e/bold-runs-visual.spec.ts` baselines only if they change (they have no on-call consults, so they
   shouldn't).
