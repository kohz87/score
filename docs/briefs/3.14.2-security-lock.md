## Behaviour (done when)
1. **No password set** (`GET /api/session/security` → `passwordSet: false`): only the first-run card ("Set a security password
   first", new + again, "Set password and open"). `PUT /api/session/security/password { password }`; the server unlocks this
   session on the first set, so after success refetch the status and show the unlocked view.
2. **Locked** (`unlockedUntil: null`): only the light lock card: lock icon, "This section is locked", the explanation, one
   "Security password" field and **Unlock** (`POST /api/session/security/unlock { password }`), errors `wrong_password` ("That
   is not the security password."), `too_many_attempts` ("Too many wrong passwords. Wait 15 minutes and try again."), and the
   line about auto-lock and `scripts/score password`. Nothing else of the section renders, and no locked query runs (paired
   browsers, passkeys) while locked. The password is cleared from state right after the request.
3. **Unlocked:** the header pill "Unlocked · locks in m:ss", counting down to `unlockedUntil`, and **Lock now**
   (`POST /api/session/security/lock`). Then the cards in the mock-up's order and layout (two columns on desktop, stacked on a
   phone): Paired devices (full width) · Pair another device · Passkeys · Where agents run · Terminal in the browser ·
   Security password (full width) · HTTPS setup (`<details>`, closed).
   - **No action sends the password any more** (renew, end, end all others, pairing link, passkey add/remove): the server
     accepts the unlocked session. After each action, refetch the security status (each use pushes `unlockedUntil` out).
   - Paired devices: one row per device: label, "this one" for the current browser, a "not a browser" tag when the label
     looks like a script client (`/^(curl|wget|python|node|go-http|httpie|okhttp)\b/i`), the address · last seen · access
     until line; Renew; End (not for this browser); "End all other devices" (only with others); "Log out this browser".
   - Security password card: "Set · it unlocks this section. Forgot it? `scripts/score password` on the Score machine." and
     **Change password**, which opens current / new / again (`PUT … { password, current }`) inline.
   - The old top password box, "Check password", the "Enter the security password above…" hints and "Go to the password
     field" links are **gone**.
4. **It locks itself:** when the countdown reaches 0 (refetch the status → locked view); when the person leaves the section
   (unmount: fire-and-forget `POST /api/session/security/lock`); and whenever any request answers `403` with code `locked`
   (refetch the status, show the lock card, keep no stale list on screen).
5. Protected: the lock card, the first-run card and the unlocked container carry `data-protected` and are added to the
   protected list (`apps/web/src/styles/protected.css` and its test), per AGENTS.md design rules.
6. Phone layout matches `Phone*.dc.html` (full-width buttons, ≥44 px targets).
