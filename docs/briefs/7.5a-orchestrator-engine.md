# Brief 7.5a: Orchestrator engine (server, contract, MCP tools)

**Design:** `docs/briefs/7.5-orchestrator.md` — v3 at the top **with the v3.1 amendments in
`docs/reviews/2026-10-10-7.5-orchestrator-v3-lead.md`**, then v2 and v1 where v3 doesn't replace them. Safety rules it
inherits from 7.1: `docs/briefs/7.1-workflow-builder.md` (v6 → v3). Where this brief and the design disagree, ask.

## Stage A scope (no web UI; 7.5b does the pages)
1. **Migration 0048:** orchestrations, lead attempts, steps (+ attempts), commands (receipts), gates/inquiries, wake
   causes/cursor, obligations (owed stops, reservations), ownership/transition history.
2. **Execution journal** outside `$SCORE_HOME` (`$XDG_STATE_HOME/score/execution-journal`, default
   `~/.local/state/score/…`; tests use a temp dir): append + fsync before each external effect; startup replay; global
   admission fence + reconciliation data; daily compaction of reconciled entries; size alarm. `scripts/score restore
   <backup>` (sets the fence and `untrusted-history` before start) — argv only, no shell strings.
3. **Executor** (`apps/server/src/domain/orchestration/`): one admission authority; typed orchestration dispatch for lead
   and step runs (fixed recipient, no mention routing, no plan materialization, no summaries, fresh session per attempt);
   per-turn capability (`orc_…`, hashed, placeholder in stored input, in-memory insert, new generation on re-dispatch;
   `orc_` added to `redact()`; step inputs scanned for the prefix); event-driven wake with a durable cause cursor;
   commands with `commandId` receipts; gates bound to assignments (`every-step` default, `lead-asks` via
   `orch.requestApproval`, `none`); inquiries as data; finish/cancel barriers, `replaces` lineage, waiver; unknown
   fencing; abandonment; termination evidence per 7.1 v6; budgets (estimates, reservations, provisional vs complete);
   limits and storage reserve; global capacity limits; deadlines.
4. **MCP tools** on the 7.4d server: `orch.plan`, `orch.assign`, `orch.cancel`, `orch.ask`, `orch.requestApproval`,
   `orch.note`, `orch.finish`, `orch.receipt` — require MCP access + an active capability (not the writes switch).
5. **HTTP + contract** (`docs/API-CONTRACT.md` + `packages/contract` together): create orchestration (paired; includes the
   acknowledgement and preflight result), get snapshot (asOfSeq), stream events, decisions (gate, inquiry answer,
   budget, waiver, abandonment, fence lift after reconciliation) with expected revisions, Stop/Pause/Resume; the
   ownership transition table and `409 orchestration_owned` guards on rooms/messages/briefs/flow/team actions.
6. **Fake adapter:** a scripted fake lead that calls the orch tools so e2e (7.5b) and server tests can run a whole
   orchestration without models.

## Done when
Server tests (fake adapter, recorded fixtures, no model calls) for every test listed in the design (v1, v2, v3 lists):
event loop, batching, refusals, limits, budgets, every gate policy, Stop during admission and late admission, unknown
steps, restart recovery, journal-detected restores (DB-only, after Stop) and the restore script, capability rules
(cross-session, stale generation, redaction, step scanning), command receipts (lost reply, conflict, retry), finish with
queued work, cancel + replacement, quota exhaustion. `pnpm check` green.
