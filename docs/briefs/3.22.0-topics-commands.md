## Build
1. **One conversation per chat.** A group chat shows the messages of all its jobs (topics) in time order. Each topic
   starts with a divider: "Topic · <title> · <state>" (working / waiting on you / done / closed), as the mock-up. The
   default job's messages are the chat's general conversation (no divider before them). The desktop **job tabs and
   filter chips go**; the Info panel's Topics list stays (clicking a topic scrolls to its divider and makes it current).
   Pinned needs-you cards, exchange cards, reply versions and every existing message action keep working inside the
   merged stream.
   - **Data.** Find how messages are read today (`GET /api/rooms/:id/messages?job=…`). If there is no way to read a
     room's messages across its jobs in one ordered, paged read, add one server route, e.g.
     `GET /api/rooms/:roomId/messages?all=1&before=<cursor>&limit=` (messages of every non-deleted job, newest first,
     each with its `jobId`), with the contract (`packages/contract`, `docs/API-CONTRACT.md`) and route tests. The stream
     events already carry `jobId`; the client merges live messages into the one list. Keep paging (no loading every
     message of every job).
2. **The current topic.** The composer sends to the current topic: the newest open (not done/closed) topic, or the
   default job when there is none, or the one the person picked (Info › Topics, or clicking a divider). The context bar
   says where it goes: "To <lead> (owner) · in <topic>".
3. **The `/` palette** (mock-up): typing `/` at the start opens a list above the composer, in the layout flow, filtering
   as you type, arrow keys + Enter to pick, Esc to close, with a one-line description each. Commands, each calling what
   already exists where possible:
   `/new <title>` create a job (topic) in this room and make it current · `/rename <title>` the current topic ·
   `/done` close the current topic · `/reopen` reopen the current topic · `/lead @agent` set the room's lead ·
   `/add @agent`, `/remove @agent` room members · `/workspace <name>` the room's workspace (3.19 routes; `none` clears)
   · and the existing ones: `/assign @agent <task>`, `/model`, `/usage`, `/compress` (and `/orchestrate` when enabled).
   A command that changes something says so in the stream as a small system line ("You made builder the owner").
   Unknown command: a plain-words hint, nothing sent.
4. **Context bar** under the composer (mock-up): "To <who> · in <topic>", the context meter (reuse the composer's
   existing context reading, `context-meter.ts` / `/usage` data), the model of the agent addressed, and "/compress when
   it fills up". Only show what the existing data provides; no new server data for it.
5. **Phone**: the same merged conversation with dividers; the `?jobs=1` list becomes "All topics".
