# 9.2 Theme engine and safety (PLAN 9.2; design docs/briefs/9-themes.md §2–4, §6, §10; decision 90)

Goal: the web app applies a theme manifest + CSS safely; built-in packs become themes; the owner can always get back.

Binding: `packages/contract/src/themes.ts` and API-CONTRACT § 16 (the server routes are being built in parallel as 9.1:
in unit tests and e2e, mock `/api/themes*` and `/api/look` with `page.route` exactly per the contract).

Work:
1. `apps/web/src/themes/engine.ts`: manifest → `<html>` attributes (`data-pack` stays for 8.3 packs; new
   `data-radius`, `data-density`, `data-elevation`, `data-surface`, `data-border`, `data-nav`, `data-width`,
   `data-chat`), a generated token stylesheet (`--<token>` for light/dark from `colors`; fonts → `--font-*`), `@font-face`
   rules from `fonts.faces` (asset URLs), a `<link rel="stylesheet">` to `/api/themes/<id>/style.css` **after** the app's
   CSS, background image. Only the 40 public colour tokens; anything else ignored. Apply/remove cleanly when switching.
   Attribute *styles* for elevation/surface/border/radius/density are written here in `themes/variants.css` (minimal:
   cards and panels; 9.3 extends to every component).
2. `apps/web/src/themes/sanitise.ts`: per design § 4.1 — parse with `new CSSStyleSheet().replaceSync()` (guard for
   environments without it: drop everything), walk rules recursively (media/supports/layer blocks), drop and report
   per `ThemeSanitiseReport`, re-serialise. Applied to the CSS **before** linking: fetch the stylesheet text, sanitise,
   and apply the cleaned text through a constructed stylesheet (`document.adoptedStyleSheets`) instead of the `<link>` if
   simpler — either way only sanitised CSS reaches the page.
3. **Protected surfaces**: add `data-protected` to the components in design § 4.3 (find them: ApprovalCard,
   RunDecisions cards, CodingCards reach/unknown cost, password dialogs, permission/sandbox settings, Needs-you badge and
   AskingCard, AgentGlyph, error toasts, the Reset look control). `styles/protected.css` in `@layer score-protected`
   re-asserts with `!important`: `position: relative`, `isolation: isolate`, `z-index` floor, `opacity: 1`,
   `visibility: visible`, `display` per element, `transform: none`, `filter: none`, `clip-path: none`, and colours from
   the default tokens when the theme's pair fails WCAG AA (compute in the engine; set `data-contrast-fallback`).
4. **Escape hatches**: `?look=safe` (skips theme + override for this page load, shows a banner "Safe look: your theme is
   off for this visit" with a link to Settings › Look), `Ctrl+Shift+0` and a ⌘K command "Reset look on this device"
   (clears the per-device override and cache), a theme that throws during apply is skipped with a banner.
5. **Shared + per-device**: `useLook()` reads `GET /api/themes` (`active`, `mode`) and `GET /api/themes/:id`; listens to
   `look.changed` (stream; if 9.1's event isn't merged yet, poll on focus); per-device override in localStorage
   (`score.look.device` = theme id or null), try/catch everywhere. Settings › Look: "Theme for every device" (calls
   `PUT /api/look`) and "This device" (Shared / a theme), plus the existing light/dark/system. Keep 8.3's style cards
   (now listing all themes from the API) — show them always (owner found the hidden picker hard to find); this changes the
   Settings baselines: update exactly those and say so.
6. Boot: extend `public/boot-look.js` to apply the cached attributes + token CSS text (`score.look.cache`) before first
   paint, still CSP-safe (no inline script; inserting a `<style>` text node is allowed by `style-src 'unsafe-inline'`).
7. 8.3 packs as built-in themes: `paper`, `night`, `dense` keep their CSS files; the engine maps their ids to the pack
   attributes. Score default pixel-identical (every existing baseline unchanged except Settings › Look).

Tests (fail without the change): sanitiser unit tests (each drop reason; nested @media; escapes resolved by the parser;
`:has()` reaching `[data-protected]`); engine tests (attributes, tokens, fonts, unknown tokens ignored, switching cleans
up); e2e with a mocked **hostile theme** (fake "Approve" overlay via `::after`, `display:none` on Needs-you,
`opacity:0` on Deny, `z-index: 9999` cover, `!important`) asserting the real approval card stays visible, on top
(`elementFromPoint`), with its own labels; e2e for `?look=safe`, the shortcut, the ⌘K entry, per-device override and
`look.changed` switching another page.
