## Design (from the lead)

- **Seam**: 2.1 left `routeMessage()` in the message POST path; 2.2's pure `parseMessage(text, agents)` is in
  `apps/server/src/domain/parse.ts`. Routing lives in `apps/server/src/domain/routing.ts` (decisions, pure where
  possible) + side effects through the port.
- **Targets** for a human message: explicit `to` ∪ known @mentions (deduped, order kept); none → the room's
  `leadAgentId` (direct room → its agent); no lead → 400 `no_recipient`. `routedTo` in the response.
- **Commands** (`parseMessage().command`): `/assign` → `port.createTask` (2.9) → `{kind:'assign', taskId}`; `/model`
  → route the remaining message with that model (one-shot, `startRun({model})`); `/routine`, `/remember`, `/skill` →
  `501 not_implemented` for now (their tasks come later) with the parser's usage text; `invalid` → 400 with `error`
  and `usage`.
- **Runs**: for each target, `port.startRun({ agentId, input, turnId, sessionId? })` where `input` = the message text
  plus a compact room context (the last 10 messages as `author: text` lines, ≤ 8 KB, redacted) and `turnId` =
  deterministic per (message, agent) so retries are idempotent. Create the agent's reply message immediately
  (`author:{kind:'agent'}`, `streaming:true`, `parts:[]`, `refs:[{kind:'run',runId}]`) and keep a
  `message_runs(message_id, run_id, room_id, agent_id, chain_id, hop)` mapping (migration `0011_message_runs.sql`, reserved).
- **Streaming** (2.4): run output deltas → `message.delta {messageId, roomId, append}` and the message's text part;
  run completion → `message.completed`, `streaming:false`, and a `tools` part `{summary, runId}` when the run used
  tools ("Ran 3 commands and edited 2 files" from the run's tool calls). Live: the run SSE translator currently ignores
  `message.delta`/`message.interim` (`apps/server/src/hermes/live/translate.ts`) — translate them into this message
  (only for runs in `message_runs`; keep everything through the single ingest path and the run's checkpoint). Fake:
  `startRun` in `fake-port.ts` must emit a few deltas then completion (with the scenario's speed).
- **Hand-offs**: when an agent message completes and its text @mentions other known agents, start runs for them with
  that reply as input (same chain). **Hop limit**: 4 hops per chain (configurable constant); **ping-pong guard**: an
  agent can't be handed the chain back by the agent it just handed to within the same chain (A→B→A stops). Stopped
  hand-offs add a `system` text part "Hand-off limit reached" to the last message; emit `handoff.created` (contract)
  for each started hand-off. All decisions table-tested.
- Idempotency: the message POST already supports `Idempotency-Key`; routing must not start runs twice on replay.
