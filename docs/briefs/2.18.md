## Design (from the lead)

- **Mapping** (see the review): Go ahead = pattern keys in `command_allowlist`; Ask me = dangerous categories not
  allowlisted; Never = globs in `approvals.deny`; plus `approvals.mode` (manual/smart/off) shown with plain
  consequences. Pinned list of valid pattern keys from the tested Hermes version
  (`../reference/hermes-agent/tools/approval_detection.py`), with human labels (e.g. "Delete in root path"); unknown keys
  found in config are read-only.
- **Reads**: `hermes -p <p> config get --json command_allowlist|approvals` (add these exact shapes to the CLI capture
  allowlist). **Writes**: only `hermes -p <p> config set command_allowlist <json>`, `config set approvals.deny <json>`,
  `config set approvals.mode <mode>`, with read → modify → write → re-read verify and a ≤ 3 retry merge (review finding
  3). Never any other key.
- **Endpoints** (contract §10 + §8; extend the contract schemas in `packages/contract/src/http.ts` / `settings.ts` as
  needed and note it): `GET /api/settings/rules` → `{ mode, goAhead, askMe, never, drift: { agentId, differs }[] }` with
  `Rule = { id, label, pattern }`; **H** `PUT /api/settings/rules` (team baseline → every profile; `?dryRun=1` → `{ preview:
diff }`); **H** `PATCH /api/agents/:agentId/permissions/:permId {level}` — stricter only relative to the team baseline
  (remove Go-ahead, add Never; 400 `not_stricter` otherwise); `AgentDetail.permissions` filled. `POST
/api/settings/rules/apply/:agentId` re-applies the baseline to a drifted profile.
- **UI**: the Settings "Rules and approvals" section (dark card in `docs/design/settings.png`: Go ahead / Ask me / Never
  columns, "Add a rule"), the approval-style selector with consequences, the guardrail note for Never, drift list; the
  Team Permissions tab (per-agent, stricter-only controls).
- **Fake**: in-memory team baseline and per-agent overrides with the same rules.
