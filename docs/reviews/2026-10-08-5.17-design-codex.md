1. **Critical — An ended attempt does not prove that Stop stopped the worker.**

   `reclaim` attempts host-local termination, using SIGTERM and potentially SIGKILL. It can refuse signaling or fail to terminate. Crucially, **manual reclaim still releases the claim and closes the attempt** after that failure. Checking `task_runs.ended_at` therefore permits a false `{ok:true}` while model work continues. Hermes explicitly tests an operator reclaim that succeeds while sending no signal to a live worker. [Hermes kanban_db_dispatch.py:443](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db_dispatch.py:443), [kanban_db.py:2652](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db.py:2652), [test_kanban_worker_pid_fingerprint.py:139](/home/raven/.hermes/hermes-agent/tests/hermes_cli/test_kanban_worker_pid_fingerprint.py:139)

   **Design change:** Separate attempt closure from process termination. Stop success requires authoritative termination evidence for the selected worker, with host and process-fingerprint checks. Missing or unverified identity must produce an explicit unsupported/failed result.

2. **High — Reclaim enables another dispatch and cannot fence the selected attempt.**

   Reclaim restores `ready` or `review`; it resets the failure counter. Consequently, a successful termination can immediately be followed by another worker. The CLI accepts a **task id**, without an expected attempt id or claim lock. A delayed command or retry can reclaim a successor attempt instead of the one Score selected. Hermes’s internal CAS protects the lock read by that command, not Score’s earlier selection. [kanban_db.py:2641](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db.py:2641), [kanban_db.py:2406](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db.py:2406), [kanban.py:600](/home/raven/.hermes/hermes-agent/hermes_cli/kanban.py:600)

   `block` supplies a hold but closes the attempt without immediate termination; terminal-worker cleanup has a grace period. It also cannot be substituted for the contracted Stop without further work. [kanban_db.py:3353](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db.py:3353), [kanban_db_dispatch.py:504](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db_dispatch.py:504)

   **Design change:** Require a Hermes operation fenced by board, attempt and claim that holds dispatch and verifies termination. Reclaim-then-block has a dispatch race. Persist Stop intent for retries. Route controls through stored provenance: today [live-port.ts:634](/home/raven/score/apps/server/src/hermes/live/live-port.ts:634) sends every stop to the gateway Runs API.

**Corrected design I would approve**

- Materialize one Kanban run per proven claimed attempt, using a durable source/history/attempt mapping. Keep synthetic transitions in task history.
- Extend the existing event tailer with bounded baseline/reconciliation. Atomically update runs, task links, derived events and checkpoint. Preserve raw outcomes alongside truthful terminal statuses.
- Carry exact board/attempt/claim identities through the bridge and spool. Capture per-event ownership; persist observed session/model information and explicit continuation/helper links. Resolve early and late evidence durably.
- Update Flow, Now, logs and Team history for attempt roles and retries. Keep attempts finite, preserve idle gaps, and distinguish task disposition from attempt outcome.
- Keep Reports spend sourced once from session accounting. Use disjoint time categories and preserve unknown costs.
- Offer Kanban Stop only with an attempt-fenced Hermes hold-and-terminate operation and verified termination. Until supported, expose the limitation explicitly; reclaim remains a retry action.
- Land the contract and migration prerequisites with recorded/fake tests covering synthetic rows, repeated ids, same-second retries, event reordering, session rotation, failed termination, successor races, accounting and redaction. A fake Stop test must prove these semantics before 5.17 is considered complete.
