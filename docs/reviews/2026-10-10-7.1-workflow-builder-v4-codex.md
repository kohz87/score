### [high] Ten minutes without a session is not proof of non-dispatch

**Where:** [V4 reconciliation rule](/home/raven/score/docs/briefs/7.1-workflow-builder.md:6), [Hermes admission](/home/raven/reference/hermes-agent/gateway/platforms/api_server_runs.py:718), [session persistence](/home/raven/reference/hermes-agent/run_agent.py:349).

**What happens:** Hermes accepts attempt A and its response disappears. Execution or persistence is delayed, or session creation fails. After ten minutes, Score labels A `not_dispatched` and admits B. A can still execute or already have acted.

**Why:** Admission precedes execution and session persistence. The inspected Hermes code catches session-creation failures and allows execution to continue. There is no enforced ten-minute persistence guarantee. Database replacement or restored history also makes absence inconclusive. A unique session ID helps identify positive evidence; it cannot establish negative evidence.

**Change:** Make the horizon an escalation to `unknown`. Accept `not_dispatched` only with proof that the request was never sent and its sender is permanently fenced, or authoritative runtime evidence excluding future dispatch. Treat unavailable, changed, or incomplete databases as unknown. Test delayed execution beyond ten minutes, failed persistence, and database restore.

### [high] A session row does not recover the handle needed to observe or stop work

**Where:** [“Attach and observe”](/home/raven/score/docs/briefs/7.1-workflow-builder.md:9), [session/message readers](/home/raven/score/apps/server/src/hermes/live/sessions.ts:8), [runtime control methods](/home/raven/score/apps/server/src/hermes/live/gateway.ts:338).

**What happens:** After a lost admission response, Score finds the attempt’s user row but still does not know its Hermes `run_id`. It cannot attach the run stream, poll canonical termination, or deliver the owed Stop.

**Why:** The existing session readers provide no session-to-runtime-run mapping. Status, events, and Stop require the runtime run ID. The unique `wf-…` session ID is a different identity. The existing [recovery code](/home/raven/score/apps/server/src/hermes/live/recover.ts:77) also requires input matching and turn boundaries; any user row is insufficient evidence of the original turn.

**Change:** Specify a supported, read-only reconciliation operation returning a verified run handle under the frozen profile and credential generation. Capability-gate that operation. When the handle cannot be recovered, retain uncertainty and show that external Stop cannot be confirmed. Do not promote transcript evidence into canonical runtime status.

### [high] Parent termination leaves detached subagents outside the quiescence barrier

**Where:** [Termination barrier](/home/raven/score/docs/briefs/7.1-workflow-builder.md:14), [child-session scope](/home/raven/score/docs/briefs/7.1-workflow-builder.md:41), [Hermes background delegation](/home/raven/reference/hermes-agent/tools/delegate_tool_dispatch.py:417).

**What happens:** An agent starts a detached child, returns a final reply, and reaches canonical `completed`. Score releases successors or reports success while the child continues spending and modifying files. Stopping the completed parent does not establish child termination.

**Why:** V4 includes children for spend and replay but excludes them from execution obligations. The inspected Runs implementation enables history-delivered detached results for explicit sessions. Background dispatch [removes children from parent interrupt propagation](/home/raven/reference/hermes-agent/tools/delegate_tool_child_run.py:85), and [Stop returns immediately for terminal parents](/home/raven/reference/hermes-agent/gateway/platforms/api_server_runs.py:1260). The capability matrix does not exclude this behavior.

**Change:** Initially require an enforceable runtime policy excluding detached agent execution, or define durable execution-tree ownership with child control handles and termination evidence. Retain reservations and capacity until that tree is quiescent. Test parent completion and parent Stop while a child remains active.

### [medium] The existing lineage reader cannot provide complete attribution

**Where:** [V4 spend/replay scope](/home/raven/score/docs/briefs/7.1-workflow-builder.md:41), [compression reader](/home/raven/score/apps/server/src/hermes/live/recover.ts:40), [frame storage](/home/raven/score/apps/server/src/domain/watch-frames.ts:283).

**What happens:** Subagent costs and frames are omitted. An ambiguous compression fork is silently treated as a complete prefix. Frames arriving before run association remain unassociated, and replay can still include unrelated markers or live state.

**Why:** `compressionLineage()` follows one compression continuation, stops at forks or twenty hops, and returns no completeness indicator. It deliberately does not traverse delegation trees. Watch stores `run_id`, without a dedicated durable session/attempt identity; its markers, browser context, gaps, and live state remain agent-scoped. Merely following session IDs does not repair those projections.

**Change:** Add adapter lineage facts with ownership, provenance, and explicit completeness. Persist attempt/session associations, including unresolved associations. Scope frames, markers, gaps, pagination, browser context, and live state together. Define final cost settlement before releasing reservations; incomplete lineage must actually produce unknown spend.

### [medium] Existing controls still bypass or strand workflow ownership

**Where:** [V4 brief controls](/home/raven/score/docs/briefs/7.1-workflow-builder.md:44), [Team Resume](/home/raven/score/apps/server/src/http/team-pause.ts:96), [message controls](/home/raven/score/apps/server/src/http/rooms.ts:577), [current brief schema](/home/raven/score/packages/contract/src/briefs.ts:12).

**What happens:** Team Pause reaches delegated brief controls, but Team Resume directly clears legacy flags and never releases the executor’s corresponding hold. Workflow reply Retry can use ordinary dispatch; message Stop calls the adapter directly without the executor’s cancellation semantics.

**Why:** Ownership on briefs does not cover every route affecting their messages, rooms, or runs. V4’s blanket refusal of “holds” also needs reconciliation with the retained requirement for independent team and agent holds. Adding `owner` does not resolve `finished` versus `done/failed`, or make Now’s existing runtime-approval type represent workflow gates and budget decisions.

**Change:** Define a control matrix covering team/agent controls, message Retry/Stop, rewind, summaries, brief controls, and Flow controls. Delegate or reject workflow-owned actions explicitly, preserving hold ownership. Supply complete request, response, event, conflict, history, status-mapping, and human-action schemas before implementation.

### [medium] Safe run pruning still lacks retention boundaries and storage quotas

**Where:** [V4 retention](/home/raven/score/docs/briefs/7.1-workflow-builder.md:47), [retained limits](/home/raven/score/docs/briefs/7.1-workflow-builder.md:116), [independent frame pruning](/home/raven/score/apps/server/src/hub/retire.ts:96).

**What happens:** Workflow rows remain protected while another cleanup path removes their replay evidence. Definitions and versions accumulate forever, and high run throughput can exhaust storage despite bounded concurrency.

**Why:** “Finished runs older than 90 days” does not identify the retention timestamp. Existing Watch cleanup independently deletes seven-day-old frames without consulting workflow obligations or recording an attempt-specific retention boundary. Associated rooms, messages, intents, and ownership records have no cleanup policy or quota.

**Change:** Define retention from a persisted completion/quiescence timestamp. Specify which evidence and tombstones remain pinned, associated-data cleanup, and actual Watch retention floors. Add storage quotas with deterministic refusal/backpressure that preserves unresolved execution state.

### [medium] Unbounded verdict reasons conflict with the attempt storage limit

**Where:** [Untruncated verdicts](/home/raven/score/docs/briefs/7.1-workflow-builder.md:49), [verdict format](/home/raven/score/docs/briefs/7.1-workflow-builder.md:104), [64 KB attempt limit](/home/raven/score/docs/briefs/7.1-workflow-builder.md:116).

**What happens:** A full reply contains one valid verdict block with a reason exceeding 64 KB. Preserving that verdict violates the attempt limit; enforcing the limit requires an unspecified fallback during result acceptance.

**Why:** Strict schema validation does not itself bound string sizes. Parsing before truncation fixes block counting, but “truncation never applies” requires an independently bounded verdict representation.

**Change:** Bound the block and reason in UTF-8 bytes; oversized or incomplete source produces no verdict. Define deterministic envelope-size handling while preserving atomic result acceptance. Test oversized reasons, boundary-spanning blocks, and unavailable complete final text.
