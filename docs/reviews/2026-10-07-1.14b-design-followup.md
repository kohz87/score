Additional defects in the revised rules, including failures in the requested edge cases:

16. **Critical — The hook key is not an execution identity.** [Rule](/home/raven/score/docs/briefs/1.14b.md:149): incarnation + tool ID, with “superseded” and newest-human matching. Hermes [uniquifies only within one assistant batch](/home/raven/reference/hermes-agent/agent/message_sanitization.py:531); deterministic fallback IDs repeat for identical calls, and provider IDs [repeat across completions](/home/raven/reference/hermes-agent/agent/agent_runtime_helpers.py:3103). Same-process subagents can collide too. A-pre → B-pre → A-deny can withdraw A as superseded and deny B. CLI [`!` approvals](/home/raven/reference/hermes-agent/hermes_cli/bang_shell.py:71) can have empty IDs: their posts remain unmatched. Separate Kanban-worker incarnations prevent cross-process collisions, but do not fix reuse within a worker. **Minimal change:** mint execution and gate-occurrence IDs at the producer; include session/turn scope, bind supersession explicitly, and retain empty-key stages as uncorrelated observations.

17. **High — Request-less Score-run signals can never reconcile.** [Rule](/home/raven/score/docs/briefs/1.14b.md:160): create nothing without `requestId`; SSE has no tool ID. Scenario: bridge pre/post arrive, SSE is unavailable or truncated; no human row or decision is projected. Even if SSE later arrives, its request ID cannot match those signals. **Minimal change:** retain a view-only hook-stage row; enrich it only through an exact producer binding or exact run-status approval snapshot.

18. **High — Every queued bridge decision fails its own lease check.** [Rule](/home/raven/score/docs/briefs/1.14b.md:218): fail deliveries whose approval is “no longer actionable.” Actionability requires no delivery, or a definitively failed delivery. Scenario: POST inserts `intent`; GET sees the delivery and fails it before leasing. **Minimal change:** separate permission to submit a decision from eligibility to deliver an existing decision.

19. **High — Late application proof can be discarded in `intent`.** [Rule](/home/raven/score/docs/briefs/1.14b.md:224): positive acknowledgements transition only `delivering|unknown|failed`. Scenario: lease 1 applies; lease 2 reports failure and returns the delivery to `intent`; lease 1’s delayed positive ack receives 204 without the listed transition. Its proof can be discarded permanently. **Minimal change:** accept verified positive receipts from every uncertainty state, including `intent`; persist issued lease identities.

20. **High — Bridge sweeps erase application uncertainty.** [Rule](/home/raven/score/docs/briefs/1.14b.md:230): an `intent` becomes `failed` when its producer disappears or approval closes. A failed lease can return to `intent` with `maybe_applied=1`; the sweep then labels a possibly applied decision failed. Port “other 4xx” has the same defect after an ambiguous attempt. **Minimal change:** every terminal classification must respect the monotone `maybe_applied` flag; uncertainty becomes `unknown`.

21. **High — Transport decisions become orphan signals.** [Rules](/home/raven/score/docs/briefs/1.14b.md:156): discard transport request ID on creation, but prioritize request ID when matching posts. Hermes supplies that ID on [both hooks](/home/raven/reference/hermes-agent/tools/approval_prompt.py:238). Thus an answered transport row remains pending until expiry. **Minimal change:** store a separately namespaced transport target ID and use it for both hooks.

22. **High — Completion reconciliation depends on arrival order.** [Rules](/home/raven/score/docs/briefs/1.14b.md:172): tool completion withdraws an open human row; later choice evidence changes it to `decided`. Reverse arrival produces `executed|blocked`. **Minimal change:** persist completion evidence and recompute phase when decision evidence arrives.

23. **High — Manual retry retains an exhausted budget.** [Rule](/home/raven/score/docs/briefs/1.14b.md:199): reset state to `intent`, without resetting attempts; delivery still permits at most four attempts. A repaired connection cannot recover an exhausted decision. **Minimal change:** preserve decision identity while starting a fresh, bounded retry cycle after proven non-application.
