## Verdict

**Score works with `origin/main` as-is: 0 breaking items.** Three things need a human decision or a follow-up at upgrade time:

1. **The compatibility gate will (correctly) switch `gateway-approvals` off** on the new build, because `codeSha` and
   `codeVersion` differ from the only tested entry (`evaluateCompatibility`, `fingerprint.ts`). `score-runs` stays on. A
   tested entry for the new build can only be recorded from a live run (its `codeVersion`, `cli` and id are not derivable
   from source; see "Fingerprint" below). Nothing was added to `tested-fingerprints.json` so no untested build is
   claimed as tested.
2. Three new dangerous-command pattern keys exist upstream. Score shows them **read-only** (its documented behaviour
   for unknown keys) until `pattern-keys.ts` is regenerated for the new build.
3. `config-index.json` (advanced-settings search) still lists four removed `security.tirith_*` keys and lacks keys added
   upstream. Cosmetic.

Not verifiable from source, so listed as the live-drill checklist at the end: plugin install through the new `pm`
dependency sync, and the real `codeVersion` string (it is derived from tags in the owner's clone).

## Side observation (pre-existing, both versions)

`KNOWN_PATTERN_KEYS` includes `fork bomb` and `kill all processes`, which are also in Hermes's `HARDLINE_PATTERNS`
(`approval_detection.py`). Score therefore offers go-ahead rules for two actions Hermes never lets through. Harmless
(allowlisting cannot override a hard line) but misleading; consider hiding them.
