**BLOCK — 1 P1, 5 P2.**

1. **P1 — Policy remap permits `full` access.** [executor.ts:1505](apps/server/src/domain/orchestration/executor.ts:1505), [decisions.ts:622](apps/server/src/domain/orchestration/decisions.ts:622). Change a blocked worker to `full`; remap accepts its current policy without repeating the permission validation. The probe returned `allowed: true` and Codex arguments `-s danger-full-access`; the reach description still claimed workspace-only writes. **Fix:** reject forbidden permissions in incoming remap policies and stored policies at release.

2. **P2 — Policy remap targets the retired predecessor after renewal.** [workflows/decisions.ts:260](apps/server/src/domain/workflows/decisions.ts:260), [orchestration/decisions.ts:615](apps/server/src/domain/orchestration/decisions.ts:615). Renewal leaves the predecessor `suspended`; remap selects the first suspended attempt. Probe: predecessor received policy B, current attempt retained A and failed admission; another remap then conflicts. **Fix:** clear suspension on retirement and select only the current, created, suspended attempt.

3. **P2 — Withdrawn inputs can grant an extra execution retry.** [planner.ts:269](apps/server/src/domain/workflows/planner.ts:269), [planner.ts:559](apps/server/src/domain/workflows/planner.ts:559). After one executed failure, withdraw the second try’s inputs before send. Refunding changes `attempts_used` from 2 to 1; Retry classifies its blocked predecessor as a remap and keeps 1. Probe: another failure queued a third execution despite `attempts_max = 2`. **Fix:** distinguish withdrawal replacements from remaps and consume the refunded slot once.

4. **P2 — Twenty readiness refusals strand coding nodes.** [planner.ts:351](apps/server/src/domain/workflows/planner.ts:351), [decisions.ts:237](apps/server/src/domain/workflows/decisions.ts:237). Readiness exhaustion leaves `needs_person = 1`, without suspending the attempt or setting `held_back`. After three renewals, the probe still held one concurrency slot and $0.50; Try again returned `409` instead of failing the node. **Fix:** route coding readiness exhaustion through the same suspended hold, coding card, and terminal renewal-cap handling.

5. **P2 — Restore silently loses renewals.** [decisions.ts:250](apps/server/src/domain/workflows/decisions.ts:250), [fence.ts:305](apps/server/src/domain/orchestration/fence.ts:305). Restore a backup taken before renewal while its successor remains unsent. Probe: `renewals` reverted from 1 to 0, while `verifyJournal()` returned no mismatch. The transition records neither the count nor successor identity. **Fix:** journal renewal counts and predecessor/successor identities, preserving and verifying them through restore and compaction.

6. **P2 — Retained coding inventory can exhaust protected storage.** [runs.ts:102](apps/server/src/domain/workflows/runs.ts:102), [executor.ts:2224](apps/server/src/domain/orchestration/executor.ts:2224). `codingSteps` bounds releases, but multiple unsent, suspended nodes retain charged inputs. With ordinary storage exhausted, a valid 24-node fan-out and `codingSteps = 1` retained 645,364 bytes against a 370,944-byte coding partition, exceeding the entire run reserve by 12,276 bytes. **Fix:** reserve unsent inventory independently of the release limit and enforce capacity before retaining it.
