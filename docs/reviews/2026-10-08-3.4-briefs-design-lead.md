# Design review: 3.4 Briefs model (lead, 2026-10-08)

Codex was out of credits, so the lead did the adversarial design review PLAN requires before 3.4 (owner: "do it yourself
if codex is unavailable"). Inputs: ARCHITECTURE (owned state `briefs`, `brief_tasks`, `room_tasks`), contract §4 Flow,
`message_runs` (2.3), the steps model (2.10), the composer's Plan first toggle (2.6, accepted but unused so far), and Hermes
0.21.5: `POST /v1/runs/{id}/stop` (Score port `stopRun`), `hermes kanban block|unblock`.

## The model (decision)
A **brief** is a human message in a room plus everything it causes. Its id is the root message id, which is already the
`chain_id` of every agent turn and hand-off it caused.

| Part of a brief | Source | Link |
|---|---|---|
| The ask | the human message | exact: root message id |
| Turns and hand-offs | `message_runs` with `chain_id` = brief | exact |
| Tasks | `/assign` in that message, tasks created from an approved plan, and their Kanban children (`--parent`) | exact: recorded in `brief_tasks` when Score creates them; children by Kanban parent edges |
| Runs | Score runs of those turns and Kanban runs of those tasks | exact |

Storage: `briefs(id, room_id, title, started_at, started_by, paused_at)` and `brief_tasks(brief_id, task_id, origin:
'assign'|'plan'|'child')` (owned state, migration). Status is derived, never stored: `paused` when `paused_at` is set;
otherwise `running` if any turn or run is active or waiting; `failed` if the last turn or any task failed and nothing is
running; else `done`.

## Findings and decisions
1. **High: guessing links would make Flow lie.** An agent may create Kanban tasks during a turn, but Hermes doesn't
   record which Score turn caused them.
   *Decision:* exact links only, the same rule as approvals:
   - a task belongs to a brief if Score created it for the brief, or if it's a Kanban child of a task already in the brief;
   - other tasks stay out of Flow, even when the timing suggests a link;
   - Flow shows "Work this brief started outside Score isn't shown", once, when the brief's agents have unlinked tasks
     created in the brief's window.
2. **High: "Plan first" must not turn free agent text into actions on its own.**
   *Decision:*
   - With `planFirst`, the lead's turn gets a prompt addendum asking for the plan as a Markdown checklist, one step per
     line, `- [ ] @agent step` (the 2.10 steps syntax plus the 2.2 mention parser).
   - Score parses the reply into a `plan` message part (lanes of `planned` blocks, `briefId`).
   - Nothing runs until the person presses **Start plan** (**H**). That creates one Kanban task per step through the
     existing create path (exact `brief_tasks` rows, `origin: 'plan'`, dependencies in order). It is idempotent per
     plan message.
   - Steps that don't parse are shown as text and not created.
3. **High: pause must say what it can and can't do.** A running Hermes turn can only be stopped, not suspended.
   *Decision:* `POST /api/briefs/:id/pause` (**H**):
   - sets `paused_at` and holds Score's own queue for the brief (no new turns or hand-offs; queued ones wait);
   - blocks the brief's not-started tasks with `hermes kanban block --reason "Paused from Score"`, recording which ones
     it blocked;
   - leaves running turns and runs alone (the UI says "Current steps finish; nothing new starts").
   Resume unblocks only the tasks Score blocked, and releases the queue. Stopping a step is separate:
   `POST /api/flow/nodes/:nodeId/stop` (**H**) stops that node's active run through `stopRun`.
4. **Medium: node identity.**
   *Decision:* node ids are stable and typed: `brief:<id>`, `task:<taskId>`, `turn:<messageId>` (a turn with no task is
   its own step). Edges:
   - `flow`: dependency, parent to child;
   - `handoff`: `message_runs` hop;
   - `review`: a task handed to a reviewer;
   - `sent_back`: a task moved back from review;
   - `planned`: a plan step not started yet.
   `layout` hints come from 3.5 on the client; the server sends `col`/`row` from dependency depth only.
5. **Medium: unbounded briefs.**
   *Decision:*
   - `GET /api/briefs?status=active|recent`: active = running or paused; recent = done or failed in the last 7 days,
     newest 50;
   - a flow is capped at 200 nodes, and the rest are summarised as "+N more steps";
   - briefs are kept as long as their messages.
6. **Medium: stream.**
   *Decision:*
   - new event `brief.upserted { brief: BriefSummary }`, emitted when a brief is created, paused or resumed, or its
     derived status changes; derived through the ingest `deriveEvents` hook, the same as task updates;
   - Flow refetches its graph on `brief.upserted`, `task.upserted`, `run.*`, `message.created` and `handoff.created`
     for that brief;
   - contract §2/§4 updated before code.
7. **Low: title.** The title is the first line of the human message, redacted and capped at 120 characters.
8. **Low: stats.**
   - `spendUsd`: the sum of the brief's runs' `cost`, or null when no run has a cost;
   - `eta`: always null (Score doesn't guess);
   - `handoffs`: the number of `message_runs` hops;
   - `runningSec`: from the first turn start to now or the last end.

## Out of scope for 3.4
The Flow canvas, inspector and log UI (3.6 and 3.7). 3.4 ships the model, migration, endpoints (`/api/briefs`,
`/api/briefs/:id/flow`, pause and resume, node stop, `/api/flow/nodes/:nodeId`), the Plan first round trip and the fake
scenario brief.
