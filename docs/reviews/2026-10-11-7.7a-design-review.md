**I would block v1.** Reviewed clean `e43f5e8`, including W/X. No repository files or units changed. Installed tools report systemd 259.5, but the sandbox denies user-manager access; systemd findings use upstream documentation/source. 1. **P1 — `RemainAfterExit` defeats the deadline once the main process exits.**  
   Locations: [brief:16](docs/briefs/7.7a-coding-units.md:16), [brief:44](docs/briefs/7.7a-coding-units.md:44).

   With default `ExitType=main`, successful main-process exit enters `SERVICE_EXITED`, which disables the runtime timer. Leave a `setsid` child running, then crash Score: the child can survive indefinitely despite `RuntimeMaxSec`. The recorded probe demonstrates precisely this vulnerable state. [systemd service source](https://github.com/systemd/systemd/blob/v259/src/core/service.c).

   **Fix:** use `Type=exec`, `ExitType=cgroup`, and explicit retention settings; detect main exit separately for the leftovers grace policy. Alternatively, keep a supervisor alive until cleanup finishes. Update the proposed state machine accordingly. [ExitType documentation](https://github.com/systemd/systemd/blob/v259/man/systemd.service.xml).

2. **P1 — `inactive`/`failed` is not termination proof.**  
   Location: [brief:29](docs/briefs/7.7a-coding-units.md:29).

   Systemd eventually enters failed state even when processes remain after final SIGKILL. An uninterruptible tool therefore satisfies this brief’s ended predicate while still occupying the cgroup. [systemd stop-timeout implementation](https://github.com/systemd/systemd/blob/v259/src/core/service.c).

   **Fix:** require independently verified emptiness for every terminal state, with no pending start/restart job. On cgroup v2, use recursive `cgroup.events: populated=0`; a root `cgroup.procs` listing is not recursive. Explicitly enable task accounting, and treat unavailable metrics as unknown, never zero. [Kernel cgroup documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html), [TasksCurrent implementation](https://github.com/systemd/systemd/blob/v259/src/core/cgroup.c).

3. **P1 — “Authorised, no unit, no file” cannot prove never started.**  
   Locations: [brief:21](docs/briefs/7.7a-coding-units.md:21), [brief:26](docs/briefs/7.7a-coding-units.md:26), [brief:46](docs/briefs/7.7a-coding-units.md:46).

   Crash after spawning the `systemd-run` helper but before it submits its request. Recovery observes no unit/output and declares no-launch; the surviving helper then submits and launches work. The same race lets Stop observe “no unit” before creation and return before the CLI starts.

   **Fix:** durably transition to `launch-requested` **before** invoking any external helper. That phase means execution may have happened. Persist cancellation before delivery, reconcile outstanding helpers/jobs, and prevent late submission. Only a phase that never issued a launch request, or an authoritative refusal receipt, establishes no-launch.

4. **P1 — Transient units do not replace the restore witness required by N1.**  
   Location: [brief:48](docs/briefs/7.7a-coding-units.md:48).

   Snapshot before a launch; execute it, commit its result, collect its unit; restore the snapshot. Neither the launch row nor its unit exists. Startup enumeration detects nothing, although side effects already happened. A snapshot retaining the launch row can likewise lose its later outcome or Stop.

   **Fix:** extend the existing [external execution journal](apps/server/src/domain/orchestration/journal.ts:17) with launch requests, invocation identities, Stops and settlement tombstones. Compare it before coding admission. Unit enumeration is an additional witness for surviving work, not a durable execution history.

5. **P1 — A saved offset cannot reconstruct the current runtime’s state.**  
   Locations: [brief:37](docs/briefs/7.7a-coding-units.md:37), [service.ts:674](apps/server/src/runtimes/coding/service.ts:674), [translate.ts:26](apps/server/src/runtimes/coding/translate.ts:26), [translate.ts:281](apps/server/src/runtimes/coding/translate.ts:281).

   Read and checkpoint the final event, then crash before terminal persistence. Restart begins at EOF: final text, result and usage were only in memory. Restart between tool start/end also loses pairing. Resetting the event counter collides with existing ingest keys; resetting parser counters can erase `lossy`.

   **Fix:** atomically checkpoint observations, byte position and sufficient parser/translation state. Alternatively, reparse the retained stream from byte zero to rebuild state while deduplicating writes by `(launch, stream, record byte position, event ordinal)`. Persist loss and final-result candidates before advancing past them.

6. **P1 — Final-reply authority remains unsafe for all three supported drivers.**  
   Locations: [brief:51](docs/briefs/7.7a-coding-units.md:51), [claude.ts:185](apps/server/src/runtimes/coding/claude.ts:185), [codex.ts:100](apps/server/src/runtimes/coding/codex.ts:100), [antigravity.ts:210](apps/server/src/runtimes/coding/antigravity.ts:210), [service.ts:771](apps/server/src/runtimes/coding/service.ts:771).

   Read-only probes reproduced:
   - Claude accepts `{"type":"result"}` as success without final text.
   - Codex silently drops an `agent_message` with malformed `text`, leaves both loss counters zero, then accepts `turn.completed`.
   - Antigravity discards a differing final `response` once streamed text exists.

   The service can consequently use preliminary text as successful output.

   **Fix:** Claude authority requires a validated successful result containing final text. Codex must validate every potentially final message and preserve its identity/order through a loss-free turn. Antigravity needs an explicit final-response rule; the brief currently omits it. Unsupported OpenCode stays disabled. Remove commentary fallback from authoritative-result construction and require compatible execution disposition.

7. **P1 — Direct output files bypass mandatory redaction.**  
   Locations: [brief:17](docs/briefs/7.7a-coding-units.md:17), [brief:36](docs/briefs/7.7a-coding-units.md:36); conflicting requirement: [7.2 brief:29](docs/briefs/7.2-coding-agents.md:29).

   A CLI prints a credential in stdout/stderr. Systemd stores it immediately, before Score’s parser/redactor runs. Redacted projections do not remove the secret from retained files or backups.

   **Fix:** put a redacting spool writer inside the supervised unit, before durable storage. Create all launch artifacts exclusively in an owned 0700 directory with 0600 files; reject symlinks and unexpected existing files. The prompt’s specified mode alone does not secure the output pipeline.

8. **P1 — Bounded tailing does not bound offline disk consumption.**  
   Locations: [brief:17](docs/briefs/7.7a-coding-units.md:17), [brief:36](docs/briefs/7.7a-coding-units.md:36), [types.ts:109](apps/server/src/runtimes/coding/types.ts:109).

   While Score is down, a noisy CLI or descendant writes unlimited stdout/stderr into append files. It can fill the filesystem before its deadline, preventing Score from recording proof or Stops. Journald throttling does not limit direct file output. [Logging-limit documentation](https://github.com/systemd/systemd/blob/v259/man/systemd.exec.xml).

   **Fix:** enforce stdout, stderr and aggregate spool limits within the unit, preserve receipt capacity, and stop the cgroup on exhaustion. Define retention quotas across launches. `LimitFSIZE` alone is not an aggregate spool quota and also affects workspace files.

9. **P1 — `--setenv` does not preserve the current environment allow-list.**  
   Locations: [brief:18](docs/briefs/7.7a-coding-units.md:18), [brief:58](docs/briefs/7.7a-coding-units.md:58), [env.ts:39](apps/server/src/runtimes/coding/env.ts:39).

   User services inherit the user manager’s environment. Adding allowed variables leaves imported API keys, Score secrets or loader variables intact, even if the helper’s own environment was filtered. [Environment inheritance documentation](https://github.com/systemd/systemd/blob/v259/man/systemd.exec.xml).

   **Fix:** a trusted launcher must execute the CLI with exactly the constructed environment; also remove loader injection variables from the launcher’s unit environment. Test with harmless manager-only sentinel variables. Empty `Environment=`/`PassEnvironment=` is not a user-manager allow-list.

10. **P1 — The retained fallback still has a PID check-to-signal race after X.**  
    Locations: [brief:55](docs/briefs/7.7a-coding-units.md:55), [proc.ts:316](apps/server/src/runtimes/coding/proc.ts:316).

    The target can exit and its PID be reused after the final stat read but before `env.kill(target.pid, ...)`. My mocked probe returned `gone` while recording SIGTERM delivered to the replacement process. X narrows this window; it does not make signaling atomic.

    **Fix:** use identity-safe process handles, such as pidfds through a tested boundary, for fallback recovery. Where unavailable, retain the fence instead of signaling an uncertain numeric identity.

11. **P2 — A fresh user manager loses transient state without changing boot ID.**  
    Locations: [brief:33](docs/briefs/7.7a-coding-units.md:33), [brief:48](docs/briefs/7.7a-coding-units.md:48).

    Cold manager startup removes transient definitions when it has no serialized state. Linger does not prevent this. Thus a manager restart can erase exit status and unit witnesses on the same boot; `daemon-reexec` is a different case that normally restores serialized state. [Manager startup implementation](https://github.com/systemd/systemd/blob/v259/src/core/manager.c).

    **Fix:** record manager incarnation and durable execution receipts, distinguish reexec from fresh startup, and reconcile recorded cgroups conservatively. Missing units after manager replacement are not no-launch receipts.

12. **P2 — Stop can collect the unit before the promised terminal transaction.**  
    Locations: [brief:31](docs/briefs/7.7a-coding-units.md:31), [brief:40](docs/briefs/7.7a-coding-units.md:40), [brief:46](docs/briefs/7.7a-coding-units.md:46).

    Stop transitions the retained successful unit to inactive and makes it eligible for automatic GC. Crash before terminal persistence: main exit status and other execution metadata may already be gone. `reset-failed` also clears retained failure state/counters; it is not a stop or emptiness proof. [Unit GC documentation](https://github.com/systemd/systemd/blob/v259/man/systemd.unit.xml), [reset-failed documentation](https://github.com/systemd/systemd/blob/v259/man/systemctl.xml).

    **Fix:** produce a durable disposition receipt before deactivation can erase it, or provide retention independent of Score’s connection. Do not rely on journald: it can be volatile, rate-limited or unavailable to `journalctl --user`. [Journal configuration](https://github.com/systemd/systemd/blob/v259/man/journald.conf.xml).

13. **P2 — “Durable file” currently lacks a power-loss durability contract.**  
    Locations: [brief:21](docs/briefs/7.7a-coding-units.md:21), [brief:36](docs/briefs/7.7a-coding-units.md:36), [brief:40](docs/briefs/7.7a-coding-units.md:40), [database.ts:57](apps/server/src/db/database.ts:57).

    Append writes are not fsync receipts. After power loss, an offset/result transaction can survive while corresponding file bytes disappear, or the launch transaction can disappear under the current WAL `NORMAL` setting. Application-crash survival and power-loss survival are different guarantees.

    **Fix:** specify file/directory sync ordering and durable launch/result commits before external effects or collection. Recovery must detect missing committed bytes and preserve ambiguity rather than silently reconstructing success.

14. **P2 — Partial lines, file mutation and final draining are unspecified.**  
    Location: [brief:36](docs/briefs/7.7a-coding-units.md:36).

    Saving a read offset midway through JSON loses its prefix after restart. Parsing temporary EOF marks an unfinished record malformed. Rotation leaves the writer on the old inode; truncation followed by regrowth can evade a simple `size < offset` check. Completing immediately on unit emptiness can miss unread terminal bytes.

    **Fix:** use byte offsets at committed record boundaries, incremental UTF-8 decoding, bounded persistent skip state, and launch-qualified file identities. Forbid active-file rotation/truncation or use numbered immutable segments. Detect mutations as gaps/loss. After termination proof, drain and commit all remaining records before terminalization; use watches plus polling/stat reconciliation.

15. **P2 — A unique unit name is not an immutable invocation identity.**  
    Locations: [brief:20](docs/briefs/7.7a-coding-units.md:20), [brief:21](docs/briefs/7.7a-coding-units.md:21), [brief:48](docs/briefs/7.7a-coding-units.md:48).

    A local restart can execute a retained unit again under the same name and append another stream. Separate Score homes under one UID also see each other’s prefix and falsely classify legitimate units as lost records.

    **Fix:** bind launch records to installation scope, manager incarnation, `InvocationID`, cgroup and spool identity; fence mismatches. Use server-minted bounded IDs and validate exact `.service` names from every boundary. Reject glob characters/options, pass `--`, and never stop/reset a prefix wholesale. [Systemd invocation API](https://github.com/systemd/systemd/blob/v259/man/org.freedesktop.systemd1.xml).

16. **P2 — Argument arrays still undergo expansion; Antigravity cannot use the proposed prompt channel.**  
    Locations: [brief:18](docs/briefs/7.7a-coding-units.md:18), [brief:58](docs/briefs/7.7a-coding-units.md:58), [antigravity.ts:277](apps/server/src/runtimes/coding/antigravity.ts:277), [antigravity.ts:293](apps/server/src/runtimes/coding/antigravity.ts:293).

    `systemd-run` expands environment references in command arguments by default. An Antigravity prompt containing `$…` can change despite shell-free spawning. Antigravity currently requires `-p <prompt>`; a stdin file does not remove that prompt from argv. Systemd-run also derives the default unit description from the command line, extending prompt exposure into unit metadata/logs. [Expansion documentation](https://github.com/systemd/systemd/blob/v259/man/systemd-run.xml), [Description construction](https://github.com/systemd/systemd/blob/v259/src/run/run.c).

    **Fix:** set `--expand-environment=no`, use a neutral explicit description and bind the prepared executable/argv. Require a supported file/stdin channel for Antigravity, or explicitly narrow the security promise and supported scope; a wrapper cannot conceal its eventual `-p` argv.

17. **P2 — Deadline and Stop policy do not match the promised wall-clock/contract semantics.**  
    Locations: [brief:44](docs/briefs/7.7a-coding-units.md:44), [brief:46](docs/briefs/7.7a-coding-units.md:46), [API contract:1027](docs/API-CONTRACT.md:1027), [service.ts:670](apps/server/src/runtimes/coding/service.ts:670).

    Runtime timers use `CLOCK_MONOTONIC`, which excludes suspend. Expiry starts termination; it does not mean every task is dead at that instant. Unspecified stop timeouts inherit host settings. The proposed TERM→KILL sequence also changes today’s INT→TERM→KILL contract. [Timer implementation](https://github.com/systemd/systemd/blob/v259/src/core/unit.c), [Kernel clocks](https://docs.kernel.org/core-api/timekeeping.html).

    **Fix:** define the clock and grace allowance, persist one turn deadline across fallback launches, set explicit stop properties, and update or preserve the signal contract. Persist stop cause: `Result=timeout` can also describe a stop timeout, so it alone cannot justify “stopped at its time limit.”

18. **P2 — Cgroup emptiness proves only work retained in that subtree.**  
    Location: [brief:19](docs/briefs/7.7a-coding-units.md:19).

    `setsid` stays contained, but a same-user tool can submit another user service/scope, migrate through available manager APIs, or schedule work through an external daemon. Emptying the original cgroup then does not prove that all work it initiated ended. Antigravity already advertises scheduling/subagents.

    **Fix:** scope the guarantee precisely. For stronger worker guarantees, restrict manager/cgroup access and unsupervised delegation through an OS boundary, or explicitly retain the accepted residual risk. D7.1’s same-user acceptance does not establish whole-job containment. [Systemd process-management API](https://github.com/systemd/systemd/blob/v259/man/org.freedesktop.systemd1.xml).

19. **P2 — Late proof and human Release/Keep need separate durable transitions.**  
    Locations: [brief:34](docs/briefs/7.7a-coding-units.md:34), [brief:49](docs/briefs/7.7a-coding-units.md:49), [brief:63](docs/briefs/7.7a-coding-units.md:63), [service.ts:898](apps/server/src/runtimes/coding/service.ts:898), [service.ts:972](apps/server/src/runtimes/coding/service.ts:972), [translate.ts:327](apps/server/src/runtimes/coding/translate.ts:327).

    Current background reaping deletes records without publishing late proof; terminal guards reject subsequent terminal observations. Carrying Release’s deletion semantics over to units makes the still-live unit appear orphaned on restart. Conversely, promoting an old unconfirmed result to runtime authority can make previously ineligible output consumable.

    **Fix:** store monotonic execution proof separately from disposition and result eligibility. Retain audited release/keep tombstones and routing identities. Late proof closes obligations without reviving results or hand-offs; human Keep/Release remains a waiver, not termination evidence.

20. **P2 — Backend selection and upgrade migration can bypass unresolved work.**  
    Locations: [brief:55](docs/briefs/7.7a-coding-units.md:55), [brief:63](docs/briefs/7.7a-coding-units.md:63).

    Restart with an existing unit while the bus is temporarily unavailable, or upgrade with surviving legacy `coding_processes` rows. Selecting the process-group fallback—or reconciling only the newly selected backend—can admit another turn beside unresolved work. Default `Type=simple` also permits a successful start response before executable invocation succeeds. [Start semantics](https://github.com/systemd/systemd/blob/v259/man/systemd-run.xml).

    **Fix:** persist backend per launch and reconcile both inventories before admission. Never change backend for an uncertain launch. Use `Type=exec` and typed start receipts; test supported properties, cgroup observability and linger separately. Unique names bypass per-unit start-rate counters, so retain Score’s admission/backoff limits. The blanket enable-linger instruction should be replaced with the actual capability failure.

The acceptance suite should add these specific crash points and failures, especially main-exit deadline enforcement, Stop-triggered GC, offset/state atomicity, cold manager startup, restored history after collection, offline spool exhaustion and malformed finals. Scripted fake states alone cannot validate these semantics.

- Right: cgroups capture ordinary fork/`setsid` descendants and remove PGID ownership inference from the primary runtime.
- Right: recording before launch, separating Stop delivery from proof, and keeping uncertain work fenced are sound foundations.
