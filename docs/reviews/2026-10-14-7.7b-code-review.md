# 7.7b code review (Codex gpt-6.1-sol, max, read-only), 2026-10-14

Reviewed: main...task/7.7b-workers (parts 1–3). Verdict: BLOCK (3 P1, 4 P2, 1 P3). Fix round 7.7b-F1.

**BLOCK**

1. **P1 — Release checks stale spend.** [admission.ts:169](apps/server/src/domain/orchestration/admission.ts:169). A sibling’s terminal run row can commit before its attempt is reconciled. Release still reads the attempt’s old spend. Probe: a committed $10 cost under a $5 budget returned `{allowed:true}`; an unaccepted unknown cost also passed. **Fix:** derive release accounting from fresh run and launch facts inside the release read transaction.

2. **P1 — Claude’s policy omits configuration outside workspace ancestors.** [claude.ts:401](apps/server/src/runtimes/coding/claude.ts:401). In a Git worktree, Claude reads `.claude/settings.local.json` from the main checkout, which this ancestry-only list misses. Changing it while arming leaves the policy ID unchanged; the stat-only probe confirmed that omission. [Claude’s documented lookup](https://code.claude.com/docs/en/settings#where-claude-code-keeps-the-local-file-in-a-git-repository). **Fix:** resolve and bind the actual configuration locations, preserving stat-only access; refuse unverifiable sources.

3. **P1 — Receipt writes reopen the deadline race.** [supervisor.mjs:682](apps/server/src/runtimes/coding/supervisor.mjs:682). The expiry check precedes `released.json`’s blocking fsyncs. Probe: authorization at time 999, deadline 1000, receipt sync advancing time to 1001 still reached `spawn`. **Fix:** recheck expiry after receipt durability, immediately before spawning. Keep `mayHaveExecuted` and the step charge; add a delayed-receipt test.

4. **P2 — Remapping one step strands another for the same worker.** [decisions.ts:569](apps/server/src/domain/orchestration/decisions.ts:569). Two steps block under policy A. Remapping the first replaces the shared agent policy with B; remapping the second to B then returns `conflict`. Probe reproduced this. **Fix:** compare against each suspended attempt’s approved policy, or store step-specific mappings, retaining fresh gate approval and consent.

5. **P2 — Rejecting a renewed gate retains its reservation.** [decisions.ts:83](apps/server/src/domain/orchestration/decisions.ts:83). After policy remap, rejecting the new gate retires the step but leaves its suspended attempt `created`. Probe: the rejected step still reserved $0.50, potentially preventing the lead or other work from starting. **Fix:** atomically close the proven-unsent attempt and release its reservation when rejecting the gate.

6. **P2 — A queued crash becomes a readiness refusal.** [executor.ts:2699](apps/server/src/domain/orchestration/executor.ts:2699). Crash after coding admission but before any launch request: recovery finds the interrupted run, then defaults its closure to `start_failed`. Probe produced `send_refused` and refusal counters of 1. **Fix:** classify this restart as `send_closed/restart`, without readiness counters; test the existing-run/no-launch case.

7. **P2 — Coding storage is not protected as promised.** [ops.ts:22](apps/server/src/domain/orchestration/ops.ts:22), [decisions.ts:161](apps/server/src/domain/orchestration/decisions.ts:161). Observations can consume the added coding allowance. Raising `codingSteps` resumes further items without expanding the reserve, and the retained `coding_run_results` copy is uncharged. A tool-heavy run can exceed its advertised storage allowance when results arrive. **Fix:** protect coding inventory separately, reserve additional capacity when limits rise, and charge every retained copy.

8. **P3 — The reported `agent_changed` flake is a test artefact.** [coding-workers-release.test.ts:258](apps/server/test/orchestration/coding-workers-release.test.ts:258), [ops.ts:248](apps/server/src/domain/orchestration/ops.ts:248). `oneStep()` unconditionally finishes on lead turn two. Blocking the worker wakes that turn; finishing legitimately changes its suspended attempt from `created` to `refused`. Probe reproduced `unknown_reason = "not dispatched: run finishing"` with refusal counters still zero. **Fix:** use an assign-only lead and assert after executor idle. This is not a release-classification race.
