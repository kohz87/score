1. **P1 — Z’s directory-sync obligation disappears across journal handles.**

   Locations: [instance-local flag](apps/server/src/domain/orchestration/journal.ts:224), [append durability](apps/server/src/domain/orchestration/journal.ts:355), [compaction rename](apps/server/src/domain/orchestration/journal.ts:517).

   Writer A creates and fsyncs the journal, but directory fsync fails. A correctly throws. Writer B opens a fresh `ExecutionJournal`; because the pathname exists, B never sets `dirSyncPending`. Its append succeeds and permits execution without establishing pathname durability.

   The actual class, with in-memory filesystem mocks, reproduced: **first append threw; fresh-handle append succeeded; successful directory syncs remained zero**. Compaction has a related window: rename succeeds, directory sync fails, and later appends do not remember that obligation.

   Following power loss, the new pathname or rename can be lost, erasing B’s execution witness and allowing restored state to repeat its effect. File fsync alone does not guarantee directory-entry durability. [Linux fsync documentation](https://www.man7.org/linux/man-pages/man2/fsync.2.html?source=post_page---------------------------)

   **Fix:** establish directory durability before every effect-permitting append returns, including fresh handles and recovery after failed renames. Sync newly created ancestor entries too. Extend the [same-handle-only test](apps/server/test/orchestration/journal-durability.test.ts:123) with fresh-handle, separate-process and failed-compaction cases.

2. **P1 — PDEATHSIG can kill Codex’s launcher while leaving Codex itself running.**

   Locations: [fallback promise](docs/briefs/7.7a-coding-units.md:149), [wrapper invocation](apps/server/src/runtimes/coding/process.ts:124), [exec handoff](apps/server/src/runtimes/coding/pdeathsig-exec.py:55), [CLI selection](apps/server/src/runtimes/coding/cli.ts:36).

   The pinned npm Codex launcher **spawns** the native engine and forwards catchable signals. Parent-death configuration survives exec but is cleared for forked children. Score’s death therefore SIGKILLs the JavaScript launcher; it cannot forward that signal, and the native engine can continue model/tool work. [Codex 0.160.1 launcher](https://raw.githubusercontent.com/openai/codex/rust-v0.160.1/codex-cli/bin/codex.js)

   A harmless probe through the actual Python wrapper reproduced **launcher absent, spawned executable still sleeping** after the Score-like parent died. The local standalone Codex binary avoids this particular chain; the supported npm distribution does not.

   **Fix:** resolve and verify the actual native executable and exec it directly under PDEATHSIG. Refuse fallback execution for launcher chains whose lifetime semantics cannot be established. Test a spawning launcher, not only a directly executed Node process.

3. **P1 — “Outside the home” is not enforced by configuration or restore.**

   Locations: [external receipt assumption](docs/briefs/7.7a-coding-units.md:91), [journal-directory resolution](apps/server/src/config.ts:199), [restore marker](scripts/restore.mjs:70), [home replacement](scripts/restore.mjs:95).

   Live configuration accepts `SCORE_JOURNAL_DIR=$SCORE_HOME/history`; a read-only call confirmed this. A backup then contains the journal, registry and proposed receipts. Restoring it rewinds the witnesses alongside the database.

   Worse, the restore tool first writes its marker into that directory, then moves the whole home aside. The marker moves aside too; the restored home contains neither the newer witnesses nor the new restoration fence. Previously executed work can become dispatchable again.

   **Fix:** startup and restore must reject a canonical journal path equal to or beneath the canonical home, including symlink aliases and defaults derived from `XDG_STATE_HOME`. Validate this before writing markers or admitting work. Changing journal roots must require migration or fail closed.

4. **P2 — The shared installation registry has no shared lock.**

   Locations: [registry ownership](docs/briefs/7.7a-coding-units.md:61), [per-installation locks](docs/briefs/7.7a-coding-units.md:70).

   A and B take different installation locks while updating the same `installations.json`. Both can read the same old registry and publish replacements; the later replacement loses the earlier installation entry. After identity-file loss, the required recovery lookup becomes unreliable.

   “Any journal namespace for this path” also needs durable path provenance: namespaces are named by installation ID, and the documented coding records do not supply the missing path index.

   **Fix:** use a permanent registry-wide OS lock around bootstrap, aliases and registry updates. Keep a durable per-namespace installation manifest so registry loss cannot masquerade as a genuinely new path. Define missing/corrupt registry handling explicitly.

5. **P2 — The release CAS still lacks an explicit commit/rollback protocol.**

   Locations: [release ordering](docs/briefs/7.7a-coding-units.md:86), [journal authority](docs/briefs/7.7a-coding-units.md:98), [private lock API](apps/server/src/domain/orchestration/journal.ts:240).

   The wording permits sending `go` after journal fsync while the database transaction remains open. If commit then fails, the database can remain `armed` while the journal records release possibility. A subsequent DB-only revocation CAS must not convert that into pre-release no-launch evidence.

   Conversely, a fsynced release record followed by rollback and **no** `go` needs a defined conservative outcome. The existing journal API locks individual operations; it does not expose the enclosing critical section required by this CAS.

   **Fix:** specify journal-authoritative monotonic release possibility, database commit, then an explicit post-commit `go` effect. Failed commit must preserve uncertainty. Provide one lock/transaction API covering the authority read, CAS, witness and projection, with a fixed lock order.

6. **P2 — Legacy migration still has no stable source snapshot or cutover.**

   Locations: [migration](docs/briefs/7.7a-coding-units.md:73), [current shared writer](apps/server/src/start-server.ts:265), [restore scope/marker](scripts/restore.mjs:65).

   Destination locks do not exclude appends or compaction through the legacy journal’s lock. Calling the old file a “read-only witness” does not make existing writers stop. Interrupted copying, scope/checkpoint translation and subsequent restores remain undefined.

   **Fix:** lock or quiesce the legacy source, publish a fsynced idempotent migration/cutover record, translate scopes and checkpoints explicitly, and update restore in the same change. Preserve the frozen legacy witness.

7. **P2 — Clearing `Environment=` plus enumeration is still not `env -i`.**

   Location: [startup environment](docs/briefs/7.7a-coding-units.md:48).

   User services inherit manager variables independently of the unit’s `Environment=` list. A variable imported after enumeration and absent from the unconditional list survives. This includes newly imported credentials and omitted startup controls such as `GLIBC_TUNABLES`. The expanded fixed list substantially reduces the original injection risk, but the exact-environment claim remains false. [Systemd execution environment](https://raw.githubusercontent.com/systemd/systemd/v259/man/systemd.exec.xml)

   **Fix:** define a supported bootstrap that establishes the minimal environment before Node starts, or explicitly retain a deny-list guarantee instead. Preserve trusted systemd-generated notification/identity variables separately. Test imports between enumeration and process creation.

8. **P2 — Watchdog expiry does not guarantee whole-cgroup death within approximately ten seconds.**

   Locations: [watchdog](docs/briefs/7.7a-coding-units.md:30), [disconnect bound](docs/briefs/7.7a-coding-units.md:29).

   Default SIGABRT enters watchdog-abort handling, which uses `TimeoutAbortSec`, potentially inherited from manager configuration. With mixed killing, payload processes wait for main-process termination or subsequent escalation; slow core dumping can extend that interval. `TimeoutStopSec` alone does not define it. [Watchdog and abort semantics](https://raw.githubusercontent.com/systemd/systemd/v259/man/systemd.service.xml)

   SIGABRT also permits storing the supervisor’s unredacted memory, including prompt/output buffers, despite stdout/stderr being null. [Systemd core storage](https://raw.githubusercontent.com/systemd/systemd/v259/man/systemd-coredump.xml)

   **Fix:** use a non-core-producing watchdog kill policy, preferably `WatchdogSignal=SIGKILL`, and define the full failure-to-kill budget. If retaining abort handling, pin `TimeoutAbortSec` and establish a verified core policy. Keep termination proof independent of elapsed time.

9. **P2 — Live fallback signaling remains numeric on main.**

   Location: [live signal implementation](apps/server/src/runtimes/coding/process.ts:149).

   Production escalation still calls `process.kill(-child.pid, …)` and falls back to `child.kill()`. Group-number reuse between observation and signaling can reach an unrelated replacement group. Y’s recovery helper does not repair this path.

   **Fix:** implement v5’s retained identity-safe live signaling, including group-scoped pidfds. Unavailable or uncertain identity must retain the unresolved record and fence; it must not authorize numeric signaling.

10. **P2 — Inventory, collection and name-reuse rules remain implicit.**

    Locations: [identity/actions](docs/briefs/7.7a-coding-units.md:125), [acceptance suite](docs/briefs/7.7a-coding-units.md:156).

    V5 references inventory but does not restate the exact generated namespace, unknown-launch fence, removed-agent routing, collection ordering or application-wide launch backoff. Default collection retains failed units; successful-unit GC can discard execution metadata. Resetting failure also clears rate counters. [Unit collection](https://raw.githubusercontent.com/systemd/systemd/v259/man/systemd.unit.xml), [reset-failed](https://raw.githubusercontent.com/systemd/systemd/v259/man/systemctl.xml)

    Checking InvocationID and then issuing a name-based stop/reset is also a check-to-action race if names can be reused.

    **Fix:** retain the earlier lifecycle rules explicitly: globally unique names never reused for another launch, installation ownership across creators, journal/inventory reconciliation before admission, orphan fencing, durable routing after agent removal, and collection only after settlement plus qualifying emptiness. Test cold manager replacement between observation and action.
