1. **P1 — Launch-only routing breaks Stop before launch, including Chat (§2).**  
   [service.ts:511](apps/server/src/runtimes/coding/service.ts:511) creates the coding run before queueing; [service.ts:558](apps/server/src/runtimes/coding/service.ts:558) returns its handle before any launch exists. Process-group Chat runs also lack unit launch rows. **Scenario:** Stop a queued Chat turn; §2 routes it to Hermes, leaving the coding queue authorized to execute later. **Fix:** route primarily by durable `runs.runtime`, with launch metadata as recovery fallback. Never infer Hermes from absence of a launch row.

2. **P1 — Returning to `created` does not reopen journal dispatch authority (§§6,10).**  
   [journalDispatches](apps/server/src/domain/orchestration/journal.ts:252) recognizes `send_refused`, but ignores coding revocations. [beginSend](apps/server/src/domain/orchestration/executor.ts:1886) permanently rejects a journaled `sent` attempt. **Scenario:** pause revokes g1; §6 returns it to `created`; Resume finds g1 still `sent` and changes the attempt to `unknown`. The same problem affects §10’s bare `send_started` recovery. **Fix:** define a durable, generation-qualified no-launch closure that dispatch folding, verification and replay recognize, without incrementing readiness-refusal counters.

3. **P2 — Release-time rebuilding does not identify what the supervisor will execute (§§3,6,9).**  
   [unit-backend.ts:985](apps/server/src/runtimes/coding/unit-backend.ts:985) prepares the command and deadline before arming. [go()](apps/server/src/runtimes/coding/coding-socket.ts:202) sends no replacement payload; the supervisor enforces [the original spec deadline](apps/server/src/runtimes/coding/supervisor.mjs:579). **Scenario:** tighten a future deadline while arming; checking that the new deadline remains future can release a supervisor carrying the old expiry. **Fix:** prepare and authenticate the frozen invocation before arming; authorize its actual policy/spec hash and prepared expiry. A mismatching prepared expiry must revoke and prepare a new generation, or use an explicitly designed authenticated update protocol.

4. **P2 — Permanent tombstones do not yet provide a permanent orchestration-to-launch association (§§5,8).**  
   [CodingState](apps/server/src/domain/orchestration/coding-records.ts:36) contains no orchestration or attempt owner. [Send compaction](apps/server/src/domain/orchestration/journal.ts:755) retains attempt/orchestration IDs but would discard §5’s added launch binding. **Scenario:** restore an older database after compaction; counting through database joins misses lost attempts, while the coding tombstone cannot directly identify its orchestration. **Fix:** define immutable owner IDs in coding journal state, projections and tombstones, or another permanent association. Count folded `mayHaveExecuted` launches for that owner under the release lock.

5. **P2 — The authorization cause table is not exhaustive or mapped to real attempt states (§§6–10).**  
   The predicate includes budget, unknown-spend acceptance and withdrawn inputs, but the table omits their outcomes, expired `"deadline"`, and recovery’s `"restart"`. Literal `cancelled` and `send_refused` also are not [attempt states](apps/server/src/domain/orchestration/store.ts:130). **Scenario:** a queued worker loses budget authorization; its durable receipt has no defined transition or wake condition. Blanket missing-cost treatment can also classify proven no execution as unknown spend. **Fix:** specify every cause’s actual attempt/step transition, wake condition and counter effect; proven no execution carries known-zero execution spend.

6. **P2 — Adding a policy ID does not make policy-only remap reachable (§§3–4,12; contract changes).**  
   [remapAgent](apps/server/src/domain/orchestration/decisions.ts:387) rejects unchanged or `untracked` incarnations. Coding permission/workspace edits [do not change incarnation](apps/server/src/http/coding-agents.ts:168), and [gate payloads](apps/server/src/domain/orchestration/commands.ts:367) contain no policy ID. **Scenario:** an ordinary settings edit blocks a queued worker, but its advertised remap still returns “was not replaced.” **Fix:** define policy-only remap validation, journal the resulting policy mapping, and bind any renewed step approval to its new policy and payload. State whether old blocked assignments remain blocked or receive a fresh approval.

7. **P2 — The 104 KiB reserve cannot cover 20 retained generations (§§5,11).**  
   Each admitted generation stores its full input in [a command intent](apps/server/src/runtimes/coding/service.ts:494). A 32 KiB input therefore produces about **640 KiB of intent payloads alone** across 20 generations, before runs, replies, receipts and results. [chargeObservation](apps/server/src/domain/orchestration/ops.ts:290) does not charge those admissions. **Scenario:** repeated post-handle holds exhaust physical storage while the advertised item reserve remains 104 KiB. **Fix:** reserve and charge every generation’s retained inventory, or discard proven unlaunched payload copies under an explicit recovery-safe retention rule.

8. **P2 — Pruning still searches logical turn IDs and misses generation runs (§§5,11).**  
   [pruneAssociated](apps/server/src/domain/orchestration/prune.ts:7) collects `orc_attempts.turn_id`, then deletes runs/intents matching that exact value. New coding IDs append `:gN`. **Scenario:** pruning releases orchestration quota but leaves every coding generation’s run, prompt intent, thinking and tool rows. **Fix:** enumerate associated records by durable attempt/generation/run identities; delete the covered inventory atomically while retaining the required launch projections and tombstones.

9. **P3 — Qualify the remaining baseline descriptions (§0 and introduction).**  
   The introduction’s “every coding turn” unit claim excludes the [process-group path](apps/server/src/runtimes/coding/service.ts:995). `isEvidence` also requires [completed/failed status](apps/server/src/domain/orchestration/executor.ts:140). Restart clears the eligible reply but [preserves pending output](apps/server/src/runtimes/coding/service.ts:811). **Scenario:** applying the unqualified statements globally changes Chat recovery or assumes unit proof for fallback runs. **Fix:** state these qualifications explicitly. The other §0 claims match current code.
