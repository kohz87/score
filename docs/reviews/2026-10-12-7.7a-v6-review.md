1. **P1 — Startup bypasses AA’s ancestor-directory syncing.**

   Locations: [startup ordering](apps/server/src/domain/orchestration/fence.ts:544), [lock initialization](apps/server/src/locks/os-lock.ts:44), [durable mkdir](apps/server/src/domain/orchestration/journal.ts:315), [append sync](apps/server/src/domain/orchestration/journal.ts:394).

   `startupCheck()` calls `readRestoreMarker()` before `open()`. Taking that read lock recursively creates the journal directory without syncing its ancestors. `mkdirDurable()` subsequently sees existing directories and skips them. An append then permits execution after syncing only the journal file and its immediate directory.

   The mocked production ordering reproduced exactly that. A second probe also reproduced a failed ancestor sync followed by a successful fresh-handle append without retrying the failed parent. Power loss can therefore remove an ancestor and its execution witnesses, allowing an older restored database to repeat work.

   **Fix:** establish ancestor durability before lock initialization creates paths, and recover outstanding parent-sync obligations across handles. Test the actual startup ordering and failed ancestor initialization.

2. **P1 — Missing `PATH` bypasses the native-executable requirement.**

   Locations: [resolver fallback](apps/server/src/runtimes/coding/native-exec.ts:123), [version detection](apps/server/src/runtimes/coding/cli.ts:107), [eventual exec](apps/server/src/runtimes/coding/pdeathsig-exec.py:55).

   With `PATH` unset, `findOnPath()` searches nothing and returns `{ ok: true, file: 'codex' }`. The eventual Python `execvp()` still searches its default path. A working npm launcher installed there can consequently pass version detection and run without native inspection. Its spawned engine survives the launcher’s PDEATHSIG SIGKILL—the original v5 failure. The read-only resolver call confirmed the bare-command acceptance; Python’s default search behavior and Codex’s spawning launcher are explicit upstream. [CPython implementation](https://github.com/python/cpython/blob/3.13/Lib/os.py), [Codex 0.160.1 launcher](https://github.com/openai/codex/blob/rust-v0.160.1/codex-cli/bin/codex.js).

   **Fix:** missing resolution must refuse execution. Use consistent search semantics and return only a verified absolute native executable. Test absent `PATH` and empty/relative search components.

3. **P1 — Restoring the home can erase the journal-root guard.**

   Locations: [missing-pointer acceptance](apps/server/src/journal-location.ts:41), [unsynced pointer write](apps/server/src/journal-location.ts:57), [startup root recording](apps/server/src/start-server.ts:237), [root-local registry](docs/briefs/7.7a-coding-units.md:72).

   Back up before `journal-root` exists, execute work under J1, then restore that backup. Start with J2 configured. The guard returns `null`; startup records J2, while J1’s witnesses and restore marker remain unconsulted. A backup preceding dispatch has no `sent_at` history to trigger the fresh-journal fence. Its pending intent can run again.

   The probe confirmed acceptance despite an existing old journal. V6’s registry and manifests also live beneath the selected root, so they cannot discover J1 from an empty J2. Unreadable and empty pointers likewise permit root changes.

   **Fix:** retain root provenance outside the restored home and independently of the newly selected root. Missing/corrupt provenance for an existing database must require reconciliation. Root migration must move the registry, namespaces, receipts and restore markers under locks.

4. **P2 — AA’s native resolver rejects the pinned npm Codex layout.**

   Locations: [native candidates](apps/server/src/runtimes/coding/native-exec.ts:75), [matching test fixture](apps/server/test/runtimes/coding-native-exec.test.ts:61).

   Codex 0.160.1 resolves its native binary as `vendor/<target>/bin/codex`, including its optional platform package. AA searches `vendor/<target>/codex/codex`. The tests construct AA’s assumed layout instead of the pinned launcher’s layout. [Pinned launcher](https://github.com/openai/codex/blob/rust-v0.160.1/codex-cli/bin/codex.js).

   An in-memory package tree matching upstream contained a native ELF and was nevertheless refused.

   **Fix:** resolve the optional platform package and native path used by the pinned distribution. Test both its platform-package layout and its package-local fallback.

5. **P2 — Live pidfds authenticate replacement processes as if they belonged to the old run.**

   Locations: [leaderless signaling](apps/server/src/runtimes/coding/process.ts:170), [fresh member recording](apps/server/src/runtimes/coding/process.ts:193).

   After the leader exits, signaling scans the current occupants of its numeric PGID and passes their freshly observed identities to `signalPid()`. If the original group emptied and that number was reused, the pidfd correctly signals an unrelated replacement process. Fresh-member recording can also bless those replacements.

   The mocked current module reproduced SIGINT to a replacement member after leader exit.

   **Fix:** require previously recorded ownership or verified ancestry continuity, as recovery does. A fresh scan establishes existence, not ownership; uncertain groups must retain their records and fence.

6. **P2 — The bootstrap cannot reliably preserve generated identity variables as written.**

   Locations: [direct-Node command](docs/briefs/7.7a-coding-units.md:26), [`env -i` bootstrap](docs/briefs/7.7a-coding-units.md:53), [enumerated exclusions](docs/briefs/7.7a-coding-units.md:65).

   With expansion disabled, `/usr/bin/env` does not substitute `$INVOCATION_ID` or `$NOTIFY_SOCKET`; the design needs an actual runtime pass-through mechanism. Moreover, enumerating every manager variable except PATH/HOME/LANG can put those two names into `UnsetEnvironment`, removing even systemd’s generated values. Identity verification or notification then fails. [Systemd environment rules](https://github.com/systemd/systemd/blob/v259/man/systemd.exec.xml).

   `GLIBC_TUNABLES` is also absent from the unconditional exclusions: a late import reaches the dynamically linked bootstrap before `env -i` clears the environment. [Glibc tunables](https://sourceware.org/glibc/manual/latest/html_node/Tunables.html).

   **Fix:** specify one executable bootstrap, preserve and independently verify fresh unit-generated identity values, exclude their names from blanket enumeration, and complete the bootstrap’s unconditional loader exclusions.

7. **P2 — Moving the CLI after spawning permits descendants outside `payload/`.**

   Locations: [self-only observation](docs/briefs/7.7a-coding-units.md:27), [placement ordering](docs/briefs/7.7a-coding-units.md:40), [payload-empty exit](docs/briefs/7.7a-coding-units.md:45).

   “Before `go` completes” permits spawning first, then moving the CLI. A fast fork remains in the original cgroup; moving the parent does not move existing children. A descendant in another child subgroup can coexist with root `cgroup.procs={supervisor}` and empty `payload/`. Supervisor exit then prematurely SIGKILLs that tool. External ended proof remains valid, but graceful completion is misclassified. [Kernel migration semantics](https://docs.kernel.org/admin-guide/cgroup-v2.html#processes).

   **Fix:** place a gated child in `payload/` before CLI exec/fork, or use atomic cgroup placement. Unexpected occupants elsewhere in the unit subtree must trigger cleanup and invalidate normal eligibility.

8. **P2 — The wire EOF rule conflates stderr text with structured records.**

   Locations: [generic partial-line rule](docs/briefs/7.7a-coding-units.md:130), [both-stream completeness](docs/briefs/7.7a-coding-units.md:146), [Codex loss exclusion](docs/briefs/7.7a-coding-units.md:168), [current stderr handling](apps/server/src/runtimes/coding/process.ts:275).

   As written, an otherwise successful CLI emitting a stderr warning without a trailing newline loses a record and becomes ineligible. Stderr is currently arbitrary diagnostic text, rather than the driver’s NDJSON stream.

   **Fix:** specify stream-specific decoding: strict structured-record completeness for stdout; bounded, redacted text handling for stderr, including its final unterminated text. Preserve sequence/EOF completeness for both.

9. **P3 — The obsolete lock prescription still contradicts Z.**

   Location: [journal lock specification](docs/briefs/7.7a-coding-units.md:85).

   It still prescribes `<…>/lock` with O_EXCL/pid ownership, while the release critical section requires an OS lock and the password store now uses SQLite locking.

   **Fix:** replace this with the permanent `lock.sqlite` OS lock. Also make current authorization revalidation an explicit step in the new release protocol instead of leaving it under “Formerly.”
