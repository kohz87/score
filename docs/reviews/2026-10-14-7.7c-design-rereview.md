New findings:

1. **P2 — Try again spends the wrong allowance (§§1,4).**  
   [runs.ts:167](apps/server/src/domain/workflows/runs.ts:167) sets `attempts_max = retries + 1`; [tryAgain:188](apps/server/src/domain/workflows/decisions.ts:188) currently continues refused dispatches independently of that allowance. **Scenario:** a zero-retry node has already used its sole logical attempt when twenty launches are refused. V2’s fresh attempt is either forbidden or consumes an execution retry despite nothing having run. Leaving the old attempt merely “as history” also leaves its capacity and reservation unless explicitly closed. **Fix:** define a bounded coding dispatch-renewal allowance separately from execution retries; atomically retire the proven-unsent predecessor, transfer its reservation and preserve approved payload/policy bindings. Keep Hermes Try again unchanged.

2. **P2 — The generation cap becomes an automatic replacement (§4, “other blocked dispositions”).**  
   [executor.ts:2333](apps/server/src/domain/orchestration/executor.ts:2333) blocks generation 21 for human intervention. [planner.ts:298](apps/server/src/domain/workflows/planner.ts:298) clears that block’s step association; [pendingKind:473](apps/server/src/domain/workflows/planner.ts:473) treats its replacement as a remap. **Scenario:** twenty temporary revocations reach the cap; an unrelated admission change creates another queued step automatically, with `attempts_used = attempts_max = 1`. The probe reproduced this. **Fix:** give generation exhaustion an explicit Needs-you state and human renewal action; exclude it from automatic replacement.

3. **P2 — Incarnation remap lacks coding consent and retirement semantics (§4; Contract changes).**  
   [WorkflowRemapDecisionSchema:861](packages/contract/src/workflows.ts:861) accepts no policy or reach acknowledgement; [wfRemap:1324](apps/server/src/domain/orchestration/executor.ts:1324) obtains no worker report. [remapWorkflow:269](apps/server/src/domain/workflows/decisions.ts:269) skips retiring blocked steps. **Scenario:** replace an agent while its coding attempt is suspended. Remap creates replacement work but leaves the old attempt reserving $0.50; the probe showed $1 reserved for one logical node. Replacement settings also cannot be approved through this contract. **Fix:** extend incarnation remap with current policy/readiness and renewed consent; close all affected proven-unsent attempts, including suspended blocked ones, while preserving possibly-executed obligations.

4. **P2 — Workflow result copies exceed the protected item allowance (§5).**  
   [ops.ts:70](apps/server/src/domain/orchestration/ops.ts:70) allocates **176.25 KiB**, already assigned to coding inventory. Workflows additionally retain `wf_results` output at [verdict.ts:100](apps/server/src/domain/workflows/verdict.ts:100) and node output/verdict at [planner.ts:219](apps/server/src/domain/workflows/planner.ts:219). **Scenario:** ordinary observations exhaust their pool; maximum coding inventory plus these two 32 KiB copies spills into protected control capacity. Adding only `wf_results` still misses node output. **Fix:** specify a workflow item constant covering both copies, verdict metadata and renewal inventory; charge their writes. Use that same constant for creation, preflight and limit-growth accounting—[setLimits:185](apps/server/src/domain/orchestration/decisions.ts:185) currently divides reserves by the orchestration constant.

5. **P2 — The shared decision cards require data and actions v2 omits (§6).**  
   [RunDecisions.tsx:296](apps/web/src/routes/orchestrations/RunDecisions.tsx:296) requires `coding.workers` and `acceptedUnknownCost`; the proposed block supplies neither. [PolicyChangedCard:509](apps/web/src/routes/orchestrations/RunDecisions.tsx:509) calls orchestration preflight using `leadAgentId`. **Scenario:** a budgeted Codex workflow pauses for unknown cost; direct card reuse cannot render its scoped control. Policy recovery also has no lead with which to run that query. **Fix:** specify compatible shared data, or refactor cards around explicit workflow selectors, preflight callbacks and node policy-remap actions. Do not introduce a placeholder lead.

6. **P2 — Withdrawn-input cancellation strands a running node (§4; inherited cause table).**  
   [applyClosure:223](apps/server/src/domain/orchestration/coding-attempts.ts:223) turns a pre-release `inputs_withdrawn` denial into a cancelled step. [planner.ts:308](apps/server/src/domain/workflows/planner.ts:308) handles cancellation only when its disposition says “remapped.” **Scenario:** upstream evidence is withdrawn while a coding consumer is queued or arming. Release correctly refuses execution, but its node stays `running` indefinitely, without a recovery card; the probe reproduced this. **Fix:** define workflow node transitions for every coding closure cause. Withdrawn inputs need an unresolved/recovery state; Stop and deadline cancellation must retain their terminal behavior.

7. **P2 — Workflow fan-out exceeds the reused consent bound (§§1–2; Contract changes).**  
   [CodingReachAcknowledgementSchema:149](packages/contract/src/orchestration.ts:149) accepts at most eight policy IDs, while [WorkflowRunCreateSchema:808](packages/contract/src/workflows.ts:808) permits thirty mapped agents. **Scenario:** a valid nine-worker graph requires nine distinct reach acknowledgements; the reused schema rejects them. The validation/schema probe confirmed this. **Fix:** define workflow-specific consent cardinality from the workflow’s distinct coding agents, preserving orchestration’s eight-worker limit.

8. **P3 — §0 overstates the generation cap (§0, lines 21–22).**  
   The cap at [executor.ts:2332](apps/server/src/domain/orchestration/executor.ts:2332) applies only to coding step attempts. **Scenario:** treating it as universal motivates changing Hermes Try again or adding a new Hermes cap, contradicting §1’s unchanged-path promise. **Fix:** say “coding attempts are capped at twenty generations.” Every other §0 claim checked matches current code.
