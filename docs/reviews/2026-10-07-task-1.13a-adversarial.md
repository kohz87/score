1. **High — Queue eviction can execute hostile code on the hook thread.**

   **Evidence:** [sender.py:22](/home/raven/score-worktrees/1.13a-bridge-plugin/hermes-plugin/score_bridge/sender.py:22) acquires a blocking mutex. The evicted `old` record is released when `put_nowait()` returns, potentially running payload destructors on the caller thread.

   Reproduced from `hermes-plugin/`, using the existing virtualenv interpreter with `-B`:

   ```python
   class Slow:
       def __del__(self):
           time.sleep(0.1)

   sender = Sender(ScoreClient(), capacity=1)
   hook = score_bridge._make_hook("pre_tool_call", sender)
   hook(result=Slow())
   started = time.perf_counter()
   hook(result="replacement")
   ```

   The second hook took **100.16 ms**. Holding `sender.queue.mutex` also prevented a hook from returning until the lock was released. Hermes makes `pre_tool_call` timeouts fail closed, so blocking telemetry can block actual tools.

   **Fix:** Use nonblocking admission with counted contention losses. Transfer evicted references to sender-side reclamation; never release arbitrary payload objects on the hook thread.

14. **Medium — Spool directory checks have a symlink replacement race.**

    **Evidence:** [spool.py:82](/home/raven/score-worktrees/1.13a-bridge-plugin/hermes-plugin/score_bridge/spool.py:82) checks `is_symlink()`, then performs path-based `chmod`, opens, replacements, and deletions.

    With a writable parent directory, another process can replace `spool` after the check. `O_NOFOLLOW` on `.lock` or a JSONL file protects only that final component; intermediate directories still resolve through symlinks. Restricting the checked directory to 0700 does not prevent its replacement through a writable parent.

    **Fix:** Open and validate the private directory using a directory descriptor and perform child operations relative to it. Validate ownership and restrictive permissions of the parent used to locate that directory.
