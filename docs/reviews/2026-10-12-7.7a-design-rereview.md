The remaining and newly exposed failure cases follow.

1. **P1 — Final authorization still precedes an asynchronous launch without a revocation barrier.**  
   Locations: [v2:55](docs/briefs/7.7a-coding-units.md:55), [service.ts:509](apps/server/src/runtimes/coding/service.ts:509).

   Score authorizes, spawns `systemd-run`, then receives Stop or crashes before the helper submits. The supervisor subsequently starts the CLI unconditionally. Carrying over today’s `!entry.launched ⇒ stopped` shortcut would falsely acknowledge Stop during this interval. Checking systemd jobs cannot detect a request the helper has not submitted yet.

   **Fix:** distinguish requested, armed, released, and settled phases. Track/quiesce the helper. Have the supervisor wait for a single-use release before spawning the CLI; persist revocation before delivery. Once launch intent exists, absence alone must remain uncertain.

2. **P1 — Restore reconciliation cannot stop at “journal request without a row.”**  
   Locations: [v2:52](docs/briefs/7.7a-coding-units.md:52), [v2:61](docs/briefs/7.7a-coding-units.md:61).

   Restore a snapshot containing the `authorised` row but predating invocation registration, Stop, or terminal settlement. The row-existence check passes despite lost execution history. After spool retention expires, those facts may exist only in the external journal.

   **Fix:** define journal payloads and compare the latest phase, invocation identity, cancellation, proof, disposition, and settlement against database state. Compaction must retain that witness. Reconciliation must make witnessed execution permanently unsendable before any fence lift.

3. **P1 — The existing external journal is unsafe across multiple Score homes.**  
   Locations: [v2:51](docs/briefs/7.7a-coding-units.md:51), [journal.ts:271](apps/server/src/domain/orchestration/journal.ts:271), [journal.ts:419](apps/server/src/domain/orchestration/journal.ts:419), [config.ts:203](apps/server/src/config.ts:203).

   Different homes share the default journal directory but have separate home locks. Concurrent writers can allocate the same sequence number. Worse, one process can fsync an admission after another process’s compaction snapshot; the subsequent rename discards that admission while its external effect proceeds.

   **Fix:** serialize append, tail repair, sequence allocation, and compaction across processes, or use independently locked journals per persistent installation identity.

4. **P1 — “The same redactor” does not define a safe spool format or equivalent secret coverage.**  
   Locations: [v2:35](docs/briefs/7.7a-coding-units.md:35), [redact.ts:24](apps/server/src/redact.ts:24), [redact.ts:63](apps/server/src/redact.ts:63).

   A probe applying `redact()` to ordinary result JSON produced `"output_tokens":[redacted]`, invalidating the record. Another produced `Bearer [redacted]QRSTUVWXYZ` when the credential crossed chunks; whole-string redaction removed the suffix. A fresh supervisor import also starts with an empty `knownSecrets` registry.

   **Fix:** frame bounded records, redact parsed values, and serialize valid JSON. Give stderr a streaming redaction state. Transfer the necessary secret context through a private in-memory bootstrap channel, with an explicit generation; importing the module is insufficient.

5. **P1 — The proposed ingest key collides within a single line.**  
   Locations: [v2:75](docs/briefs/7.7a-coding-units.md:75), [codex.ts:119](apps/server/src/runtimes/coding/codex.ts:119), [ingest.ts:203](apps/server/src/hub/ingest.ts:203).

   One Codex command-completion line can emit both tool start and tool end. Assigning both `(launch, segment, line)` causes the second observation to be discarded. An in-memory probe left the tool stored as `running`. Usage/result and Claude content-block fan-out have the same problem.

   **Fix:** include stream identity and deterministic event ordinal, or ingest all effects of one line atomically under one key.

6. **P1 — Replay plus deduplication does not rebuild today’s translator.**  
   Locations: [v2:76](docs/briefs/7.7a-coding-units.md:76), [translate.ts:192](apps/server/src/runtimes/coding/translate.ts:192), [translate.ts:281](apps/server/src/runtimes/coding/translate.ts:281).

   Translation sequence, tool pairing, and usage mutate inside `Observation.apply`. Duplicate ingest never invokes it. The actual in-memory replay probe returned `duplicate`, with reconstructed state still `seq: 0, usage: null`.

   **Fix:** separate deterministic replay reduction from database effects and run the reducer for every record, including duplicates. Preserve original observation times and pin the parser/translation version so upgrades do not reinterpret old keys.

7. **P1 — There is no sufficient witness that the recovered stream is complete.**  
   Locations: [v2:37](docs/briefs/7.7a-coding-units.md:37), [v2:78](docs/briefs/7.7a-coding-units.md:78), [v2:93](docs/briefs/7.7a-coding-units.md:93).

   The mutation rule covers segments *already ingested*. An unobserved missing segment containing Codex’s actual final message can leave earlier commentary and a later `turn.completed` apparently valid. Same-size replacement also evades a size check. At terminal EOF, an incomplete suffix currently just “waits”; no rule turns it into durable loss.

   **Fix:** seal the stream with segment sequence, lengths, record counts, hashes, and explicit dropped/torn-record accounting. Validate all gaps, including unseen ones. Await pipe EOF and pending writes, fsync the final segments, then seal them before publishing eligible output. Cgroup emptiness cannot establish stream completeness.

8. **P1 — Final-message rules still lack an execution-disposition acceptance rule.**  
   Locations: [v2:85](docs/briefs/7.7a-coding-units.md:85), [v2:94](docs/briefs/7.7a-coding-units.md:94), [service.ts:771](apps/server/src/runtimes/coding/service.ts:771).

   A CLI can emit a valid success event, then exit nonzero or encounter a deadline/quota failure. Current service code lets `result.ok` select `completed` ahead of exit status. Antigravity’s proposed “response present ⇒ authoritative” rule also includes responses belonging to failed results.

   **Fix:** define an acceptance matrix requiring compatible CLI exit, unit outcome, stop cause, complete durable stream, and successful driver terminal evidence. Antigravity requires validated `status === SUCCESS` and nonempty response. Unknown disposition supplies no successful hand-off.

9. **P1 — Chat hand-offs still derive authority from commentary.**  
   Locations: [v2:95](docs/briefs/7.7a-coding-units.md:95), [message-runs.ts:568](apps/server/src/domain/message-runs.ts:568), [message-runs.ts:612](apps/server/src/domain/message-runs.ts:612).

   Commentary says “@builder implement this”; the authoritative final says “Do not proceed.” Completion preserves differing streamed text unless a particular loss flag is set, then parses hand-offs from that text. Fixing driver output alone still launches the unwanted turn.

   **Fix:** pass the eligible authoritative reply separately into hand-off and plan parsing. Commentary may remain visible, but cannot authorize either action.

10. **P1 — Fallback signaling remains unsafe, including the planned Y group path.**  
    Locations: [v2:100](docs/briefs/7.7a-coding-units.md:100), [proc.ts:318](apps/server/src/runtimes/coding/proc.ts:318), [Y:14](docs/briefs/fix-y-pidfd-signal.md:14).

    The current mocked probe returned `gone` after recording SIGTERM to a replacement PID. Y addresses individual signals, but verifies a leader and then still calls numeric `kill(-pgid)`: the group can disappear and its number be reused between those operations. Y’s assertion that group signaling through a pidfd is impossible is also outdated: Linux implements `PIDFD_SIGNAL_PROCESS_GROUP`. [Kernel implementation](https://github.com/torvalds/linux/blob/v6.18/kernel/signal.c).

    **Fix:** use identity-safe individual and supported group-scoped pidfd signals. A verification handle does not make a subsequent numeric kill safe. Unsupported cases retain the fence.

11. **P2 — The supervisor’s `ended` check ignores ordinary descendants in its own cgroup.**  
    Location: [v2:45](docs/briefs/7.7a-coding-units.md:45).

    Normal children share the supervisor’s cgroup; they need not create child cgroups. Checking child cgroups is therefore vacuously successful while a `setsid` tool remains in the root. Conversely, testing root `populated=0` cannot succeed while the supervisor itself lives. The external proof check prevents premature termination proof, but the supervisor can exit early and leave tools running until the full runtime deadline. [Kernel cgroup semantics](https://docs.kernel.org/admin-guide/cgroup-v2.html#un-populated-notification).

    **Fix:** specify a separate payload subgroup, or qualify the receipt as cleanup/drain completion rather than termination proof. Define leftovers grace and whole-cgroup cleanup, including reparented descendants.

12. **P2 — The supplied stop properties implement INT → KILL, not INT → TERM → KILL.**  
    Locations: [v2:16](docs/briefs/7.7a-coding-units.md:16), [v2:24](docs/briefs/7.7a-coding-units.md:24).

    With `KillMode=control-group`, systemd sends SIGINT to both supervisor and CLI, then the final SIGKILL after `TimeoutStopSec`. It adds no intervening SIGTERM. Forwarding SIGINT can deliver it twice; setting the timeout to one grace interval kills the supervisor when its own TERM stage should begin. [systemd kill semantics](https://github.com/systemd/systemd/blob/v259/man/systemd.kill.xml).

    **Fix:** define one escalation owner, allow both grace intervals plus flushing, and persist Stop before calling systemd. Specify how runtime expiry is distinguished from other SIGINT sources and how disposition survives forced supervisor death.

13. **P2 — The proof predicate contradicts missing-unit and reboot recovery.**  
    Locations: [v2:68](docs/briefs/7.7a-coding-units.md:68), [v2:82](docs/briefs/7.7a-coding-units.md:82).

    After normal GC or cold manager startup, there is no unit to satisfy “inactive/failed.” After reboot, the same-boot fallback cannot apply, although old-boot processes are gone. Also, `ActiveEnterTimestampMonotonic` is a **unit** property; the brief does not identify how it obtains that property for the user manager. [Systemd D-Bus properties](https://github.com/systemd/systemd/blob/v259/man/org.freedesktop.systemd1.xml).

    **Fix:** define separate loaded-unit, authoritative absence, manager-replacement, and boot-change branches. Record the actual manager PID/start identity or identify the system manager’s `user@UID.service` observation. Treat permission/transport errors as unknown, never absence.

14. **P2 — Supervisor environment filtering can race manager imports.**  
    Location: [v2:33](docs/briefs/7.7a-coding-units.md:33).

    `UnsetEnvironment` accepts explicit names/assignments, not an allow-list or `LD_*` wildcard. Enumerating imported variables and then starting leaves a window for a newly imported `NODE_OPTIONS` or loader variable to affect Node before supervisor code replaces the CLI environment. Unsetting names also overrides later explicit assignments. [Environment semantics](https://github.com/systemd/systemd/blob/v259/man/systemd.exec.xml).

    **Fix:** unconditionally deny startup-control variables, including ones absent during enumeration; define how remaining ambient variables are cleared before trusted code runs. Preserve and validate systemd-generated invocation identity separately.

15. **P2 — Aggregate quotas and the receipt reserve need an enforcement protocol.**  
    Location: [v2:39](docs/briefs/7.7a-coding-units.md:39).

    Two offline supervisors can each consume the same observed remaining aggregate allowance. Segment size does not bound an unterminated line or queued redaction/write buffers. A logical “reserve” does not ensure receipt writes succeed under ENOSPC or inode exhaustion.

    **Fix:** reserve disjoint per-launch allowances durably before release, or use shared atomic accounting. Charge buffered/raw bytes, cap records and queues, and preallocate bounded control storage. Test simultaneous offline writers and failure while writing the exhaustion receipt.

16. **P2 — The prompt delivery channel disappeared from the launch protocol.**  
    Locations: [v2:19](docs/briefs/7.7a-coding-units.md:19), [v2:31](docs/briefs/7.7a-coding-units.md:31).

    The unit has null stdin and the enumerated spec has no prompt/input field. Claude and Codex receive their prompt through stdin today. Nothing defines the supervisor’s delivery of those bytes or its failure handling.

    **Fix:** specify immutable input bytes or a private, hash-bound prompt file; fsync it before release, pipe it to CLI stdin, close stdin, and handle rejection/EPIPE. Keep the authorization channel separate.

17. **P2 — Failed-unit collection and global start pressure remain unspecified.**  
    Locations: [v2:23](docs/briefs/7.7a-coding-units.md:23), [v2:59](docs/briefs/7.7a-coding-units.md:59).

    Default `CollectMode=inactive` retains failed units. Deleting launch directories does not collect them. Fresh unit names bypass per-unit start limits, while resetting failure state destroys counters and retained status. [Collection/rate limits](https://github.com/systemd/systemd/blob/v259/man/systemd.unit.xml), [reset-failed](https://github.com/systemd/systemd/blob/v259/man/systemctl.xml).

    **Fix:** after durable settlement and qualified emptiness, collect only the matching exact unit. Preserve application-wide launch/backoff limits. Journald remains diagnostic, not a substitute for receipts.

18. **P2 — Removing an agent can still redirect Stop away from its durable launch.**  
    Locations: [v2:70](docs/briefs/7.7a-coding-units.md:70), [coding-agents.ts:211](apps/server/src/http/coding-agents.ts:211), [port.ts:84](apps/server/src/runtimes/coding/port.ts:84).

    An unconfirmed run is terminal, so the deletion guard permits removing its agent. The composite port then stops recognizing that agent as coding and routes Stop to Hermes. Storing backend identity alone does not change that routing.

    **Fix:** route Stop/recovery by durable run/launch identity, including removed agents. Block deletion while execution remains unresolved or retain a routing tombstone.

19. **P2 — Antigravity’s argv exception exposes prompts beyond the owner’s UID.**  
    Locations: [v2:11](docs/briefs/7.7a-coding-units.md:11), [antigravity.ts:293](apps/server/src/runtimes/coding/antigravity.ts:293), [contract:1030](docs/API-CONTRACT.md:1030).

    A private spec file protects its contents, but Antigravity’s eventual argv still contains the prompt. With ordinary procfs settings, other local users can read command lines; the current contract describes only visibility to the owner’s user. This is separate from the accepted same-user risk. [Procfs visibility](https://docs.kernel.org/filesystems/proc.html#mount-options).

    **Fix:** state the broader exposure in Chat consent/documentation. A stronger secrecy guarantee requires a supported private prompt channel or an explicitly verified host isolation requirement.
