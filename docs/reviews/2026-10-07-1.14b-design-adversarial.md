I would block implementation until the identity and delivery rules are revised. This is a design review; no files were changed.

Verified against Hermes `e97923c3`: the run-id approval namespace, standard SSE request fields, positive `resolved` response, both 409 codes, and endpoint-only `approval.responded` emission are correct. Human hooks carry no human actor; smart hooks identify `aux_llm`, and escalation emits no smart post hook. See [Runs API](/home/raven/reference/hermes-agent/gateway/platforms/api_server_runs.py:1168) and [smart hooks](/home/raven/reference/hermes-agent/tools/approval_smart.py:134). The follower claim is wrong, and the hook outcome list is incomplete, as detailed below.

1. **Critical — Escalation can bind the wrong command.** [Rule 1](/home/raven/score/docs/briefs/1.14b.md:115) selects the newest guardian operation by `pattern_keys` within ten minutes, without checking command identity. Sequence: smart pre A (`rm -rf /srv/data`) → smart pre B (`rm -rf /tmp/cache`) → human request A. A’s request id attaches to B’s card; approving the displayed cache deletion can approve A. **Change:** require a stable operation/gate correlation id; preserve an immutable request snapshot and reject conflicting enrichment. Pattern and time are insufficient.

2. **Critical — 1.13b’s proposed exact-id capture is not exact.** The brief consumes [“requestId from 1.13b”](/home/raven/score/docs/briefs/1.14b.md:130); [D4.2](/home/raven/score/docs/ARCHITECTURE.md:220) assumes the newest matching queue entry belongs to the current hook. Sequence: thread A enqueues → thread B enqueues an identical command → A’s hook snapshots the queue and selects B. Both hooks can report B, losing A. Hermes releases the queue lock before firing hooks and [disables coalescing during terminal preparation](/home/raven/reference/hermes-agent/tools/approval_gateway_wait.py:158). **Change:** capture identity from the actual entry/notification, or expose it upstream; ambiguous snapshots remain view-only.

3. **High — “Unique open operation” does not prove identity.** [Pre/post fallbacks and newest smart matching](/home/raven/score/docs/briefs/1.14b.md:125) depend on what Score has observed. Sequence: subagents A/B share a session key; B’s creation is delayed; B’s denial matches the sole open A. Redaction or truncation can also make different commands equal. **Change:** correlate by producer incarnation, session id, tool-call id and gate occurrence; retain unmatched signals. Hermes [already adds tool/turn/session identifiers](/home/raven/reference/hermes-agent/tools/approval_context.py:66). Digests supplement identity; identical commands still need distinct occurrence ids.

4. **High — Follower semantics contradict Hermes.** [“Newest” leader selection and unconditional mirroring](/home/raven/score/docs/briefs/1.14b.md:122) are wrong. With two matching leaders, Hermes selects the first queue entry while Score selects the newest. Separately: leader receives `once` → follower requests fresh consent; Score mirrors approval and creates another operation for that prompt. [Hermes explicitly excludes `once` from adoption](/home/raven/reference/hermes-agent/tools/approval_gateway_wait.py:104). **Change:** carry an explicit leader identity; detach and continue the follower’s own operation after `once`. Respect independent follower withdrawal/timeout.

5. **High — Guardian denial is not necessarily final.** [Smart deny → `decided`](/home/raven/score/docs/briefs/1.14b.md:138) assumes authorization has ended. Sequence: smart pre → smart deny → human override prompt → human approval. The brief leaves a terminal guardian-denied operation and creates another for the same action. [Hermes permits human override after guardian denial](/home/raven/reference/hermes-agent/tools/approval.py:761). **Change:** record the guardian verdict separately; determine whether a human stage follows before declaring the operation decided. Preserve its restricted `once|deny` choices.

6. **High — Transport ids are routed to the wrong resolver.** [“request_id on transport surfaces” → gateway operation](/home/raven/score/docs/briefs/1.14b.md:130) treats transport ids as gateway queue ids. Sequence: transport request → Score decision → `resolve_gateway_approval` returns zero, while the transport remains waiting. For Score runs, “never create” can instead lose the operation because the selected transport bypasses the SSE notification. [Transport hooks also emit `transport_timeout`, `transport_error`, etc.](/home/raven/reference/hermes-agent/tools/approval_prompt.py:238), contradicting the stated choice enumeration. **Change:** distinguish target kinds; unsupported transports remain observable but view-only; normalize their failure outcomes.

7. **High — Dedupe only works in one arrival order.** [Smart pre always creates; unmatched run hooks are merely recorded](/home/raven/score/docs/briefs/1.14b.md:119). Sequence: human SSE arrives before the spooled smart pre → human operation created → separate guardian operation created. Post before SSE is likewise discarded for projection purposes, leaving a later request pending after resolution. **Change:** maintain durable correlation records/tombstones and reconcile stored signals whenever either side arrives. Gateway creation must also check the exact target before inserting.

8. **High — Settle can permanently hide the actual choice.** [“First terminal signal wins” and resolved settle → `decided/unknown`](/home/raven/score/docs/briefs/1.14b.md:135). Sequence: exact settle `resolved` → operation closes → id-less post `deny` cannot match an “open” operation. This is [Hermes’s normal ordering](/home/raven/reference/hermes-agent/tools/approval_gateway_wait.py:185). A deadline race can even emit settle `timeout` followed by a committed choice. **Change:** separate request closure from known decision evidence; correlate posts to closed operations and allow authoritative evidence to refine placeholders.

9. **High — Settle callbacks overwrite one another.** The [1.13b settle dependency](/home/raven/score/docs/briefs/1.14b.md:143) assumes subscription semantics. Sequence: Score registers during pre → Telegram notification registers its timeout callback → Score never receives settle. [Registration assigns one slot](/home/raven/reference/hermes-agent/tools/approval.py:199); the [gateway registers afterward](/home/raven/reference/hermes-agent/gateway/run_turn_runner.py:1488). **Change:** require composable observer registration, handle registration failure, and reconcile exact queue state. Re-registering blindly merely displaces another surface.

10. **High — Ordinary transport uncertainty gets false attribution.** [Port transient error → `intent`; later 409 → `not_pending`](/home/raven/score/docs/briefs/1.14b.md:174). Sequence: Hermes applies Score’s approval → HTTP response is lost → retry returns 409 → UI says “answered elsewhere.” Exhausted ambiguous retries can similarly become `failed` despite application. **Change:** persist whether any attempt may have applied; subsequent absence/error means `unknown`, using the same conservative rule as crash recovery.

11. **High — Acks lack attempt identity and discard stronger evidence.** [Ack by delivery id; terminal acks never change state](/home/raven/score/docs/briefs/1.14b.md:192). Sequence: lease 1 applies → expires → lease 2 reports `not_pending`, producing `unknown` → lease 1’s delayed positive ack is ignored. A stale failure can also finalize a newer attempt prematurely. **Change:** add lease/attempt tokens and receipts, fence negative outcomes, and allow verified late application evidence to refine uncertainty. Exact-target application should require `resolved = 1`, not merely ≥1.

12. **High — A leased delivery can remain forever.** [Cleanup only covers expired leases with attempts ≥3, or absent producers while `intent`](/home/raven/score/docs/briefs/1.14b.md:196). Sequence: producer leases once → dies → lease expires → nobody can poll to increment attempts. Approval expiry does not terminate the delivery. **Change:** independently sweep every delivery against lease, producer and target deadlines; abandoned possibly-applied leases become `unknown`. Enforce expiry when leasing.

13. **High — Healthy waiting producers become “gone.”** [Two-minute freshness requirement](/home/raven/score/docs/briefs/1.14b.md:107). Sequence: producer reports a prompt → waits quietly while polling decisions → no event updates `last_seen_at` → card becomes non-actionable or intent fails. Existing freshness updates come from hello/events. **Change:** authenticated decision polling/acks must refresh liveness, or define a heartbeat.

14. **High — Definitive delivery failure permanently disables recovery.** [Any delivery row prevents actionability; one row per approval](/home/raven/score/docs/briefs/1.14b.md:104). Sequence: decision accepted → definitively fails before application → connection repaired → every subsequent decision gets 409 although Hermes still waits. **Change:** provide retry of the existing decision identity after proven non-application, without allowing a second competing decision.

15. **High — The schema lacks future target and completion bindings.** [Request-id-required actionability, run-only refs and generic delivery arguments](/home/raven/score/docs/briefs/1.14b.md:95) cannot directly represent a Kanban grant. Sequence: worker blocks → human approves an exact digest for the next eligible attempt; there is no pending Hermes request id. Also, applied approval → tool completion has no specified transition to `executed|blocked`. **Change:** reserve origin-specific target records containing tool correlation or board/task/attempt/digest, and define grant delivery/completion semantics. This avoids repurposing `request_id`. Contract changes must come first; the brief’s “Don’t edit docs” restriction conflicts with AGENTS.md.

**Things that are fine:** Transactional observation/ledger/event updates, durable intent before external effects, exact-id resolution once correctly bound, credential-generation routing, producer-scoped delivery, paired human authorization, and keeping `not_pending` distinct from denial are sound foundations.
