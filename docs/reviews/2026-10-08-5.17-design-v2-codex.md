1. **High — Filesystem incarnation does not provide the promised database-history identity.**

   V2 says inode-based incarnation ensures recreated/restored boards never reuse a run identity. An in-place restore preserves `dev`, inode and birth time, while rolling back attempt ids and the event cursor. Conversely, copying the same logical history onto a new inode can materialize retained attempts again under new Score ids. Claim locks cannot repair this: Hermes generates `host:pid`, not a unique claim nonce. [V2 identity claim](/home/raven/score/docs/briefs/5.17.md:23), [incarnation implementation](/home/raven/score/apps/server/src/hermes/live/sqlite.ts:47), [Hermes claim identity](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db.py:1164)

   Task identity also needs attention: `task_projections` remains keyed solely by upstream task id, so namespacing runs alone does not namespace their historical task relationships. [Task projection schema](/home/raven/score/apps/server/migrations/0010_tasks.sql:1)

   **Change:** Define replacement, rollback, and restoration policy explicitly. Use a durable logical generation when available; otherwise detect contradictions and retain ambiguous evidence as unassociated with a gap. Preserve source-qualified historical task links. Remove the absolute restore guarantee unless Hermes supplies sufficient immutable identity.

2. **High — The bridge envelope cannot construct the pending evidence key.**

   Events carry `{board, attemptId, claimLock, role}`, while pending evidence requires `(source, history, attempt_id)`. A board slug supplies neither the database root nor its history. Looking up the currently observed file when delayed spool delivery arrives can attach an old worker’s evidence to a replacement database. [Proposed envelope and pending key](/home/raven/score/docs/briefs/5.17.md:48)

   Hermes supplies `HERMES_KANBAN_DB` specifically because a worker’s profile-scoped `HERMES_HOME` may differ from the board root. Score currently reads one default database path. [Hermes database pin](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db_dispatch.py:2922), [Score paths](/home/raven/score/apps/server/src/hermes/live/paths.ts:11)

   **Change:** Specify how immutable source/history provenance is captured, serialized, recovered and validated. Resolve evidence only against matching stored claim provenance, including task and claim identity; ambiguous history stays unassociated. Pin future mutations to the observed database source.

3. **High — Per-hook role capture still cannot establish helper ownership in every supported mode.**

   Current producer registration caches process/profile identity and reads the task directly from process environment. Helpers and cron execution can share that producer. V2 correctly moves ownership capture to each hook, but a role flag alone does not establish a child’s relationship to an attempt. [Cached identity](/home/raven/score/hermes-plugin/score_bridge/client.py:71), [producer allocation](/home/raven/score/hermes-plugin/score_bridge/sender.py:177)

   Hermes’s ownership predicate distinguishes delegated and unrelated execution. However, `subagent_start` fires in the **parent context**, carrying explicit parent/child session ids; context classification alone would classify that hook as worker activity. Delegated subprocess environments also remove task/run/claim variables. [Ownership predicate](/home/raven/.hermes/hermes-agent/agent/delegation_context.py:71), [subagent hook](/home/raven/.hermes/hermes-agent/tools/delegate_tool.py:323), [environment scrubbing](/home/raven/.hermes/hermes-agent/agent/delegation_context.py:122)

   Under plugin-host isolation, RPC forwards arguments, not the caller’s ownership ContextVars. Private lookups inside the host cannot reconstruct them. [Host RPC](/home/raven/.hermes/hermes-agent/hermes_cli/plugin_host.py:326)

   **Change:** Separate immutable producer identity, event execution role, and explicit session lineage. Interpret hook semantics individually. Leave host-mode ownership unknown unless upstream transports it. Add the new private APIs and isolation behavior to the tested fingerprint; Score currently records `bridge: null`. [Fingerprint omission](/home/raven/score/apps/server/src/hermes/live/fingerprint.ts:20)

4. **High — Unknown profile and unknown closure are not representable by the proposed migration/contracts.**

   V2 retains null profiles and displays “ended (unknown),” but adds only `closure_reason` to `RunSummary`. Score’s SQL requires `profile NOT NULL`; `RunSummary.agentId` is mandatory; its status enum has no unknown terminal state. Internal run parsers and terminal sets impose the same assumptions. [Runs migration](/home/raven/score/apps/server/migrations/0003_runs.sql:9), [RunSummary schema](/home/raven/score/packages/contract/src/types.ts:268), [run parser/lifecycle](/home/raven/score/apps/server/src/hermes/live/translate.ts:22)

   In-memory schema checks reject both a null agent and an unknown terminal status.

   **Change:** Specify the nullable-agent representation and an explicit terminal unknown state, including migration, stream validation, terminal guards, filters and UI. Unknown attribution must not become a fabricated profile. Allow later terminal classification refinement without reopening execution.

5. **High — Full-field content identity is still not a revision, and the sweep misses closed changes.**

   Including every field in a dedupe identity does not ensure every change survives. With current ingest semantics, summary **A → B → A** repeats an already-seen identity; the last update is discarded if the implementation uses the listed field hashes as its identity. [V2 observation rule](/home/raven/score/docs/briefs/5.17.md:38), [permanent-key dedupe](/home/raven/score/apps/server/src/hub/ingest.ts:189)

   The proposal’s example is also inaccurate: editing a completed summary emits an `edited` event with its run id. The genuinely silent PID cleanup can affect **closed** rows, outside the proposed open-attempt sweep. [Hermes summary edit](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db.py:3268), [terminal PID cleanup](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db_dispatch.py:547)

   **Change:** Use event ids for immutable event observations and persisted monotonic revisions for changed reconciliation snapshots; hashes compare current content rather than identify all historical revisions. Reconcile relevant closed attempts too. Correct D2.3’s insufficient revision example. [Architecture example](/home/raven/score/docs/ARCHITECTURE.md:132)

6. **High — Recovery lacks an atomic commit and complete baseline policy.**

   The current tailer advances the checkpoint with task projection, then projects review transitions separately. Extending that pattern with run projection creates a crash window: the event is acknowledged before its attempt/link facts exist. [Tailer submission ordering](/home/raven/score/apps/server/src/hermes/live/tasks.ts:117)

   Claim events are not permanent. Hermes prunes old done/archived events while retaining attempt rows, and the ordinary task-detail reader retrieves only 50 events. “Equivalent claim provenance” therefore needs a precise definition; absence of a claim event cannot automatically mean synthetic execution. [Hermes event retention](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db.py:4370), [activity window](/home/raven/score/apps/server/src/hermes/live/kanban.ts:117)

   Late evidence also cannot simply replay the original bridge observation: ingest will dedupe it, and existing Watch frames may already have an inferred or null run link. [Watch association](/home/raven/score/apps/server/src/domain/watch-frames.ts:363)

   **Change:** Commit mapping, run, task links, pending resolution, derived events and checkpoint in one writer transaction. Define a paged, resumable historical baseline and explicit unknown-provenance gaps. Resolve late evidence through a distinct association operation, updating existing Watch frames at the same frame sequence and publishing the corresponding updates.

   **Change:** Observe session ids across supported hooks and reconcile exact persisted compression lineage. Preserve profile/source-qualified session identity and parent links. Keep helper role separate from continuation relationship—a compressed helper remains a helper. Define how multiple observed models are displayed; missing evidence stays null.

    **Change:** For Kanban attempts, derive the finite boundary from `ended_at` regardless of pending approval presentation. Preserve every attempt block and gap. Late approvals from surviving workers remain separate evidence rather than reopening an ended attempt. Use persisted attempt role for review labels.

14. **Medium — Pending evidence needs the complete privacy boundary, not just generic scrubbing.**

    The summary/error byte limits and metadata allowlist are improvements. But existing bridge normalization additionally removes credential-bearing tool arguments/results and credential-file content. Those rules are stronger than secret-pattern scrubbing. A pending-store branch before those filters becomes a new persistence bypass. [Server credential-tool/file filtering](/home/raven/score/apps/server/src/hermes/bridge/translate.ts:195)

    The new closure reason and provenance fields also need bounded validation; “raw” must not mean arbitrary unbounded display text.

    **Change:** Use one normalization path before both immediate projection and pending storage: forced plugin redaction, server credential filters, server scrub, validation and byte limits. Specify pending row/aggregate limits, orphan retention and safe error logging. Expiration records a gap.

15. **High, deferred — The upstream Stop draft still lacks launch fencing and durable recovery.**

    Fence/hold/terminate/idempotency are sound requirements, but the draft does not define durable stopping intent, restart recovery, or handling of a worker between claim and PID registration. Current dispatcher PID registration updates the task and whichever run is current using **task id only**. A safe Stop operation needs coordination with that path, not just a fence in the Stop command. Missing PID during launch cannot prove “not running.” [Stop draft](/home/raven/score/docs/proposals/hermes-attempt-fenced-stop.md:26), [spawn ordering](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db_dispatch.py:2124), [PID registration](/home/raven/.hermes/hermes-agent/hermes_cli/kanban_db_dispatch.py:1468)

    The HTTP route also selects the current run from a node at request execution. If Stop promises to stop the attempt displayed to the user, an upstream fence protects the wrong selection unless the request includes the expected Score run id. [Stop route](/home/raven/score/apps/server/src/http/briefs.ts:85)

    **Change:** Require durable intent/results, attempt-fenced launch registration and lifecycle transitions, recovery after each crash boundary, and an expected run id from the client. Test direct and scoped launches; define whether termination covers worker descendants. Hermes already distinguishes whole-scope teardown from plain PID signaling. [Scope cleanup semantics](/home/raven/.hermes/hermes-agent/tools/process_registry.py:470)

16. **Medium — Retry scope and acceptance criteria still conflict with the split.**

    “Offers reclaim” is ambiguous in a read-only projection task. An app retry action is absent from §7 and existing action arguments. Relabeling reclaim does not eliminate its ability to leave an old worker alive while enabling another dispatch. [Task action contract](/home/raven/score/docs/API-CONTRACT.md:439), [action arguments](/home/raven/score/apps/server/src/hermes/live/task-actions.ts:81)

    `PLAN.md` still requires Stop to work in fake mode before 5.17 is done. V2’s unavailable-response test cannot satisfy that requirement. [Plan acceptance criteria](/home/raven/score/docs/PLAN.md:278)

    **Change:** Keep reclaim in Hermes for 5.17a, or specify a separate contracted retry feature with truthful surviving-worker semantics. Update PLAN to distinguish completed 5.17a from deferred 5.17b. Add crash/restart, in-place restore, A→B→A, pruned-claim, short-gap, unknown-state, host-isolation and requested-changes acceptance fixtures.

The corrected design I would approve is:

- Materialize one run per proven claimed attempt. Persist immutable source-qualified claim, task and role provenance; retain unknowns explicitly. Treat filesystem identity as an observation boundary, with a documented restore/ambiguity policy.
- Extend the existing tailer with paged historical recovery and reconciliation. Atomically commit attempts, links, pending resolution, stream events and checkpoints. Use genuine observation revisions.
- Carry validated provenance per hook, preserve explicit helper/continuation lineage, and degrade unsupported isolation modes. Discover compression sessions from exact evidence; preserve observed model history.
- Store tool observations by producer/counter. Pair only with guaranteed invocation identity. Backfill existing Watch frames without changing their frame sequence and update logs/file consumers.
- Separate attempt closure, review verdict, task acceptance and worker termination. Keep Now attempts finite and distinct; expose unknown attribution and closure through supported schemas and labels.
- Keep Reports spend sourced once from session accounting, propagate unknown totals, and use historical ownership for waits. Leave unproven attempt attribution null.
- Ship 5.17a with explicit Stop unavailability. Ship 5.17b only after a durable, launch-safe, attempt-fenced Hermes operation passes termination, successor-race and recovery fixtures.
