The remaining failures and newly introduced regressions follow.

1. **P1 — A failed capability-marker write permits fallback after restart.**  
   [unit-backend.ts:495](apps/server/src/runtimes/coding/unit-backend.ts:495), [line 353](apps/server/src/runtimes/coding/unit-backend.ts:353).

   `rememberCapable()` catches persistence errors and still declares the backend usable. Its in-memory flag also prevents another persistence attempt. After restart, only marker existence remembers the pass.

   With a mocked `ENOSPC`, the probe returned `kind: unit`, `usable: true`; restarting with a capability failure returned `process-group`, with no admission block. This violates decision 69.

   **Fix:** require durable capability memory before permitting launches, retry failed persistence, and recover positive capability evidence from owned unit history.

2. **P1 — Production has an explicit bypass of the narrowed scope.**  
   [start-server.ts:387](apps/server/src/start-server.ts:387), [unit-backend.ts:482](apps/server/src/runtimes/coding/unit-backend.ts:482).

   `SCORE_CODING_BACKEND=process-group` bypasses the ever-capable pause. The probe with `capable = true` returned fallback and no block.

   The exception is documented at [SETUP.md:310](docs/SETUP.md:310) and asserted by a new test, but conflicts with the supplied scope: process-group execution only on hosts that never passed.

   **Fix:** remove this production exception for ever-capable installations; keep any forced-backend seam confined to tests.

3. **P1 — Confirmed copies retain sendable refusals and deliver source Stops.**  
   [installation.ts:506](apps/server/src/installation.ts:506), [line 534](apps/server/src/installation.ts:534), [fence.ts:346](apps/server/src/domain/orchestration/fence.ts:346).

   Confirmation treats every journal `attemptId` as already handled. A journaled refusal therefore excludes a still-`created` attempt from retirement; reconciliation explicitly leaves refused attempts sendable. Running attempts are also excluded, and inherited handles/owed Stops remain actionable through [executor.ts:2407](apps/server/src/domain/orchestration/executor.ts:2407).

   A probe through the actual confirmation and reconciliation functions produced `attempts: []`, retained the refused attempt as `created`, and issued a Stop for `source-live-run`.

   **Fix:** durably retire the complete inherited attempt set, including refused and running attempts. Dispatch and Stop delivery must consult that retirement disposition.

4. **P1 — Process ownership defaults to permission precisely when installation ownership is unresolved.**  
   [start-server.ts:411](apps/server/src/start-server.ts:411), [service.ts:1302](apps/server/src/runtimes/coding/service.ts:1302).

   Production supplies `ownsProcessRow` only for a resolved, unblocked installation. Otherwise its default is `true`, and recovery still processes copied rows. An unconfirmed copied home can consequently stop the source’s live fallback group before confirmation. The probe observed a signal request for the copied PID.

   A confirmed copy with lost retirement history has a related problem: [coding-journal.ts:63](apps/server/src/domain/orchestration/coding-journal.ts:63) accepts readable empty history as ownership.

   **Fix:** always wire a conservative production ownership check. Unresolved installation identity or missing copy-retirement history must prohibit signaling.

5. **P1 — Lifting the missing-journal fence allows a witnessed turn to execute again.**  
   [fence.ts:389](apps/server/src/domain/orchestration/fence.ts:389), [line 552](apps/server/src/domain/orchestration/fence.ts:552).

   Restore SQLite to before execution and lose the journal while retaining routing and receipts. Startup detects the loss, but a generic lift suppresses older launch folders by timestamp. Nothing reconstructs their turn identities as permanently unsendable.

   The probe raised `journal_missing`, lifted it, then obtained `requested` and `releasing` for the same turn named by the surviving receipt folder.

   **Fix:** reconcile surviving launch files into permanent turn dispositions before admission resumes. A timestamp-based generic lift cannot substitute for that reconciliation.

6. **P1 — Local ACK flushing plus absent unit metadata still permits false success.**  
   [coding-socket.ts:479](apps/server/src/runtimes/coding/coding-socket.ts:479), [unit-backend.ts:1289](apps/server/src/runtimes/coding/unit-backend.ts:1289).

   The write callback proves local flushing, not supervisor consumption. If the supervisor dies with that ACK unread, then manager replacement removes its failure metadata, `supervisorExit()` treats absence as `clean`.

   Probes returned `eligible: true` with no peer ACK consumption, and `clean` for an absent supervisor. The existing `ended` receipt predates ACK and cannot establish normal completion.

   **Fix:** require positive evidence that the recorded supervisor received ACK and completed normally—such as a durable final receipt. Missing exit metadata must preserve uncertainty.

7. **P1 — Dropped driver records still leave successful authority.**  
   [codex.ts:165](apps/server/src/runtimes/coding/codex.ts:165), [line 285](apps/server/src/runtimes/coding/codex.ts:285), [claude.ts:236](apps/server/src/runtimes/coding/claude.ts:236).

   Codex unknown records increment `unknown` without sticky loss. Claude has no equivalent final loss check: an explicit success followed by a rejected error-result record retains the success.

   Both probes retained eligible candidate replies despite dropped records; Claude’s rejected record explicitly claimed an error.

   **Fix:** distinguish explicitly validated ignorable records from lost records. Rejected terminal records and other authority-relevant loss must invalidate the entire attempt through final EOF processing.

8. **P1 — The new bounds cut secrets before redaction.**  
   [note.ts:140](apps/server/src/runtimes/coding/note.ts:140), [translate.ts:192](apps/server/src/runtimes/coding/translate.ts:192), [note.ts:61](apps/server/src/runtimes/coding/note.ts:61).

   Cutting a quoted credential removes its closing quote and changes how the redactor recognizes its value. A tool name containing a long quoted `password` stored repeated secret words. Cutting through a registered opaque gateway credential also stored its recognizable prefix.

   The shared diagnostic accumulator has the same problem at its raw cap: the probe leaked quoted password text on both engines.

   **Fix:** redact complete CLI fields before bounding them. On diagnostic overflow, discard uncertain context or mask the entire open credential value.

9. **P1 — Forced fallback pipe closure is certified as complete.**  
   [process.ts:447](apps/server/src/runtimes/coding/process.ts:447), [line 405](apps/server/src/runtimes/coding/process.ts:405).

   Cleanup destroys pipes without recording forced stdout loss. A candidate success can survive while unread terminal/error data is discarded.

   The boundary probe discarded 77 bytes containing a failure record but returned `streamComplete: true`, no loss reasons, `groupGone: true`, and an eligible candidate.

   **Fix:** track natural stdout EOF separately from destruction. Forced stdout closure must disqualify completion.

10. **P2 — The installation memory budget still omits translator and delivery retention.**  
    [unit-backend.ts:820](apps/server/src/runtimes/coding/unit-backend.ts:820), [translate.ts:37](apps/server/src/runtimes/coding/translate.ts:37), [coding-socket.ts:692](apps/server/src/runtimes/coding/coding-socket.ts:692).

    Production charges parser retention but never uses `translationBytes()`. With 128 accepted tool starts, the probe retained **2,057,106 bytes** in translator details while the parser reported zero and the reservation remained 524,288 bytes.

    Reservations also disappear on socket outcome while proof and terminal delivery can still retain state.

    **Fix:** account for all retained run state and release its budget only when that state is cleared.

11. **P2 — Live completion clears an adopted durable stop cause.**  
    [unit-backend.ts:1309](apps/server/src/runtimes/coding/unit-backend.ts:1309), [line 1311](apps/server/src/runtimes/coding/unit-backend.ts:1311).

    After socket loss, receipt adoption records `socket-loss`. The subsequent projection writes the session’s null `stopCause` over SQLite’s adopted cause.

    The probe ended with journal cause `socket-loss`, SQLite cause `null`, and a `verifyCoding()` divergence. Receipt adoption also silently ignores unreadable/invalid files and does not validate generation.

    **Fix:** project the journal’s first cause without independently clearing it; validate stop receipts and retain visible uncertainty on receipt errors.
