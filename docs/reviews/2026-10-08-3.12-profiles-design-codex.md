The draft needs changes before implementation. I checked Hermes checkout `e97923c3`, matching Score’s recorded 0.21.5 build. The listed command families exist; per-profile `config set API_SERVER_KEY`, `model.default`, and `model.provider` are valid. Several claimed effects and recovery assumptions are wrong.

1. **High — Clone copies substantially more than the person confirms.**  
   **Rule:** D7.1 explicit human decisions; the existing stricter-only permission policy.  
   `--clone-from` copies config, non-channel `.env` credentials, SOUL, skills, `memories/MEMORY.md`, `memories/USER.md`, installed plugins and their provenance, and the active external memory provider’s configuration, potentially including credentials. It does **not** copy `AGENTS.md`, `auth.json`, session history/state.db, or cron jobs through this normal clone path. Channel stripping removes bot credentials, channel allowlists, platform sections, and **API_SERVER_KEY**. Thus “replace the inherited API key” is misleading: the usable API key is stripped before publication. Command allowlists and approval settings still travel with config.  
   **Scenario:** “Copy configuration and personality” also gives the new agent private notes, tool credentials, enabled plugin code, and permissive approval settings.  
   **Minimal change:** Explicitly confirm those inherited capabilities and data, or disable clone pending selective upstream support. Apply and verify team permissions before activation. [Hermes cloning](/home/raven/reference/hermes-agent/hermes_cli/profiles.py), [channel stripping](/home/raven/reference/hermes-agent/hermes_cli/profile_channels.py).

2. **High — Creation can activate before provisioning finishes; the gateway topology is wrong.**  
   **Rule:** D2.5, D2.6, and confirmation scope.  
   `create_profile` publishes atomically, then immediately asks the running multiplexer to serve the profile; periodic discovery also picks it up. Step 5 is therefore not the activation boundary. The supported topology uses one host gateway and `/p/<profile>/…` routes. Starting another `gateway run` can be refused or create competing listeners/dispatchers. Named-profile stop can park a satellite; an unconfirmed control request can still return successfully.  
   **Scenario:** Copied plugins or queued work become available before the selected model, bridge, and permissions are ready.  
   **Minimal change:** Require inactive provisioning, using upstream atomic parked creation or an explicitly confirmed maintenance window. A later `gateway stop` cannot close the publication race. Never silently install services, force a second gateway, or restart the host. [Create publication](/home/raven/reference/hermes-agent/hermes_cli/profiles.py), [profile lifecycle](/home/raven/reference/hermes-agent/hermes_cli/gateway_profile_lifecycle.py).

3. **High — Rename has unconfirmed side effects and changes the API ownership namespace.**  
   **Rule:** D2.5 credential/run ownership; AGENTS.md restrictions on global changes.  
   Named-profile rename removes supervisor registrations, stops its gateway and Bot Desktop, moves the directory, updates sticky selection, creates a new shell alias **even when creation used `--no-alias`**, attempts identity migration, and hot-serves the new name. `rename default NEW` only changes its display name; its ID remains `default`. Hermes’s identity migration does not rewrite shared Kanban assignees/reviewers. Runs API ownership hashes **profile plus key**, so moving Score’s rows and retaining the same key does not preserve control of an active run.  
   **Scenario:** Rename strands an approval, removes a service the person expected to retain, or incorrectly migrates `default` credentials to another ID.  
   **Minimal change:** Drain before rename; preview alias/service/runtime effects; handle default display rename separately; explicitly handle Kanban references. [Rename implementation](/home/raven/reference/hermes-agent/hermes_cli/profiles.py:2456), [run ownership](/home/raven/reference/hermes-agent/gateway/platforms/api_server_runs.py:360).

4. **High — “Idempotent intent” does not make these CLI effects idempotent or transactional.**  
   **Rule:** D2.6 acceptance reconciliation and D5 outbox.  
   Profile creation has no upstream idempotency key. Rename can exit successfully despite failed identity migration; delete can fail **after the directory has been removed** because identity settlement remains pending. Score’s current CLI wrapper discards the diagnostics. A key-file move also cannot participate in a SQLite transaction.  
   **Scenario:** After a timeout, recovery adopts an unrelated same-name profile, overwrites its key, or repeats a destructive operation against a replacement profile.  
   **Minimal change:** Require a durable operation ID, request hash, locks, target identity, and verified per-step postconditions. An existing directory alone is insufficient proof. Recover through `profile migrate-identity` or `purge-identity` as appropriate; keep ambiguous states blocked from admission. Persist credential references/generations, never keys or secret-bearing argv. Automatic rollback must not delete, import, rotate, or restart without matching confirmation. [Identity recovery](/home/raven/reference/hermes-agent/hermes_cli/profile_identity.py), [CLI wrapper](/home/raven/score-worktrees/3.12-profiles/apps/server/src/hermes/live/cli.ts).

5. **High — The proposed export is sensitive and is not a complete rollback backup.**  
   **Rule:** D7 secret/privacy protection; reliable recovery before deletion.  
   Export excludes `.env`, `auth.json`, other recognized credential stores, and scrubs supported text formats. Named-profile exports can retain **unscrubbed binary databases**, including conversations and embedded secrets. Export stages files with ordinary copying, not a consistent SQLite snapshot. Its archive writer already creates a private temporary file, but the draft leaves destination ownership, containment, retention, and access unspecified.  
   **Scenario:** A live export captures mismatched database/WAL files; later import restores neither credentials nor a reliably complete state. A backup-download endpoint exposes retained conversations.  
   **Minimal change:** Quiesce before export, verify completion and archive integrity, and disclose credential omission. Store under configured `$SCORE_HOME` in an owner-only, path-checked directory; keep archives private and define retention. Never present export as a complete undo. [Export implementation](/home/raven/reference/hermes-agent/hermes_cli/profiles.py:2307).

6. **High — Busy checks and “archive rows” do not retire an agent safely.**  
   **Rule:** D2.3 identity separation, D2.4 reconciliation, D5 durable routing.  
   Score’s displayed activity is derived from its projections; it is not authoritative evidence that every CLI, cron, gateway, or Kanban producer is idle. Room queues retry and identify agents by profile name. Retained membership, lead selection, pending intents, or Kanban assignments can outlive deletion.  
   **Scenario:** A newly created profile reusing a deleted name receives an old queued turn and its private room context.  
   **Minimal change:** Freeze admissions durably, reconcile all work origins, and refuse unknown activity. Confirm disposition of pending work and assignments. Remove active routing references while preserving historical attribution; reserve retired names or introduce incarnation-aware identity. [Routing queue](/home/raven/score-worktrees/3.12-profiles/apps/server/src/domain/routing-dispatch.ts).

7. **High — Authentication and contract changes are not specified sufficiently.**  
   **Rule:** D7.1 and API contract conventions.  
   `(H)` is correct intent, but pairing is enforced **per route**, not globally. The contract’s existing create endpoint is not marked H; rename, describe, delete, and operation recovery are absent. `agent.upserted` is not a contracted event: the existing event is `agent.updated`. CSRF headers alone are forgeable by a local process. Reads are unpaired, and `config.ts` permits non-loopback hosts despite D7’s loopback posture.  
   **Scenario:** An implementer follows the existing create contract without `humanGuard`, or adds an unauthenticated operation/backup endpoint on a LAN-bound server.  
   **Minimal change:** Update contract and schemas first; guard every lifecycle mutation and sensitive operation/backup read. Keep this feature loopback-only until remote-access protections exist. [Contract](/home/raven/score-worktrees/3.12-profiles/docs/API-CONTRACT.md:269), [CSRF guard](/home/raven/score-worktrees/3.12-profiles/apps/server/src/auth/csrf.ts).

8. **Medium — Description and plugin mechanisms need exact corrections.**  
   **Rule:** D2.1 adapter boundaries, D2.6 write exception, explicit scope.  
   Describe uses `--text`, not `--set`; empty `--text` reads rather than clears. Unqualified administrative calls can follow sticky profile selection, and describing `default` can target that current home. “Blank” creation seeds the active model/custom-provider configuration and bundled skills; `--no-skills` is incompatible with cloning and still seeds essentials. Plugin `adopt` only records provenance for an already self-cloned Git directory.  
   **Scenario:** Editing default’s description edits another profile, or a failed plugin installation prompts an unauthorized symlink fallback.  
   **Minimal change:** Pin administrative calls to `-p default`, validate canonical names/reserved names, and use explicit nonempty description text without `--auto`. Install the dependency-free bridge through a pinned Git/file URL subdirectory using Hermes CLI; enable its manifest name, **`score-bridge`**. Never link/copy into Hermes from Score or bypass a refused scan. [Description handler](/home/raven/reference/hermes-agent/hermes_cli/profile_cmd.py), [plugin installation](/home/raven/reference/hermes-agent/hermes_cli/plugins_cmd.py).

9. **High — Throwaway live tests violate AGENTS.md.**  
   **Rule:** Testing explicitly forbids live Hermes calls and model-token spending.  
   **Scenario:** A disposable profile still shares the owner’s gateway, provider access, and plugin dependency environment.  
   **Minimal change:** Replace automated live tests with fake-adapter acceptance tests and recorded/stubbed CLI fixtures. The draft/PLAN live-testing language conflicts with the governing rule and must be corrected. [Testing rule](/home/raven/score-worktrees/3.12-profiles/AGENTS.md:59).

The implementer should follow this corrected sequence:

1. Define guarded lifecycle, preview, operation-status, recovery, and retirement contracts; retain Hermes knowledge inside the adapter.
2. Bind confirmation to canonical targets, revisions, inherited data/capabilities, runtime effects, backup location, and pending-work disposition.
3. Persist an operation and freeze admissions. Provision inactive; otherwise refuse until the person confirms the necessary maintenance window.
4. Create through exact CLI argv. Atomically preserve one fresh Score-owned key before setting it remotely; configure model, team permissions, and pinned `score-bridge`. Honor configured Score home and bridge address.
5. Verify authenticated profile capabilities, model/permission readback, and bridge handshake before marking ready. Do not launch a test conversation automatically.
6. Rename only after draining; verify identity settlement, reconcile Kanban and Score references, and journal filesystem changes separately from SQL.
7. Delete only after quiescence and verified private export. Reconcile actual deletion/purge outcomes, retire routing, preserve history, and prevent accidental name reuse.
8. Test crashes after every external step, stale confirmations, concurrent admissions, name reuse, authorization, redaction, and partial settlement using fakes and fixtures.

Typed-name deletion, refusing default deletion, fresh per-profile credentials, avoiding `--clone-all`/`--clone-channels`, color-plus-shape styling, and preserving historical messages are sound choices.
