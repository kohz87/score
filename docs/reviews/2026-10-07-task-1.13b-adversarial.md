1. **P1 — Capture can authorize another invocation.** [approvals.py:39](/home/raven/score-worktrees/1.13b-gateway-approvals/hermes-plugin/score_bridge/approvals.py:39)  
   A enqueues an approval, then another surface resolves A before its hook runs. Thread B enqueues an identical command during terminal preparation. A’s hook sees only B, claims B’s id, and reports A’s description with B’s actionable identity. The claims check cannot establish ownership because B has not claimed its entry yet.

   A probe using Hermes’s actual queue and gateway-wait functions reproduced this and successfully resolved B using A’s captured id. Separately, after 4,096 later claims evict an active id, an unrelated CLI hook can claim that id again.

   **Minimal fix:** require an id bound to the hook’s own entry upstream; otherwise report `null`. Do not treat a unique command/pattern match or absence from an evicting cache as ownership proof. The brief’s suggested algorithm conflicts with the contract’s exactness guarantee.

2. **P1 — Approval capture blocks the Hermes hook thread without a bound.** [approvals.py:39](/home/raven/score-worktrees/1.13b-gateway-approvals/hermes-plugin/score_bridge/approvals.py:39), [hermes_private.py:34](/home/raven/score-worktrees/1.13b-gateway-approvals/hermes-plugin/score_bridge/hermes_private.py:34)  
   `list_gateway_approvals` acquires Hermes’s lock without a timeout. Holding that real lock blocked capture for the probe’s entire 200 ms hold; a stuck holder blocks indefinitely. The 64-entry limit also runs **after** Hermes copies every pending entry under that lock, so it does not bound snapshot work.

   **Minimal fix:** use a timed, capped snapshot operation at the private boundary, checking queue length before copying. Return `null` when the bounded operation is unavailable or contended.

3. **P1 — Fork cleanup can deadlock the child.** [decision_transport.py:64](/home/raven/score-worktrees/1.13b-gateway-approvals/hermes-plugin/score_bridge/decision_transport.py:64), [__init__.py:54](/home/raven/score-worktrees/1.13b-gateway-approvals/hermes-plugin/score_bridge/__init__.py:54)  
   If the poller is reading a response body during fork, its buffered reader may hold an internal lock. `HTTPConnection.close()` calls `HTTPResponse.close()`, which waits for that lock in the child, where the owning thread no longer exists. This runs synchronously in the fork callback.

   A pipe-backed real `HTTPResponse` reproduced the child hanging until killed.

   **Minimal fix:** child cleanup must close raw inherited descriptors without closing inherited buffered response objects or acquiring their locks.

4. **P2 — Resolution can commit after lease expiry.** [decisions.py:54](/home/raven/score-worktrees/1.13b-gateway-approvals/hermes-plugin/score_bridge/decisions.py:54)  
   Lease validity is checked before calling the resolver. Hermes’s resolver then waits indefinitely for its approval lock. The probe advanced beyond `leaseUntil` while that call waited; releasing the lock still committed `once`. Shutdown likewise cannot stop that waiting resolution.

   **Minimal fix:** make resolution deadline-aware, checking expiry and cancellation after acquiring the approval lock, before committing. The existing late-`applied` receipt rule accommodates delayed acknowledgements; it does not fence this late mutation.

5. **P2 — Shutdown does not cancel token renewal or lock waits.** [client.py:118](/home/raven/score-worktrees/1.13b-gateway-approvals/hermes-plugin/score_bridge/client.py:118), [client.py:96](/home/raven/score-worktrees/1.13b-gateway-approvals/hermes-plugin/score_bridge/client.py:96)  
   Renewal uses the sender’s transport under `_hello_lock`, with a three-second timeout. `stop_decisions()` closes only the decision transport. A renewing poller, or one waiting behind the sender’s renewal, survives the two-second shutdown budget. The probe confirmed this.

   **Minimal fix:** make poller renewal and lock acquisition cancellable within the shutdown deadline, and recheck closure after renewal before sending.
