# 7.7a code review (Codex gpt-6.1-sol, max, read-only), 2026-10-12

Reviewed: v1.0.3...task/7.7a-part3 at 1b81cf7 against design v7. Verdict: block (11 P1, 6 P2). Fix batches FX1–FX4.

**I would block this merge.** Reviewed `v1.0.3...HEAD` at `1b81cf7` against design v7. Repository unchanged; no systemd units created. Read-only, in-memory probes reproduced the failures identified below. Six driver control checks and `git diff --check` passed; full suites were not run.

1. **P1 — Cleanup waits for the pipes that surviving tools keep open.**  
   [supervisor.mjs:373](apps/server/src/runtimes/coding/supervisor.mjs:373), [supervisor.mjs:217](apps/server/src/runtimes/coding/supervisor.mjs:217).  
   A CLI exits while a detached descendant retains stdout/stderr. `maybeDrained()` cannot start until both pipes close, while `requestStop()` returns because the child exited. After socket loss, the supervisor keeps pinging its watchdog without killing the populated payload. The probe reproduced this stall. Work can continue until the original turn backstop. **Fix:** supervise and escalate payload cleanup independently of pipe EOF; enforce the disconnect budget even after leader exit.

2. **P1 — A run can be `completed` without ended proof.**  
   [service.ts:1042](apps/server/src/runtimes/coding/service.ts:1042), [service.ts:1067](apps/server/src/runtimes/coding/service.ts:1067).  
   Success checks the verdict and CLI exit, then assigns `group: unconfirmed` separately. The probe produced `status: completed` with an explicit “tools may still be running” error. **Fix:** require qualifying ended proof before committing successful status or an eligible reply.

3. **P1 — Malformed Codex records can leave commentary authoritative.**  
   [codex.ts:119](apps/server/src/runtimes/coding/codex.ts:119), [codex.ts:128](apps/server/src/runtimes/coding/codex.ts:128).  
   A malformed `agent_message` with a missing/invalid item ID fails the outer schema, increments only `unknown`, and bypasses `messageInvalid`. Valid preliminary text followed by that malformed final and `turn.completed` returned `eligible: true` in the probe. Malformed updated messages also bypass invalidation. **Fix:** detect potentially authoritative messages before outer validation, make semantic loss sticky, and evaluate eligibility after complete stdout processing.

4. **P1 — Permanent launch witnesses do not prevent replaying their turn.**  
   [service.ts:413](apps/server/src/runtimes/coding/service.ts:413), [coding-checkpoint.ts:173](apps/server/src/domain/orchestration/coding-checkpoint.ts:173).  
   Reconciliation sets `unsendable`, but admission never reads it. After restoring a database that lost the accepted intent/run, the same witnessed `turnId` receives a new run and launch ID. The probe admitted and dispatched a turn whose recovered tombstone was already `unsendable: 1`. **Fix:** reconstruct or retire the corresponding execution intent and enforce journal authority by turn/generation at admission and release.

5. **P1 — Backend selection bypasses fences and reconciliation.**  
   [service.ts:410](apps/server/src/runtimes/coding/service.ts:410), [start-server.ts:359](apps/server/src/start-server.ts:359).  
   A failed capability check skips `unit.block()`; the probe admitted work without calling the blocker. An unresolved installation, missing runtime directory, or forced `process-group` backend removes `UnitBackend` entirely, skipping its inventory and held-launch checks. **Fix:** separate backend selection from mandatory admission barriers and reconciliation. Reconcile both inventories and enforce installation/journal/orphan fences for every backend, including immediately before release.

6. **P1 — Fallback execution witnesses remain inside the restored home.**  
   [service.ts:940](apps/server/src/runtimes/coding/service.ts:940), [service.ts:1090](apps/server/src/runtimes/coding/service.ts:1090).  
   Fallback release records only `coding_processes` in SQLite; it creates no external coding-launch witness. Restoring a snapshot can erase both execution evidence and survivor identities, allowing repetition and preventing restart cleanup. **Fix:** journal fallback launches and release possibility before opening the gate, with durable backend and process identity information.

7. **P1 — Pending terminal storage writes unredacted replies to disk.**  
   [service.ts:719](apps/server/src/runtimes/coding/service.ts:719).  
   `keepPending()` serializes raw `output` and the new authoritative `reply` before the terminal observation redacts them. The probe stored `password=review-sentinel`, which the normal redactor recognizes. Deleting the row afterward does not remove its earlier WAL/database bytes. **Fix:** redact and bound every free-text pending field before serialization.

8. **P1 — An empty receipt can become termination proof.**  
   [unit-backend.ts:799](apps/server/src/runtimes/coding/unit-backend.ts:799), [unit-backend.ts:830](apps/server/src/runtimes/coding/unit-backend.ts:830), [supervisor.mjs:55](apps/server/src/runtimes/coding/supervisor.mjs:55).  
   Receipt reading validates neither JSON nor launch identity. An unreadable manager identity counts as an incarnation change. With an unreadable cgroup and an empty `ended.json`, the probe returned `proven: true`. Receipt writing also ignores short-write counts. **Fix:** write whole receipts, validate their identity and contents, distinguish unreadable from changed incarnation, and retain uncertainty when whole-unit termination cannot be proven.

9. **P1 — Unarmed recovery adopts the current invocation before signaling it.**  
   [unit-backend.ts:749](apps/server/src/runtimes/coding/unit-backend.ts:749).  
   Without a recorded InvocationID, `stopByName()` trusts whichever invocation currently occupies the name. A refused creation/name collision or replacement after a crash can therefore make Score stop a foreign invocation. The boundary probe confirmed the stop command is issued using that freshly observed identity. **Fix:** require independently established launch ownership; never substitute the current invocation for missing recorded identity.

10. **P1 — Copy confirmation does not reconcile inherited execution intents.**  
    [installation.ts:481](apps/server/src/installation.ts:481).  
    `confirmCopy()` publishes a new identity and writes a restore marker, but never consults the source journal. Copy before source dispatch, let the source execute, then confirm and lift the copy’s fence: the copied pending attempt remains sendable because its source witness is absent from the new namespace. A crash before marker publication adds another gap. **Fix:** durably reconcile or retire inherited intents from source evidence before publishing an admissible copy identity.

11. **P1 — A cutover is accepted without checking its destination witness.**  
    [journal-migration.ts:100](apps/server/src/domain/orchestration/journal-migration.ts:100).  
    Once a cutover exists, migration returns `already` without verifying the destination journal. The probe returned success with the namespace journal missing, despite surviving legacy send evidence. An older restored database can consequently repeat those sends. **Fix:** validate the destination against the retained cutover snapshot and fail closed on missing/corrupt namespace evidence; consult the legacy witness during reconciliation.

12. **P2 — Reconciliation compares sequence numbers instead of full state.**  
    [coding-checkpoint.ts:111](apps/server/src/domain/orchestration/coding-checkpoint.ts:111), [coding-checkpoint.ts:169](apps/server/src/domain/orchestration/coding-checkpoint.ts:169).  
    Equal-number rows with different phase, revocation, invocation, unit or cgroup pass verification. The probe returned no mismatches and left the divergent state unrepaired. **Fix:** validate and compare the complete authority-relevant projection, including immutable identity, and fence unexplained divergence.

13. **P2 — Restart can promote a pending candidate to successful output.**  
    [service.ts:760](apps/server/src/runtimes/coding/service.ts:760), [service.ts:1284](apps/server/src/runtimes/coding/service.ts:1284).  
    Crash after storing a pending success but before terminal commit: startup commits that success, potentially creating hand-offs, before unit reconciliation. V7 §4 explicitly requires interruption when Score restarts before terminal commit. **Fix:** invalidate unit-owned pending eligibility across Score incarnations while preserving already committed terminal outcomes.

14. **P2 — Released-run stop causes are not durable before signaling.**  
    [unit-backend.ts:385](apps/server/src/runtimes/coding/unit-backend.ts:385), [unit-backend.ts:855](apps/server/src/runtimes/coding/unit-backend.ts:855).  
    The stop cause initially exists only in memory/protocol state; database persistence happens during finishing. Score and supervisor death before finishing can erase a user stop or shutdown cause. **Fix:** journal and project the first stop cause before sending the control frame.

15. **P2 — Buffer accounting and overflow handling do not implement the stated bounds.**  
    [coding-socket.ts:324](apps/server/src/runtimes/coding/coding-socket.ts:324), [coding-socket.ts:338](apps/server/src/runtimes/coding/coding-socket.ts:338).  
    Partial records and queue-entry overhead are uncounted. Two partial records totaling 1,200 bytes reported zero usage against a 1,000-byte installation budget. Oversize decoded records are dropped without stopping the run. **Fix:** account for partial buffers and queue overhead, bound retained application text, and stop on the specified overflow conditions.

16. **P2 — Manifest recovery selects the wrong current path after moving back.**  
    [installation.ts:300](apps/server/src/installation.ts:300), [installation.ts:437](apps/server/src/installation.ts:437).  
    After A → B → A, the path array remains `[A, B]`; rebuilding a lost registry declares B current and refuses A as moved away. **Fix:** persist explicit current/moved state in manifests instead of inferring it from array position.

17. **P2 — User-facing text promises containment beyond the design.**  
    [CodingBackend.tsx:46](apps/web/src/routes/team/CodingBackend.tsx:46), [SETUP.md:293](docs/SETUP.md:293).  
    Both promise termination of “everything it started,” omitting work handed to another service, scheduler or daemon. Such work is expressly outside v7’s proof. **Fix:** state the cgroup boundary and delegation exclusion in consent and the user guide.

What is solid:

- Journal appends handle whole writes and directory syncs; compaction retains permanent coding tombstones.
- The unit builder, minimal Node bootstrap, pre-exec payload placement, token binding/replay protection, UTF-8 reassembly and ingest-before-ACK sequencing are substantial improvements.
- Basic driver acceptance rules and authoritative-text hand-off routing correctly remove the earlier exit-zero/commentary fallback.
