### [high] Restoring Score can invalidate the non-dispatch proof

**Where:** [V5 `sendStarted` rule](/home/raven/score/docs/briefs/7.1-workflow-builder.md:6), [startup epoch reset](/home/raven/score/apps/server/src/start-server.ts:205), [backup guidance](/home/raven/score/docs/SETUP.md:238).

**What happens:** A backup contains an admission intent before `sendStarted`. Score subsequently sends the request and Hermes accepts it. Restoring that backup makes the attempt appear never sent, permitting a replacement while the original execution remains active.

**Why:** Absence of a marker proves non-dispatch only when the intent history has not been reverted. V5 explicitly handles restored **Hermes** databases, but leaves restored **Score** execution history untreated. Resetting the stream epoch repairs browser caches; it does not establish external execution safety.

**Change:** Define a restore protocol that quarantines restored execution state and disables automatic admission until outstanding external work is accounted for. Automatic recovery must require trusted intent history; a reverted marker cannot authorize retry. Test restoration across intent, send, acceptance, and Stop boundaries.

### [high] The delegation check does not bind the admitted runtime

**Where:** [V5 restriction](/home/raven/score/docs/briefs/7.1-workflow-builder.md:20), [Score’s tool reader](/home/raven/score/apps/server/src/hermes/live/agent-config.ts:185), [Hermes agent construction](/home/raven/reference/hermes-agent/gateway/platforms/api_server.py:2400).

**What happens:** Score reads delegation as disabled. A toolset change occurs before Hermes constructs the agent, which then receives delegation and can start a detached child. The parent completes while that child continues.

**Why:** The configuration read and runtime construction are separate operations. Hermes reloads tool configuration during construction; Score’s [admission payload](/home/raven/score/apps/server/src/hermes/live/gateway.ts:53) carries no frozen execution policy. Disabling delegation also leaves [persistent terminal jobs](/home/raven/reference/hermes-agent/tools/terminal_tool.py:169) available, so the broader claim that work cannot outlive the run is unsupported.

**Change:** Require a tested runtime capability that enforces the attempt’s frozen tool/execution policy when constructing the agent. Treat unreadable tool inventory as unknown. Define which background execution is excluded or owned by the termination barrier. Test a configuration change between validation and construction, plus persistent execution without delegation.

### [high] Canonical shutdown status does not prove worker termination

**Where:** [Termination predicate](/home/raven/score/docs/briefs/7.1-workflow-builder.md:53), [Hermes shutdown interruption](/home/raven/reference/hermes-agent/gateway/platforms/api_server.py:1305), [worker lifetime tracking](/home/raven/reference/hermes-agent/gateway/platforms/api_server_runs.py:33).

**What happens:** During shutdown, Hermes publishes `interrupted` before its agent worker exits. Score treats that canonical terminal status as `terminated`, releases reservations/capacity, and can finish the workflow while execution continues.

**Why:** Hermes marks runs interrupted **before** requesting cooperative interruption. Its code explicitly tracks executor workers separately because cancelling an async task does not stop its worker thread. Canonical lifecycle status and execution termination are different facts, even with delegation disabled.

**Change:** Specify accepted termination evidence by runtime outcome and provenance. Shutdown interruption, cancelled wrappers, forgotten runs, and 404 must not establish termination without verified worker exit or process-death evidence. Preserve obligations and capacity otherwise. Test a worker that remains active after terminal shutdown status becomes observable.

### [medium] Compression attribution still lacks completeness and settlement

**Where:** [V5 attribution](/home/raven/score/docs/briefs/7.1-workflow-builder.md:27), [existing lineage reader](/home/raven/score/apps/server/src/hermes/live/recover.ts:40), [reservation release rule](/home/raven/score/docs/briefs/7.1-workflow-builder.md:147).

**What happens:** An ambiguous compression fork, missing continuation, schema error, or traversal limit produces a partial session list. That prefix can become apparently known spend. Reservations can also be released before final cost evidence is settled.

**Why:** `compressionLineage()` returns session IDs without a completeness indicator. It silently stops at ambiguity, errors, or twenty hops. “Unprovable means unknown” cannot be implemented reliably using that return value unchanged. Runtime termination alone does not define final accounting.

**Change:** Add adapter facts containing qualified session ownership, completeness, observation time, and settlement state. Define aggregation and reservation-to-cost settlement explicitly. Incomplete lineage must produce unknown spend. Test forks, traversal limits, missing continuations, and delayed final cost publication.

### [medium] Session identity does not implement exact Watch replay

**Where:** [Retained session-based replay requirement](/home/raven/score/docs/briefs/7.1-workflow-builder.md:103), [frame storage](/home/raven/score/apps/server/src/domain/watch-frames.ts:283), [Watch queries](/home/raven/score/apps/server/src/domain/watch-frames.ts:453).

**What happens:** Frames arriving before admission association remain unowned; compression frames can be omitted. An attempt replay can still show another attempt’s markers, browser context, gaps, or live status.

**Why:** Frames persist `run_id`, without durable attempt/session ownership. Session lookup selects the newest matching run. Markers and browser context remain agent-scoped; the [Watch endpoint](/home/raven/score/apps/server/src/http/watch.ts:73) also selects agent-wide live state, gaps, and the latest session. V5 does not amend these projections.

**Change:** Persist attempt-owned session associations before dispatch, including compression continuations and unresolved associations. Apply the same attempt scope to frames, markers, browser context, gaps, pagination, live state, and stream updates. Specify the corresponding API response and retention floor.
