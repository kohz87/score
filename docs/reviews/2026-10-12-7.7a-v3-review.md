The remaining and newly exposed failures follow.

1. **P1 — Release and revocation need one ordering point.**  
   Locations: [phases](docs/briefs/7.7a-coding-units.md:45), [revocation/no-launch rule](docs/briefs/7.7a-coding-units.md:48), [current Stop shortcut](apps/server/src/runtimes/coding/service.ts:509).

   A ready handler checks authorization, awaits registration, and then sends `go`; meanwhile Stop durably revokes the launch. Nothing specifies the transaction or compare-and-set that prevents the ready handler from using its earlier authorization. Likewise, `revoked + no released receipt` is not no-launch proof while an already-issued `go` or receipt write remains outstanding.

   **Fix:** commit a generation-qualified `release-intent` and external journal witness **before** sending `go`, under the same guard that excludes revocation. Revocation winning that transition must permanently prevent release. Once release intent wins, execution is possible until qualified refusal/end evidence arrives. Keep cancellation effective during receipt fsync, and replace the current `!launched` shortcut with this durable state machine.

2. **P1 — Missing `released` is only evidence if the artifact history is trustworthy.**  
   Locations: [artifact creation](docs/briefs/7.7a-coding-units.md:28), [receipts](docs/briefs/7.7a-coding-units.md:39), [restart inference](docs/briefs/7.7a-coding-units.md:52).

   Snapshot the home after release intent but before the supervisor receipt exists. The CLI subsequently runs; Score crashes before recording further external evidence. Restoring that home removes the receipt. Journal/database phases can still agree, and the unit/cgroup can be gone, yet §3 declares proven no-launch.

   Power loss creates another gap: syncing the receipt and launch directory does not establish durability of newly created ancestor directory entries. The current database also uses [WAL `synchronous=NORMAL`](apps/server/src/db/database.ts:55), whose commits can disappear after system failure. [SQLite durability documentation](https://www.sqlite.org/pragma.html#pragma_synchronous).

   **Fix:** qualify receipt absence by durable, retained, unrestored artifact provenance—or keep the execution witness outside the restored home. Specify complete write/fsync ordering, including directory creation, and fail closed on write/sync/read errors. A present pre-spawn receipt means **execution may have happened**; it does not prove execution succeeded, since the supervisor can crash or encounter `ENOENT` before exec.

3. **P1 — Journal comparison can still miss revocation, and retention can erase restore evidence.**  
   Location: [journal reconciliation and retention](docs/briefs/7.7a-coding-units.md:55).

   The payload contains revocation, proof and disposition, but reconciliation explicitly compares “latest phase and identity.” A restored row can retain the same armed phase/identity while losing its revoked flag. Those comparisons pass.

   “Until settled + retention” also permits losing the last launch witness unless tombstones are explicitly excluded. That conflicts with the [permanent-tombstone contract](docs/API-CONTRACT.md:1749). An older restored database then has neither a unit nor a journal witness to stop repetition.

   **Fix:** compare the full authority-relevant state, including revocation, release possibility, disposition and waiver state. Retain permanent compact witnesses, with run/turn/generation links and a monotonic checkpoint. Alternatively, define and enforce a restore floor that fences older backups. Reconciliation must make all witnessed executions permanently unsendable before admission resumes.

4. **P1 — Socket loss does not currently imply prompt whole-cgroup termination.**  
   Locations: [supervisor cleanup](docs/briefs/7.7a-coding-units.md:36), [unit lifecycle](docs/briefs/7.7a-coding-units.md:16).

   A tool forks, calls `setsid`, and becomes reparented. The supervisor’s process-tree cleanup misses it, then the supervisor exits. `ExitType=cgroup` retains the service; it does not initiate cleanup because the main PID exited. The survivor can run until the original runtime deadline. Supervisor death after release produces the same problem. This behavior is explicit in the [v259 service implementation](https://github.com/systemd/systemd/blob/v259/src/core/service.c).

   **Fix:** specify a whole-cgroup stop mechanism independent of ancestry and ordinary supervisor exit. With a long-lived supervisor, `ExitType=main` plus `RemainAfterExit=no` is one viable approach; alternatively provide an independent unit-stop trigger. Preserve external emptiness proof and unresolved obligations when termination fails. State the permitted disconnect cleanup grace explicitly.

5. **P1 — Pipe EOF and `cli-exited` do not prove Score accepted the complete stream.**  
   Locations: [framed output](docs/briefs/7.7a-coding-units.md:34), [receipt definitions](docs/briefs/7.7a-coding-units.md:39), [acceptance rule](docs/briefs/7.7a-coding-units.md:67).

   The supervisor drains its pipes and reports exit while Score still has pending parser/ingest work. An observation fails, but every socket frame arrived. Current code [swallows event-ingest failures](apps/server/src/runtimes/coding/service.ts:717), so “no frame dropped” can coexist with missing durable effects.

   Normal completion is also undefined: the supervisor must eventually exit to allow cgroup emptiness, closing its socket. Without an explicit terminal exchange, that close is indistinguishable from the socket loss that disqualifies completion.

   **Fix:** define a versioned wire protocol with typed control/output records, per-stream sequence numbers, explicit pipe EOF, terminal high-water marks and loss flags. Score must finish parsing and processing every required record before terminal acceptance. Distinguish a validated normal terminal close from unexpected EOF; define restart-before-terminal-commit as interrupted, and preserve already-settled outcomes.

6. **P1 — The acceptance matrix still cannot establish final authority for every driver.**  
   Locations: [driver requirements](docs/briefs/7.7a-coding-units.md:67), [Codex message validation](apps/server/src/runtimes/coding/codex.ts:100), [Claude success inference](apps/server/src/runtimes/coding/claude.ts:201), [Antigravity final selection](apps/server/src/runtimes/coding/antigravity.ts:210).

   The Codex probe supplied valid commentary, an `agent_message` with numeric `text`, then `turn.completed`. The parser silently discarded the malformed final, reported both loss counters as zero, and returned success. Reliable socket delivery cannot detect that semantic loss. The [upstream exec schema](https://github.com/openai/codex/blob/main/codex-rs/exec/src/exec_events.rs) supplies message text and completion usage without a final-message identifier; the final-selection rule therefore needs a tested ordering contract.

   Claude still defaults unspecified success fields to success. Antigravity still discards a differing final response after commentary, and v3 supplies no Antigravity acceptance rule. CLI exit zero also needs a compatible supervisor/unit outcome: cgroup emptiness after timeout is not success.

   **Fix:** track every potentially final record, including rejected records; invalidate authority on relevant semantic loss. Specify exact terminal rules for pinned driver versions. Require Claude’s explicit successful terminal result, Codex’s validated final selection in a complete turn, and Antigravity `SUCCESS` with its authoritative response. Remove the [current commentary/exit-zero fallback](apps/server/src/runtimes/coding/service.ts:771).

7. **P1 — The advertised fallback retains both identity and lifetime failures.**  
   Locations: [fallback declaration](docs/briefs/7.7a-coding-units.md:85), [numeric signals](apps/server/src/runtimes/coding/proc.ts:302), [Y’s group path](docs/briefs/fix-y-pidfd-signal.md:13).

   A mocked probe replaced the target immediately after its final stat read: recovery sent SIGTERM to the replacement and returned `gone`. Y’s leader verification followed by `kill(-pgid)` retains the same check-to-signal race. Linux supports group-scoped pidfd signaling. [Kernel implementation](https://github.com/torvalds/linux/blob/v6.18/kernel/signal.c).

   The current fallback also starts a [detached child](apps/server/src/runtimes/coding/process.ts:99), delivers its [prompt before registration](apps/server/src/runtimes/coding/process.ts:215), and keeps its [deadline timer in Score](apps/server/src/runtimes/coding/process.ts:173). It can therefore outlive Score and lose its deadline.

   **Fix:** use identity-safe pidfd signals, including supported group-scoped signaling; unavailable support retains the fence. Apply the launch barrier/journal protocol to fallback launches too. Give fallback an explicit death/timeout mechanism or document its weaker lifetime guarantee. Keep workers disabled there.

8. **P2 — CLI environment replacement does not protect supervisor startup.**  
   Locations: [unit environment](docs/briefs/7.7a-coding-units.md:20), [race dismissal](docs/briefs/7.7a-coding-units.md:24).

   A newly imported `NODE_OPTIONS` can preload code before `supervisor.mjs` executes. That code can alter launch behavior or receipts before the replacement CLI environment exists. A harmless Node probe confirmed the startup hook ran.

   Additionally, `UnsetEnvironment` applies last: enumerating `PATH`, `HOME` or `LANG` removes even the explicit `--setenv` assignments. [Systemd environment semantics](https://github.com/systemd/systemd/blob/v259/man/systemd.exec.xml).

   **Fix:** deny startup-control variables unconditionally, including absent-at-enumeration names, and define a trusted startup path unaffected by remaining ambient variables. Construct the minimal supervisor environment before Node starts. Preserve and independently verify invocation identity. An ordinary dynamically linked `env -i` wrapper alone does not neutralize loader injection.

9. **P2 — Token authentication does not attest the reported invocation.**  
   Locations: [socket authentication](docs/briefs/7.7a-coding-units.md:31), [identity tuple](docs/briefs/7.7a-coding-units.md:80).

   A token-authenticated peer can report the wrong PID/cgroup. Recording an absent claimed cgroup then satisfies the end predicate while the real cgroup remains populated. Authentication also lacks a defined Score incarnation binding, replay rejection and server-authentication mechanism.

   **Fix:** bind authentication to installation, launch, generation, prepared-spec identity and Score incarnation. Independently compare reported PID/start time, invocation and cgroup against systemd and `/proc` before arming. Make token consumption atomic; reject duplicate/reconnected sessions. Define server authentication and token-safe logging. The private filesystem excludes other UIDs; [D7.1](docs/ARCHITECTURE.md:354) still accepts hostile same-user access.

10. **P2 — Bounded frames do not bound queues or shutdown time.**  
    Locations: [live forwarding](docs/briefs/7.7a-coding-units.md:34), [disconnect behavior](docs/briefs/7.7a-coding-units.md:36).

    Score stops consuming output. The supervisor can queue unlimited bounded frames unless it honors backpressure. Awaiting a blocked drain can also delay cleanup. Half-close handling matters: waiting only for `close` can defer cancellation behind queued writes. Separately, Node’s `server.close()` retains existing connections, allowing a shutdown wait to deadlock with active runs. [Node socket semantics](https://github.com/nodejs/node/blob/v24.x/doc/api/net.md).

    **Fix:** bound raw line buffers, stdout/stderr totals, socket queues, receiver queues and aggregate active-run memory. Keep control handling independent of output drainage. On overflow, read failure or unexpected `end`/`error`, stop and invalidate eligibility. Explicitly stop/destroy accepted sockets during shutdown while keeping receipt ingestion available.

11. **P2 — Direct unit Stop still truncates the promised signal sequence.**  
    Locations: [stop properties](docs/briefs/7.7a-coding-units.md:17), [socket fallback Stop](docs/briefs/7.7a-coding-units.md:41), [public contract](docs/API-CONTRACT.md:1026).

    Direct unit Stop sends INT to supervisor and payload together. After one grace interval, systemd sends KILL just as the supervisor’s TERM stage would begin. Forwarding INT can duplicate delivery. Runtime expiry has the same problem if it initiates supervisor escalation. [Systemd kill semantics](https://github.com/systemd/systemd/blob/v259/man/systemd.kill.xml).

    **Fix:** define one escalation owner, sufficient time for both intervals and flushing, and explicit forced-stop exceptions. Persist stop cause for released runs too. Restore the clock distinction: systemd runtime timing is monotonic, while the existing turn contract says wall time. Preserve one remaining deadline across launch attempts and define suspend/resume behavior.

12. **P2 — Per-installation locking needs ownership and an upgrade protocol.**  
    Locations: [new journal scope](docs/briefs/7.7a-coding-units.md:59), [existing shared journal wiring](apps/server/src/start-server.ts:265), [path-derived scope](apps/server/src/domain/orchestration/journal.ts:503).

    Adding a coding journal does not protect existing orchestration writers. Switching all writers without migration can hide old witnesses and restore markers. Two copied homes sharing an installation ID can also serialize appends while independently passing stale startup checks and releasing duplicate work.

    Locking the journal file itself introduces another trap: compaction renames it, potentially leaving one process locking the old inode while another locks the replacement.

    **Fix:** define persistent installation identity and migrate legacy scopes, witnesses and [restore markers](scripts/restore.mjs:65) under ownership locks. Use a stable sidecar lock across reads, repair, append and compaction. Enforce one active owner per installation—or revalidate shared journal state at every release. Test separate installations and copied homes.

13. **P2 — Recording manager identity is insufficient without recovery/action rules.**  
    Locations: [ended proof](docs/briefs/7.7a-coding-units.md:64), [manager incarnation and collection](docs/briefs/7.7a-coding-units.md:81).

    V3 does not identify the incarnation source or say how it qualifies Stop/reset operations. A cold manager startup can remove transient definitions on the same boot; graceful reexec is different. [Manager startup implementation](https://github.com/systemd/systemd/blob/v259/src/core/manager.c). Missing definitions must not erase obligations, and an old exact name must not authorize acting on a replacement invocation.

    **Fix:** define actual manager PID/start identity or an equivalent verified source. Distinguish authoritative absence from permission/transport failure; recheck incarnation during inventory/proof operations. Fence mismatched invocations, never substitute the process backend for uncertain unit work, and qualify reset/cleanup by identity and proof. Successful-unit GC must be tolerated without inventing success from missing metadata.

14. **P2 — Antigravity still contradicts the universal stdin description and privacy implication.**  
    Locations: [Chat-only statement](docs/briefs/7.7a-coding-units.md:12), [stdin description](docs/briefs/7.7a-coding-units.md:33), [actual argv channel](apps/server/src/runtimes/coding/antigravity.ts:277), [consent wording](docs/API-CONTRACT.md:1030).

    Antigravity remains supported in Chat and requires `-p <prompt>`. Private launch files do not conceal that eventual argv. Ordinary procfs configurations expose command lines beyond the owner’s UID. [Kernel procfs documentation](https://docs.kernel.org/filesystems/proc.html#mount-options).

    **Fix:** make supervisor input delivery driver-specific. Document the broader Chat exposure, or require a supported private channel/verified host isolation. Chat-only scope resolves neither delivery nor disclosure.

15. **P3 — Socket readiness is missing from capability/startup handling.**  
    Locations: [socket pathname](docs/briefs/7.7a-coding-units.md:31), [capability check](docs/briefs/7.7a-coding-units.md:85).

    A long custom `$SCORE_HOME` exceeds the Unix socket pathname limit; a crash also leaves a stale pathname that prevents rebinding. Both can occur while every listed systemd capability passes. [Node IPC documentation](https://github.com/nodejs/node/blob/v24.x/doc/api/net.md).

    **Fix:** validate pathname byte length and actual listener readiness before requesting launches. Prefer a short private runtime-directory endpoint. Acquire ownership before stale-socket cleanup; refuse foreign/live endpoints. Probe the complete launch prerequisites, including the CLI flags actually used.

The [acceptance suite](docs/briefs/7.7a-coding-units.md:89) needs explicit cases beyond “matrix rows”:

| Case | Required outcome |
|---|---|
| Valid final, exit 0, complete processing, normal terminal close, ended proof | Completed and eligible |
| Valid final followed by nonzero exit, unit timeout or forced cleanup | Ineligible |
| Malformed/oversized potentially final record | Ineligible |
| Complete transport followed by failed required ingestion | Ineligible |
| EOF with partial frame or incomplete terminal exchange | Ineligible |
| Crash after terminal frame but before terminal commit | Interrupted; no reconstructed authority |
| Stop racing release/receipt fsync | No-launch only if revocation won release |
| Settled successful run encountered on restart | Preserve settled disposition |

Add crash injection around every release/receipt/journal boundary, copied-home lock tests, supervisor death with descendants, manager replacement, Stop-triggered GC and receipt-loss restore tests.

Right: kernel cgroup identity, recursive emptiness, and the explicitly scoped containment guarantee provide a sound primary termination proof.
