## 7.3 Web terminal — **approved with changes**
1. [high] The ticket is in the WebSocket URL query: Fastify's request log records `req.url`. Redact `ticket` in the log
   serializer (and in any error path) and test it.
2. [high] "`script -qfc …`" is a shell string (AGENTS.md: never). Use `node-pty` (MIT; native build → needs an
   `allowBuilds` entry and the owner's OK, since install scripts are off by default) with argv `[shell, '-l']`; it also
   gives resize. Fallback only if the owner declines: no terminal.
3. [high] The exact public route list (API-CONTRACT §3) must gain the terminal routes only when `SCORE_TERMINAL=1`, and the
   WebSocket upgrade must pass the same Host/Origin checks as other requests (upgrade requests skip some hooks).
4. [medium] Backpressure: pause the PTY when the socket's buffered amount exceeds 1 MiB; drop the terminal if the client
   stays stalled 60 s (an output flood must not grow server memory).
5. [medium] Fresh second factor: store `freshAuthAt` server-side on the session when the password check or passkey
   assertion succeeds; ticket minting requires it ≤ 60 s old; failed attempts use the existing limiter.
6. [medium] Idle timeout kills long-running foreground jobs; say so on the page ("use tmux for long jobs").
7. [low] Settings › Remote shows whether the terminal is enabled and lists open terminals.

## 7.2 Coding agents — **approved with changes** (build after 7.3)
1. [high] Read access: Codex's `workspace-write` sandbox and Claude Code's permission modes restrict writes/commands,
   not reads, so a prompt-injected coding agent can read the owner's files (incl. `~/.hermes/.env`) and print them into
   the room. Same accepted limit as Hermes agents (D7.1), but: (a) state it in Team › Add coding agent; (b) Claude Code
   gets deny rules for `~/.hermes`, `~/.score`, `~/.ssh`, `.env*` via its settings file in the workspace; (c) all output
   goes through `redact()` before storing; (d) offer "run in Docker" later.
2. [high] Version drift: pin tested CLI versions (like the Hermes fingerprint gate, 1.11b); unknown version → the agent
   shows "untested CLI version" and runs only after the owner confirms; event parsing rejects unknown shapes safely.
3. [medium] Restart: a CLI child dies with Score; on start, turns marked running become `interrupted` with a note and the
   CLI session id kept so the next turn resumes; durable intent before spawn (same admission pattern as Hermes runs).
4. [medium] Environment: allowlist only; never pass Score's environment; never pass `*_API_KEY` variables from Score's
   environment — the CLIs read their own config.
5. [medium] Quota: Codex shares the owner's ChatGPT plan with Hermes and these audits; Claude Code uses the owner's
   Claude plan. Show the runtime and "uses your <plan> quota" on the agent card.
6. [low] Kanban: v1 room work only (as written); 7.1 must respect that (Codex 7.1 finding 1).

## 7.4d Score as an MCP server — **approved with changes** (after 7.2)
1. [high] `hermes mcp add` stores the bearer token in the profile's Hermes config (plaintext). Same-user agents can read
   each other's configs (D7.1 limit), so token = identity is weak against a hostile agent: scope each token to its agent,
   rate-limit, mark every MCP post "via MCP", and make writes (rooms.post, tasks.comment, knowledge.write) a per-agent
   switch, off by default. Reads are allowed when the switch is on.
2. [medium] The MCP endpoint lives on the loopback bridge listener and must not reach `/api/*` handlers (separate route
   prefix and token kind; tests that an MCP token gets 401 on every `/api` and `/bridge/v1` path).
3. [medium] Reuse 6.4's knowledge limits and switches; coding agents (7.2) can use the same server with their own tokens.
