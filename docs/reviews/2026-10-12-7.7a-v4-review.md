The new and remaining failures follow.

1. **P1 — Restoring the home can silently select a fresh execution-history namespace.**

   Locations: [installation identity](docs/briefs/7.7a-coding-units.md:42), [external receipt namespace](docs/briefs/7.7a-coding-units.md:66), [restore copying](scripts/restore.mjs:81).

   Take a backup before `installation.json` exists. Upgrade, execute work, then restore that backup. Startup creates installation B instead of recovering installation A. A’s journal and receipts survive physically, but reconciliation searches B’s empty namespace. The restored database can consequently repeat work whose retained witness belongs to A. Moving orchestration writers into this namespace exposes existing Hermes dispatches too.

   Identity-file loss during initial setup presents the same problem unless its durability is specified.

   **Fix:** maintain a durable installation registry outside the home, including canonical home paths and move aliases. Recover a missing home identity from that registry; refuse ambiguous identities instead of minting another namespace. Make identity creation atomic and fully synced. A new ID for a copied database must reconcile or retire inherited execution intents before admission.

2. **P1 — The existing journal writer accepts a partial record as a successful execution witness.**

   Locations: [phase durability](docs/briefs/7.7a-coding-units.md:58), [journal writer](apps/server/src/domain/orchestration/journal.ts:281), [existing send barrier](apps/server/src/domain/orchestration/executor.ts:2039). Also journal lines 212–214, 250–263 and 313–323.

   `append()` calls `writeSync()` once and ignores its returned byte count. A short write followed by successful fsync returns normally, permitting the external effect. Restart repair then discards that unterminated record as “never effective.”

   The in-memory probe reproduced: **append returned success; journal read found zero entries; restart repair deleted the remaining bytes**. Restoring a database predating the dispatch then permits repetition. Directory-sync errors are also currently swallowed.

   **Fix:** write the complete encoded buffer before declaring success; reject zero-progress writes and propagate every required sync failure. Preserve the invariant that no effect is permitted by a record recovery can discard. Apply this to the shared orchestration writer in the same change.

3. **P1 — The prescribed password-store lock can admit concurrent journal writers.**

   Locations: [chosen lock implementation](docs/briefs/7.7a-coding-units.md:45), [stale recovery](apps/server/src/auth/password-store.ts:127), [callback execution](apps/server/src/auth/password-store.ts:188).

   B reads an old stale lock. A replaces it and enters its protected operation. B then renames **A’s new lock** away before checking its contents. C acquires the temporarily empty pathname. B cannot restore A’s lock because C now owns the pathname; A and C can continue inside their callbacks.

   An in-memory probe drove the actual stale-recovery helper through that interleaving. With journal operations, A’s compaction can overwrite C’s fsynced release witness after C sent `go`, permitting later repetition.

   **Fix:** use an OS lock on a permanent sidecar inode that is never renamed or unlinked. If retaining a file-ownership protocol, redesign stale recovery to prevent the pathname gap and validate ownership before entering the callback. An unreadable lock’s age alone must not authorize stealing it.

4. **P1 — Disconnect cleanup still depends on the supervisor being responsive.**

   Locations: [runtime backstop](docs/briefs/7.7a-coding-units.md:18), [disconnect guarantee](docs/briefs/7.7a-coding-units.md:22).

   Freeze only the supervisor, or hang its event loop, then crash Score. The CLI continues, but the supervisor cannot process socket EOF or enforce its wall deadline. Its main process remains alive, so `ExitType=main` initiates no stop. Cleanup waits for the original `RuntimeMaxSec`, potentially nearly a full turn rather than `2×grace + 5s`. This follows from the documented runtime and watchdog semantics. [Systemd service documentation](https://raw.githubusercontent.com/systemd/systemd/v259/man/systemd.service.xml).

   **Fix:** add manager-enforced supervisor liveness, such as a watchdog with a bounded failure-to-kill interval and no restart. Heartbeats must depend on the supervisor’s control loop remaining responsive. Test supervisor SIGSTOP followed by Score death, alongside supervisor SIGKILL.

5. **P1 — The fallback’s advertised time limit disappears with Score.**

   Locations: [fallback promise](docs/briefs/7.7a-coding-units.md:118), [detached spawn](apps/server/src/runtimes/coding/process.ts:99), [deadline timer](apps/server/src/runtimes/coding/process.ts:173), [prompt delivery](apps/server/src/runtimes/coding/process.ts:215).

   The fallback’s deadline is a timer inside Score. Killing Score removes it while the detached CLI continues. “Until their time limit” is therefore false: work can continue indefinitely until restart.

   A crash between spawn/prompt delivery and `onSpawn` recording also leaves work absent from recovery’s process inventory. Y changes signaling; it fixes neither window.

   **Fix:** apply the durable launch/release protocol to fallback execution and provide independent deadline/death enforcement. Otherwise refuse new execution when the unit backend is unavailable. Merely documenting an intact time limit does not provide one.

6. **P2 — Mixed-mode kill timing and the supervisor’s self-only predicate are misstated.**

   Locations: [supervisor polling](docs/briefs/7.7a-coding-units.md:22), [kill timing claim](docs/briefs/7.7a-coding-units.md:27).

   With `KillMode=mixed`, final cgroup killing occurs when the main process exits **or** the stop timeout expires. It need not wait for `TimeoutStopSec`. Supervisor death therefore correctly kills survivors, but can truncate their graceful sequence. [Systemd kill documentation](https://raw.githubusercontent.com/systemd/systemd/v259/man/systemd.kill.xml).

   Separately, root `cgroup.procs = {supervisor}` plus root `populated=1` cannot distinguish “only supervisor” from “supervisor plus processes in child cgroups.” Both observations have the same values. [Kernel cgroup documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html#un-populated-notification).

   **Fix:** state the immediate-kill behavior and explicit forced-stop exceptions. Keep the supervisor alive through ordinary escalation. Establish payload emptiness through a separate payload subgroup’s recursive population flag, or a defined recursive observation procedure; retain the external whole-cgroup proof.

7. **P2 — The deny-list cannot be passed as written and still leaves startup races.**

   Location: [startup environment](docs/briefs/7.7a-coding-units.md:33).

   Literal `PYTHON*` is not an `UnsetEnvironment` pattern. V259 validates names/assignments and rejects an invalid list. If it is shorthand, its expansion needs specification. [Transient-property validation](https://raw.githubusercontent.com/systemd/systemd/v259/src/core/dbus-execute.c).

   Enumeration also leaves newly imported, non-unconditional names intact. For example, `OPENSSL_CONF` is absent from the fixed deny-list but loads configuration during Node startup; `NODE_V8_COVERAGE` can cause unsolicited disk output. [Node startup environment documentation](https://raw.githubusercontent.com/nodejs/node/v24.x/doc/api/cli.md).

   **Fix:** enumerate concrete unconditional startup-control names for the supported Node/libc/OpenSSL stack and define a bootstrap that establishes the minimal environment before Node executes. Expand prefix rules explicitly. Preserve trusted systemd-generated identity separately from ambient manager variables.

8. **P2 — Wire-frame limits do not define logical CLI records or terminal settlement ordering.**

   Locations: [frame definitions](docs/briefs/7.7a-coding-units.md:80), [bounds/completeness](docs/briefs/7.7a-coding-units.md:86), [existing line allowance](apps/server/src/runtimes/coding/types.ts:109).

   An otherwise-supported 80 KiB final JSON record exceeds the 64 KiB wire-frame cap. Preserving one CLI line per frame rejects it; splitting it requires reassembly semantics. JSON escaping also makes encoded frame size differ from source byte size.

   Terminal ordering needs to distinguish acknowledging a fully processed stream from accepting the final outcome: waiting for cgroup emptiness before `ack-end` deadlocks because the supervisor waits for that ACK before exiting.

   **Fix:** define bounded byte chunks, incremental UTF-8/line reconstruction, decoded-record limits and partial-record EOF handling. Specify: drain/process → acknowledge → supervisor exit → close/ended proof → terminal commit. Define restart before that commit as interrupted. Add an installation-wide active-run memory budget.

9. **P2 — Y’s identity-safe signaling does not cover live fallback escalation.**

   Locations: [Y claim](docs/briefs/7.7a-coding-units.md:6), [live signal path](apps/server/src/runtimes/coding/process.ts:111), [repaired recovery path](apps/server/src/runtimes/coding/proc.ts:315).

   Live execution still calls numeric `process.kill(-child.pid, signal)`, with a numeric child fallback. If the original group empties and its number is reused before an escalation/reaper signal, that signal can reach the replacement group. Recovery now uses pidfds; live execution does not.

   **Fix:** use retained identity-safe handles for live signals too. Where identity or group-scoped signaling cannot be established, preserve uncertainty rather than signal a number. This is P2 under your severity restriction: erroneous signaling alone does not establish one of the specified P1 outcomes.

10. **P2 — A per-installation lock cannot protect migration of the shared legacy journal.**

    Locations: [migration protocol](docs/briefs/7.7a-coding-units.md:47), [current shared-journal wiring](apps/server/src/start-server.ts:265), [restore marker writer](scripts/restore.mjs:65).

    Installations A and B acquire different new locks while reading the same legacy file. Existing legacy writers/compactors acquire neither. “Copied under that lock” therefore does not establish a stable migration snapshot. The brief also does not specify scope/sequence translation, interrupted-migration recovery, or how subsequent restores preserve installation identity and target the new marker location.

    **Fix:** quiesce legacy writers or coordinate them through a shared migration lock; publish an idempotent, fsynced migration record before cutover. Define scope/checkpoint translation and retain the frozen legacy witness. Update the restore tool in the same change. Test concurrent migration, interrupted copying and restoration of a pre-identity backup.

Output-file append/file semantics, offsets, rotation and restart replay remain moot under decision 66’s removal of the supervisor spool. Journald stays diagnostic; it cannot replace stream completeness or execution witnesses. Retain v3’s exact-name inventory fence, collection/backoff and removed-agent routing requirements explicitly.
