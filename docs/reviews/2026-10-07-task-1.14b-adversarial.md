1. **High — Exact enrichment leaves a resolved gate’s visible card pending.**  
   [apps/server/src/domain/approvals.ts:247](/home/raven/score-worktrees/1.14b-approvals-ledger/apps/server/src/domain/approvals.ts:247)

   **Scenario:** A request-less Score-run hook creates hidden gate G. Its post records `deny`. SSE creates visible request R. A subsequent signal proves `G → R`, but the code finds two different rows and returns `false`. The visible card remains `human_pending`, with no decision; the binding stays unmatched indefinitely. Delivering that binding before SSE correctly produces a decided card.

   **Minimal fix:** Reconcile a proven binding between the hidden human stage and its canonical visible request atomically, transferring/replaying evidence, signal associations, and guardian links. Keep guardian and human stages separate.

2. **High — A valid Hermes resolution event aborts the run follower.**  
   [apps/server/src/hermes/live/translate.ts:126](/home/raven/score-worktrees/1.14b-approvals-ledger/apps/server/src/hermes/live/translate.ts:126)

   **Scenario:** Another client answers through Hermes’s run approval endpoint without supplying `request_id`. Hermes permits this for ordinary, non-room credentials and emits `approval.responded` without that field. See [the endpoint validation](/home/raven/reference/hermes-agent/gateway/platforms/api_server_runs.py:1182) and [conditional event field](/home/raven/reference/hermes-agent/gateway/platforms/api_server_runs.py:1212).

   Score requires `request_id`, so translation throws. `followRun` propagates that error; `LivePort` removes the follower without restarting it. Subsequent tool and terminal events are lost, leaving the visible approval pending after Hermes resolved it, until expiry.

   **Minimal fix:** Accept the optional upstream identifier. Retain uncorrelated evidence or record a diagnostic, then continue following the run. Reconcile only through exact bindings; don’t guess which request was answered.

3. **Medium — Completion evidence is permanently lost when replayed before gate creation.**  
   [apps/server/src/domain/approvals.ts:535](/home/raven/score-worktrees/1.14b-approvals-ledger/apps/server/src/domain/approvals.ts:535)

   **Scenario:** Bridge counter 3 (`post_tool_call`, outcome `ok`) arrives before counters 1–2 (gate pre and choice post). No approval exists, so completion does nothing. The later gate ends `decided`, with `tool_outcome = NULL`. Processing the same observations in counter order ends `executed`.

   The tool projection retains the completion, but gate creation never reconciles it. This breaks the order-independent evidence guarantee.

   **Minimal fix:** Persist completion observations and reconcile them when the correlated gate appears, using producer capture order and adequate execution scope rather than row insertion order.
