### [high] Recovered transcript text becomes false termination evidence

**Where:** [Retained result guarantee](/home/raven/score/docs/briefs/7.1-workflow-builder.md:259), [recovered observation](/home/raven/score/apps/server/src/hermes/live/translate.ts:499), [executor reconciliation](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:1335).

**What happens:** Hermes forgets a step’s run record. Score finds a matching assistant reply in session history and writes `runs.status = 'completed'`. The executor then marks the attempt terminated and accepts a successful step result, allowing successors and releasing execution capacity.

**Why:** The [live follower](/home/raven/score/apps/server/src/hermes/live/live-port.ts:650) enables transcript recovery for orchestration runs too. Reconciliation reads the status without termination provenance. This violates the explicit rule that recovered text alone leaves an attempt unknown.

**Change:** Preserve separate runtime outcome, terminal source, recovered text and observation-loss facts. Only qualifying runtime evidence may terminate an orchestration attempt. Add an owned-run fixture for `404 + matching assistant text`: show the text, retain unknown obligations, and admit no successor.

### [high] Restore quarantine misses limits and independent holds

**Where:** [V7 restore closure](/home/raven/score/docs/briefs/7.1-workflow-builder.md:24), [limits mutation](/home/raven/score/apps/server/src/domain/orchestration/decisions.ts:125), [journal verification](/home/raven/score/apps/server/src/domain/orchestration/fence.ts:50).

**What happens:** After the latest journaled dispatch, the person reduces a budget, shortens a deadline, revokes unknown-spend acceptance, or pauses the team/agent. A database-only rollback restores the earlier authorization without a corresponding journal mismatch. New work can become admissible.

**Why:** `setLimits()` writes no journal entry. [Team pause](/home/raven/score/apps/server/src/http/team-pause.ts:45) and [agent pause](/home/raven/score/apps/server/src/http/agent-pause.ts:51) also live only in database state. The journal verifies selected transitions, rather than every transition whose rollback restores authority. These cases fall within the claimed database-only restore protection.

**Change:** Journal authorization revisions covering limits, risk-acceptance revocation and independent holds, and verify them at startup. Add restore tests after each change with no further dispatch. Retain the documented whole-home limitation and mandatory operator restore protocol.

### [high] Lead-owned receipts do not supply planner idempotence

**Where:** [Planner command claim](/home/raven/score/docs/briefs/7.1-workflow-builder.md:11), [command authorization/deduplication](/home/raven/score/apps/server/src/domain/orchestration/commands.ts:129), [receipt identity](/home/raven/score/apps/server/migrations/0048_orchestrations.sql:131).

**What happens:** A workflow has no lead attempt or capability, while current commands require both and receipts are keyed by `(lead attempt, commandId)`. Even after introducing an internal caller, a stored refusal creates another problem: `wf:N:1:assign` refused for insufficient budget remains refused after the person raises the budget.

**Why:** Refused receipts are durable and returned before re-evaluating conditions. The fixed node/attempt/verb ID has no authorization generation. Reusing it prevents progress; changing it casually risks duplicate assignments or consuming an execution retry before anything ran. The existing 20-command limit also belongs to a lead turn.

**Change:** Define a server-only planner principal, durable run-scoped command identity and explicit re-evaluation generations. Atomically commit receipts, node-to-step mappings and graph transitions. Distinguish waiting for admission from execution retry, and define planner command limits. Test crashes around accepted assignments and budget-refusal recovery.

### [high] `after = resolved inputs` changes failure and skip semantics

**Where:** [V7 translation](/home/raven/score/docs/briefs/7.1-workflow-builder.md:52), [admission predicate](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:954), [dependency blocking](/home/raven/score/apps/server/src/domain/orchestration/ops.ts:116).

**What happens:** In `A --failed→ repair B → end`, assigning B with `after=[A]` blocks B. Gate/branch/join inputs cannot be used directly either: they are graph nodes, while `after` accepts existing execution-step IDs. A join containing a skipped input has the same mismatch.

**Why:** The shared executor requires every `after` step to have succeeded and transitively blocks dependents of other final outcomes. The retained workflow table instead resolves control inputs through tokens and skips. A `replaces` link does not rewrite existing dependencies.

**Change:** Persist graph control tokens separately from executor success prerequisites. Queue agent work only after graph readiness is established, and freeze consumed results independently, including routed failures and conditional defaults. Specify the `kind: node` gate decision transaction and contract; the current [gate handler](/home/raven/score/apps/server/src/domain/orchestration/decisions.ts:55) queues or rejects an assignment. Test failure routes, rejected-gate routes, mixed joins and replacement lineage.

### [high] An early end can withdraw a still-required gate

**Where:** [V7 end rule](/home/raven/score/docs/briefs/7.1-workflow-builder.md:55), [retained finish predicate](/home/raven/score/docs/briefs/7.1-workflow-builder.md:251), [Finish implementation](/home/raven/score/apps/server/src/domain/orchestration/commands.ts:553).

**What happens:** Two roots lead to `A → end` and `gate → B → end`. A completes while the gate is open. Nothing external is running, so v7’s restated rule permits `orch.finish`. Finish withdraws the gate and retires queued work; the shared executor can report success.

**Why:** “Nothing running” does not establish graph completion. The retained predicate requires no waiting, ready or running nodes. Shared Finish intentionally permits a lead to discard unfinished work, and [settlement](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:824) does not inspect graph obligations.

**Change:** Reaching an end should record its token. Issue Finish only after a precise graph-terminal predicate covers unresolved local nodes, gates, queued work, planner commands and failure disposition. Test an early end beside a pending gate and beside work waiting for capacity.

### [high] Gates-only assignments can silently rebind a replaced agent

**Where:** [Gate policy and mapping](/home/raven/score/docs/briefs/7.1-workflow-builder.md:56), [assignment incarnation capture](/home/raven/score/apps/server/src/domain/orchestration/commands.ts:311), [assignment arguments](/home/raven/score/packages/contract/src/orchestration.ts:483).

**What happens:** The person starts a workflow mapped to `builder` incarnation A. Before its node becomes ready, `builder` is replaced by incarnation B. `orch.assign` captures B as the step incarnation, and gates-only execution can dispatch it without another decision.

**Why:** Existing admission checks protect the incarnation captured when the step was assigned. They cannot compare it with the run’s approved mapping because the assignment command carries no expected incarnation. A start-only check leaves this interval unprotected.

**Change:** Freeze the complete run mapping and require assignments to match it, atomically and again before sending. A mismatch must block until a paired, revision-bound remapping decision or a new run. Test replacement after Start and before assignment.

### [medium] Clipped results cannot support the retained verdict guarantee

**Where:** [Strict verdict rule](/home/raven/score/docs/briefs/7.1-workflow-builder.md:264), [terminal output ingestion](/home/raven/score/apps/server/src/hermes/live/translate.ts:350), [accepted result storage](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:1477).

**What happens:** A final reply contains one valid `score-verdict` block near the beginning and another beyond 8 KiB. A parser reading the accepted result sees one block and can choose `passed`, although the full reply requires no verdict.

**Why:** Canonical output is clipped before the planner receives it; streamed message text is bounded too. Current accepted results lack typed verdict, authoritative-source and completeness metadata. Adding a parser solely to the graph planner cannot recover discarded information.

**Change:** Validate the complete sanitized authoritative final reply before truncation and persist bounded verdict/provenance metadata. Incomplete observation must yield no verdict. Define containment routing against the retained sanitized output explicitly. Test duplicate blocks beyond the cap and blocks crossing the truncation boundary.

### [medium] Replacement steps do not preserve node retry counts or parameters

**Where:** [Node parameters and Retry](/home/raven/score/docs/briefs/7.1-workflow-builder.md:31), [shared limits](/home/raven/score/packages/contract/src/orchestration.ts:10), [assignment handler](/home/raven/score/apps/server/src/domain/orchestration/commands.ts:314).

**What happens:** Thirty agent nodes with two retries require up to ninety execution steps, but the unchanged executor permits thirty. Each `replaces` assignment consumes another step, while its external attempt number starts again within that new step. Node-specific `estimateUsd` and `deadlineMin` also have no assignment transport: the handler uses the run-wide estimate and deadline.

**Why:** Logical node attempts and orchestration steps are different identities. Furthermore, [abandonment marks the old step failed](/home/raven/score/apps/server/src/domain/orchestration/decisions.ts:289); blindly applying the retained failed-node rule could automatically retry or route a failure without the promised explicit Retry decision.

**Change:** Define durable logical attempt numbering and bounds across replacement lineage. Preserve abandonment as an administrative state that supplies no canonical failure token. Specify Retry authorization and per-node parameter transport, or remove unsupported node parameters. Align validation and reservations with the actual maximum assignments and expanded instruction limit.

### [medium] Local sibling rows do not prove settled attribution

**Where:** [V7 settlement claim](/home/raven/score/docs/briefs/7.1-workflow-builder.md:34), [spend reader](/home/raven/score/apps/server/src/domain/orchestration/budget.ts:24), [contract’s remaining limitation](/home/raven/score/docs/API-CONTRACT.md:1541).

**What happens:** A completed run with a cost and no locally recorded open sibling can be labelled complete despite missing compression or other attributable observations. Conversely, today’s native terminal usage supplies token counts without `cost_usd`, so a budgeted run ordinarily needs explicit unknown-spend acceptance to continue.

**Why:** The reader tests Score’s observed rows, without lineage completeness, freshness or settlement facts. The contract still says unverifiable compression keeps reservations, but the reader has no fact establishing that condition. Hermes’s [terminal usage fields](/home/raven/reference/hermes-agent/gateway/platforms/api_server_runs.py:88) do not provide dollar cost.

**Change:** Supply qualified attribution, completeness, freshness and cost-scope facts. Keep reservations when proof is unavailable. Clearly expose today’s unknown-dollar-cost behavior and observed-work scope; never infer zero or settled totals. Test missing continuations, delayed costs and the actual token-only wire payload.

### [medium] Ownership tags do not remove cross-attempt Watch content

**Where:** [V7 Watch change](/home/raven/score/docs/briefs/7.1-workflow-builder.md:36), [frame construction](/home/raven/score/apps/server/src/domain/watch-frames.ts:415), [Watch response](/home/raven/score/apps/server/src/http/watch.ts:82).

**What happens:** Concurrent attempts A and B use the same agent. B produces a browser result without a URL; frame construction inherits A’s last browser URL/title. Tagging that frame as B-owned preserves the wrong content. Agent-wide markers, approvals, gaps and live state can also survive frame filtering.

**Why:** Browser fallback is selected by agent before ownership is applied. A parent session ID also needs provenance establishing a compression continuation; branches and delegated sessions have parents too.

**Change:** Apply qualified ownership during payload construction and throughout the response and stream, including browser fallback, markers, approvals, gaps, live state and cursors. Require proven compression linkage and define delayed attribution. Unassociated evidence must not imply association with each attempt. Test concurrent browser fallback and ambiguous continuation ownership.

### [medium] The shared reserve does not bound associated retained growth

**Where:** [V7 reserve closure](/home/raven/score/docs/briefs/7.1-workflow-builder.md:42), [reserve/accounting](/home/raven/score/apps/server/src/domain/orchestration/ops.ts:22), [cleanup](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:1581).

**What happens:** Charged orchestration rows remain within their allowance while copies in intents, messages, runs and history continue growing. Pruning an orchestration removes its quota charge but leaves those associated records. Immutable definition versions add another unaccounted inventory.

**Why:** `stored_bytes` is manually incremented for selected writes. [Intent payload copies](/home/raven/score/apps/server/src/hermes/live/intents.ts:253) and [history inserts](/home/raven/score/apps/server/src/domain/orchestration/store.ts:292) are outside that accounting. Enlarging the attempt multiplier does not define ownership, bounded ongoing writes or cleanup. Showing replay floors honestly exposes loss, but does not establish a retention policy.

**Change:** Define the quota’s complete inventory, charge retained copies and bounded control history, and release charges only when covered data is removed or transferred to another explicit quota. Specify protected obligation evidence and the retention policy for Watch/media and definitions. Test saturation during result acceptance and Stop, plus cleanup of associated data.

## The design I would approve

- Share the corrected admission, dispatch, Stop and abandonment machinery, with a separate durable workflow control projection.
- Define planner command ownership, receipt generations and atomic node/step associations.
- Keep graph tokens, local gates, skips and consumed results distinct from success-only executor dependencies; use a strict graph-terminal Finish predicate.
- Bind every assignment to frozen mappings and supported node parameters; preserve logical retry limits and explicit abandonment-to-Retry decisions.
- Retain the acknowledgement and conservative unknown states. Require canonical termination provenance, honest spend completeness and consistently scoped Watch evidence.
- Complete §15’s schemas, events, revisions and ownership transitions, plus quota/retention rules and recorded-fixture tests for these counterexamples, before building the editor.
