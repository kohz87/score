# Design review: 2.18 Permissions and team rules (lead, 2026-10-08)

Codex was out of credits, so the lead did the adversarial design review that PLAN requires before 2.18. Sources:
`../reference/hermes-agent/hermes_cli/config_defaults.py` (`approvals`, `command_allowlist`), `tools/approval.py`
(`_persist_choice`, permanent set), `tools/approval_detection.py`.

## Hermes's model

- Dangerous terminal commands are detected by fixed pattern categories (`detect_dangerous_command` → `pattern_key`).
- `command_allowlist` (per profile): pattern keys that never ask. Hermes itself appends to it when anyone answers
  "always" (`_persist_choice` snapshots the whole permanent set and saves it).
- `approvals.deny` (per profile): case-insensitive fnmatch globs against the command; a match blocks even under
  `--yolo` / `mode: off`.
- `approvals.mode`: `smart` (default; a guardian LLM approves, denies or escalates to a human), `manual` (always asks a
  human), `off` (never asks). Unattended contexts (`cron_mode`, `single_query_mode`, `unattended_mode`) deny by default.

## Mapping (decision)

| Score          | Hermes                                                                |
| -------------- | --------------------------------------------------------------------- |
| Go ahead       | pattern keys in `command_allowlist`                                   |
| Ask me         | dangerous pattern categories not in `command_allowlist` (the default) |
| Never          | globs in `approvals.deny`                                             |
| Approval style | `approvals.mode` shown and editable (`manual` / `smart` / `off`)      |

## Findings and decisions

1. **High — "Ask me" is not guaranteed under `smart`.** The guardian may approve a dangerous command without a human.
   _Decision:_ Score shows the mode on the rules screen with plain consequences ("Ask me = a guardian decides first and
   asks you only when unsure"), offers `manual`, and never labels `smart`'s behaviour as "asks you".
2. **High — Never-globs are evadable.** fnmatch on raw command text misses aliases, `command …`, extra spaces, subshells.
   _Decision:_ present "Never" as guardrails, not a security boundary; a short note in the UI; normalise whitespace
   in the globs Score writes (`*git* push* --force*` style suggestions only, never auto-generated broad globs).
3. **High — concurrent writers to `command_allowlist`.** Hermes appends on "always" answers.
   _Decision:_ Score writes via `hermes -p <p> config set command_allowlist <json>` with read → modify → write → re-read
   verify; if the re-read differs from what Score wrote in a way that drops an entry it didn't remove, retry the merge
   (≤ 3) and otherwise report a conflict. Same for `approvals.deny`.
4. **Medium — team vs per-agent ("stricter only").** _Decision:_ team rules are the baseline applied to every profile;
   a per-agent change may only remove Go-ahead keys or add Never globs relative to the team baseline (400 otherwise, the
   contract's rule). Profiles created later don't inherit automatically: the rules screen shows drift per profile with
   "Apply team rules".
5. **Medium — valid keys.** _Decision:_ Go-ahead entries must be known pattern keys from the tested Hermes version
   (a list pinned with the compatibility fingerprint, D2.2); unknown keys from Hermes's own config are shown read-only.
6. **Low — unattended modes.** Ask-me in cron / `-q` / unattended contexts means "blocked". _Decision:_ the UI says so.
7. **Never write secrets or anything outside these keys:** `command_allowlist`, `approvals.deny`, `approvals.mode`.
