## v3.1 amendments
1. **Journal compaction:** entries whose attempts are reconciled (terminated and recorded in the DB) are compacted away
   daily; unresolved entries are never dropped; the journal has a size alarm at 50 MB.
2. **The capability also lands in Hermes's own session history** (it's part of the lead's user turn). Accepted: it is
   bearer authority only until its attempt ends; the lead attempt's session is per attempt; redaction applies to anything
   Score stores or shows.
3. **Permission for orch tools:** `orch.*` tools require the agent's MCP access switch **and** an active orchestration
   capability; they do not depend on the writes switch (which keeps governing rooms.post / tasks.comment /
   knowledge.write). The start screen's preflight checks MCP access for the lead.
4. Hermes loads new MCP tools in a new session or after `/reload-mcp`; lead attempts use fresh sessions, so new `orch.*`
   tools are always visible to them.

## v3.2 (after Codex's v3 review, `2026-10-10-7.5-orchestrator-v3-codex.md`: 1 high, 7 medium)
1. **Compaction keeps tombstones:** the journal keeps, permanently and outside the home, a monotonic sequence plus one
   compact tombstone per admission (attempt id, send_started seq, final state) and per fence (Stop, Finish, Pause,
   Cancel, global); compaction drops detail only. Startup compares the DB against the tombstones, so a database older than
   any tombstone is detected even after compaction. Every transition that could restore admission authority if rolled
   back (finish, pause, cancel fence, waiver, abandonment, fence lift) is journaled. Compaction is crash-safe (write new
   file, fsync, rename, fsync dir). Tests: DB-only restore after compaction; restore across Finish/Pause without a
   further dispatch.
2. **Approval at assignment:** under `lead-asks`, approval is requested in the same call (`orch.assign({…,
   needsApproval: true})`); `orch.requestApproval` is refused for an admitted step (`already_admitted`).
3. **MCP manifest:** Hermes caches MCP tool lists per server connection; after deploying new tools the lead's profile
   needs `/reload-mcp` (or a gateway restart). Preflight `tool_readiness` lists the lead's visible tools via Hermes
   (`hermes mcp test score` equivalent through the adapter) and fails with "reload MCP" when `orch.*` are missing.
4. Mediums 3, 5–8: implement as the review states (capability recovery = new generation, old one revoked atomically;
   settlement only with closed lineage evidence, else provisional; ownership transition table enforced in code and
   tested; reservation formula covers retained Stop/obligation records and live updates; Watch scope stays documented as
   not done in 7.5a).
