1. **P1 — No durable protocol connects Hermes mutation to Score selection.** Design: “Score data model” and “Hermes side,” particularly [lines 59–71](/home/raven/score-worktrees/10.15-design/docs/briefs/10.15-swipe.md:59). Hermes can commit B, then Score can crash before recording B as selected; restart shows A while the agent holds B. Regeneration also has an uncovered interval after rewind but before dispatch, and no policy for failure or Stop. The existing [broker is in memory](/home/raven/score-worktrees/10.15-design/apps/server/src/hermes/bridge/rewind-broker.ts:41), and the plugin’s [result cache is process-local](/home/raven/score-worktrees/10.15-design/hermes-plugin/score_bridge/commands.py:105).

   **Change:** Specify a persisted operation journal containing source/target selection revisions, exact transcript manifests, command/run identities and operation phases. Persist a room hold before mutation and restore it before dispatch on startup. Reconcile Hermes against the recorded source, target or pre-turn baseline; commit the matching outcome, otherwise expose an unresolved state. Expiry alone must not release an uncertain operation. Define failure/Stop recovery without discarding the attempted alternative or falsely restoring the old selection.

2. **P1 — `replace_messages` does not atomically enforce `fromUids`.** Design: “Hermes side — `swap_turn`.” The [API accepts no expected transcript revision or suffix](/home/raven/reference/hermes-agent/hermes_state_messages.py:807). A bridge check followed by replacement leaves a race: another writer appends between those operations, then replacement silently archives that unseen row. The lease/compression checks do not prove that the transcript still matches the snapshot; [ordinary appends need not check a turn lease](/home/raven/reference/hermes-agent/hermes_state_messages.py:234).

   **Change:** Require a Hermes-owned atomic compare-and-swap API that validates the expected active transcript, prefix and compression generation inside the replacement transaction. Call it only through `hermes_private.py`. Until that API exists, refuse swapping; do not implement the missing transaction with bridge-owned SQL.

3. **P1 — Archive-mode replacement can retain rows from the wrong alternative.** Same design section. Hermes’s [common-prefix matcher](/home/raven/reference/hermes-agent/hermes_state_messages.py:860) compares role, content and tool-call fields, ignoring reasoning, `api_content` and alternative identity. If A and B start with identical text but different reasoning/provider content, selecting A can retain B’s opening rows. An isolated probe of this function also confirmed that it stamps B’s live UID onto the requested A row.

   **Change:** The atomic swap API must preserve only the verified **pre-turn prefix** and replace the complete alternative block, even where text matches. Preserve the full canonical row payload and identities. Store immutable row-version handles/digests: `message_uid` alone does not distinguish archived physical copies produced by repeated replacement or compaction.

4. **P1 — “After the last user turn” is not the complete reply-turn.** Design: [`capture_turn` and regeneration](/home/raven/score-worktrees/10.15-design/docs/briefs/10.15-swipe.md:61). Hermes counts user-originated steers and repaired/merged user turns, not Score replies; see [rewind’s target resolution](/home/raven/reference/hermes-agent/hermes_state_rewind.py:65). For `person input → tool calls/results → /steer → final answer`, capture records only the suffix after `/steer`. Swapping back can restore the answer without its original steering and tool history. Rewinding “exactly one” Hermes user turn is likewise not necessarily rewinding one Score reply.

   **Change:** Record an admission checkpoint identifying the original input UID, exact pre-turn prefix and resolved session generation. Capture the entire execution delta against that checkpoint. Regenerate from the original frozen admission payload and attachments. Refuse turns whose complete boundary cannot be established.

5. **P1 — Pending transcript drains can resurrect a deselected alternative or be lost.** Design: “Hermes side,” idle/lease checks. Gateway transcript writes can remain in [retry queues and disk spools](/home/raven/reference/hermes-agent/gateway/session_transcript.py:129). An idle session can therefore be swapped successfully, then acquire old alternative rows when a backlog drains or the gateway restarts. Conversely, copying rewind’s [_clear_dirty_transcript behavior](/home/raven/reference/hermes-agent/gateway/session_transcript.py:448) drops queued messages.

   **Change:** Make successful draining and verified quiescence of pending transcript writes a prerequisite to capture, rewind and swap. Include disk-spool recovery and compression reroutes. If the backlog cannot be reconciled, refuse visibly and preserve it. Delayed writes must be associated with their transcript generation so they cannot enter a replacement branch.

6. **P1 — A recorded coding session ID is not a pre-turn checkpoint; expiry can silently erase context.** Design: [scope item 3](/home/raven/score-worktrees/10.15-design/docs/briefs/10.15-swipe.md:26). Score currently [resumes the same mutable session](/home/raven/score-worktrees/10.15-design/apps/server/src/runtimes/coding/service.ts:1370). Recording its ID before A does not stop A extending it. Claude’s documented `--fork-session` creates a new ID when resuming; that flag alone does not select an earlier transcript position. [Claude CLI reference](https://code.claude.com/docs/en/cli-reference)

   There is also an existing [unknown-session fallback that forgets the ID and starts fresh](/home/raven/score-worktrees/10.15-design/apps/server/src/runtimes/coding/service.ts:1642). Reusing it for regeneration would produce an apparently valid alternative without the promised prefix.

   **Change:** Require an immutable pre-turn fork or a verified exact checkpoint, with evidence for each supported CLI version. Disable the fresh-session fallback whenever branch continuity is required. Missing baseline or alternative sessions must leave the current selection intact and report unavailability. A fresh session is valid only for a recorded empty baseline.

7. **P1 — Visible recency does not establish that an alternative has no consumers.** Design: scope item 1 and the select conflict rule. A lead summary can be queued with A’s text already frozen in its [admission input](/home/raven/score-worktrees/10.15-design/apps/server/src/domain/room-summaries.ts:179), before its reply placeholder exists. The builder is idle and A remains the latest visible reply, so selection can change to B. The queued summary later publishes A’s content and feeds it back as context. Existing stale detection can miss this because [it tests deletion after the summary’s creation time](/home/raven/score-worktrees/10.15-design/apps/server/src/domain/summary-stale.ts:77). Hand-offs similarly [reserve work before their visible hand-off event](/home/raven/score-worktrees/10.15-design/apps/server/src/domain/message-runs.ts:674).

   **Change:** Define the boundary through causal consumption and room revisions, including pending work, frozen summary inputs and reserved hand-offs. Freeze the producer when its output is consumed, or atomically retire/rebuild every provably unstarted consumer. Validate input revisions again at admission and summary completion. Serialize selection against room writes and admissions throughout the operation.

8. **P2 — Alternatives need explicit integration with rewind, versions and deletion.** Design: “Score data model,” hiding/unhiding through `deleted_at`. [Rewind counting uses completed `message_runs`](/home/raven/score-worktrees/10.15-design/apps/server/src/domain/versions.ts:179). Three alternatives can leave three run records but only one live Hermes user turn, causing `turn_count_mismatch` unless active membership is updated. Reselecting an older alternative also needs to distinguish its restored membership from historical `rewound_at`. Separately, clearing `deleted_at` must not resurrect a message hidden by explicit deletion or a room version.

   **Change:** Separate selection visibility from turn deletion/version membership. Define active Hermes-turn accounting across regeneration and reselection. A room version must retain the turn’s alternatives read-only; selection must never clear its deletion/version tombstone.

9. **P2 — Hiding messages cannot provide the promised selected-only memory/Knowledge behavior.** Design: [lines 46–48](/home/raven/score-worktrees/10.15-design/docs/briefs/10.15-swipe.md:46). If A writes a memory or Knowledge note, selecting B leaves that note available to later runs. Existing rewind explicitly preserves long-term memory, and [compaction memory notes are independent vault writes](/home/raven/score-worktrees/10.15-design/docs/API-CONTRACT.md:1398).

   **Change:** Limit the guarantee to the active transcript and frozen admission context, and explicitly include memory/Knowledge writes among persistent effects. Record provenance for derived material and invalidate internal summary projections by selection revision. Preserve historical notes; do not silently delete them or promise that `deleted_at` retracts them.

10. **P2 — The proposed stream does not specify how another client restores the selected message.** Design: contract/stream paragraph. A second tab may contain only A. Selecting previously hidden B deletes A, but today’s [`message.updated` reducer only updates existing entries](/home/raven/score-worktrees/10.15-design/apps/web/src/routes/chat/queries.ts:128). The new event carries only `selectedIndex`, so neither existing event restores B’s content.

    **Change:** Specify either an atomic turn-replacement event carrying the complete selected `Message`, or mandatory sequence-fenced refetching on alternative changes. Give alternatives reads a snapshot watermark. Define a stable logical turn position and whether selection revisions become unread, rather than inheriting accidental behavior from each alternative’s creation timestamp.

Direct answers to the design’s questions:

- **Latest reply-turn in group rooms:** A sensible conservative restriction, but insufficient without the causal rules above. Include queued consumers and all pending/active room work. A turn’s own tool/approval cards belong to that turn; they should not accidentally freeze it. Placeholder creation order and completion order also differ.
- **Archived-row reinsertion versus compaction, memory flush and drains:** Not safe through the proposed call alone. Require atomic expected-state checks, exact alternative replacement, complete row preservation and drained backlogs. Detect in-place compaction as well as session rotation. Persistent memory effects remain.
- **Gateway/Score restart:** Hermes’s individual SQLite mutation is atomic; the distributed operation is not. Hermes establishes what actually committed, while Score’s durable intent establishes what was requested. Match the observed transcript to the recorded operation and finish reconciliation before admitting work. Neither database should silently win an unexplained conflict.
- **Downstream consistency:** FTS and exports already follow `deleted_at`; their existing triggers/filters are suitable. Summaries require input-revision validation. Read receipts need explicit turn/revision semantics. Run approvals normally close at terminal completion; preserve the ledger’s `unknown`/possibly-applied delivery outcomes and never reopen approvals on reselection. Watch and Reports should retain all real executions, linked to their alternatives. Apply ownership guards to both Retry and Select; freeze hand-off producers when consumed.
- **Coding runtimes and expired stores:** Claude’s stated invocation is insufficient. This checkout implements resume for Codex and conversation resume for Antigravity, with no verified pre-turn fork mechanism. Keep unsupported combinations unavailable until recorded fixtures prove them. Expiry must disable the affected operation with a reason, preserve alternatives and prevent silent fresh-context fallback.

The restricted v1 scope is sensible.  
Soft archiving and refusing missing history are sound durability choices.  
Keeping private calls in `hermes_private.py` and mutations inside Hermes’s own APIs respects both boundaries.  
Excluding journaled executions and acknowledging persistent tool effects are sound.
