1. **P1 — Save responses discard edits made during saving.** [Customizer.tsx:412](/home/raven/score-worktrees/9.4/apps/web/src/routes/customizer/Customizer.tsx:412)  
   Controls remain editable while saving. If someone changes corners while the request is pending, the response replaces the entire current manifest with the submitted manifest, removes that change, and clears “Unsaved changes.” I reproduced this state transition. **Fix:** preserve edits made after submission and set the baseline to the submitted snapshot, or disable editing during the operation. Test with a delayed save response.

2. **P1 — ZIP saves can silently overwrite concurrent changes.** [Customizer.tsx:397](/home/raven/score-worktrees/9.4/apps/web/src/routes/customizer/Customizer.tsx:397)  
   Conflict checking is a GET followed by an unconditional `import?replace=1`. Two editors can both pass the GET check, then overwrite each other; the import request carries no etag. This affects imported themes and themes containing assets. **Fix:** use Save as new for these edits under the current API; in-place replacement needs an atomic server-side etag check and corresponding contract change.

3. **P2 — Saving an active theme applies it before “Use.”** [Customizer.tsx:423](/home/raven/score-worktrees/9.4/apps/web/src/routes/customizer/Customizer.tsx:423)  
   Save updates the existing ID and invalidates all theme queries. For an active custom theme, `LookRuntime` refetches that detail, applies it outside the preview, and updates the boot cache. Other devices pick it up on refresh. This violates the lead note requiring Save + Use. **Fix:** save an active theme’s changes under a separate revision/copy until Use selects it. Test isolation while editing an already-active custom theme.

4. **P2 — Replacing an uploaded picture or font can do nothing.** [draft.ts:385](/home/raven/score-worktrees/9.4/apps/web/src/themes/customizer/draft.ts:385)  
   Draft equality compares upload paths but ignores their bytes. Uploading a second PNG uses the same `img/background.png` path, so `edit()` discards it when the manifest is unchanged. I reproduced the old bytes remaining and `dirty === false`. The same issue affects replacement font faces. **Fix:** compare the immutable byte-array identities or content hashes, and test replacement at an existing path.

5. **P2 — Valid license files are rejected or lost.** [package.ts:31](/home/raven/score-worktrees/9.4/apps/web/src/themes/customizer/package.ts:31), [package.ts:74](/home/raven/score-worktrees/9.4/apps/web/src/themes/customizer/package.ts:74)  
   The importer rejects `LICENSE` and `OFL.txt`, although §16 permits them; I reproduced the `OFL.txt` rejection. The package model/writer also cannot preserve them, so customizing/exporting a font-bearing installed theme can strip its license. **Fix:** validate and retain both license files throughout loading, copying, saving, and exporting; obtain them through the existing export endpoint.

6. **P2 — Glass contrast checks can report unreadable text as readable.** [measure.ts:61](/home/raven/score-worktrees/9.4/apps/web/src/themes/customizer/measure.ts:61)  
   Glass uses `color-mix()`, whose computed background is `color(srgb …)`. `parseColor()` returns null for that form, so the checker skips the glass layer. A targeted reproduction with a 70% white glass layer over black and `#b0b0b0` text returned no findings despite approximately **1.03:1** actual contrast. **Fix:** parse computed color forms before compositing; test actual glass styles rather than only manually supplied RGBA layers.
