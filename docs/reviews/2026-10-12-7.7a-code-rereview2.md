The remaining failures and newly identified gaps follow. The fallback-proof, pidfd-stop and unit-waiver findings include regressions from the second fix round.

1. **P1 — R3: rejected Codex records still allow success.**  
   [codex.ts:167](apps/server/src/runtimes/coding/codex.ts:167), [codex.ts:139](apps/server/src/runtimes/coding/codex.ts:139).

   A valid candidate followed by a malformed `command_execution` and `turn.completed` produced `unknown: 1`, `lossReason: null`, and `eligible: true`. A malformed `turn.failed` after success did the same. The fix protects message records, but does not implement “any dropped record.”

   **Fix:** make rejection of recognized records sticky across the entire attempt, including malformed terminal records, and finalize authority only after complete stdout processing.

2. **P1 — R5: production restore and journal fences still permit execution.**  
   [start-server.ts:388](apps/server/src/start-server.ts:388), [service.ts:1222](apps/server/src/runtimes/coding/service.ts:1222).

   The callback requires a fence item whose reference starts with `coding`. Restore markers, `journal`, and `journal-root` do not qualify. A probe using the production callback returned `block: null` with a restore fence up, then successfully appended `releasing`.

   **Fix:** make unresolved journal history, restore uncertainty and installation uncertainty mandatory admission barriers for both backends, including inside release.

3. **P1 — R6/new regression: proof for fallback attempt A ends live attempt B.**  
   [service.ts:1405](apps/server/src/runtimes/coding/service.ts:1405), [service.ts:1213](apps/server/src/runtimes/coding/service.ts:1213), [service.ts:1354](apps/server/src/runtimes/coding/service.ts:1354).

   Restore a backup containing attempt A’s process row after a refused resume has advanced the same run to attempt B. External recovery skips B because *some* process row exists for the run. Normal recovery proves A gone; `forgetProcess()` then calls `endFallback()` for every open launch of that run.

   The probe inspected only A’s identity, marked B `ended`, deleted the process projection, and left admission unblocked. B’s surviving tools need never be inspected.

   **Fix:** associate process projections and proof with launch ID/generation and exact identity. Merge external member evidence even when a database row exists. End only the launch whose processes were proven gone.

4. **P1 — R10: restoring a confirmed copy reopens inherited unwitnessed intents.**  
   [coding-checkpoint.ts:209](apps/server/src/domain/orchestration/coding-checkpoint.ts:209), [fence.ts:589](apps/server/src/domain/orchestration/fence.ts:589), [fence.ts:596](apps/server/src/domain/orchestration/fence.ts:596).

   When the source has no coding launch witness yet, first-start retirement writes only SQLite and consumes the copy marker. Restore that copied backup later: the intent becomes pending again, the restore marker has origin `restore`, and no permanent inherited-turn witness blocks it. The probe retired the intent, simulated restoration, then admitted and released it again.

   Copy handling also passes its retirement flag only into coding reconciliation; unwitnessed orchestration attempts are not retired.

   **Fix:** durably record the exact inherited execution-intent identities before publishing an admissible copy or consuming its marker. Recovery must enforce those retirements after every restore.

5. **P1 — A4: fallback stderr still leaks labeled secrets.**  
   [process.ts:305](apps/server/src/runtimes/coding/process.ts:305), [service.ts:1072](apps/server/src/runtimes/coding/service.ts:1072).

   The fallback retains the last raw stderr bytes. `password=` plus a 10,000-character value loses its label; later redaction preserves the secret tail. The probe confirmed the retained text had no label and still leaked after `redactBounded`.

   **Fix:** use the safe diagnostic accumulator on both backends, preserving redaction context and discarding overflow.

6. **P1 — Newly identified: a confirmed copy signals source fallback processes without journal launches.**  
   [coding-checkpoint.ts:194](apps/server/src/domain/orchestration/coding-checkpoint.ts:194), [service.ts:1698](apps/server/src/runtimes/coding/service.ts:1698), [service.ts:1717](apps/server/src/runtimes/coding/service.ts:1717).

   `retireInherited()` removes process projections only for imported launches. A copied process row from the pre-journal fallback has no such launch. Normal recovery signals it without checking installation ownership. The probe applied copy retirement with empty launch history, then observed a stop call for the source group.

   **Fix:** classify and retire all inherited process projections from the copied snapshot, including legacy rows. Require owned execution evidence before recovery signals anything.

7. **P1 — Newly identified: restored supervised launches can have invisible holds.**  
   [unit-backend.ts:1419](apps/server/src/runtimes/coding/unit-backend.ts:1419), [unit-backend.ts:1205](apps/server/src/runtimes/coding/unit-backend.ts:1205), [service.ts:1513](apps/server/src/runtimes/coding/service.ts:1513).

   If restoration loses both launch and run rows, routing reconstruction cannot obtain `agent_id`. Recovery sets `held = 1`, but `held(agentId)` requires an exact agent match. Unlike fallback recovery, there is no installation-wide hold for unattributed units.

   The probe had a populated recorded cgroup and a held launch, but returned no visible hold and `hasUnresolvedGroup('builder') === false`.

   **Fix:** persist unit routing outside SQLite and fence all coding admission when an unresolved owned launch cannot be attributed.

8. **P1 — New regression: pidfd stopping proceeds without a proven current boot.**  
   [unit-backend.ts:950](apps/server/src/runtimes/coding/unit-backend.ts:950).

   The code rejects only a *known different* boot. Missing recorded or current boot identity falls through to signaling. PID/start-time pairs can recur across boots, so a restored identity can identify a foreign process. This path also makes no manager-incarnation or current unit-identity check.

   The probe issued a signal with current boot unreadable and made zero manager/unit reads.

   **Fix:** require a known matching boot before opening/signaling the recorded target, and perform the required incarnation and ownership checks. Missing identity must remain uncertainty.

9. **P1 — Newly identified: fallback completeness accepts an unterminated success record.**  
   [process.ts:353](apps/server/src/runtimes/coding/process.ts:353), [service.ts:1065](apps/server/src/runtimes/coding/service.ts:1065).

   The fallback parses the final partial line as a complete record. Its `complete` flag checks only ingestion failure. A Claude success JSON value without a terminating newline produced an eligible verdict, exit zero and `groupGone: true`.

   Read errors are also swallowed by the launcher.

   **Fix:** return explicit stream completeness from `spawnCli`; partial stdout, read failures and dropped records must disqualify completion.

10. **P1 — Newly identified: queuing ACK is treated as proof it was exchanged.**  
    [coding-socket.ts:446](apps/server/src/runtimes/coding/coding-socket.ts:446), [coding-socket.ts:467](apps/server/src/runtimes/coding/coding-socket.ts:467), [unit-backend.ts:1032](apps/server/src/runtimes/coding/unit-backend.ts:1032).

    `ackSent` becomes true before the write completes. If that queued ACK is lost, closure is classified as normal. The supervisor exits for socket loss, but ended proof accepts an inactive or failed unit; successful supervisor termination is not checked. The boundary probe returned `eligible: true` with ACK undelivered.

    **Fix:** distinguish queued and flushed ACK, and establish that the recorded supervisor received it and completed normally before eligibility. A pre-ACK ended receipt cannot establish normal terminal close.

11. **P1 — Newly identified: a deadline after `end` disappears from the verdict.**  
    [supervisor.mjs:265](apps/server/src/runtimes/coding/supervisor.mjs:265), [supervisor.mjs:484](apps/server/src/runtimes/coding/supervisor.mjs:484), [supervisor.mjs:584](apps/server/src/runtimes/coding/supervisor.mjs:584).

    While waiting for Score to finish ingestion and ACK, the deadline timer still calls `requestStop('deadline')`. With the child exited, it updates only private state. The already-sent `end` and written receipt retain `stopCause: null`; ACK still exits zero.

    With a 50 ms deadline and delayed ACK, the probe exited normally after about 170 ms, with no error frame and no recorded stop cause.

    **Fix:** a stop incurred after `end` must durably invalidate the terminal candidate and notify Score before normal acknowledgment can complete.

12. **P1 — Newly identified: CLI tool names bypass redaction.**  
    [translate.ts:230](apps/server/src/runtimes/coding/translate.ts:230), [translate.ts:238](apps/server/src/runtimes/coding/translate.ts:238).

    Eligibility-note redaction does not cover other CLI metadata. A valid tool event with `tool: "password=review-sentinel"` stored that value verbatim in both `tool_calls.tool` and `runs.tools_used` in the transactional probe.

    **Fix:** redact human-readable CLI metadata before bounding or persisting it, including tool names and their derived aggregates.

13. **P1 — Newly identified: loss of the whole journal can look fresh after restoration.**  
    [journal.ts:326](apps/server/src/domain/orchestration/journal.ts:326), [fence.ts:610](apps/server/src/domain/orchestration/fence.ts:610), [unit-backend.ts:1363](apps/server/src/runtimes/coding/unit-backend.ts:1363).

    A missing journal reads as an empty valid journal. Restore SQLite to before launch, lose `journal.ndjson`, and let the finished unit be collected: startup sees neither database witnesses nor live units. Recovery never enumerates surviving launch/identity/receipt files. The probe remained unfenced and allowed another request for the turn.

    **Fix:** retain durable evidence that a namespace has execution history, reconcile the union of journal, database, units and launch files, and fence unowned launch files or missing expected journals.

14. **P2 — R11: cutover validation still loses non-dispatch authority.**  
    [journal-migration.ts:217](apps/server/src/domain/orchestration/journal-migration.ts:217), [journal-migration.ts:259](apps/server/src/domain/orchestration/journal-migration.ts:259).

    Authorization, hold, remap, global-fence and run-handle records are not covered by the witness checks. A probe retaining the send and checkpoint but removing a tightened authorization returned `ok: true, state: "already"`. Reconciliation then reads only the destination and misses the lost limit.

    **Fix:** verify every retained authority-bearing record against a covering successor or permanent disposition, and consult retained legacy evidence during reconciliation.

15. **P2 — A8: restored process rows defeat permanent fallback waivers.**  
    [service.ts:1386](apps/server/src/runtimes/coding/service.ts:1386), [service.ts:1717](apps/server/src/runtimes/coding/service.ts:1717).

    External recovery skips the waived launch, but the independent database-process loop still stops a resurrected process row. The probe observed another stop call after applying durable waiver evidence to an older projection.

    **Fix:** retire waived process/member projections before recovery inventories are captured, and check journal disposition before every recovery signal.

16. **P2 — New regression: unit Release creates its own journal mismatch.**  
    [unit-backend.ts:1239](apps/server/src/runtimes/coding/unit-backend.ts:1239), [coding-records.ts:170](apps/server/src/domain/orchestration/coding-records.ts:170).

    Waiver sets SQLite `proof = 'waiver'`; the journal waiver carries no such proof. Immediately after Release, the probe’s `verifyCoding()` reported a proof divergence. The next start unnecessarily fences coding again.

    **Fix:** keep waiver projections identical to journal state. Represent waiver separately from ended proof.

17. **P2 — R14: several stop paths still have no durable first cause.**  
    [supervisor.mjs:265](apps/server/src/runtimes/coding/supervisor.mjs:265), [coding-socket.ts:234](apps/server/src/runtimes/coding/coding-socket.ts:234), [process.ts:265](apps/server/src/runtimes/coding/process.ts:265).

    Supervisor deadlines/socket loss, socket overflow/ingestion failure, and fallback timeouts bypass `CodingJournal.recordStop`. Death before the eventual ended receipt loses their causes. Explicit stop recording also catches failures and signals anyway.

    **Fix:** give all Score stop paths a common durable recording hook and autonomous supervisor stops an external first-cause receipt. Failed recording must remain visible uncertainty through recovery.

18. **P2 — R15: retained state exceeds its reservation by tens of megabytes.**  
    [codex.ts:27](apps/server/src/runtimes/coding/codex.ts:27), [translate.ts:221](apps/server/src/runtimes/coding/translate.ts:221), [coding-socket.ts:503](apps/server/src/runtimes/coding/coding-socket.ts:503).

    Limiting sets/maps to 1,024 entries does not bound their values. Sixty-four accepted records with large IDs retained approximately 30 MiB in the parser while the installation budget charged 0.5 MiB. Tool details and candidate replies can also exceed the reservation.

    **Fix:** bound individual retained values and charge actual retained bytes, including pending terminal delivery state, until those buffers are released.
