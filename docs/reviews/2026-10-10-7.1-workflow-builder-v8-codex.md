### [high] H grants runtime provenance to legacy recovered completions

**Where:** [H’s NULL rule](/home/raven/score/docs/briefs/fix-h-orchestrator.md:8), [recovered completion writer](/home/raven/score/apps/server/src/hermes/live/translate.ts:499), [executor reconciliation](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:1335).

**What happens:** Before upgrade, an owned run receives `404` and matching assistant text. Score stores `completed` without provenance. After H, NULL means “legacy runtime,” so reconciliation can accept that text, release execution obligations and admit successors.

**Why:** This is precisely the old synthetic completion H is supposed to reject. Adding provenance to future writes does not establish the source of existing rows. Already accepted false results also need consideration.

**Change:** Backfill provenance from attributable observation records; treat unproved owned legacy attempts as unknown and fence affected execution. Reconcile already accepted results and released obligations conservatively. Add upgrade fixtures containing both unreconciled recovered completion and previously accepted synthetic success.

### [high] Manual Pause disappears while a budget pause is active

**Where:** [Independent-holds guarantee](/home/raven/score/docs/briefs/7.5-orchestrator.md:84), [Pause](/home/raven/score/apps/server/src/domain/orchestration/decisions.ts:156), [limits update](/home/raven/score/apps/server/src/domain/orchestration/decisions.ts:144).

**What happens:** A budget-paused run receives a valid paired Pause request. Pause succeeds without recording a manual hold. Raising the budget then changes the run to `running`, allowing queued work without Resume.

**Why:** Pause returns immediately whenever status is already `paused`; one `pause_reason` cannot represent independent holds. A memory-only probe confirmed this sequence. H’s journaling requirement cannot preserve a hold that was never recorded.

**Change:** Persist manual hold independently from budget and other admission conditions. Limits changes clear only their corresponding condition; Resume clears only the manual hold. Journal the resulting authorization revision. Test both ordering permutations and restoration after the overlapping holds.

### [medium] Remapping does not define replacement of an existing frozen assignment

**Where:** [H remapping](/home/raven/score/docs/briefs/fix-h-orchestrator.md:18), [v8 mismatch classification](/home/raven/score/docs/briefs/7.1-workflow-builder.md:24), [frozen gate payload](/home/raven/score/apps/server/src/domain/orchestration/commands.ts:360), [send-time mismatch](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:1153).

**What happens:** An assignment for incarnation A is approved; the agent becomes B before sending. Updating the run mapping leaves the existing step, attempt and gate bound to A. Keeping them unchanged strands the node; rewriting them silently uses approval of a different payload.

**Why:** H specifies updating the run mapping, not disposition of existing assignments. V8 also calls mapping mismatch a permanent failure while separately promising that the node waits for remapping.

**Change:** Define a remappable waiting state. For provably unsent work, revise or replace the assignment, withdraw the old gate and require approval of the new frozen payload under `every-step`. Preserve obligations for possibly sent work. Specify assignment-slot and retry accounting, including legacy runs without a provable initial mapping. Test remapping after approval and crashes around that transaction.

### [medium] Waiting nodes lack a complete durable wake protocol

**Where:** [v8 wake-only passes](/home/raven/score/docs/briefs/7.1-workflow-builder.md:24), [cause cursor](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:907), [limits mutation](/home/raven/score/apps/server/src/domain/orchestration/decisions.ts:125), [wake-source settlement](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:833).

**What happens:** A pass consumes its cause and leaves a node ready but waiting for budget or capacity. Raising the budget, releasing another run’s capacity, resuming an agent, or lifting a fence does not necessarily create another durable cause. The unchanged executor can also pause with `no_wake_source` because it does not inspect workflow readiness.

**Why:** Calling `kick()` or performing a periodic sweep does not create a cause beyond the consumed cursor. Workflow waiting state introduces obligations the current settlement predicate cannot see.

**Change:** Define durable wakes or persisted resource revisions for every mutable admission condition. Include workflow obligations in settlement and startup recovery. Test capacity released by another run, each hold/fence release, and restart between a condition change and planner execution.

### [medium] The 32 KB instruction limit does not bound the actual dispatched payload

**Where:** [v8 transported parameters](/home/raven/score/docs/briefs/7.1-workflow-builder.md:48), [assignment schema](/home/raven/score/packages/contract/src/orchestration.ts:483), [shared renderer](/home/raven/score/apps/server/src/domain/orchestration/render.ts:166).

**What happens:** Today’s assignment schema rejects instructions above 8 KiB. Raising that limit alone permits another failure: the renderer adds wrappers and then silently clips the entire payload at 32 KiB. A valid instruction can lose its final constraint after approval.

**Why:** V8 bounds the instruction rather than the final encoded request. A memory-only probe using a 32 KiB instruction confirmed that its final directive disappeared.

**Change:** Render and validate the final UTF-8 payload before freezing the assignment and presenting its gate. Reject oversized instructions or expose any permitted truncation before approval. Define the workflow-specific internal schema. Test multibyte text, quoting expansion and equality between approved instruction content and dispatched content.

### [medium] “Qualifying facts” do not exist in the inherited spend reader

**Where:** [v8 settlement rule](/home/raven/score/docs/briefs/7.1-workflow-builder.md:61), [spend reader](/home/raven/score/apps/server/src/domain/orchestration/budget.ts:24), [reservation release](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:1412).

**What happens:** A completed run with a dollar cost and no locally recorded open sibling is marked complete even without evidence that its compression lineage and cost observations are complete. Reservations are then released.

**Why:** The reader explicitly cannot see lineage forks. Its predicate checks local rows, not qualified closure, freshness or settlement. A memory-only probe returned `complete: true` without lineage facts. Hermes’s [native terminal usage](/home/raven/reference/hermes-agent/gateway/platforms/api_server_runs.py:88) supplies tokens rather than dollar cost.

**Change:** Explicitly replace this reader with an adapter-qualified evidence contract covering attribution, lineage completeness, freshness and cost scope. Without proof, keep spend provisional and reservations held. Unknown-spend acknowledgement must remain a risk decision, never settlement evidence. Test missing continuations, delayed costs and the actual token-only payload.

### [medium] Bounded records do not establish bounded retained storage

**Where:** [v8 reserve](/home/raven/score/docs/briefs/7.1-workflow-builder.md:66), [automatic unsent retry](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:1263), [history writes](/home/raven/score/apps/server/src/domain/orchestration/store.ts:292), [cleanup](/home/raven/score/apps/server/src/domain/orchestration/executor.ts:1581).

**What happens:** Repeated provably unsent failures create fresh attempt/input records without consuming logical execution retries. Pause/Resume and limits changes add unlimited history. Pruning orchestration rows releases their charge while associated intents, messages, runs and history remain.

**Why:** Eight KiB per transition bounds record size, not transition count. Admission increments stored bytes without enforcing available storage for each new attempt. Full [intent payload copies](/home/raven/score/apps/server/src/hermes/live/intents.ts:253) also sit outside the counter.

**Change:** Define the complete charged inventory, bounds or compaction for unsent attempts and control records, and protected space for Stop evidence. Release charges only after deletion or transfer to another explicit quota. Count retained definition versions. Test prolonged adapter unavailability, repeated controls, saturation and associated-row cleanup.

## The design I would approve

Keep v8’s separate graph projection, deterministic planner commands, local gates, strict Finish predicate and scope cuts, with these additional requirements:

- H upgrades legacy state conservatively and preserves independent manual holds.
- Remapping defines assignment retirement, renewed approval, retry accounting and durable wake generation.
- Workflow readiness participates in executor settlement and recovery.
- The approved payload is validated against the final wire limit.
- Settlement requires explicit adapter evidence; unavailable evidence remains provisional.
- Storage covers retained copies and bounds ongoing writes.
- Contract review and recorded-fixture tests cover these counterexamples before engine work. Include Abandon → Retry → successful replacement, ensuring the final projection preserves the executor’s unresolved outcome whenever the old execution remains unconfirmed.
